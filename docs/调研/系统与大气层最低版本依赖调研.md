# 家长控制基本功能与系统／大气层最低版本依赖调研

调研日期：2026-11-24。本文面向 PlayWise（任我玩）当前标准分发实现，梳理“家长控制”基本功能的底层依赖，并逐层核查官方固件（Horizon OS，简称 HOS）与大气层（Atmosphère）的最低版本要求。

## 结论速览

| 依赖项 | 代码硬性最低要求 | 仓库唯一已实测参考基线（`verified`） | 决定性原因 |
| --- | --- | --- | --- |
| **官方固件（HOS）** | **`21.0.0+`** | `22.5.0`（文档另注明 `23.0.1` 可用） | `platform/switch/pctl_adapter.c` 强绑定 PCTL 私有命令 `145601` / `195101` 与 **`0x44`（68 字节）**布局，无旧命令或 `0x36` 布局回退 |
| **大气层（Atmosphère）** | **`1.10.0+`**（且须匹配当前 HOS） | `1.11.2`（`23.0.1` 对应 `1.12.1`） | `1.10.0` 是首个支持 HOS `21.0.0`、21.0.0 TLS ABI，以及热加载/在线更新所用 `pm:shell` cmd `12`（`GetProcessId`）的版本 |
| **浮窗管理器（外部）** | Tesla / Ultrahand + `nx-ovlloader` | `Ultrahand 2.5.3` + `nx-ovlloader 2.0.2` | 手动浮窗兼容常规 Tesla；若启用实验性“游玩受限提醒”简要提示则最低需 **Ultrahand `v2.3.0+`** |

> [!IMPORTANT]
> **事实与未证明边界**：
> - **源码事实**：当前生产适配器在低于 HOS `21.0.0` 的固件上无法满足 `145601`/`195101` + `0x44` 契约，启动预检会失败并进入只读 `protection` 态；低于 Atmosphère `1.10.0` 无法引导 HOS `21.0.0+`，且缺少 `pm:shell` cmd `12`。
> - **静态推导（未真机实测）**：HOS `21.0.0–22.4.x` 配合对应 Atmosphère `1.10.0–1.11.1` 在接口与布局上满足当前代码门槛，但在代码中记为 `accepted_unknown`（需家长确认），本仓库尚未留存该区间的正式真机资格报告。
> - **已实测基线**：仅 **Nintendo Switch OLED + HOS `22.5.0` + Atmosphère `1.11.2`** 在 `sysmodule/sysmodule_setup.c` 中命中 `verified`。

## 一、“家长控制”基本功能与底层依赖映射

PlayWise 不在 CFW 层重实现锁屏或进程暂停，而是通过后台 sysmodule（Title ID `4200000000BD2300`，服务 `pctc:u`）、主机应用（`pctc.nro`）和游戏内浮窗（`playwise.ovl`）管理 Nintendo 官方家长控制服务（Horizon `pctl` / `pctl:s`）。使用前提为：主机已开启官方家长控制、未处于官方 PIN 临时解除状态，且系统时间准确（亮屏包括 HOME/设置均计入额度，待机休眠冻结）。

| 功能分组 | 具体能力 | 底层核心依赖 |
| --- | --- | --- |
| **四级每日总额度与当日调度** | `今日调整` > `指定日期额度` > `地区法定节假日日历`（内置 2026–2027 中国大陆，支持 JSON 导入） > `每周常规计划`；支持设置今日总额度、快速加时（+15/+30/+60/自定义 1–120 分）、今日不限时、清除今日调整 | `pctl` / `pctl:s`（`1006`/`1031`/`1035`/`1451`–`1455`/`145601`/`195101`/`1952`）、`time:u`、`fsp-srv`（SDMC） |
| **离线加时与自主缓冲** | 8 位 HMAC-SHA256 离线加时码（Switch 或手机/电脑离线网页生成，无需 Switch 联网，一次性防重放 `used_nonces.jsonl`）；可选每日一次 5/10/15 分钟自主缓冲 | 同上 + `randomGet` 密钥生成；无网络依赖 |
| **三大独立健康/作息关卡** | 1）**就寝时间（Bedtime）**：跨夜时段限制与跳过/关闭；2）**护眼休息提醒**：连续使用 1–240 分 / 休息 1–60 分周期，待机计入休息，支持 PIN 跳过；3）**电视模式规则**：仅电视模式（Switch Lite 禁止）或非电视每日限额（0–1440 分）及今日豁免。三项与每日总额度独立生效，加时不豁免 | PCTL `BLOCKED`/目标合成 + `omm`（cmd `0` 只读 `GetOperationMode`）+ `set:sys`（`GetProductModel` 识别 Lite） |
| **受限期游戏内浮窗** | 每日额度耗尽或就寝触发官方遮罩阻断 NRO 后，在游戏内呼出 `playwise.ovl` 供孩子兑换加时码/领缓冲，或家长凭任我玩 PIN 单次解限、跳过休息/就寝、恢复安装前设置 | `nx-ovlloader` + Tesla / Ultrahand + vendored `libtesla`（`vi`、`hid`、`hidsys`、`pl`、`pmdmnt`、`set`、`set:sys`、`time:u`、`pctc:u` / SD 队列） |
| **安全状态机与恢复** | 安装前完整 `0x44` + timer 快照保存与恢复；写入前像、30 秒回读确认与精确回滚；`disable.flag` 仅熔断控制写入并保留诊断/恢复；脱敏诊断包导出、十一组配置备份与选择导入、家庭活动/兑换历史与 7/30 天摘要 | `fsp-srv` 原子文件事务、独立 `auth.json`（任我玩 PIN）与 `credentials.json` |
| **可选增强功能** | 1）**相册高级入口限制**（改写 `override_config.ini` 限制从相册直接启动 hbmenu）；2）**免重启热加载 & 应用内在线更新**；3）**游玩受限提醒（实验，默认关闭）**（自有浮窗自动详情 + Ultrahand 简要提示） | 1）Atmosphère `override_config.ini`；2）`pm:shell` + `nifm`/`bsd`/`ssl` + `libcurl`；3）Ultrahand `v2.3.0+` `.notify` 协议 |

## 二、官方固件（HOS）分层最低版本要求

逐项核查 `platform/switch/`、`sysmodule/`、`companion/` 及 `../libnx` 后，各层门槛如下（按从高到低排列，**最终硬性门槛为 `HOS 21.0.0+`**）：

| HOS 门槛 | 涉及组件与源码位置 | 具体依据 | 低于该版本的行为 |
| --- | --- | --- | --- |
| **`21.0.0+`（核心硬性门槛）** | `platform/switch/pctl_adapter.c`（L20–L30、L138–L154、L486–L511）、`platform/switch/play_timer_settings_layout.h`（L8–L18） | 适配器固定调用 `145601`（`GetPlayTimerSettings`）与 `195101`（`SetPlayTimerSettingsForDebug`），并在编译期断言结构体大小为 **`0x44`（68 字节，34 个 `u16`）**。SwitchBrew `Parental Control services`（2026-11-24 核对）记录：`145601` / `195101` 于 `18.0.0` 引入（当时为 `0x36` 字节），于 **`21.0.0+`** 扩展为 **`0x44` 字节**。 | `< 18.0.0` 无 `145601`/`195101` 命令（旧固件为 `1456`/`1951`）；`18.0.0–20.5.0` 载荷长度（`0x36`）与布局不匹配。在 `sysmodule/sysmodule_setup.c`（L169–L172）预检失败（`pctl_backup_failed` / `pctl_layout_mismatch`），进入只读 `protection` 态，无法接管与控制。 |
| `21.0.0+`（TLS ABI 适配） | `docker/Dockerfile`（`devkitpro/devkita64:20260215`）、`libnx >= 4.10.0` | Nintendo 在 HOS `21.0.0` 破坏了 userland↔kernel TLS 保留区 ABI；构建所用 `libnx 4.12.x` 包含 `cad06c00`（`USER_TLS_BEGIN` 调整）与 21.x ABI 标记。 | 已兼容 HOS `21.0.0+` 与 Atmosphère `1.10.0+`。 |
| `16.0.0+`（已做分支兼容） | `companion/overlay/vendor/libtesla/include/tesla.hpp`（L3808–L3812）、`companion/nro/ui_graphics.c`（L47–L52） | HOS `16.0.0+` 移除 `pl:s` 的共享字体支持；`libtesla` 按 `hosversionAtLeast(16,0,0)` 自动切至 `pl:u`，NRO 直接使用 `pl:u`。`PlSharedFontType_ChineseSimplified` 自 HOS `1.0.0` 即存在。 | 已双向适配，不高于 `21.0.0` 门槛。 |
| `4.0.0+` | `platform/switch/pctl_adapter.c`（L10–L11、L89–L112）、`companion/nro/ptc_audio.c`（L112） | 1）PCTL 会话建立硬编码工厂 cmd `1`（`CreateServiceWithoutInitialize`）+ 会话 cmd `1`（`Initialize`），未提供 libnx `pctl.c` 中 `< 4.0.0` 的 cmd `0` 回退；2）NRO 音效停止调用 `audoutFlushAudioOutBuffers`，libnx `audout.c` 明确限制 `hosversionBefore(4,0,0)` 返回 `IncompatSysVer`。 | `< 4.0.0` 无法打开 `pctl`/`pctl:s` 会话，且音效刷新失败。 |
| `3.0.0+` | `sysmodule/sysmodule.json`（L94–L96） | NPDM 内核能力声明 `min_kernel_version: "0x0030"`。 | `< 3.0.0` 内核拒绝加载 sysmodule。 |

其他核心服务核查结果：
- `omm` cmd `0`（`GetOperationMode`，`platform/switch/operation_mode.c`）：libnx `omm.c` 无最低版本门禁（`3.0.0+` 门禁仅限 cmd `10`/`11`，PlayWise 未使用）。
- `time:u`（`platform/switch/time_provider.c`、`companion/auth_clock.c`）：无高于 `1.0.0` 的门禁。
- `set:sys`（`GetFirmwareVersion`、`GetFirmwareVersionDigest`、`GetProductModel`、`GetColorSetId`）：`GetFirmwareVersion` 在 libnx 中自动适配 `< 3.0.0` / `3.0.0+`；digest 为可选字段，缺失仅记提示。

## 三、大气层（Atmosphère）分层最低版本要求

依据本地 `../Atmosphere` commit `5388824be146a89619e8d641acd64599cf1c5f62`（tag `1.11.2`，工作树干净）已跟踪源码与 `docs/changelog.md` 核查，**最终硬性门槛为 `Atmosphère 1.10.0+`（并随主机 HOS 版本同步升级）**：

| Atmosphère 门槛 | 对应功能与仓库位置 | Atmosphère 上游依据 | 低于该版本的影响 |
| --- | --- | --- | --- |
| **`1.10.0+`（核心硬性门槛）** | 1）引导 HOS `21.0.0+`；2）免重启热加载与在线更新后台核验（`companion/nro/hot_reload.c` L343、`companion/nro/online_update.c` L629） | 1）`docs/changelog.md` 记录 **`1.10.0`** 是首个支持 **HOS `21.0.0`** 与 21.0.0 TLS ABI 的版本；2）`pm:shell` cmd `12`（`ShellService::GetProcessId`，对应 libnx `pmshellGetProcessId`）由 commit `4b32a2b96` 加入 `stratosphere/pm`，**首个包含发布的版本同为 `1.10.0`**。 | 低于 `1.10.0` 无法引导 HOS `21.0.0+`；若在旧版环境下运行，`pmshellGetProcessId` 失败会使热加载与在线更新自动降级为提示整机重启（不阻塞核心控制）。更高 HOS 必须匹配支持该 HOS 的 Atmosphère（例如 HOS `22.0.0` → `1.11.0+`，HOS `22.5.0` → `1.11.2+`，HOS `23.0.1` → `1.12.1+`）。 |
| `1.0.0+` | 环境识别与展示（`sysmodule/source/environment.c` L54–L59、`common/protocol/atmosphere_version.c` L3–L12） | 通过 `splGetConfig(65000)` 读取 `ExosphereApiVersion`；`ptc_atmosphere_version_decode` 要求 `major != 0` 才判定为已知 Atmosphère。 | `0.x` 会被记为 `atmosphere: false`（未知兼容），仅影响状态提示，不阻断控制。 |
| `0.16.0+` | 可选“相册高级入口限制”（`companion/album_restriction.c` L8–L13） | 写入 `/atmosphere/config/override_config.ini` 的 `[hbl_config]`，包含 `0.16.0` 引入的 `override_address_space=39_bit`（`override_config.ini` 文件名由 `0.10.0` 自 `loader.ini` 更名而来）。 | 仅影响可选相册限制功能。 |
| `0.10.0+` | 后台 sysmodule 自启动（`sysmodule/source/main.c` L172、安装包目录结构） | 使用 `/atmosphere/contents/4200000000BD2300/exefs.nsp` 与 `flags/boot2.flag`（`0.7.0` 引入自定义 `boot2.flag`，`0.8.0` 移入 `flags/`，`0.10.0` 将 `/atmosphere/titles/` 改名为 `/atmosphere/contents/`）。 | 低于 `0.10.0` 无法自动加载后台。 |
| `0.19.0+`（SM 兼容说明） | 自定义 IPC 服务 `pctc:u`（`sysmodule/ipc_server.c` L393） | 后台调用 `smRegisterServiceCmif`。Atmosphère `0.19.0+` 虽将 `sm` 切换至 TIPC，但 `stratosphere/sm/source/sm_user_service.cpp` 保留了 `RegisterService` / `UnregisterService` 的 CMIF 兼容垫片。 | 跨版本兼容，不构成额外阻断。 |

## 四、支持更低固件（`< 21.0.0`）的技术缺口

当前版本**不支持** HOS `21.0.0` 以下固件。若未来需要向下兼容：
- **HOS `18.0.0–20.5.0`**：需在 `platform/switch/pctl_adapter.c` 与 `platform/switch/play_timer_settings_layout.c` 中按真实 HOS 版本分支支持 `145601` / `195101` 的 `0x36` 字节结构与独立布局校验，并补充对应固件的真机 A/B 证据。
- **HOS `< 18.0.0`**：还需额外适配旧命令 `1456` / `1951` 与对应结构；且热加载在 Atmosphère `< 1.10.0` 下不能依赖 `pmshellGetProcessId`（cmd `12`），需保持重启回退路径或另行设计核验方案。
