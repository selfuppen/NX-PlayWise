# 独立使用时间能力探测

## 目标和证据边界

本探测针对“接管前已用超过额度，设置额度后已使用显示随加时上涨”的现象，优先寻找包含 HOME、设置、自制应用和游戏、排除真睡眠的整机使用统计。游戏前台时间单独对照。

本轮从原始数据重新判断，不读取旧 Lab 报告作为已验证依据；独立探针不使用 Lab session、phase、人工观察或资格封存协议。接口成功、数据结构可解释和产品口径成立是不同结论。实验产物带 `advisory:true`，不修改标准版统计或发布资格。

现有实现的事实：`platform/switch/pctl_adapter.c` 会将负的剩余纳秒截为零；`sysmodule/sysmodule_results.c` 用配置额度减去非负剩余分钟估算用量。该机制可能使超额显示随额度增加，本轮需对原始 `1454` 和 `1952` 验证，不能仅凭代码确认设备根因。

## 采样和控制接口

`ready.json` 绑定源码哈希、设备启动 ID、PID、HOS 和 PDM/PM 初始化 Result。`latest.json` 是最新采样；持续追加原始数据到 `samples.jsonl`、`events.jsonl`、`stats.jsonl`、`ranges.jsonl`。没有采样成功的字段保持未知。

计时样本保存 `sample_error`、各 IPC 的 Result、有符号 `remaining_ns`/`spent_ns`、timer/restriction/temporary-unlock 状态、当前配置、原始 68 字节 settings hex、应用 PID/ID、系统 UTC 偏移、steady source 和启动 ID。64 位计数以十进制字符串编码，禁止通过 JSON 浮点数丢精度。工作日通过 `timeGetCurrentTime` 与 `timeToCalendarTimeWithMyRule` 读取；自定义 sysmodule 不依赖未初始化的 C runtime 日历。

PDM 使用本机 libnx 的 `pdmqryGetAvailablePlayEventRange`、`pdmqryQueryPlayEvent`、按应用及账号查询累计值。历史分批读取，每轮有上限；事件保留原始结构 hex 和三种时间戳，账号统计使用本轮序号。原始事件 hex 仍含本机账号标识，应仅作为本地设备资料保存，公开分享前脱敏。统计按最近观察到的程序查询，不能把整个生命周期累计直接称作当天用量。初始历史导出可能拉长采样间隔，报告必须使用实际设备时间差。

宿主通过 FTP 临时文件与重命名发布 `command.json`，形式为 `{ "id":"<随机小写十六进制>", "op":"sample" }`，可选 `value`。唯一 ID 的最终回执位于 `results/<id>.json`，包含操作前后样本、`ok` 和原始 Result。已有回执的 ID 不再执行；结果未知时不得用新 ID 自动重试写入。Horizon/FAT 和 FTP 的重命名不覆盖目标，更新元数据需保留上一代文件再替换。

支持 `sample`、`begin`、`resume`、`limit`（0–1440 整数分钟）、`unlimited`、`unconfigured`、`start`、`stop`、`clock`（UTC 秒十进制字符串）、`restore`、`reboot`、`finish` 和只读状态下的 `exit`。`begin` 保存完整 PCTL 前像；`resume` 在新启动中只接受相同源码身份的前像。除 sample/exit 外，实验写入必须具有独占控制证明和前像。没有隐式 `1451` fallback；显式启停只在后段独立实验调用。

后续实现补充 `clock_local`（同一输入格式，指定 LocalSystemClock）、只冻结日志追加的 `export` 和恢复采集的 `collect`。Horizon 的文件读写锁可能使 FTP 下载与追加写入冲突，活跃探针导出前必须等待 export 回执，导出后再 collect；冻结日志不停止官方计时。PDM 统计同时保存结构 raw hex，避免只能依赖解释后的字段。NSP 内的 NSO 可能压缩，产物身份校验先按 PFS0/NSO 段解码 LZ4 并核对段 SHA-256，再检查嵌入身份，不能直接搜索压缩字节。

小于 10 分钟的实验额度有设备侧 30 秒恢复期限，不依赖宿主或浮窗存活；连续写入会更新期限。普通写入会话最长一小时。恢复只还原完整 settings 并回读证明，不为了复原旧 timer 布尔值自动调用 `1451`；计时器实际状态仍需另存样本。失败或缺少独占证明停止新的实验写入。

## 快速批次和人工观察

## 绕开 hbmenu 的自启动只读批次

`tools/usage_probe_autostart.py` 使用独立探针的 boot2.flag，完全不调用 sys-botbase 输入或截图。准备阶段校验 ZIP、保存安装前像、隔离遗留 command、上传并回读 boot-observe.json；取得标准后台事务 quiesce 回执后备份标准 flag，最后启用探针 flag。需要一次正常重启使此入口运行；现有可验证接口不能在不经过已故障 hbmenu 的情况下直接启动新模块。

boot-observe.json 包含 version=1、plan_id、source_hash 与 observe_timeout_s。只要文件存在，C 探针从启动时进入硬只读捕获策略；配置身份不匹配时退出。额外只读策略禁止 begin/resume/limit/unlimited/unconfigured/start/stop/clock/clock_local/restore/finish 以及旧 reboot，即使遗留请求存在也不能获得 PCTL/时钟写权限。允许 sample/export/collect/exit，以及绑定当前 plan ID 的显式 reboot_readonly 与 handoff_standard；因此只读指 PCTL/时钟，不将电源操作伪装为读取。

自启动先等待系统服务，PDM 首次只读最近 512 项，减少反复扫描历史的负载。ready 说明 boot_id 是探针进程会话随机 ID，不能单凭变化证明系统重启。reboot_readonly 必须先 export 冻结日志并完成宿主下载；回执只表示 BPC 初始化及重启请求准备成功，实际返回另记 reboot-return.json。宿主以断联、新自启动会话和新采样核验，不自动重发未知电源请求。
