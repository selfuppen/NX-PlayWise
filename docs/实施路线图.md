# 实施路线图

## PCTL runtime effect probe

已新增 `probe_play_timer_effect` 最短底层验证路径：Companion 一键提交，sysmodule 绕过 token/rules/nonce，使用 opaque 0x44 snapshot/restore 验证写入是否被 PCTL runtime 采纳。快速探针成功且恢复通过后同时设置 `play_timer_write_verified` 与 `play_timer_effect_verified`；Grant/Enforce 现要求两个 capability。旧 write/apply probe 保留为 IPC/raw 高级诊断，不能单独开放业务写入。

本文档把架构评审稿拆成可执行阶段，并记录当前已实现和未实现的功能状态。

## 当前验证命令与开发流程

当前 host-side 验证：

```powershell
python .\tools\test.py
```

默认开发流程：

1. 本地运行唯一测试入口 `python .\tools\test.py`。
2. 本地提交并推送 `master`。
3. 运行 `python .\tools\package_remote.py` 完成远程测试、构建、校验和下载。

本机缺少 `make`、`gcc` 或可用 WSL 发行版时，不应把 C host 验证记录为不可执行；C host、Companion NRO 和 package 的默认验证路径就是远程 devkitPro 容器。

远程 devkitPro 容器完整验证：

```powershell
python .\tools\package_remote.py
```

远端命令会覆盖：

- C host core 编译与测试。
- Python token / observe 回归。
- Companion NRO 构建。
- Sysmodule NSP 构建，并复制为 `build/switch/exefs.nsp`。
- safe NRO、disabled、observe、grant 和 enforce boot2 package 生成、校验与下载。
