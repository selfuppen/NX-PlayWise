# 详细测试计划

本文档是开发验证、模拟器验证和真实 Switch observe 验证的分步测试计划。

当前代码库目标是 Observe MVP：

- Host 侧 token 和 request queue 行为可用。
- `offline_code` 和 `status` 请求可以在 observe 模式下处理。
- 生成的 SDMC 目录布局默认安全。
- Companion NRO 文件协议可先做 safe NRO-only 验证；boot2、PCTL 和强控制仍需分阶段验证。

## 1. 开发环境

### 1.1 必需的 Host 工具

最低 host 工具要求：

- Windows PowerShell。
- Python 3.12 或更新版本。
- Git。

Switch 二进制文件默认通过 SSH 远程 devkitPro 容器构建。远程环境需要：

- devkitPro。
- devkitA64。
- libnx。
- GNU Make。
- Switch homebrew 构建环境变量，尤其是 `DEVKITPRO`。

本机 host 快速验证不需要 devkitPro。需要构建或打包 Switch 产物时，先本地提交并推送 `master`，再通过 SSH 让远程仓库 `git pull --ff-only origin master` 后直接执行构建测试。

### 1.2 仓库状态检查

运行：

```powershell
git status --short
python --version
```

预期：

- Python 可用。
- 工作区只包含有意保留的本地改动。

### 1.3 MVP Token 测试

运行：

```powershell
python .\tests\mvp\test_token_v1.py
```

预期：

- fixture 文件生成在 `tests/fixtures/token_v1_fixture.json`。
- 输出包含 `MVP token v1 tests passed`。

验证行为：

- 有效 token 可以通过校验。
- 固定 nonce 时 CLI 输出是确定性的。
- 错误 secret 返回 `bad_signature`。
- 错误日期返回 `wrong_date`。
- 重复 nonce 返回 `used_token`。
- 加时时长超过上限返回 `minutes_exceed_limit`。

### 1.4 Observe Queue 测试

运行：

```powershell
python .\tests\observe\test_observe_queue.py
```

预期：

- 有效 `offline_code` 请求生成 `ok` result，且 `dry_run: true`。
- `status` 请求生成 `ok` result，且 `dry_run: true`。
- 签名错误生成 `error` result，reason 为 `bad_signature`。
- request 文件从 `pending` 移动到 `done`。
- observe 模式不会消费 nonce ledger。

### 1.5 远程构建与完整验证

远程 devkitPro 容器：

```text
249-nintendo-switch-dev
```

远程仓库路径：

```text
/ws/switch-play-time-control-local
```

本地完成快速回归、提交并推送 `master` 后运行：

```sh
ssh 249-nintendo-switch-dev 'export DEVKITPRO=/opt/devkitpro; export DEVKITARM=/opt/devkitpro/devkitARM; export DEVKITA64=/opt/devkitpro/devkitA64; export PATH=$DEVKITA64/bin:$PATH; cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make && make companion-nro && make package-safe package-observe package-safe-nro'
```

预期：

- `make` 编译并运行 C host 测试，然后运行 Python 回归。
- `make companion-nro` 生成 `build/switch/pctc.nro`。
- `make package-safe package-observe package-safe-nro` 生成当前阶段可用于复制检查的 package。
- 默认 package 不包含 `boot2.flag`。

## 2. Host 侧协议 Probe

协议 probe 会创建一个本地 SDMC 风格目录布局，并可提交和处理 observe 请求。

### 2.1 初始化 SDMC 布局

运行：

```powershell
python .\tools\protocol_probe.py init `
  --root .\.tmp\sdmc `
  --device test-device `
  --secret test-secret
```

预期目录布局：

```text
.tmp/sdmc/switch/play-time-control/
├── config.json
├── auth.json
├── rules.json
├── state.json
├── capabilities.json
├── inbox/
│   ├── pending/
│   ├── processing/
│   └── done/
├── results/
├── logs/
├── ledger/
├── backups/
└── flags/
```

重要默认值：

- `control_mode` 为 `observe`。

### 2.2 生成测试加时代码

运行：

```powershell
python .\tools\grant_code.py `
  --minutes 30 `
  --device test-device `
  --secret test-secret `
  --day-index 2380 `
  --nonce 4660
```

记录打印出的代码。

### 2.3 提交离线码请求

运行：

```powershell
python .\tools\protocol_probe.py request `
  --root .\.tmp\sdmc `
  --type offline_code `
  --code <CODE_FROM_PREVIOUS_STEP>
```

预期：

- `inbox/pending/` 下出现一个 JSON request。

### 2.4 处理 Observe 请求

运行：

```powershell
python .\tools\protocol_probe.py process-observe `
  --root .\.tmp\sdmc `
  --day-index 2380
```

预期：

- request 被移动到 `inbox/done/`。
- `results/` 下出现匹配的 result。
- result 包含 `"dry_run": true`。
- 不尝试写入 PCTL。

### 2.5 提交状态请求

运行：

```powershell
python .\tools\protocol_probe.py request `
  --root .\.tmp\sdmc `
  --type status

python .\tools\protocol_probe.py process-observe `
  --root .\.tmp\sdmc `
  --day-index 2380
```

预期：

- 写出一个 status result。
- result 包含 `mode: "observe"` 和 `dry_run: true`。

## 3. 模拟器测试

模拟器测试只用于 companion UI 和文件协议。

需要验证：

- NRO 可以启动。
- 离线码输入会写出 request JSON。
- 家长区 PIN 流程可用。
- 家长区操作会写出预期 request type。
- 手工放入的 result JSON 能被正确显示。

不要把模拟器验证结论用于以下能力：

- boot2 sysmodule 启动。
- PCTL IPC。
- Play timer 行为。
- raw block。
- suspend。

模拟器 observe 准备：

1. 使用 `protocol_probe.py init` 创建 SDMC 布局。
2. 将生成的 `switch/play-time-control/` 目录复制或挂载到模拟器 SD 卡路径。
3. 在 companion NRO 可用后运行它。
4. 从 UI 提交 request。
5. 如果模拟器里没有 sysmodule，则对同一个 SDMC 目录手工运行 host `process-observe`，或手工写入 result JSON。

通过标准：

- UI 生成协议兼容的 request 文件。
- UI 读取匹配的 result 文件。
- 超时显示为后端未响应，而不是业务失败。

## 4. 真实 Switch 测试

真实 Switch 测试必须分阶段进行，不要从 enforce 开始。

### 4.1 硬件前置条件

需要：

- 真实 Nintendo Switch。
- Atmosphere CFW。
- 可写 SD 卡。
- Homebrew Menu。
- 必要时可从 SD 卡移除 boot2 sysmodule 的已知恢复方式。
- 在 boot2 测试前，已理解 `disable.flag` 恢复路径。

### 4.2 为 Observe 准备 SD 卡

在 PC 上运行：

```powershell
python .\tools\protocol_probe.py init `
  --root .\.tmp\sdmc `
  --device kid-switch `
  --secret replace-with-long-random-secret
```

复制：

```text
.tmp/sdmc/switch/play-time-control/
```

到：

```text
sdmc:/switch/play-time-control/
```

确认 SD 卡上：

- `config.json` 存在。
- `control_mode` 为 `observe`。
- 除非正在故意测试 fail-open，否则 `flags/disable.flag` 不存在。

### 4.3 仅 NRO 阶段

目的：

- 在没有 sysmodule boot2 风险的情况下验证 SD 卡布局和 companion 文件访问。

通过远程构建生成 `build/switch/pctc.nro` 和 safe NRO package 后执行：

1. 将 safe NRO package 解压到 SD 卡根目录。
2. 从 Homebrew Menu 启动。
3. 提交 status 请求。
4. 确认 request 出现在 `inbox/pending/`。
5. 手工提供匹配 result，或在复制出的 SDMC 内容上运行 host observe processor。

通过标准：

- Companion 读写预期路径。
- 未安装 boot2 sysmodule。

### 4.4 Disabled Boot2 阶段

目的：

- 在不访问 PCTL 的情况下验证 sysmodule 启动。

必需配置：

```json
{
  "version": 1,
  "control_mode": "disabled"
}
```

sysmodule 二进制可用后执行：

1. 将 sysmodule 文件安装到 Atmosphere contents 路径下。
2. 包含 `boot2.flag`。
3. 启动 Switch。
4. 检查 `logs/sysmodule.log`。
5. 提交一个 request。
6. 确认 result reason 为 `disabled`。

通过标准：

- Sysmodule 启动并写出日志。
- Request result 被写出。
- 不尝试读取或写入 PCTL。

### 4.5 Observe Boot2 阶段

目的：

- 验证真实 sysmodule request 处理和 PCTL 只读路径。

必需配置：

```json
{
  "version": 1,
  "control_mode": "observe"
}
```

步骤：

1. 安装 sysmodule 后启动。
2. 生成一个当天有效代码。
3. 从 companion 提交 offline code。
4. 等待 result。
5. 检查 `results/<request_id>.json`。
6. 检查 `logs/events.jsonl`。

通过标准：

- Result 包含 `status: "ok"`。
- Result 包含 `mode: "observe"`。
- Result 包含 `dry_run: true`。
- 不写入 PCTL。
- 不消费 nonce。
- 如果存在 PCTL read adapter，则包含 state。
- 如果 PCTL 读取失败，result 仍是结构化且稳定的。

### 4.6 Observe 拒绝用例

在 observe 模式下运行：

- 错误 secret。
- 错误日期。
- 加时时长超过上限。
- 格式错误的 token。
- 未知 request type。
- 坏 JSON。

通过标准：

- Result 为 `status: "error"`。
- Reason 稳定。
- 不消费 nonce。
- 不尝试写入 PCTL。
- sysmodule 已处理 request 时，companion 不显示后端超时。

## 5. 恢复与回滚

禁用 sysmodule 行为：

1. 创建 `sdmc:/switch/play-time-control/flags/disable.flag`。
2. 必要时重启。
3. 如果需要完全停止 boot 行为，移除 `boot2.flag`。

清理 request 状态：

- 将卡在 `inbox/processing/` 的文件移回 `inbox/pending/`，或归档它们。
- 保留 `results/` 和 `logs/events.jsonl` 以便调试。

在后续 grant/enforce 阶段复核 PCTL 写入行为前，不要删除备份。
