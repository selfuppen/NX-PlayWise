# 应用内在线更新 v1

[设计索引](../README.md#设计) · [协议](协议.md) · [使用指南](../使用/使用指南.md#应用内在线更新)

这是 `online_update_version:1` 的实现契约，不是某个候选的真机资格声明。首次取得此能力仍需手动完整安装；旧 NRO 不会凭商店元信息获得更新功能。

## 入口与版本策略

家长区“支持与恢复 → 软件信息”按 X 或触摸“更新”打开更新页。正常家长认证后可下载与安装；只读支持模式只能检查、查看和退出。更新页共用手柄／触摸几何、三语、双主题和端对端文本测量。

`config.json` 新增两个可选布尔字段：`update_check_on_startup`（缺省 true）、`update_stable_only`（缺省 false）。它们与 `theme_style` 一起属于配置备份的界面偏好组。关闭自动检查不影响手动检查或离线功能。

首次设置完成后，每次打开应用至多自动发起一次异步元信息检查，不轮询、不自动下载、不强制联网。当前存在安装恢复或备份原回执待确认时不发起普通自动检查。

版本按有界严格 SemVer 比较：核心数字最多为无符号 32 位整数，完整文本小于 64 字节，数字前导零、空标识及非法字符拒绝；预发布数字标识按数字长度及内容比较，构建元数据不影响高低。默认跟随当前运行 NRO：正式版排除预发布，测试版可收到更高测试版或正式版；家长可选择始终仅正式版。低版本、相同版本及同版本不同构建均不提供在线替换。

主机应用版本、SD 已安装版本、商店版本和后台构建身份分别展示。文件已安装、应用待重开、后台待加载、需要安全重新检测和全部核验完成是不同状态。Overlay 文件替换不代表已打开的旧 Overlay 立即换版；真机生命周期需单独验收。

更新详情按 Y 或触摸“完整更新说明”阅读限长纯文本；分页与正文使用同一个字宽测量和换行器，L/R、方向键及触摸页脚均可翻页，B 返回。备份列表显示归档校验状态、日期和来源身份，L/R 与页脚提供同一翻页操作；触摸清理仍经过 PIN 和长按，清理拒绝时保留材料并显示原因。

确认存在更高且通道允许的版本时，主页面右上状态卡的额度行显示低调的“有更新”入口：次要文字、极浅底和一个强调色小点，不闪烁，不替换状态时效或健康信息。点击直达更新详情；儿童页先通过原家长认证，取消则留在儿童页，重试成功后继续原目的页。检查失败／离线／版本相同／通道排除时不显示；弹层、等待任务、恢复及未保存编辑期间不提供切页入口。只读支持进入后仍只读。

## 更新源与网络边界

固定读取：

- [商店元信息](https://download.nswiki.cn/gayking/store/repo.json)：只从根对象 `packages` 数组精确选择唯一 `name == "NX-PlayWise"`。
- [商店安装包](https://download.nswiki.cn/gayking/store/zips/NX-PlayWise.zip)：冻结前一次检查的版本和 MD5 后下载。

首版依照用户选定的现有源策略，使用 HTTPS、整包 MD5、组件 SHA-256、内嵌 manifest 和 NRO 元信息验证。这些是传输／完整性检查，**不构成独立发行者签名验证**。相同源同时被替换的元信息和程序不能由这套方案鉴别；新增签名端点不属于 v1。

网络仅在 NRO 的单个工作任务初始化，后台与 Overlay 不初始化网络。libcurl 使用 libnx SSL 后端，强制验证证书和主机名，只允许 `https://download.nswiki.cn/`，最多三次同主机 HTTPS 重定向；重定向正文丢弃且限长，不附加到 ZIP。连接超时 8 秒，无进展 15 秒；元信息和 ZIP 请求的总期限分别为 20、180 秒，跨重定向计算。没有自动网络重试，手动重试先重新检查版本。

元信息最大 2 MiB，ZIP 最大 32 MiB，所有成员累计解压最大 64 MiB，ZIP 最多 96 个成员。元信息按 UTF-8、严格字段类型和重复键拒绝策略解析；商店 KiB 大小仅标注“约”，不作为精确长度或空间依据。空间按 ZIP 实际目录、当前旧资产及备份／事务余量核对，下载期间保留空间余量。

更新 JSON 在调用解析器前扫描字符串／转义边界，结构嵌套最多 24 层；对象最多 128 项，数组最多 4096 项。对象宽度先于重复键逐项比较检查，避免异常输入放大递归栈或二次方扫描；这些界限同样用于更新 journal 和待备份绑定。

工作线程只写自己的结果对象和原子进度／取消位。UI 在完成信号的 acquire 和 thread join 后接收结果；同一控制器不允许第二个工作线程，晚到的下载取消也必须在启动配置备份前生效。退出时关闭线程、curl、NIFM 和 socket。

## 安装包契约

只允许标准包的 13 个运行资产：三个程序组件、空 `boot2.flag`、`build.json`、`package-artifacts.json`、六个 defaults JSON 和字体。商店根 `info.json`／`manifest.install` 必须同时存在或同时缺失；存在时核对版本及完整 `U:` 白名单，但从不执行指令，也不安装到 SD 根目录。ZIP 目录成员不直接解压。

拒绝绝对路径、盘符、反斜杠歧义、点目录、重复及大小写冲突、加密、链接／未知文件类型、不支持的压缩方法、异常膨胀和 CRC／长度错误。所有文件先进入独立 staging，不能直接解到 SD 根目录。

目标必须声明 `profile:release` 和 `online_update_version:1`，协议、恢复、PCTL layout 版本必须与本更新器一致，六个 defaults 的现有数据版本必须兼容。`build.json`、商店版本、可选 `info.json` 一致；三组件大小／SHA-256及 NRO／Overlay 内嵌 manifest 一致。额外核对 NRO0、ASET、NACP 边界、标题和显示版本。缺少在线更新声明时提示手动更新。

不因 `source_dirty` 或 `qualification:pending` 自动增加资格，也不以版本排序代替数据兼容性。v1 没有跨数据 schema 迁移或在线降级。

## 持久化目录与请求

```text
switch/playwise/updates/
├── pending-backup.json           原 create_config_backup 请求绑定，未知时保留
├── install.lock                 独占创建，内容为拥有者 32 位 hex 事务 ID
├── active.json                  安装／恢复 journal v1
├── startup-blocked.json         后台启动时发现中断安装的原因
└── <32位hex事务ID>/
    ├── download.zip
    ├── download.json            阶段、来源、请求 ID、curl／I/O 结果；无秘密
    ├── stage/                   验证后的新资产与惰性商店描述
    ├── before/                  旧程序前像；含可单独打开的旧 pctc.nro
    ├── config-backup.json       本次独立配置归档，含安全资料
    ├── journal.json             与 active 对应的本次 journal
    └── receipts/<request-id>.json  新后台成功 status 的原回执
```

新事务目录和安装锁使用独占创建，不覆盖他人文件。配置备份仍使用请求 49（`create_config_backup`），选择恢复仍使用请求 50（`restore_config_backup`），不增加业务请求类型。提交请求 49 前持久化原 ID／来源／目标绑定；重开或超时后只等待同一请求，不再次提交。只有匹配原回执且归档重新载入验证成功，才进入程序备份与安装。

待备份记录还保存验证完成时冻结的 13 项目标大小／SHA-256；重开时恢复这些绑定，prepare 逐项核对，不能把后来变化的 staging 重新当成目标。儿童页只提示家长处理，原备份轮询及安装只在已进入的正常家长区继续；只读支持不能恢复到安装。若等待期间离开家长区，保留原回执和 stage，返回后仍只读取原请求。

未知备份回执显示待确认，不继续安装；“等待备份原回执”只恢复轮询。普通手工归档 `backups/config-backup.json` 不被自动更新覆盖。

## journal 与安装／回退

journal v1 保存事务 ID、源／目标 release、目标版本、源 PID／boot、配置备份请求 ID、ZIP MD5／实际 SHA-256、配置归档大小／SHA-256、13 项固定路径的前后大小／SHA-256及原存在性、`next_file` 与阶段。完成时还必须有目标 PID／新 boot、成功 status 的 ID 与原回执 SHA-256。

阶段为 `prepared → installing → files_installed → completed`；回退为 `rolling_back → rolled_back`，恢复不明保留记录。先写并读回本事务私有 journal，再独占安装锁，再发布 active；因此上一轮终结记录仍在时，新事务也能通过锁归属定位自身前像。

所有前像和配置归档核验完成后才发布第一个程序文件。逐文件持久化意图、复制到相邻临时文件、读回、新旧摘要检查、发布、检查 SD commit，再记录下一位置。实际删除／重命名前再次核对目标摘要，写后再次确认；这可发现可观测的 FTP／商店冲突，不能原子锁住外部安装器，也不声称消除两次核对之间的竞争。`build.json` 最后发布；空 boot flag 在正常安装中不删除、不重建。

安装锁期间，新的普通业务写请求返回已有 `325 control_busy`；状态、既有恢复入口和 Enforce 仍可运行，不退款、不自动解限、不重置 nonce。新后台在 defaults 初始化与 PCTL 调度前发现锁、半安装或损坏 journal 时记录原因并正常退出，等待 NRO 处理。

写入失败后，只有源身份仍为原 PID／boot／release，或已连续三次证明该 Title ID 无进程，才能回退；未知进程或目标已运行时停止。回退先验证全部前像与当前文件，拒绝外部未知字节，只恢复本次固定程序资产；相邻临时文件也必须匹配本事务前／后摘要才能清除。回退本身可在下次重开继续。

恢复程序文件与恢复后台进程分别判断。若恢复后原后台已不存在，而既有热加载中断恢复也不适用，使用支持流程核对后的正常重启；不将“文件已恢复”描述为后台已恢复，不强杀或自动重启主机。

完整安装后退出并正常重开 NRO，由新 NRO 复用现有热加载交接。环境重新检测和接管仍须家长走现有确认流程，不删除停用标记绕过门禁。只有文件摘要、新运行身份、新 boot、active setup 与原成功 status 回执均确认，才保存 completed。

## 配置恢复、历史与错误

备份列表最多展示最近 16 项；归档先以 journal 中的大小／摘要验证，选择后再用现有归档解析、十一组预览、PIN 和长按确认。无有效配置归档的已知失败下载只用于清理，不能恢复配置。PIN 恢复和配对密钥轮换沿用原协议。

普通更新与程序回退不覆盖配置、用量、领取资格、nonce、ledger、活动或原 PCTL 安装快照。显式配置恢复也不退还正常成功业务消费。归档包含密钥，只保存在本机；不得加入更新请求、公共日志或普通诊断。

完成后尽力保留最近三项成功更新；失败／未知事务不自动删除。手动清理要求 PIN 和长按，只处理已确认归属、非活动且目录内容均在白名单内的历史。材料损坏、枚举超过上限、未知文件或清理失败均保留现场，不伪装成清理成功。

更新错误域独立于业务协议：`0 none`、`1 network`、`2 manual_required`、`3 package`、`4 storage`、`5 backup`、`6 conflict`。UI 分别显示下载／备份／安装／重新检测状态和本地化原因；原 curl、errno、FS Result 保留在本机更新记录，不把业务错误码重编号。

## 验证边界

`test_online_update.c` 使用可注入 I/O 覆盖每个安装／回退故障点、上一轮 journal 与新锁交叉、原像和活跃数据保留。`tests/online_update/package_test.c` 执行生产包验证与真实文件系统安装／回退，隔离外部 ZIP／MD5 服务以注入 CRC、头部和格式错误，不声称测过真实 minizip 解压或 MD5 算法。`network_test.c` 执行生产网络编排，隔离 curl／libnx，验证 HTTPS 策略、重定向、总超时、响应上限、取消、单线程及释放；不产生真实网络调用。

软件门禁为 `python tools/test.py` 和统一 `python tools/package_remote.py --with-previews`，保留默认 Eden NRO。真实 TLS 权限与证书链、SD 文件占用、Overlay 生命周期、后台交接、断电恢复及人工画面仍需绑定 clean 候选和环境单独验收。Host／Eden 和在线下载成功均不自动证明这些范围。
