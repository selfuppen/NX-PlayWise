# 节假日日历数据

PlayWise 离线执行地区节假日规则，按已发布的日期表识别放假和调休。中国大陆 2026–2027 年编译进规则核心，后续年份可通过在线更新清单自动导入。家长也可[自制并导入其他地区的一年日历](../使用/自制节假日日历格式.md)。

## 在线发布与导入

在 `data/holiday-calendars/CN-YYYY.json` 添加经维护者核对的年度通知数据，沿用自制日历的 JSON 结构，地区 ID 固定为 `CN`，填写 `source_note`。合入 `main` 后，现有同步工作流校验年份、范围、重复日期和字段，将日历写入版本 1 更新清单的可选 `holiday_calendars` 数组，并随清单同步到 Gitee 和 GitHub。新增日历可独立于软件版本发布。

家长可进入“时间计划 → 节假日安排 → 管理日历 → 日历更新”单独检查，并设置独立的启动检查开关。两种检查共用 HTTPS 传输与发布清单。软件检查只处理版本，日历检查只处理日历。成功读取经 HTTPS 验证的清单后，独立校验各年度数据，并把新年份写入 SD 卡 `/switch/playwise/calendars/published/CN-YYYY.json`。旧清单仍可用于检查软件版本，单项日历无效时跳过该项。中国大陆选项优先使用编译内置的年份，再读取已导入的后续年份。日历写入与家长手动导入的目录和地区选择分开。后台在正常规则求值时读取本地日历，当前年份如在导入后首次获得覆盖，当天额度和就寝可能在下次求值时采用节假日规则。

在线导入按年份追加，保留已安装年份，避免镜像回退或重复检查改动同年规则。已导入年份的更正通过后续软件内置数据交付。

## 更新与回退

内置数据版本随程序发布。用户导入文件的 `format_version` 仅为格式版本，同地区同年可在家长确认后覆盖库索引，不要求内容版本递增。导入不会立即改动已应用的日历或 PCTL；须另行确认应用。运行时按摘要重新校验已应用文件；损坏时报告错误并停止新的控制写入，不改选其他地区。

日历覆盖终点前 30 天开始提示更新。进入未覆盖年份后，国家节假日层停止参与规则选择并回退每周计划；今日额度调整仍保持最高优先级。

当前威胁模型假设儿童无法修改主机日期或直接篡改 SD 卡数据。启用 Nintendo 官方家长控制后，修改 Switch 系统日期和时间需要输入 Nintendo 官方家长控制 PIN；该 PIN 与只保护任我玩家长区的 PlayWise PIN 相互独立。因此首版直接采用主机当前本地日期和时间，不实现独立的系统时间回退检测，也不实现日历包签名。关闭 Nintendo 官方家长控制后的系统时间保护不在本项目承诺范围内。完整的时钟信任边界与请求鉴权边界统一声明见[协议 · 威胁模型与信任边界](协议.md#威胁模型与信任边界)。
