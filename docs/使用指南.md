# 使用指南

PlayWise 公开版只有一个安装包，面向日常额度管理、系统计时和到期提醒。它不会承诺到期强制锁屏，也不会在正常界面提供危险探针。

## 构建和安装

生成并验证最终包：

```powershell
python .\tools\package_remote.py
```

使用 `build/packages/playwise-0.1.2-alpha.zip`。解压后可运行包内安装器；将 `E:` 替换为 SD 卡盘符：

```powershell
powershell -ExecutionPolicy Bypass -File .\playwise-install\install_package_to_sd.ps1 -SourceFolder <解压目录> -Drive E: -Apply
```

命令先显示将替换的路径并要求输入目标盘符确认。普通升级会：

- 替换 sysmodule、NRO、Overlay、`boot2.flag` 和 `build.json`；
- 只 seed 缺失的普通配置；
- 保留 secret、PIN、规则、状态、nonce、日志、备份和恢复数据；
- 不会静默改写旧配置为某个控制模式。

`-Clean`/`-Full` 会删除整个 `switch/playwise` 后重装，仅在已备份且确实要清空全部数据时使用。

## 首次设置

首次打开“任我玩”会进入四步向导，已完成的进度会保存到 `config.json`，中途退出后会从上次步骤继续：

1. **设置快捷键**：页面先说明始终有效的固定入口 `Minus -`，再列出 `L + R`、`ZL + ZR` 及分别搭配方向键、`Plus +`、`Minus -` 的 14 种常见组合，也可录制其他组合。选择或录制只形成草稿，按 `+` 明确确认后才保存并启用；未确认时只保留 `Minus -`。录制时按住实际组合，按 `A` 加入草稿、按 `B` 取消。自定义组合不会替换固定入口。
2. **设置 PIN**：输入 1–64 位纯数字 PlayWise 管理 PIN，然后再次输入确认。PIN 只保护本应用家长区、规则和安全设置，不是 Nintendo 官方家长控制 PIN。少于 4 位时只提示容易被猜到的风险，不会阻止保存；旧版 6 位 PIN 仍兼容。
3. **确认接管系统控制**：沿用现有接管流程。确认后先执行只读兼容预检，通过后保存安装前 snapshot、解除当前限制并进入约 5 秒同步宽限；确认前不会写入 PCTL。
4. **选择进入区域**：初始化完成后默认选中家长区。点击孩子区或家长区卡片只会切换选择，必须再点击“确认进入家长区/孩子区”才会进入。孩子区单独按下并松开 `Minus -`，或长按已启用的自定义组合约 400ms，可进入家长区并验证 PIN；家长区按 `B` 返回孩子区。首次确认进入家长区时不会重复要求刚设置的 PIN。

第 3 步接管成功后，从第 4 步返回查看时会显示“系统控制接管已完成”；再次继续只回到第 4 步，不会重复修改系统设置或重新开始同步。

之后可在家长区的“加时码与安全”页面管理设备配对信息，在“周计划”页面设置一周额度。快捷键设置和区域提示开关也会保留在 `config.json`。

如果显示“保护模式”，先进入“支持与恢复”执行当前推荐的“重试修复”。如果出现错误码 `306`，先到“系统设置 → 家长控制 → 开启家长控制”，返回后选择“重新检测”。不要通过编辑文件绕过 snapshot、layout、旧事务、PCTL 读取或 manifest 失败。

- 正常运行：新的规则已确认；
- 正在同步：系统设置正在传播，通常稍后完成；

## 日常使用

孩子首页展示今天已玩、总额度、剩余时间、8 位码输入和处理状态。状态语言为：

- 正常运行：新的规则已确认；
- 正在同步：系统设置正在传播，通常稍后完成；
- 兼容性待确认：环境结构可用，但不属于已验证组合；
- 保护模式：暂停新的控制修改，状态和恢复仍可使用。
- 控制已停用：红色横幅表示紧急停用已开启，普通写入被阻止；状态、诊断和恢复仍可使用。

家长区：

- 今日额度：进入页面和操作前自动刷新，显示受影响日期、当前已玩、当前剩余、调整后可玩时间以及上次刷新时间；设置和临时加时均支持 ±5/±15、点击分钟数手工输入和小时/分钟换算；不限时状态不能临时加时，设置总额度会恢复限时。不限时改限时与恢复周计划的确认框使用状态卡突出操作前后结果；操作后为 0，或已玩时间不可用、无法判断是否立即限制时，必须长按 `A` 执行；
- 周计划：页面按周一到周日展示七天编辑器，周六与周日使用不同强调样式，今天使用更醒目的边框。方向键在日期、切换模式、放弃和保存之间移动，`A` 执行当前候选；`X` 切换模式、`ZL` 放弃、`+` 保存、`Y` 刷新。不限时日期不能编辑分钟，按 `A` 或点按会提示先切换模式；切回限时后恢复此前保留的分钟数。存在草稿时用左右键选择保存、放弃或继续编辑，再按 `A` 确认；保存计划不会清除今日临时设置，“恢复周计划”才会清除；
- 加时码与安全：管理设备名、管理加时码密钥、加时码生成、修改任我玩PIN，以及“家长区快捷键管理”。设备名和密钥页使用方向键选择、`A` 确定；`X` 手工输入、`Y` 随机生成、`+` 保存，密钥页另有 `ZR` 显示/隐藏和 `R` 演示密钥。输入和随机结果先成为草稿，保存后才持久化；带草稿离开时会询问继续编辑或放弃。修改 PIN 前必须先验证当前 PIN；管理页可选择/录制组合、关闭自定义入口，并显示孩子区提示开关与当前状态；
- 支持与恢复：环境状态、唯一推荐操作、紧急停用/恢复、恢复安装前状态、导出诊断。

固定 `Minus -` 和启用的自定义组合都需要 PIN。孩子区只在“家长区快捷键管理”的提示开关开启时显示当前自定义组合，不显示固定的兜底入口。

“加时码生成”以“扫二维码生成加时码”为主要入口。方向键选择功能并按 `A` 执行，`Y` 直达二维码、`X` 直达本机生成。验证管理 PIN 后，用手机扫描二维码打开家长网页；建议收藏扫码后打开的地址。拍照保存二维码也可以，但二维码包含生成加时码的权限，应妥善保护相册。进入“本机生成 8 位码”时会主动刷新并突出今天已玩、当前还能玩和兑换后预计还能玩；方向键可选中每个时长按钮、生成和返回，`L/R` 约 ±15、`ZL/ZR` 约 ±30、`+` 生成。生成只签发代码，不会立即修改额度；预计时间按生成时状态冻结，且最多到每日 24 小时。

同一天可以生成多个仍可兑换的代码。调整时长或再生成不会撤销旧码，页面会继续标明当前显示代码的签发时长，并提示此前代码仍可能有效；关闭页面后不会提供历史码列表。当天 512 个 nonce 均已签发或消费时，本机将拒绝继续生成并要求次日再试，不会复用 nonce。

Overlay 打开时自动读取一次状态，空闲时可按 `Y` 或点按顶部按钮刷新。刷新会保留已经输入的加时码和上一次成功状态，并显示“刚刚刷新 / N 秒前”；超过 30 秒会提示数据可能过期。剩余分钟不做本地倒计时，以后台最新状态为准。
```powershell
python .\tools\grant_code.py --minutes 30 --device kid-switch --secret <credentials.json中的secret> --day-index 2380 --nonce 4660
```

secret 只应保存在 Switch 和家长端。短码绑定设备与日期，并且 nonce 只在成功写入、结果保存和 ledger 提交后才消费。连续多次错误会触发 10 分钟冷却。

更新加时码密钥后，旧家长网页配置和旧码立即失效，需要重新导入。诊断包不会包含密钥。

“公共演示密钥”用于降低首次试用门槛。它是公开值，没有次数或分钟能力限制；任何知道设备名的人都能生成码，并可把当天额度累计到 1440 分钟。启用前需要重新验证 PIN 和二次确认，启用期间所有家长页面持续显示红色警告。退出后自动生成新的随机 64 位密钥并要求重新配对。

## 同步、回滚和紧急停用

普通规则写入均有恢复事务。Enforce 写入后最多等待 30 秒确认系统状态；期间显示“正在同步”。超时会回滚；若无法证明恢复，自动进入保护并创建：

```text
sdmc:/switch/playwise/flags/disable.flag
```

该 flag 只熔断新的控制写入。孩子页和所有家长页会持续显示红色停用横幅，额度、周计划和加时码写入显示为不可用；仍可查询状态、导出诊断、重试修复、解除停用或恢复安装前状态。家长区“支持与恢复”会提供“解除停用并重新接管”，先执行只读安全预检，只有通过后才删除停用标记并恢复控制。

## PWA 常见排错

- 无法配对：确认使用当前 Switch 的二维码和可信 HTTPS 页面；自定义站点需支持相同 fragment 契约。也可改用 `parent-import.json`。
- 加时码无效或已使用：核对设备名、密钥、UTC+8 日期；修改密钥后旧码失效，已使用时重新生成。
- 日期不正确：先校准家长设备与 Switch 日期，再刷新状态并重新生成。
- 设备无响应：等待“正在同步”完成并刷新；仍失败时从支持页导出诊断。
- 紧急停用：该状态会阻止新的控制写入。确认故障已排除后，在家长区“支持与恢复”选择“解除停用并重新接管”；不要直接删除 SD 卡上的 flag 绕过预检。

PWA 页面内也提供折叠式“常见排错指南”。高级排查可检查 `logs/`、`flags/disable.flag` 和恢复状态，但不要对外发送 `credentials.json`、`auth.json`、完整 ledger 或原始离线码。

也可离线创建：

| 目的 | 路径 |
| --- | --- |
| 熔断新写入 | `flags/disable.flag` |
| 重试 setup 修复 | `flags/retry_setup_release.flag` |
| 恢复安装前状态 | `flags/restore_install_snapshot.flag` |

恢复标记优先于 `disable.flag`。安装 snapshot 恢复成功后 phase 为 `restored`，并保持写入熔断；启动遗留事务恢复后也可能保持 `active + disable.flag`。两种状态都会在“支持与恢复”显示“解除停用并重新接管”。确认后会先执行只读预检，只有通过才解除停用并进入接管和 5 秒宽限；预检失败会继续保持停用，不需要手工删除 `setup.json`。

如果需要彻底停止 sysmodule 随开机运行，移除：

```text
sdmc:/atmosphere/contents/4200000000BD2300/flags/boot2.flag
```

## 支持与隐私

“导出诊断包”使用白名单，只包含 build、非秘密 config、rules、state、setup、compatibility 和 environment 信息。它不包含 `credentials.json`、`auth.json`、8 位码、完整 nonce 或 recovery 原始前像。

系统时间异常时日志保存在 `logs/undated/<boot-id>/`，不会因日期不可用而消失。发现 snapshot 损坏、回滚失败等红色问题时，先导出诊断并停止新的额度写入。

## 当前资格状态

声明基线为 OLED / HOS 22.5.0，资格测试使用 Atmosphère 1.11.2。最终 `0.1.2-alpha` Zip 仍需在该设备组合上重新完成完整资格验证，因此当前版本不应升级为 `1.0.0` 或宣称已完成发布认证。
