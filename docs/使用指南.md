# 使用指南

本文面向安装和使用任你玩（PlayWise）的家长。首次启用前，请确认你能读写 Switch SD 卡、使用 Nintendo 官方 PIN/App 解锁，并知道如何删除开机自启标记文件（`boot2.flag`）以停止后台服务自动启动。

## 工作原理

### 组件与数据流

家长网页控制台（PWA）或命令行工具在本地生成当天有效、绑定设备的一次性 8 位加时码（token）。Switch 主程序界面（Companion NRO）或快捷悬浮窗（Tesla Overlay）将加时请求提交给后台服务程序（sysmodule）；后台服务程序验证加时码（token）、防范重复使用（nonce），并通过 Switch 官方家长控制服务（PCTL API）应用时间与控制规则。

Switch 客户端优先使用内存快速通信通道（`pctc:u` IPC）。在服务不可用时，会自动回退到 SD 卡传输队列（SD file queue）。快捷悬浮窗（Tesla Overlay）不读取密钥文件（`grant_secret`）、不验证加时码（token），也不直接调用官方控制服务（PCTL）。

### 首次引导

第一次启动时，后台服务程序（sysmodule）会先自动保存安装前的官方家长控制快照（install snapshot），再解除当前设备的限制。成功后初始化阶段（setup phase）进入“限制已解除”（`released`）；家长在主程序界面确认状态并开启“自动控制”后，系统等待 5 秒倒计时，再进入“自动控制已启用”（`active`）状态并开始执行家长规则控制（Enforce）。

在“限制已解除”（`released`）阶段，家长可以查看状态和执行引导操作，但加时、规则写入、高风险功能探针和规则控制（Enforce）都会提示“初始化未完成”（`308 setup_pending`）。

### 写入与恢复

修改每日限制时长、取消限制（unlimited）、提交 8 位加时码、规则恢复和规则控制（Enforce）不需要运行“游戏时间控制能力探针”（play-timer capability probe）。每次写入控制前，系统都会先保存恢复事务记录（recovery transaction），启动计时器并确认运行状态；确认成功后才会真正提交规则（rules）、状态（state）、结果（result）和防重复标记（nonce）。

“强行封锁”（`raw_block`）和“暂停游戏”（`suspend`）属于可选的高风险控制能力，必须分别通过独立的能力探针（capability probe）。任何恢复操作无法被精确证明成功时，系统会自动创建紧急停用标记文件（`disable.flag`），停止正常的控制写入。

## 使用步骤

### 1. 构建安装包（Package）

只修改 Python、协议或文档时，可先运行本地自动化回归测试：

```powershell
python .\tools\test.py
```

涉及 C 代码、Makefile、主程序界面（Companion NRO）、快捷悬浮窗（Tesla Overlay）、后台服务程序（sysmodule）或安装包（package）时，运行权威容器构建脚本：

```powershell
python .\tools\package_remote.py
```

构建完成后使用 `build/packages/playwise-<timestamp>.zip`。包内包含后台服务程序（sysmodule）、主程序界面（Companion NRO）、快捷悬浮窗（Tesla Overlay）和开机自启标记文件（`boot2.flag`），初始控制模式（`control_mode`）为“规则控制中”（`enforce`）。

### 2. 安装到 SD 卡

将 `E:\` 替换为实际 SD 卡盘符后执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_package_to_sd.ps1 -SourceFolder <解压后的包目录> -Drive E: -Apply
```

默认情况下，安装脚本只替换程序文件和缺失的初始模板，不删除已存在的 `switch/playwise` 文件夹，从而保留授权密钥（`grant_secret`）、家长区密码（PIN）、控制规则（rules）、运行状态（state）、审计日志（ledger）、系统日志（logs）和备份文件（backups）。

若需要**完全安装**（清空 SD 卡上 `switch/playwise` 及其所有旧数据并重新复制包内数据），添加 `-Clean` 或 `-Full` 参数：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_package_to_sd.ps1 -SourceFolder <解压后的包目录> -Drive E: -Apply -Clean
```

### 3. 完成首次设置

1. 将 SD 卡装回 Switch 并重启主机。
2. 打开 Switch 主程序界面（Companion NRO），确认首次引导页显示“官方控制快照（snapshot）可用”、“当前限制已解除”，且初始化阶段（setup phase）显示为“限制已解除”（`released`）。
3. 设置或验证本地 PIN 密码。该密码仅用于保护 PlayWise 主程序的“家长区”，并非 Nintendo 官方系统 PIN 密码。
4. 进入家长区的“安全工具”页面，选择“启用自动控制”。
5. 页面会自动进入 5 秒倒计时，无需手动刷新。倒计时结束后，页面自动确认初始化阶段已进入“自动控制已启用”（`active`），并自动切换到孩子页展示，界面状态显示为“自动控制：已启用”。

若初始化阶段显示为“解除失败”（`failed`），不要继续执行规则控制（Enforce）或运行高风险能力探针。请先按“停用与恢复”章节处理，并保留现场日志与配置文件。

### 4. 生成 8 位加时码

家长在手机、平板或电脑浏览器中可以直接打开部署好的在线版家长网页控制台（PWA）：

👉 **在线控制台（直接可用）：[https://selfuppen.github.io/playwise/](https://selfuppen.github.io/playwise/)**

*提示：在手机浏览器菜单中选择“添加到主屏幕”，可作为 App 随时在脱网/离线状态下使用。授权密钥（`grant_secret`）仅保存在家长手机/电脑浏览器的本地存储中，不会发送到任何服务器。*

若需要在本地搭建预览或在局域网私有环境运行，也可启动本地服务：

```powershell
python .\tools\ptc_frontend_server.py
```

在浏览器打开 `http://127.0.0.1:8765`。

也可以使用命令行生成 30 分钟 v2 版本加时码：

```powershell
python .\tools\grant_code.py --tier-minutes 30 --device kid-switch --secret <grant_secret>
```

### 5. 在 Switch 上加时

1. 打开主程序界面的“孩子页”（Companion NRO）或按快捷键唤出“快捷悬浮窗”（Tesla Overlay）。
2. 使用十字键或左摇杆在数字软键盘中选择数字，按 `A` 输入；`X` 退格、`Y` 清空、`Plus` 提交，`B` 取消。
3. 等待处理结果，确认界面上的“今日剩余额度”已真实增加，且当前画面不再显示受限阻断。

提示：如果界面提示超时，仅代表截止时间前未收到后台返回结果，并不代表后台一定没有执行。请勿重复提交，建议先刷新页面状态或查看上一次请求的处理结果（result）。

### 6. 管理控制规则

在主程序界面（Companion NRO）中按手柄 `Minus` 键或肩键组合，进入受密码保护的“家长区”。在此处可设置今日可玩时长限额、一周时长计划（周计划）、就寝时间（Bedtime）、限制方式以及开启“家长临时解锁”。

家长区和编辑弹窗均可完全使用手柄操作：十字键或左摇杆移动选择，`L`/`R` 切换页面，`A` 或 `Plus` 保存提交，`B` 取消或返回。所有支持手动输入的分钟或时间编辑器统一按 `Y` 打开十宫格数字键盘；触屏直接点击当前分钟数或开始/结束时间也会进入手动输入。分钟数值框左右按 5 分钟调整、上下按 15 分钟调整；就寝时间框上下按 15 分钟调整。周计划中 `X` 切换限时/不限时/禁玩模式，就寝时间中 `X` 切换启用状态。本地家长 PIN 仍使用系统密码键盘并允许字母。

“今日管理”中的“解除当前限制”会直接提交当天不限时操作，不根据界面缓存状态预判官方家长控制是否已开启或当前是否受限。成功后会立即解除已经生效的限制，并让今天保持不限时；次日继续按每周计划执行。该操作不会删除 Nintendo 官方家长控制配置、恢复安装前快照或永久停用 PlayWise。

普通控制规则不需要额外运行能力探针。只有在准备使用“强行封锁”（`raw_block`）或“暂停游戏”（`suspend`）功能时，才需要在“安全工具”页面运行对应的能力探针（capability probe）。快捷悬浮窗（Tesla Overlay）能否覆盖 Nintendo 官方系统的硬性限制弹窗，取决于具体的 Switch 系统版本（HOS）、Atmosphere 自定义系统及 nx-ovlloader 悬浮窗加载器的组合情况。

#### 就寝时间与每日限制时长的叠加与冲突显式处理规则

“就寝时间（Bedtime）”与“每日限制时长（Limit Minutes）”采用**显式计算、冲突透明提醒、最严优先**原则：

1. **配额与就寝时间冲突提醒**：
   - 当设置或增加的游玩配额超过了当前时刻距离就寝时间的剩余倒计时时（例如距离 21:00 就寝仅剩 30 分钟，但设置加时 60 分钟），界面会**显式标注冲突提醒**（`⚠️ 冲突提醒：配额超过就寝倒计时`），提示到就寝时间将优先截止。
2. **控制动作与强行关停联动**：
   - 若启用了就寝时间，但控制动作设为“仅界面提醒”（`remind`），到了就寝时间系统仅在屏幕上提示，**不会强行断网/锁屏**。
   - 若需在到达就寝时间时强行关停，需在“控制动作”选项中显式选择【强行禁玩】（`raw_block`）或【悬停锁屏】（`suspend`）。界面会在就寝设置和控制动作编辑区提供明确的关联提醒与选择导引。
3. **谁先触发，谁先锁定**：在强控制动作下，即使今日剩余可玩时长未用完，只要到达设定的就寝时间（例如 21:00），系统也会立即强行锁屏；反之，若未到就寝时间但今日配额耗尽，同样触发锁屏。
4. **夜间加时限制**：在就寝时间段内使用 8 位加时码加时，增加的额度会正常累加至今日总时长中，但**不会冲破就寝时间的夜间锁定**。加时额度将在次日就寝时间结束（例如 08:00）后自动生效。
5. **临时解锁特例**：在主程序界面（Companion）或快捷悬浮窗（Tesla Overlay）中开启“家长临时解锁（Parent Unlock）”，可同时暂停就寝锁与时长锁。

### 7. 停用与恢复

在 SD 卡对应路径创建空文件，可手动触发应急恢复逻辑：

| 恢复目的 | 标记文件路径（SD卡） | 详细说明 |
| --- | --- | --- |
| 紧急停止正常控制 | `sdmc:/switch/playwise/flags/disable.flag` | 紧急停用控制标记（`disable.flag`） |
| 重试首次解除限制 | `sdmc:/switch/playwise/flags/retry_setup_release.flag` | 仅在初始化阶段处于未完成（`pending`）或失败（`failed`）状态时有效 |
| 恢复安装前官方状态 | `sdmc:/switch/playwise/flags/restore_install_snapshot.flag` | 恢复初始官方快照标记（`restore_install_snapshot.flag`） |

说明：两个恢复标记文件的优先级高于紧急停用标记（`disable.flag`）。**注意：**重试首次解除标记（`retry_setup_release.flag`）仅在初始化阶段处于未完成（`pending`）或失败（`failed`）时有效；若在“限制已解除”（`released`）、“自动控制中”（`active`）或“已恢复快照”（`restored`）状态下使用，系统将返回“请求无效”（`bad_request`）。恢复官方控制快照成功后，初始化阶段进入“已恢复快照”（`restored`），并会自动生成紧急停用标记（`disable.flag`）。

Companion NRO 的“安全工具”会根据 `disable.flag` 是否存在，在“紧急停用控制”和“解除紧急停用”之间自动切换。解除操作只删除紧急停用标记并恢复后台正常控制，不会重置 `setup.json`、规则或安装快照；应仅在故障已排除且确认当前配置安全后执行。若初始化阶段已经是 `restored`，仍需按重新安装流程完成初始化，单独解除停用不会把阶段改回 `active`。

若要彻底禁止后台服务程序（sysmodule）随系统开机自动启动，请删除以下文件：

```text
sdmc:/atmosphere/contents/4200000000BD2300/flags/boot2.flag
```

排查故障前，请妥善保留初始化配置文件（`setup.json`）、未完成的恢复事物目录（`recovery/`）、初始官方快照备份（`backups/install_pctl_snapshot.json`）、请求结果目录（`results/`）以及当天的日志目录（`logs/`）。

### 8. 更新与复测

重复步骤 1（构建包）和步骤 2（安装到 SD 卡）即可完成升级，安装脚本会自动保留所有用户配置与历史数据。

进行普通代码修改时，默认不需要上 Switch 真机测试。当修改涉及官方控制接口（PCTL）、首次引导流程、主程序/悬浮窗界面输入（Companion/Overlay）、规则控制（Enforce）、强行封锁（`raw_block`）或暂停游戏（`suspend`）时，请按[测试指南](测试指南.md)进行实机场景测试。

在新 Switch 设备上首次启用，或 Switch 系统（HOS）/ 官方控制服务（PCTL）行为发生变化后，必须完成一次完整的单包端到端验收：在受限状态下安装程序并确认能自动解除官方限制，完成首次设置（setup）后使用一个 15 分钟加时码，重启主机确认配置持久化保留，并验证一次恢复初始官方快照功能。
