# 使用指南

本文面向安装和使用任你玩（PlayWise）的家长。首次启用前，请确认你能读写 Switch SD 卡、使用 Nintendo 官方 PIN/App 解锁，并知道如何删除 `boot2.flag` 停止自动启动。

## 工作原理

### 组件与数据流

家长端 PWA 或命令行工具在本地生成当天有效、绑定设备的一次性加时码。Companion NRO 或 Tesla Overlay 将请求交给 sysmodule；sysmodule 验证加时码、管理 nonce，并通过 PCTL 应用规则。

Switch 客户端优先使用 `pctc:u` IPC。服务不可用时才回退到 SD 文件队列。Overlay 不读取 `grant_secret`、不验证 token，也不直接调用 PCTL。

### 首次引导

第一次启动时，sysmodule 会先保存安装前的完整 PCTL snapshot，再解除当前限制。成功后 setup 进入 `released`；家长确认状态并启用自动控制后，系统等待 60 秒，再进入 `active` 并开始 Enforce。

在 `released` 阶段可以查看状态和执行引导操作，但加时、规则写入、高风险探针和 Enforce 都会返回 `308 setup_pending`。

### 写入与恢复

普通 set limit、unlimited、加时、规则恢复和 Enforce 不需要 play-timer capability 探针。每次写入都会先保存恢复事务，再启动 timer 并确认运行时状态；确认成功后才提交 rules、state、result 和 nonce。

`raw_block` 和 `suspend` 是可选高风险能力，必须分别通过独立探针。任何恢复无法被精确证明时，系统会创建 `disable.flag`，停止正常控制写入。

## 使用步骤

### 1. 构建 Package

只修改 Python、协议或文档时，可先运行本地回归：

```powershell
python .\tools\test.py
```

涉及 C、Makefile、Companion、Overlay、sysmodule 或 package 时，运行权威容器入口：

```powershell
python .\tools\package_remote.py
```

构建完成后使用 `build/packages/playwise-<timestamp>.zip`。包内包含 sysmodule、Companion NRO、Tesla Overlay 和 `boot2.flag`，初始 `control_mode` 为 `enforce`。

### 2. 安装到 SD 卡

将 `E:\` 替换为实际 SD 卡盘符后执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_package_to_sd.ps1 -Package .\build\packages\playwise-<timestamp>.zip -SdRoot E:\
```

安装脚本只替换二进制和缺失的初始模板，不删除整个 `switch/playwise`。更新时会保留 `grant_secret`、PIN、rules、state、ledger、日志和备份。首次安装或从旧五包迁移时，脚本会备份旧配置、设置 Enforce，并创建 phase 为 `pending` 的 `setup.json`。

### 3. 完成首次设置

1. 将 SD 卡装回 Switch 并重启。
2. 打开 Companion，确认首次引导页显示 snapshot 可用、当前限制已解除，setup phase 为 `released`。
3. 设置或验证本地 PIN。该 PIN 只保护 PlayWise 家长区，不是 Nintendo 官方 PIN。
4. 进入家长区的“安全工具”，选择“启用自动控制”。
5. 页面会自动进入 60 秒倒计时，无需手动刷新。倒计时结束后，页面自动确认 setup 已进入 `active`，切换到孩子页，并显示“自动控制：已启用”。

若 setup 显示 `failed`，不要继续 Enforce 或运行高风险探针。先按“停用与恢复”处理并保留现场文件。

### 4. 生成 8 位加时码

本地启动家长端 PWA：

```powershell
python .\tools\ptc_frontend_server.py
```

在浏览器打开 `http://127.0.0.1:8765`。手机正式使用时，应部署到可信的 HTTPS 静态站点；`grant_secret` 只保存在家长设备的浏览器本地。

也可以用命令行生成 30 分钟 v2 码：

```powershell
python .\tools\grant_code.py --tier-minutes 30 --device kid-switch --secret <grant_secret>
```

### 5. 在 Switch 上加时

1. 打开 Companion 孩子页或 Tesla Overlay。
2. 输入 8 位数字码并提交。
3. 等待结果，确认今日额度已经真实增加，且界面不再显示当前受限。

超时只表示截止时间前没有收到结果，不代表后台一定没有执行。不要立即重复提交；先刷新状态或检查同一请求的 result。

### 6. 管理规则

在 Companion 中按 `Minus` 或肩键组合进入 PIN 保护的家长区。可设置今日额度、周计划、bedtime、限制方式和家长临时解锁。

普通规则不需要额外能力探针。只有准备使用 `raw_block` 或 `suspend` 时，才在安全工具中运行对应探针。Overlay 能否覆盖 Nintendo 官方硬限制弹窗，取决于目标 HOS、Atmosphere 和 nx-ovlloader 组合。

### 7. 停用与恢复

在 SD 卡创建对应空文件：

| 目的 | 文件 |
| --- | --- |
| 紧急停止正常控制 | `sdmc:/switch/playwise/flags/disable.flag` |
| 重试首次解除 | `sdmc:/switch/playwise/flags/retry_setup_release.flag` (限 pending/failed 阶段) |
| 恢复安装前 PCTL 状态 | `sdmc:/switch/playwise/flags/restore_install_snapshot.flag` |

两个恢复 flag 的优先级高于 `disable.flag`。**注意：**重试首次解除 (`retry_setup_release.flag`) 仅在初始化阶段处于 `pending` 或 `failed` 时有效，若在其他状态（如 `active`、`released` 或 `restored`）下尝试将返回 `bad_request`。安装 snapshot 恢复成功后，setup 进入 `restored`，并保留 `disable.flag`。

若要完全停止 sysmodule 随 boot2 启动，删除：

```text
sdmc:/atmosphere/contents/4200000000BD2300/flags/boot2.flag
```

排查前保留 `setup.json`、`recovery/`、`backups/install_pctl_snapshot.json`、对应的 `results/` 和当天 `logs/`。

### 8. 更新与复测

重复步骤 1 和步骤 2 即可更新，安装脚本会保留用户数据。

普通代码回归默认不做真机测试。改动涉及 PCTL、首次引导、Companion/Overlay 输入、Enforce、raw block 或 suspend 时，按[测试指南](测试指南.md)追加对应真机场景。

新设备首次启用或 HOS/PCTL 行为变化后，必须完成一次单包端到端验收：在受限状态安装并确认自动解除，完成 setup 后使用一个 15 分钟 v2 码，重启确认持久化，并验证一次安装 snapshot 恢复。
