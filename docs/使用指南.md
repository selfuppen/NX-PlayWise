# 使用指南

PlayWise 当前处于 `0.1.3-alpha` 开发验证阶段，生成一个标准安装包，面向日常额度管理、系统计时和到期提醒。当前产品不承诺到期强制锁屏，也不在日常界面提供危险探针。

## 构建和安装

生成并验证候选包：

```text
python tools/package_remote.py
```

使用 `build/packages/playwise-0.1.3-alpha.zip`。候选 Zip 只包含 Switch 运行时文件；从与包版本匹配的仓库工具运行安装脚本，将 `E:` 替换为 SD 卡盘符：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_package_to_sd.ps1 -SourceFolder <解压目录> -Drive E: -Apply
```

安装脚本不属于运行时 Zip；发布给其他设备时，应与候选包一并提供同一版本的 `tools/install_package_to_sd.ps1`。

命令先显示将替换的路径并要求输入目标盘符确认。安装器的数据保留规则是：

- 替换 sysmodule、NRO、Overlay、`boot2.flag` 和 `build.json`；
- 只 seed 缺失的普通配置；
- 保留 secret、PIN、规则、状态、nonce、日志、备份和恢复数据；
- 不会在现有配置中写入运行时控制模式。

`-Clean`/`-Full` 会删除整个 `switch/playwise` 后重装，仅在已备份且确实要清空全部数据时使用。

## Overlay 与推荐环境

Companion NRO 是日常使用的主入口：孩子可在其中输入加时码；家长验证 PlayWise PIN 后，可进入家长区管理今日额度、周计划、设备配对、密钥、诊断和恢复等完整功能。

PlayWise Overlay 提供第二个加时码入口。平时可在游戏内快速查看今天已玩、总额度和剩余时间，并输入、预览和兑换 8 位加时码；更重要的是，当家长控制限制已经生效、Companion NRO 无法打开时，仍可通过 Overlay 紧急输入加时码并恢复可玩时间。这是保留两个加时码入口的主要原因，并非让 Overlay 重复 Companion NRO 的完整管理功能。Overlay 通过 PlayWise transport 向 sysmodule 提交请求，不直接访问 PCTL。

推荐环境由以下部分组成：

- 与主机 Atmosphère 环境兼容的 [Ultrahand Overlay](https://github.com/ppkantorski/Ultrahand-Overlay)，用于管理和打开 Overlay；
- PlayWise sysmodule，负责规则、安全校验、PCTL 写入和恢复；
- Companion NRO，负责完整管理；
- `sdmc:/switch/.overlays/pctc.ovl`，作为游戏内快速入口。

可参考[大气层包安装与使用说明](https://docs.qq.com/doc/DVW9PVE5sU0FEd0tP)准备整合环境，使用交流 QQ 群为 `1051287661`。Ultrahand Overlay 和大气层整合包是外部项目，不包含在 PlayWise 安装包中；PlayWise 不写入或修改 Overlay 管理器的全局配置。上述外部项目与说明链接于 2026-08-10 核对。

## 首次设置

首次打开“任我玩”会进入四步向导，已完成的进度会保存到 `config.json`，中途退出后会从上次步骤继续：

1. **设置快捷键**：页面先说明始终有效的固定入口 `Minus -`，再列出 `L + R`、`ZL + ZR` 及分别搭配方向键、`Plus +`、`Minus -` 的 14 种常见组合，也可录制其他组合。选择或录制只形成草稿，按 `+` 明确确认后才保存并启用；未确认时只保留 `Minus -`。录制时按住实际组合，按 `A` 加入草稿、按 `B` 取消。自定义组合不会替换固定入口。
2. **设置 PIN**：输入 1–64 位纯数字 PlayWise 管理 PIN，然后再次输入确认。PIN 只保护本应用家长区、规则和安全设置，不是 Nintendo 官方家长控制 PIN。少于 4 位时只提示容易被猜到的风险，不会阻止保存；6 位 PIN 按相同规则处理。
3. **确认接管系统控制**：确认后先执行只读兼容预检，通过后保存安装前 snapshot、解除当前限制并进入约 5 秒同步宽限；确认前不会写入 PCTL。
4. **选择进入区域**：初始化完成后默认选中家长区。点击孩子区或家长区卡片只会切换选择，必须再点击“确认进入家长区/孩子区”才会进入。孩子区单独按下并松开 `Minus -`，或长按已启用的自定义组合约 400ms，可进入家长区并验证 PIN；家长区按 `B` 返回孩子区。首次确认进入家长区时不会重复要求刚设置的 PIN。

第 3 步接管成功后，从第 4 步返回查看时会显示“系统控制接管已完成”；再次继续只回到第 4 步，不会重复修改系统设置或重新开始同步。

之后可在家长区的“加时码与安全”页面管理设备配对信息，在“周计划”页面设置一周额度。快捷键设置和区域提示开关也会保留在 `config.json`。

如果显示“保护模式”，先进入“支持与恢复”执行当前推荐的“重试修复”。如果出现错误码 `306`，先到“系统设置 → 家长控制 → 开启家长控制”，返回后选择“重新检测”。不要通过编辑文件绕过 snapshot、layout、未完成事务、PCTL 读取或 manifest 失败。

## 日常使用

孩子首页展示今天已玩、总额度、剩余时间、8 位码输入和处理状态。状态语言为：

- 正常运行：新的规则已确认；
- 正在同步：系统设置正在传播，通常稍后完成；
- 兼容性待确认：环境结构可用，但不属于已验证组合；
- 保护模式：暂停新的控制修改，状态和恢复仍可使用。
- 控制已停用：红色横幅表示紧急停用已开启，普通写入被阻止；状态、诊断和恢复仍可使用。

家长区：

- 今日额度：进入页面和操作前自动刷新，显示受影响日期、当前已玩、当前剩余、调整后可玩时间以及上次刷新时间；设置和临时加时均支持 ±5/±15、点击分钟数手工输入和小时/分钟换算；不限时状态不能临时加时，设置总额度会恢复限时。不限时改限时与恢复周计划的确认框使用状态卡突出操作前后结果；操作后为 0，或已玩时间不可用、无法判断是否立即限制时，必须长按 `A` 执行；
- 周计划：页面按周一到周日展示七天编辑器，今天使用绿色边框，今天同时被选中时会显示深蓝底色。方向键在日期、切换模式、放弃和保存之间移动，`A` 执行当前候选；`X` 切换模式、`ZL` 放弃、`+` 保存、`Y` 刷新。不限时日期不能编辑分钟，按 `A` 或点按会提示先切换模式；切回限时后恢复此前保留的分钟数。只有修改会影响今天的周计划规则时，页面和分钟输入才显示当前与保存后的预计剩余；若今天有临时设置，则预计值说明会在之后恢复周计划后生效，并持续提示保存周计划不会清除临时设置。存在普通草稿时用左右键选择保存、放弃或继续编辑，再按 `A` 确认；
- 加时码与安全：依次提供“立即生成加时码”“手机/电脑生成加时码”“加时码生成管理”“修改任我玩PIN”和“家长区快捷键管理”。前两个入口直接打开对应生成页，不再经过中转菜单。“加时码生成管理”集中提供管理加时码设备名、管理加时码密钥、导出手机/电脑配置、编辑二维码跳转地址和恢复二维码跳转默认地址。设备名和密钥页使用方向键选择、`A` 确定；`X` 手工输入、`Y` 随机生成、`+` 保存，密钥页另有 `ZR` 显示/隐藏和 `R` 演示密钥。输入和随机结果先成为草稿，保存后才持久化；带草稿离开时会询问继续编辑或放弃。修改 PIN 前必须先验证当前 PIN；快捷键管理页可选择/录制组合、关闭自定义入口，并显示孩子区提示开关与当前状态；
- 支持与恢复：环境状态、唯一推荐操作、紧急停用/恢复、恢复安装前状态、导出诊断，以及显示当前版本、项目仓库和家长网页地址的“软件信息”。

固定 `Minus -` 和启用的自定义组合都需要 PIN。孩子区只在“家长区快捷键管理”的提示开关开启时显示当前自定义组合，不显示固定的兜底入口。

“立即生成加时码”直接进入本机生成页，主动刷新并突出今天已玩、当前还能玩和兑换后预计还能玩；方向键可选中每个时长按钮、生成和返回，`L/R` 约 ±15、`ZL/ZR` 约 ±30、`+` 生成。生成只签发代码，不会立即修改额度；预计时间按生成时状态冻结，且最多到每日 24 小时。

“手机/电脑生成加时码”使用双栏说明：左侧可用手机或电脑扫描二维码自动导入本机配置；右侧说明如何从“加时码生成管理”导出 `parent-import.json`、传到家长设备、手动打开当前二维码跳转地址，并依次选择“导入配置文件”和“导入此设备”。二维码和导入文件都包含生成加时码的权限，不得分享给他人。二维码页面只使用 `B` 或触摸返回，不设置隐藏关闭快捷键。

公开托管的家长端 PWA 位于 [https://selfuppen.github.io/NX-PlayWise/](https://selfuppen.github.io/NX-PlayWise/)。推荐流程：

1. 在 Switch 打开“加时码与安全 → 手机/电脑生成加时码”，验证 PlayWise PIN 后显示二维码和手动导入说明。
2. 使用可信的家长手机扫描二维码；不便扫码时，从“加时码生成管理”导出配置，把 `sdmc:/switch/playwise/parent-import.json` 传到手机或电脑，并在当前二维码跳转 PWA 中导入。
3. 确认设备 ID，选择 UTC+8 生效日期和加时时长，然后生成 8 位码。
4. 把代码交给孩子在 NRO 或 Overlay 中兑换。配对后可收藏页面，但不要分享二维码、导入文件或密钥。

PWA 使用浏览器 Web Crypto 在本地计算 HMAC 和加时码，本项目不会把设备 ID、密钥、日期或生成出的代码提交给业务后端。二维码把配对参数放在 URL fragment 中，fragment 不会进入 HTTP 请求，并会在页面读取后立即从地址栏移除。设备 ID、密钥、常用时长和已签发 nonce 会以明文保存在 `selfuppen.github.io` origin 的 `localStorage`；同一 origin 下的其他路径共享这份存储，因此只能在可信的家长设备和可信站点上使用。首次加载或页面更新需要联网获取静态资源，缓存完成后可离线生成。

### 自部署家长端 PWA

仓库中的 `tools/ptc_frontend` 已包含二维码配对和“导入配置文件”功能，是无需构建、无需后端的纯静态 PWA。将该目录完整发布到可信的 HTTPS 静态站点，再到 Switch 的“加时码生成管理 → 编辑二维码跳转地址”填写部署后的根地址即可。页面资源、manifest 和 Service Worker 均使用相对路径，可部署在域名根目录或子路径。`python tools/ptc_frontend_server.py` 仅用于电脑本机预览，不是正式自部署方式。

Switch 只校验地址格式，不会联网判断页面是否兼容。请使用官方 PWA 或完整部署项目所提供的前端；自定义页面能够读取设备名和加时码密钥，只能填写可信地址。正式部署推荐 HTTPS；localhost、回环地址或私有网络 HTTP 只用于本地调试。底层二维码 fragment 和文件格式契约见[协议](协议.md)。

同一天可以生成多个仍可兑换的代码。调整时长或再生成不会撤销已经签发的代码，页面会继续标明当前显示代码的签发时长，并提示同日签发的其他代码仍可能有效；关闭页面后不会提供已签发代码列表。当天 512 个 nonce 均已签发或消费时，本机将拒绝继续生成并要求次日再试，不会复用 nonce。

Overlay 打开时自动读取一次状态，空闲时可按 `Y` 或点按顶部按钮刷新。刷新会保留已经输入的加时码和最近一次成功状态，并显示“刚刚刷新 / N 秒前”；超过 30 秒会提示数据可能过期。剩余分钟不做本地倒计时，以后台最新状态为准。
```powershell
python .\tools\grant_code.py --minutes 30 --device kid-switch --secret <credentials.json中的secret> --day-index 2380 --nonce 4660
```

secret 只应保存在 Switch 和家长端。短码绑定设备与日期，并且 nonce 只在成功写入、结果保存和 ledger 提交后才消费。连续多次错误会触发 10 分钟冷却。

更新加时码密钥后，当前家长网页配对和使用原密钥签发的代码立即失效，需要重新导入。诊断包不会包含密钥。

“公共演示密钥”用于降低首次试用门槛。它是公开值，没有次数或分钟能力限制；任何知道设备名的人都能生成码，并可把当天额度累计到 1440 分钟。启用前需要重新验证 PIN 和二次确认，启用期间所有家长页面持续显示红色警告。退出后自动生成新的随机 64 位密钥并要求重新配对。

## 同步、回滚和紧急停用

普通规则写入均有恢复事务。Enforce 写入后最多等待 30 秒确认系统状态；期间显示“正在同步”。超时会回滚；若无法证明恢复，自动进入保护并创建：

```text
sdmc:/switch/playwise/flags/disable.flag
```

该 flag 只熔断新的控制写入。孩子页和所有家长页会持续显示红色停用横幅，额度、周计划和加时码写入显示为不可用；周计划进入只读状态，仍可查看、移动焦点和放弃已有草稿，但不能再切换模式、输入分钟或保存。停用前的草稿可在本次运行期间保留，退出程序后不会持久化。仍可查询状态、导出诊断、重试修复、解除停用或恢复安装前状态。家长区“支持与恢复”会提供“解除停用并重新接管”，先执行只读安全预检，只有通过后才删除停用标记并恢复控制。

## PWA 常见排错

- 无法配对：确认使用当前 Switch 的二维码和可信 HTTPS 页面；自定义站点需支持相同 fragment 契约。也可改用 `parent-import.json`。
- 加时码无效或已使用：核对设备名、密钥、UTC+8 日期；修改密钥后使用原密钥签发的代码失效，已使用时重新生成。
- 日期不正确：先校准家长设备与 Switch 日期，再刷新状态并重新生成。
- 设备无响应：等待“正在同步”完成并刷新；仍失败时从支持页导出诊断。
- 紧急停用：该状态会阻止新的控制写入。确认故障已排除后，在家长区“支持与恢复”选择“解除停用并重新接管”；不要直接删除 SD 卡上的 flag 绕过预检。

PWA 页面内也提供折叠式“常见排错指南”。高级排查可检查 `logs/`、`flags/disable.flag` 和恢复状态，但不要对外发送 `credentials.json`、`auth.json`、完整 ledger 或原始离线码。

也可离线创建：

| 目的 | 路径 |
| --- | --- |
| 熔断新写入 | `flags/disable.flag` |
| 重试 setup 修复 | `flags/retry_setup_release.flag` |
| 恢复安装前状态 | `flags/restore_install_snapshot.flag` |

恢复标记优先于 `disable.flag`。安装 snapshot 恢复成功后 phase 为 `restored`，并保持写入熔断；启动遗留事务恢复后也可能保持 `active + disable.flag`。两种状态都会在“支持与恢复”显示“解除停用并重新接管”。确认后会先执行只读预检，只有通过才解除停用并进入接管和 5 秒宽限；预检失败会继续保持停用，不需要手工删除 `setup.json`。

如果需要彻底停止 sysmodule 随开机运行，移除：

```text
sdmc:/atmosphere/contents/4200000000BD2300/flags/boot2.flag
```

## 支持与隐私

“导出诊断包”使用白名单，只包含 build、非秘密 config、rules、state、setup、compatibility 和 environment 信息。它不包含 `credentials.json`、`auth.json`、8 位码、完整 nonce 或 recovery 原始前像。导出进行中、成功或失败均在“支持与恢复”当前页面显示，不打开结果弹层；成功时显示完整路径、提交 GitHub Issue 的提示和 Issue 地址，直到离开页面或再次导出。

系统时间异常时日志保存在 `logs/undated/<boot-id>/`，不会因日期不可用而消失。发现 snapshot 损坏、回滚失败等红色问题时，先导出诊断并停止新的额度写入。
