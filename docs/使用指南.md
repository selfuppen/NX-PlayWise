# 使用指南

本文面向安装和使用任你玩（PlayWise）的家长。项目依赖 Atmosphere、自制系统和 Nintendo 官方家长控制；首次启用前必须掌握 SD 卡读写、官方 PIN/App 解锁以及移除 `boot2.flag` 的恢复方式。

## 准备工作

- 可运行 Atmosphere 的 Nintendo Switch 和可直接读写的 SD 卡。
- 主机日期、时间和时区正确；离线码、每日规则和 PCTL 计时依赖主机时间。
- Windows 与 Python 3。
- 构建完整 package 时，本地 devkitPro 容器可通过 `root@127.0.0.1:1888` 访问，仓库挂载到 `/ws/playwise`。
- 使用 Overlay 时，自行安装与当前 HOS/Atmosphere 匹配的 nx-ovlloader 和 Tesla Menu。项目 package 不捆绑它们。

## 选择 Package

| Package | 适用阶段 | 说明 |
| --- | --- | --- |
| `safe-nro` | 首次安装 | 不启动 sysmodule，不含 Overlay，仅验证 UI 和文件协议 |
| `disabled-boot2` | 停用或启动排障 | 启动完整 sysmodule，但拒绝控制请求 |
| `observe-boot2` | 首次后台验证 | 读取状态并演练请求，不写 PCTL、不消费 nonce |
| `grant-boot2` | 显式控制 | 快速设备测试通过后允许加时和家长操作 |
| `enforce-boot2` | 自动规则 | grant 业务链路稳定后自动对账每日规则和 bedtime |

默认从 `safe-nro` 开始。`grant` 和 `enforce` 不是安装后的默认状态，也不能绕过 capability gate。

## 构建与安装

先运行本地回归：

```powershell
python .\tools\test.py
```

生成完整 package：

```powershell
python .\tools\package_remote.py
```

产物位于 `build/packages/`。解压选定 zip 后，用安装脚本复制并校验 SD 卡内容：

```powershell
.\tools\install_package_to_sd.ps1 -SourceFolder <解压目录> -Drive H -Apply
```

脚本要求再次输入目标盘根路径，切换到 `safe-nro` 时会移除本项目旧 Overlay，但不会删除其他第三方 Overlay。

应用数据位于：

```text
sdmc:/switch/play-time-control/
```

首次使用前编辑 `config.json`，至少替换：

- `device_id`：区分目标 Switch 的稳定标识。
- `grant_secret`：足够长的随机密钥，不得使用仓库占位值。
- `max_add_minutes`：单个加时码允许的上限。
- `control_mode`：保持与所选 package 阶段一致。

同一真实 `grant_secret` 只应存在于该 Switch 配置和家长可信设备。不要将它写入日志、截图、公开 fixture 或仓库。

## 生成 8 位加时码

### 家长端 PWA

本机预览：

```powershell
python .\tools\ptc_frontend_server.py
```

浏览器打开 `http://127.0.0.1:8765`。正式手机使用应将 `tools/ptc_frontend/` 部署到可信 HTTPS 静态站点；普通局域网 HTTP 不保证 Web Crypto 和 PWA 可用。

PWA 在浏览器本地保存设备、密钥和 nonce 历史，生成过程不会把密钥提交给静态服务器。不同浏览器或设备之间不共享 nonce；若发生极少数碰撞，Switch 会返回“授权码已使用”，重新生成即可。

### 命令行

生成 v2 30 分钟数字短码：

```powershell
python .\tools\grant_code.py --tier-minutes 30 --device kid-switch --secret <grant_secret>
```

`--tier-minutes` 只接受 5–120 的 5 分钟倍数，并默认维护当前设备、UTC+8 日期对应的递增 nonce。`--minutes` 生成兼容用 v1 任意分钟码，不是 Companion 和 PWA 的默认用户流程。

## Switch 端使用

### 孩子页面

- Companion 启动后显示今日规则、剩余时间、已玩时间、限制方式和最近结果。
- 按 `A` 或触摸输入按钮录入 8 位数字码；按 `Y` 刷新状态。
- 只有匹配请求返回非 dry-run 成功结果，且计时器已启用、当前限制已解除，才显示真实加时成功。
- 错误页允许重新输入或返回，并保留最近一次有效状态。

### 家长区

孩子页面不显示家长入口。按 `Minus`，或长按两侧肩键加 `X`，仍必须通过本地 PIN 才能进入。家长区可管理今日额度、周计划、bedtime、限制方式、临时解锁和安全探针。

该 PIN 只保护本项目 UI，不是 Nintendo 系统 PIN，也不能解除已经生效的官方 Horizon 限制。

### Tesla Overlay

Overlay 使用标准 Tesla 入口和 3×4 数字键盘提交同一后台请求。它不读取密钥、不验证签名、不直接调用 PCTL。官方硬限制弹窗上能否打开并接收输入取决于 HOS、Atmosphere 和 nx-ovlloader 组合，必须按[测试指南](测试指南.md)真机验收。

## 分阶段启用

1. 安装 `safe-nro`，确认 Companion UI、PIN、输入和 SD 文件可用。
2. 安装 `observe-boot2`，确认后台状态、dry-run 请求、日志和恢复路径；此阶段不应写 PCTL 或消费 nonce。
3. 安装 `grant-boot2`，在“安全工具”执行快速设备测试，确认临时写入、运行时效果和完整恢复全部通过。
4. 按测试指南验证加时累加、重复码拒绝、今日操作和重启持久化。
5. 需要强制阻止或暂停软件时，分别执行对应能力探针；未通过前不要启用。
6. 只有 grant 链路稳定后才安装 `enforce-boot2`，验证去重、跨日、bedtime 和停用恢复。

任何阶段失败都应停在当前阶段，不要用手工修改 `capabilities.json` 绕过验证。

## 停用与恢复

紧急停用后台控制：

```text
sdmc:/switch/play-time-control/flags/disable.flag
```

`disable.flag` 优先于所有控制模式。它阻止本项目继续执行控制操作，但不承诺撤销 Nintendo 官方家长控制已经生效的限制。

完全停止 boot2 时，删除：

```text
sdmc:/atmosphere/contents/4200000000BD2300/flags/boot2.flag
```

也可安装 `disabled-boot2` 进行恢复排查。若官方限制已阻止前台应用，应使用 Nintendo 官方 PIN 或 Parental Controls App 恢复访问，再处理 SD 卡文件。

探针、写入或恢复失败时，保留以下材料：

- `results/` 中对应 request result。
- 当天 `logs/YYYY-MM-DD/`。
- `capabilities.json`。
- `backups/last_pctl_backup.txt`。

不要删除证据后继续尝试更高风险模式。

## 常见问题与边界

### 配置正确但限制不生效

先确认主机日期、时间和时区，执行一次完整网络时间同步并重启。固件升降级后，错误的时间状态可能让配置、探针和 result 看似正常但系统限制不生效。可选用与系统匹配的时间同步工具；第三方工具需自行核对来源和版本。

### 能否按用户或游戏分别限时

不能。Nintendo play timer 是整台主机级别，本项目不提供 per-user、per-title、年龄分级、社交、通信或 eShop 购买控制。

### 能否替代官方家长控制

不能。本项目提供本地规则和离线加时通道，不拥有官方限制弹窗，也不替代官方 PIN、官方 App 或系统的 `Suspend Software` 设置。

### 更新系统后是否需要复测

需要。HOS、Atmosphere、nx-ovlloader 或相关系统配置变化后，应重新执行快速设备测试；依赖 Overlay 的场景还必须重新验证官方硬限制弹窗上的显示和输入。

协议字段和错误语义见[协议](协议.md)，完整验收步骤见[测试指南](测试指南.md)。
