# 使用指南

本文面向安装和使用任你玩（PlayWise）的家长。项目依赖 Atmosphere、自制系统和 Nintendo 官方家长控制；首次启用前必须掌握 SD 卡读写、官方 PIN/App 解锁，以及移除 `boot2.flag` 的恢复方式。

## 构建与安装

本地回归：

```powershell
python .\tools\test.py
```

涉及 C、Makefile、Companion、Overlay、sysmodule 或 package 的改动，通过 devkitPro 容器入口构建：

```powershell
python .\tools\package_remote.py
```

构建只生成 `build/packages/playwise-<timestamp>.zip`。包内包含 sysmodule、Companion NRO、Tesla Overlay 和 `boot2.flag`，初始 `control_mode` 为 `enforce`。

使用权威安装入口：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_package_to_sd.ps1 -Package .\build\packages\playwise-<timestamp>.zip -SdRoot E:\
```

安装脚本只替换不可变二进制和缺失的初始模板，不删除整个 `switch/playwise`。更新时保留 `grant_secret`、PIN、rules、state、ledger、日志和备份；首次安装或旧五包迁移会备份旧配置、设置 Enforce 并创建 `setup.json: pending`。

## 首次引导

重启后 sysmodule 在 IPC 和普通 scheduler 之前处理 setup：

1. 捕获完整 0x44 PCTL settings 与 timer enabled 状态。
2. 首次写入 `backups/install_pctl_snapshot.json`；后续重试不得覆盖。
3. 若当前受限，写入当天 unlimited、启动 timer，并确认 `unrestricted_today=true`、`restricted_now=false`。
4. 成功进入 `released`；失败则精确恢复 snapshot、创建 `disable.flag` 并进入 `failed`。

Companion 启动后优先显示首次引导页。设置或验证本地 PIN，确认状态可读和当前限制已解除，然后在家长区“安全工具”选择“启用自动控制”。系统保存 60 秒激活宽限，宽限结束后 setup 进入 `active`，Enforce 才开始应用规则。

`released` 阶段允许状态和引导操作，但普通加时、规则写入、raw/suspend 探针和 Enforce 都会返回 `308 setup_pending`。

## 日常使用

### 生成 8 位加时码

家长端 PWA 本地预览：

```powershell
python .\tools\ptc_frontend_server.py
```

浏览器打开 `http://127.0.0.1:8765`。正式手机场景应部署到可信 HTTPS 静态站点。密钥只保存在浏览器本地。

命令行生成 30 分钟 v2 码：

```powershell
python .\tools\grant_code.py --tier-minutes 30 --device kid-switch --secret <grant_secret>
```

### Companion 与 Overlay

Companion 孩子页显示今日状态并提交 8 位数字码；按 `Minus` 或肩键组合进入 PIN 保护的家长区。家长区可管理今日额度、周计划、bedtime、限制方式、临时解锁和恢复入口。

Overlay 只提交同一请求，不读取 `grant_secret`、不验证 token、不直接调用 PCTL。它能否覆盖官方硬限制弹窗取决于目标 HOS、Atmosphere 和 nx-ovlloader 组合。

普通 set limit、unlimited、加时、恢复规则和 Enforce 不要求 play-timer capability 探针。每次写入都会保存恢复事务，启动 timer 并确认运行时状态，随后才提交 rules/state/ledger/result。

`raw_block` 与 `suspend` 仍是高风险可选能力，只在相关功能需要时运行独立探针。

## 停用与恢复

紧急停用正常控制：

```text
sdmc:/switch/playwise/flags/disable.flag
```

重试首次解除：

```text
sdmc:/switch/playwise/flags/retry_setup_release.flag
```

恢复安装前 PCTL 状态：

```text
sdmc:/switch/playwise/flags/restore_install_snapshot.flag
```

两个恢复 flag 的优先级高于 `disable.flag`。恢复安装 snapshot 成功后 setup 进入 `restored`，并保留 `disable.flag`。

完全停止 boot2 时删除：

```text
sdmc:/atmosphere/contents/4200000000BD2300/flags/boot2.flag
```

若恢复事务或 setup 恢复无法被精确证明，系统会创建 `disable.flag`。保留 `setup.json`、`recovery/`、`backups/install_pctl_snapshot.json`、对应 `results/` 和当天 `logs/` 后再排查。

## 更新与复测

普通代码回归默认不做真机测试。只有改动涉及 PCTL、启动引导、Companion/Overlay 输入、Enforce、raw block 或 suspend 时，才执行[测试指南](测试指南.md)中的对应单项场景。

HOS/PCTL 行为变化或新设备首次启用时，必须完成一次单包端到端验收：受限状态安装并确认自动解除、完成 setup 后使用一个 15 分钟 v2 码、重启确认持久化，并首次验证一次安装 snapshot 恢复。
