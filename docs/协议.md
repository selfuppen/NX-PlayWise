# 协议

本文是公开 Release 的权威契约。文件 schema 为 v1；离线 token 保留 v1/v2 解码，用户界面默认使用 v2 8 位数字码。Device Lab 使用独立 profile 和根目录，其危险请求不属于公开协议。

## 运行目录

```text
sdmc:/switch/playwise/
├── build.json
├── config.json
├── credentials.json
├── auth.json
├── rules.json
├── state.json
├── setup.json
├── compatibility.json
├── environment.json
├── inbox/{pending,processing,done}/
├── results/
├── ledger/used_nonces.jsonl
├── backups/install_pctl_snapshot.json
├── recovery/active/
├── flags/
├── logs/
│   ├── YYYY-MM-DD/
│   └── undated/<boot-id>/
└── support/
```

`build.json` 是程序资产，每次升级替换；其余 JSON 是运行数据或首次安装 seed。Release 不创建 `capabilities.json`。

## 配置契约

### `build.json`

与包内 `playwise-install/release-manifest.json` 完全一致，至少包含：

```json
{
  "schema_version": 1,
  "playwise_version": "0.1.0",
  "commit": "<40-hex>",
  "release_id": "playwise-0.1.0+<12-hex>",
  "profile": "release",
  "protocol_version": 1,
  "recovery_version": 1,
  "pctl_layout_version": 1,
  "build": {
    "devkitpro": "<compiler identity>",
    "libnx": "<version>",
    "libtesla_commit": "<40-hex>"
  },
  "verified_environment": {
    "model": "Nintendo Switch OLED",
    "hos": "22.5.0",
    "atmosphere": "1.11.2",
    "qualification_date": "2026-08-07",
    "result": "requires-requalification-for-final-artifact"
  }
}
```

同一紧凑 JSON 必须嵌入 sysmodule、NRO 和 Overlay。profile、版本或 release ID 不匹配返回 `504 release_manifest_invalid`。

### `config.json` 与 `credentials.json`

```json
{
  "version": 1,
  "device_id": "kid-switch",
  "max_add_minutes": 120,
  "default_request_timeout_ms": 60000
}
```

```json
{
  "version": 1,
  "grant_secret": "<sysmodule 首次启动生成的 64 位小写 hex>"
}
```

正式模式的 secret 不得进入模板、manifest、日志或支持包。首次启动仍由 sysmodule
使用 `randomGet` 生成设备唯一的 64 位小写十六进制 secret。管理界面允许保存 32–64
个非空白可打印 ASCII 字符；更新加时码密钥会使家长端旧配置和此前签发的码失效。

家长可在再次验证 PlayWise PIN、查看具体风险并二次确认后，主动切换到公开演示密钥
`playwise-public-demo-secret-0001`。该值不是私密凭证，不得作为安装 seed；启用后任何知道
设备名的人均可签发多个 1–120 分钟码，并可将当日额度累计至 1440 分钟。家长页面必须
持续显示红色低安全警告。退出演示模式时生成新的随机 64 位密钥，不保存旧密钥副本。

### `auth.json`

```json
{
  "version": 1,
  "pin_hash": "<64-hex>",
  "pin_salt": "<32-hex>",
  "hash": "hmac-sha256",
  "updated_at": 1783526400
}
```

PIN 必须恰好 6 位。hash 的 key 为 PIN UTF-8，message 为 `"PTC-PIN1" || salt16`。空 hash/salt 表示首次设置未完成。

### `rules.json`

```json
{
  "version": 1,
  "week": [
    {"mode": "unlimited", "minutes": 120},
    {"mode": "limit", "minutes": 60},
    {"mode": "limit", "minutes": 60},
    {"mode": "limit", "minutes": 60},
    {"mode": "limit", "minutes": 60},
    {"mode": "limit", "minutes": 60},
    {"mode": "unlimited", "minutes": 120}
  ],
  "today_override_present": false,
  "today_override_day_index": 0,
  "today_override_mode": "limit",
  "today_override_minutes": 60
}
```

星期顺序为 Sun=0 到 Sat=6。mode 只允许 `limit` 和 `unlimited`；不存在 `blocked`、bedtime 或 `limit_action`。

### `state.json`

关键字段：

```json
{
  "version": 1,
  "last_enforced_day_index": 0,
  "last_enforced_mode": 0,
  "last_enforced_minutes": 0,
  "apply_status": "idle",
  "apply_pending_confirmation": false,
  "apply_confirmation_deadline": 0,
  "pending_mode": 0,
  "pending_minutes": 0,
  "updated_at": 0,
  "v2_failed_attempts": 0,
  "v2_cooldown_until": 0
}
```

Enforce 写入后先保存 `apply_status:"applied_pending_confirmation"`。确认期限为写入后 30 秒；确认成功清空 pending，超时回滚。连续 5 次 v2 格式或签名失败触发 10 分钟冷却。

### setup、兼容与环境

`setup.json.phase` 允许 `unconfigured`、`pending`、`released`、`active`、`failed`、`protection`、`restored`。`compatibility_status` 使用 `pending`、`verified`、`accepted_unknown` 或 `protection`。

`environment.json` 记录 HOS、firmware hash/digest、产品型号和是否运行于 Atmosphère；精确 Atmosphère 版本只记录在资格 manifest，不作为严格运行时判定。

`compatibility.json` 保存家长接受的精确环境指纹和时间。未知兼容可由 PIN + 长按确认；snapshot、PCTL layout、旧事务、PCTL 初始化/读取或 manifest 失败不可由 Release 绕过。

## Request

文件路径为 `inbox/pending/<request_id>.json`；IPC service 为 `pctc:u`。通用外壳：

```json
{
  "version": 1,
  "request_id": "client-unique-id",
  "type": "status",
  "created_at": 1783526400,
  "payload": {}
}
```

Release 只接受：

| ID | type | payload |
| ---: | --- | --- |
| 1 | `offline_code` | `{"code":"12345678"}` |
| 2 | `status` | `{}` |
| 3 | `set_today_limit` | `{"minutes":60}` |
| 4 | `add_today_minutes` | `{"minutes":15}` |
| 5 | `disable_today_limit` | `{}` |
| 7 | `restore_today_policy` | `{}` |
| 8 | `set_weekly_template` | `{"days":[7 个 mode/minutes 对象]}` |
| 19 | `complete_setup` | `{}` |
| 20 | `retry_setup_release` | `{}` |
| 21 | `restore_install_snapshot` | `{}` |

ID 6、9–18 永久不属于 Release；旧字符串返回 `102 unknown_request_type`。`disable.flag` 存在时 status 与 setup/recovery 请求仍可执行，普通控制写返回 `300 disabled`。

## Result

结果原子写入 `results/<request_id>.json`，并将请求移入 `inbox/done/`。成功结构：

```json
{
  "version": 1,
  "request_id": "client-unique-id",
  "type": "status",
  "status": "ok",
  "state": {
    "day_index": 2380,
    "limited_today": 1,
    "blocked_today": 0,
    "unrestricted_today": 0,
    "remaining_available": true,
    "remaining_minutes": 45,
    "played_minutes_available": true,
    "played_minutes": 15,
    "play_timer_enabled": 1,
    "restricted_now": 0
  },
  "completed_at": 1783526400
}
```

失败将 `status` 改为 `error` 并增加：

```json
"error": {"code": 312, "reason": "protection_mode", "message": "安全前置检查失败，已进入保护模式"}
```

result 不输出控制模式或 dry-run 字段。

## 家长网页配对

Companion 使用当前 `device_id` 和 `grant_secret` 生成以下 HTTPS fragment URL 的二维码：

```text
https://selfuppen.github.io/playwise/#device_id=<url-encoded>&grant_secret=<url-encoded>
```

fragment 不随 HTTP 请求发送。PWA 读取后必须立即用 `history.replaceState` 清除地址栏参数，
验证设备名为 1–32 位 `[A-Za-z0-9_-]`、密钥为 32–64 个非空白可打印 ASCII 字符，并在
家长确认后才替换 `localStorage` 中的当前设备。取消、缺字段或验证失败不得改写旧配置。

文件配对使用 `sdmc:/switch/playwise/parent-import.json`：

```json
{"version":1,"device_id":"kid-switch","grant_secret":"<32–64 chars>"}
```

二维码显示、导出文件、显示当前密钥和保存新密钥均需再次验证 PlayWise 管理 PIN。

## 写入与恢复顺序

普通写入的提交顺序固定为：

1. 读取并验证 request、setup、配置、规则和 token；
2. 在 `recovery/active/` 原子保存 PCTL snapshot 及 rules/state/ledger 前像；
3. 应用 PCTL 目标并启动 timer；
4. 观察运行时目标；Enforce 允许短暂 pending，其余写请求失败即回滚；
5. 原子保存 rules/state/result；
6. 仅对成功 token 追加 nonce；
7. 清除恢复事务并归档 request。

无效 token、写失败、result 失败、ledger 失败和回滚路径不得提前消费 nonce。回滚无法精确证明时保留现场并创建 `disable.flag`。

## 日志与支持

有效 UTC+8 日期写入 `logs/YYYY-MM-DD/`；日期无效时写入 `logs/undated/<boot-id>/`。支持导出只允许 build/config/rules/state/setup/compatibility/environment 白名单字段，禁止 credentials、auth、离线码、完整 nonce 和原始 recovery 数据。

## Device Lab 协议边界

Device Lab 使用 `profile=device-lab`、`pwtl:u`、Title ID `4200000000BD23F0` 和 `sdmc:/switch/playwise-device-lab`。其 probe 请求只在 `PLAYWISE_DEVICE_LAB` 编译下解析和分发，公开 package 的二进制扫描会拒绝这些字符串。
