# 协议

This document defines the v1 file and token contracts used between companion, sysmodule, and developer tools.

## SD Card Root

```text
sdmc:/switch/play-time-control/
```

Tesla overlay 本体安装在应用根目录之外：

```text
sdmc:/switch/.overlays/pctc.ovl
```

它仍只通过上述 `play-time-control` request/result 文件协议通信。

## PCTL Role

PCTL refers to the Nintendo Switch parental-control service surface exposed through libnx `pctl*` APIs. In this project it is accessed only through the platform PCTL adapter:

- `observe` may read PCTL status and report it in `result.state`, but must not write PCTL.
- `grant` and later `enforce` may write PCTL only after policy checks and backup succeed.
- PCTL read or write failures must be returned as structured results when a request id can be parsed.

## Config Files

`config.json`:

```json
{
  "version": 1,
  "device_id": "kid-switch",
  "grant_secret": "replace-with-long-random-secret",
  "max_add_minutes": 120,
  "control_mode": "observe",
  "allow_unlimited_to_limited": false,
  "default_request_timeout_ms": 60000
}
```

`auth.json`:

```json
{
  "version": 1,
  "pin_hash": "hex-encoded-hmac-sha256",
  "pin_salt": "hex-encoded-16-bytes",
  "hash": "hmac-sha256",
  "updated_at": 1783526400
}
```

`capabilities.json`:

```json
{
  "version": 1,
  "play_timer_write_verified": false,
  "play_timer_write_backend": "pctl-s-v2",
  "play_timer_effect_verified": false,
  "play_timer_effect_backend": "pctl-s-runtime-v2",
  "raw_block_verified": false,
  "raw_block_backend": "pctl-s-rawblock-v1",
  "suspend_verified": false,
  "suspend_backend": "pctl-s-suspend-v1",
  "verified_at": {
    "play_timer_write": 0,
    "raw_block": 0,
    "play_timer_effect": 0,
    "suspend": 0
  }
}
```

Every capability flag is gated by its backend string. A missing or non-matching
`raw_block_backend` or `suspend_backend` invalidates the corresponding `*_verified`
value on load, so a hand-edited or stale `capabilities.json` cannot unlock
`block_today` or the `suspend` limit action.

PIN hash:

- `pin_salt` is 16 random bytes encoded as 32 lowercase hex symbols.
- `pin_hash` is lowercase hex HMAC-SHA256 with key = the UTF-8 PIN bytes and message = `"PTC-PIN1" || salt16`.
- An empty `pin_hash` and empty `pin_salt` means the Companion parent-area PIN has not been initialized yet.
- This PIN protects only the local Companion parent area; it is not the Nintendo system parental-control PIN.

`rules.json`:

```json
{
  "version": 1,
  "week": [
    { "mode": "unlimited", "minutes": 120 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "unlimited", "minutes": 120 }
  ],
  "today_override_present": false,
  "today_override_day_index": 0,
  "today_override_mode": "limit",
  "today_override_minutes": 60,
  "bedtime_enabled": false,
  "bedtime_start_min": 1260,
  "bedtime_end_min": 480,
  "limit_action": "remind"
}
```

`state.json`:

```json
{
  "version": 1,
  "parent_unlock_until": 0,
  "last_enforced_day_index": 0,
  "last_enforced_mode": 0,
  "last_enforced_minutes": 0,
  "updated_at": 1783526400
}
```

Rules/state compatibility:

- Missing `rules.json` or `state.json` is read as the default rules/state above.
- Invalid `"version"` in `rules.json` returns `rules_invalid`.
- `mode` values are `limit`, `unlimited`, and `blocked`.
- `limit_action` values are `remind`, `raw_block`, and `suspend`.
- `parent_unlock_until` is a Unix timestamp; `0` means inactive.
- `parent_unlock_until` records a local temporary parent unlock window created by `parent_unlock_start`.
  While the current Unix time is before this value, result state reports `parent_unlock_active: true`,
  and local rule evaluation does not mark `restricted_now` only because of `blocked` mode or bedtime.
  It is not the Nintendo system parental-control PIN and does not by itself clear an already active
  Horizon/PCTL restriction.
- `last_enforced_*` fields are used only by `enforce` to avoid rewriting the same play timer target every loop. Missing fields are treated as not yet enforced.

## Token v1

Display format:

```text
XXXX-XXXX-XXXX-XXXX
```

Encoding:

- Crockford Base32.
- 16 symbols total.
- 80 bits total.
- 60-bit payload.
- 20-bit truncated HMAC-SHA256.

Payload:

```text
version:              4 bit
action:               4 bit
minutes:             11 bit
day_index_since_2020:16 bit
nonce:               25 bit
```

HMAC input:

```text
"PTC1" || device_id || NUL || payload_bits_as_bytes
```

Supported action:

```text
1 = add_today_minutes
```

`add_today_minutes` stacks the granted minutes onto today's existing limit; it does
not overwrite the daily total. The base is today's effective LIMIT minutes (today
override if present, otherwise the weekly template); an unlimited or blocked day
starts from 0. The result is clamped to the single-day maximum (1440) so the PCTL
write always stays in range. In `grant`/`enforce` the sysmodule persists the stacked
value into `today_override` in `rules.json`, so the enforce reconciliation keeps it
instead of reverting to the weekly template. `observe` dry-runs neither stack nor
persist.

Other local parent operations must use request queue types, not offline token actions.

## Request Queue

Companion writes requests atomically:

1. Generate `request_id` as `<unix_ms>-<random16>`.
2. Write `inbox/pending/<request_id>.json.tmp`.
3. Rename to `inbox/pending/<request_id>.json`.

Sysmodule processing:

1. Rename pending request to `inbox/processing/<request_id>.json`.
2. Process request.
3. Write `results/<request_id>.json`.
4. Move original request to `inbox/done/<request_id>.json`.

Request shape:

```json
{
  "version": 1,
  "request_id": "1783526400123-a4f2",
  "type": "offline_code",
  "created_at": 1783526400,
  "payload": {
    "code": "241W-2AE0-04HM-YKC7"
  }
}
```

Supported request types:

- `offline_code`
- `status`
- `set_today_limit`
- `add_today_minutes`
- `disable_today_limit`
- `block_today`
- `restore_today_policy`
- `set_weekly_template`
- `set_bedtime`
- `set_limit_action`
- `parent_unlock_start`
- `parent_unlock_end`
- `probe_play_timer_write`
- `probe_apply_today_limit`
- `probe_play_timer_effect`
- `probe_raw_block`
- `probe_suspend`

Request payloads:

- `offline_code`: `{ "code": "XXXX-XXXX-XXXX-XXXX" }`
- `status`: `{}`
- `set_today_limit`: `{ "minutes": 45 }`
- `add_today_minutes`: `{ "minutes": 15 }`
- `disable_today_limit`: `{}`
- `block_today`: `{}`
- `restore_today_policy`: `{}`
- `set_weekly_template`: `{ "days": [{ "mode": "limit", "minutes": 60 }, ... seven items total ...] }`
- `set_bedtime`: `{ "enabled": true, "start_min": 1260, "end_min": 480 }`
- `set_limit_action`: `{ "action": "remind" }`
- `parent_unlock_start`: `{ "duration_minutes": 15 }`
- `parent_unlock_end`: `{}`
- `probe_play_timer_write`: `{}`
- `probe_apply_today_limit`: `{ "minutes": 1, "start_timer": true }`
- `probe_play_timer_effect`: `{ "wait_for_expiry": false }`; this request bypasses token, nonce, rules and ordinary capability gates, but still obeys `disable.flag`, backup and mode (`grant`/`enforce`).
- `probe_raw_block`: `{}`
- `probe_suspend`: `{}`

`parent_unlock_start` sets `state.parent_unlock_until` to `now + duration_minutes * 60`;
`parent_unlock_end` sets it back to `0`. In `observe` mode these requests remain dry-run and do not
persist the state change. This parent unlock affects only the project's local rule evaluation and
status reporting; it is separate from the official Nintendo parental-control unlock flow.

Host sysmodule v1 validates `version`, `request_id`, `type`, `created_at`, `payload`, known request type, and the required payload fields before dispatch. A request with a parsable `request_id` should still receive a structured result when validation fails.

Success result shape:

```json
{
  "version": 1,
  "request_id": "1783526400123-a4f2",
  "type": "offline_code",
  "status": "ok",
  "mode": "observe",
  "dry_run": true,
  "state": {
    "day_index": 2380,
    "limited_today": -1,
    "blocked_today": -1,
    "unrestricted_today": -1,
    "remaining_available": false,
    "remaining_minutes": -1,
    "play_timer_enabled": -1,
    "restricted_now": -1,
    "bedtime_active": false,
    "parent_unlock_active": false
  },
  "capabilities": {
    "play_timer_write_verified": false,
    "raw_block_verified": false,
    "suspend_verified": false
  },
  "completed_at": 1783526401
}
```

Error result shape:

```json
{
  "version": 1,
  "request_id": "1783526400123-a4f2",
  "type": "offline_code",
  "status": "error",
  "mode": "observe",
  "dry_run": true,
  "error": {
    "code": 203,
    "reason": "bad_signature",
    "message": "授权码签名不匹配"
  },
  "completed_at": 1783526401
}
```

`probe_apply_today_limit` result keeps the same top-level success/error schema and adds a `probe_apply` object. The object includes `target_weekday`, `target_minutes`, `target_mode`, `start_timer_requested`, `start_timer_called`, `pctl_error`, `write_ipc_result`, `start_timer_error`, before/after PCTL status snapshots, and `debug_evidence` with `before_raw_hex`, `after_raw_hex`, `before_slots`, `after_slots`, `raw_changed`, and a short troubleshooting `hint`. These fields are developer evidence only; they do not contain `grant_secret`, PIN, or offline token text.

`probe_raw_block` adds `pctl_raw_block_probe` with `verdict` (`pass`, `fail`, `not_run`),
`failure_stage`, a fixed `target_minutes: 0`, `before`/`active`/`restored` status snapshots,
`opaque_snapshots.before_hex`/`active_hex`/`restored_hex`, `checks.raw_target_written`,
`checks.blocked_observed`, `checks.raw_restored`, `checks.timer_restored`, and `ipc_result`.
`result.state` describes the restored device, not the momentary blocked state the probe wrote.
`failure_stage` values are `none`, `observe`, `before_read`, `snapshot`, `backup`, `write`,
`start_timer`, `raw_target`, `runtime_status`, `restore`, and `capability_persist`.

`probe_play_timer_effect` adds `pctl_effect_probe` with `verdict` (`pass`, `fail`, `inconclusive`), `failure_stage`, `target_minutes`, `before`/`active`/`restored` status snapshots, `opaque_snapshots.before_hex`/`active_hex`/`restored_hex`, `checks.raw_target_correct`, `checks.timer_enabled`, `checks.remaining_available`, `checks.raw_restored`, `checks.timer_restored`, `ipc_result`, and `expiry_observed`. Fast mode temporarily uses a 1440-minute daily limit. When 1440 already matches the original raw settings, it lowers the target by at most 10 minutes while preserving at least one minute of reported remaining time; if no such safe target exists, the probe reports `inconclusive` and restores without forcing expiry. It must verify raw adoption and a remaining-time change in the expected direction while the timer stays enabled before polling for up to five seconds. This avoids treating an absolute daily limit as remaining play time and avoids an immediate expiry after play time has already accumulated. The probe must always restore the complete opaque 0x44 settings snapshot plus the original timer enabled state. Expiry mode polls for up to 90 seconds; an applet that does not count play time must report `inconclusive` rather than success.

## Mode Semantics

- `disabled` and `flags/disable.flag` reject requests with `disabled`; `disable.flag` is checked before offline token validation or write-path PCTL access.
- `observe` returns dry-run results and does not persist rule/state/capability changes, does not write PCTL, and does not consume nonce. It may report that PCTL is currently unrestricted, but it does not reject offline-code dry-runs with `unlimited_not_allowed`.
- `grant` may apply direct parent requests and offline-code grants through the backup gate.
- `enforce` is reserved for the later timer refresh and automatic policy application path.
- Offline-code nonce is consumed only after PCTL write succeeds and `results/<request_id>.json` is persisted.
- In `grant`/`enforce`, `offline_code` success additionally requires `StartPlayTimer (1451)` and a runtime status observation within five seconds where `play_timer_enabled == 1` and `restricted_now == 0`. If this is not observed, the result is `pctl_effect_not_observed`; the nonce and today's override remain unpersisted, and retrying re-applies the same absolute target.
- `unlimited_not_allowed` applies only to write-capable modes when PCTL currently reports unrestricted and `allow_unlimited_to_limited` is false.
- Before `probe_play_timer_write` succeeds outside `observe`, `grant` and `enforce` PCTL writes are rejected with `pctl_write_not_verified` unless an earlier policy guard applies. In particular, when PCTL reports unrestricted and `allow_unlimited_to_limited` is false, `unlimited_not_allowed` takes precedence.
- `grant` and `enforce` writes require both `play_timer_write_verified` and `play_timer_effect_verified`; an old capability file missing the effect fields is treated as unverified.
- `probe_play_timer_write` performs a conservative read -> same-value write -> readback check for play timer settings through the multi-session `pctl:s` service. It sets `play_timer_write_verified` only after backup and successful readback, and persists `play_timer_write_backend: "pctl-s-v2"`.
- `probe_apply_today_limit` is a development-only bottom-layer verification request. In `grant` or `enforce` it reads PCTL status, backs up raw play timer settings, writes today's play timer target to an explicit limit value (default 1 minute), immediately reads back raw settings, optionally calls `start_timer`, reads PCTL status again, and writes a result with debug evidence. In `observe` it is dry-run and must not write PCTL. `disable.flag` still wins before any write path. This request never consumes offline token nonce and does not require or set `play_timer_write_verified`.
- `probe_play_timer_effect` is the dedicated runtime-effect probe. It bypasses token, nonce, rules and ordinary capability gates, but `observe` only returns `dry_run:true`/`verdict:"not_run"`; `grant`/`enforce` perform the fast or optional expiry probe. Any restore failure returns `pctl_restore_failed`, clears both write/effect capabilities and creates `disable.flag`.
- A missing or different `play_timer_write_backend` invalidates an old `play_timer_write_verified` value. Layout v2 also requires `play_timer_effect_backend: "pctl-s-runtime-v2"`; v1 capability values are invalidated. The adapter never opens or falls back to the single-session `pctl:a` service. The same rule applies to `raw_block_backend: "pctl-s-rawblock-v1"` and `suspend_backend: "pctl-s-suspend-v1"`.
- `probe_raw_block` is the raw block capability probe. It uses no new PCTL command: it rehearses exactly what `block_today` performs by writing today's weekday with the restricted flags and `minutes = 0` through the already verified play timer settings write path, then confirms the device reports the restriction at runtime, then restores the complete opaque 0x44 snapshot and the original timer enabled state. It is refused with `pctl_write_not_verified` or `pctl_effect_not_verified` until plain writes and their runtime effect are proven, so a hard block is never rehearsed on an unproven write path. In `observe` it returns `dry_run:true`/`verdict:"not_run"` and writes nothing. A restore failure returns `pctl_restore_failed`, clears `raw_block_verified` and creates `disable.flag`, because a failed restore can otherwise leave the console blocked.
- `probe_suspend` is read-only. It opens `pctl:s`, reads `IsPlayTimerAlarmDisabled` (1458) and requests the play timer suspension event through `GetPlayTimerEventToRequestSuspension` (1457), then closes the handle without waiting. A usable event handle is the evidence that the suspend limit action is deliverable; a disabled play timer alarm fails the probe because it would swallow the suspension request. `suspend_verified` therefore records that the system suspension-request channel is available. Horizon performs the actual suspension according to the console's own parental-control setting; this project does not suspend software itself.
- `raw_block` and `suspend` limit actions are rejected until the matching capability is verified. Probe requests can set capability flags only outside `observe` and only after backup and probe success.

## PCTL Debug Evidence

`logs/pctl_debug.jsonl` is an internal developer/debug JSON Lines file written around PCTL write-capable paths. It is not a child-visible UI surface and must not contain `grant_secret`, PINs, or offline token text.

Each line records one PCTL evidence point:

```json
{"ts":1783526401,"request_id":"1783526400123-a4f2","type":"offline_code","stage":"apply_target","mode":"grant","target_mode":"limit","target_minutes":30,"weekday":5,"error":"ok","ipc_result":"0x00000000","before_available":true,"before_error":"ok","before_ipc_result":"0x00000000","before_raw_hex":"...","before_slots":"h:257,1,0,0,0,0,0;d0:flag=1536,enabled=256,m=60;...","after_available":true,"after_error":"ok","after_ipc_result":"0x00000000","after_raw_hex":"...","after_slots":"h:257,1,0,0,0,0,0;d0:flag=1536,enabled=256,m=60;..."}
```

Stable `stage` values currently include:

- `backup`
- `probe_play_timer_write`
- `probe_apply_before`
- `probe_apply_write`
- `probe_apply_after`
- `probe_apply_start_timer`
- `probe_raw_block`
- `probe_suspend`
- `apply_target`
- `start_timer`

`before_raw_hex` and `after_raw_hex` are the adapter-visible play timer raw settings snapshots when available. Layout v2 comes from the existing PCTL implementation plus a matching real-device 0x44 snapshot: words `0..6` are the header, and day `n` starts at word `7 + 4n`. The day fields are `flag`, `enabled`, and `minutes` at offsets `+0`, `+1`, and `+2`; records except Saturday also have a trailing padding word. Slot summaries use `h:<seven header words>;d<weekday>:flag=<word0>,enabled=<word1>,m=<minutes>`. Limited/blocked writes set `flag=0x0600` and `enabled=0x0100`; unlimited writes clear both fields. Writes preserve every unrelated word and reject snapshots whose flags or minute values fall outside the verified layout. These fields are diagnostic evidence only; real system effect is still confirmed by the official parental-control page or actual play timer behavior.

Real-device A/B evidence shows that `GetPlayTimerRemainingTime (1454)` returns an inline signed `s64` nanosecond duration: after the configured daily limit has already expired, the value is negative. The Switch adapter converts positive values to whole minutes using `remaining_ns / (60 * 10^9)` and clamps zero or negative values to `0` before populating `remaining_minutes`; it must not dispatch into `u32`, reinterpret the value as unsigned, or treat the raw value as minutes.

For `probe_apply_today_limit`, failure interpretation is intentionally concrete:

- `pctl_init_failed` points first to `pctl:s` init/session/permission problems.
- `probe_play_timer_write` same-value write success followed by `probe_apply_today_limit` write failure points first to command id, write permission, or parameter shape.
- Raw readback changes but the official parental-control page does not change points first to raw layout, missing commit/apply semantics, or a required start/apply condition.
- The official page changes but play time does not count down points first to `start_timer` or play timer enable conditions.

This request verifies only whether today's play timer write can become system-visible for the target minute value. It does not verify every parental-control setting, raw block, suspend, bedtime, or all weekly layout semantics.

## Error Contract

Each error code must have:

- Numeric code.
- Stable reason string.
- User-facing Chinese message.
- Developer log detail.

Unknown schema, unknown request type, bad JSON, bad token, disabled mode, capability guard failure, backup failure, PCTL failure, and storage failure must all map to stable errors.

The runtime-effect probe uses `pctl_effect_not_verified` when ordinary writes lack the verified effect capability, `pctl_effect_not_observed` when runtime status does not adopt the target or expiry is not observed, and `pctl_restore_failed` when the opaque settings/timer restoration cannot be proven.

For child-facing clients, `status:"ok"` on a write-capable `offline_code` now means the PCTL target write, timer start and runtime restriction release were all observed. `observe` remains a dry-run and must never be presented as an unlock.
