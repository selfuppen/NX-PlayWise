# 协议

本文是 Companion、Tesla Overlay、sysmodule 和开发工具之间的权威契约。文件协议版本为 v1，离线 token 同时支持 v1 和 v2；用户界面默认使用 v2 8 位数字短码。

## SD 卡布局

应用根目录：

```text
sdmc:/switch/playwise/
├── config.json
├── auth.json
├── rules.json
├── state.json
├── capabilities.json
├── inbox/
│   ├── pending/
│   ├── processing/
│   └── done/
├── results/
├── logs/YYYY-MM-DD/
│   ├── sysmodule.log
│   ├── events.jsonl
│   └── pctl_debug.jsonl
├── ledger/used_nonces.jsonl
├── backups/last_pctl_backup.txt
└── flags/
    ├── disable.flag
    └── reload.flag
```

Overlay 位于 `sdmc:/switch/.overlays/pctc.ovl`，仍只通过相同 IPC/request/result 契约通信。五个配置文件及 request/result JSON 顶层必须包含 `"version": 1`；JSON Lines 日志和 ledger 使用各自下文定义的逐行契约。

`disable.flag` 优先于所有控制模式。外部工具原子创建一次性 `reload.flag` 后，sysmodule 强制刷新配置并对账，再删除该文件。

日志、day index 和清理日期统一使用 UTC+8。系统保留当天及之前 29 个自然日；第 30 天及更早的日志目录、`results/*.json` 和 `inbox/done/*.json` 才可清理。时间无效、日期在未来或文件名未知时必须保留。

## 配置文件

### `config.json`

```json
{
  "version": 1,
  "device_id": "kid-switch",
  "grant_secret": "replace-with-long-random-secret",
  "max_add_minutes": 120,
  "control_mode": "observe",
  "allow_unlimited_to_limited": false,
  "default_request_timeout_ms": 60000
}
```

`grant_secret` 只允许 sysmodule 和家长可信设备读取。未知 `control_mode` 按 `observe` 处理。

### `auth.json`

```json
{
  "version": 1,
  "pin_hash": "hex-encoded-hmac-sha256",
  "pin_salt": "hex-encoded-16-bytes",
  "hash": "hmac-sha256",
  "updated_at": 1783526400
}
```

- `pin_salt` 是 16 个随机字节的小写 hex。
- `pin_hash` 是 HMAC-SHA256 小写 hex，key 为 UTF-8 PIN，message 为 `"PTC-PIN1" || salt16`。
- `pin_hash` 和 `pin_salt` 同时为空表示尚未初始化。
- 该 PIN 只保护本地家长区，不是 Nintendo 系统 PIN。

### `rules.json`

```json
{
  "version": 1,
  "week": [
    { "mode": "unlimited", "minutes": 120 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "unlimited", "minutes": 120 }
  ],
  "today_override_present": false,
  "today_override_day_index": 0,
  "today_override_mode": "limit",
  "today_override_minutes": 60,
  "bedtime_enabled": false,
  "bedtime_start_min": 1260,
  "bedtime_end_min": 480,
  "limit_action": "remind"
}
```

星期顺序为 Sun=0 到 Sat=6。`mode` 取 `limit`、`unlimited`、`blocked`；`limit_action` 取 `remind`、`raw_block`、`suspend`。缺失文件使用上述默认值，版本或字段无效返回 `rules_invalid`。

`grant` 只保存 bedtime 和限制方式，不运行分钟边界自动控制。`enforce` 在有限额度剩余时间为 0 或进入 bedtime 时段时执行限制方式：

- `remind` 保持普通有限目标，系统提醒由官方设置决定。
- `raw_block` 要求有效 `raw_block_verified`，写入 `blocked`、0 分钟目标。
- `suspend` 要求有效 `suspend_verified`，写入有限模式、0 分钟目标，由 Horizon 暂停请求通道处理。
- bedtime 结束或本项目临时解锁生效时恢复当天规则。
- 能力未验证时保持 fail-open，记录稳定错误，不写 PCTL。

### `state.json`

```json
{
  "version": 1,
  "parent_unlock_until": 0,
  "last_enforced_day_index": 0,
  "last_enforced_mode": 0,
  "last_enforced_minutes": 0,
  "last_enforced_bedtime_active": false,
  "updated_at": 1783526400,
  "v2_failed_attempts": 0,
  "v2_cooldown_until": 0
}
```

缺失文件或新增字段使用零值。`parent_unlock_until` 为 Unix 秒，0 表示未启用；它只抑制项目本地规则，不解除已经生效的 Horizon/PCTL 限制。`last_enforced_*` 用于自动对账去重和 bedtime 恢复。

连续 5 次 v2 格式或签名失败触发 10 分钟冷却，并随 state 原子持久化。成功完成可写 v2 加时后清零。冷却不影响 v1、状态或家长区请求。

### `capabilities.json`

```json
{
  "version": 1,
  "play_timer_write_verified": false,
  "play_timer_write_backend": "pctl-s-v2",
  "play_timer_effect_verified": false,
  "play_timer_effect_backend": "pctl-s-runtime-v2",
  "raw_block_verified": false,
  "raw_block_backend": "pctl-s-rawblock-v1",
  "suspend_verified": false,
  "suspend_backend": "pctl-s-suspend-v1",
  "verified_at": {
    "play_timer_write": 0,
    "play_timer_effect": 0,
    "raw_block": 0,
    "suspend": 0
  }
}
```

每个 verified 值必须与预期 backend 同时匹配。字段缺失、backend 不同或旧 v1 write/effect backend 一律视为未验证，手工将布尔值改成 `true` 不能解锁能力。

## Token

### v2 8 位数字短码

纯 8 位 ASCII 数字按 v2 解析，允许前导零。固定动作为“今日加时”，分钟档位为 5–120，每 5 分钟一档。

```text
tier_index: 5 bit    // 0..23, minutes = (tier_index + 1) * 5
nonce:      9 bit    // 0..511
mac:       12 bit    // truncated HMAC-SHA256
value = (tier_index << 21) | (nonce << 12) | mac
```

签名 transcript 使用固定宽度大端整数：

```text
"PTC2" || device_id || NUL || day_index_u16 || tier_index_u8 || nonce_u16
```

日期和设备参与签名但不显示。超过 26 bit、长度错误或档位非法返回 `bad_code`。ledger 记录 `"token_version": 2`，与 v1 nonce 命名空间分离。

CLI 的 `--tier-minutes` 使用本地按设备/日期递增的 nonce 状态，达到 511 后拒绝继续签发。PWA 使用 Web Crypto 和 `crypto.getRandomValues()`，在当前 origin 的 `ptc.frontend.config.v1` 与 `ptc.frontend.nonces.v1` 保存配置和已签发 nonce；不同浏览器或 origin 不同步，碰撞由 Switch 以 `used_token` 拒绝。

### v1 兼容码

含连字符或 16 个 Crockford Base32 字符按 v1 解析，显示格式为 `XXXX-XXXX-XXXX-XXXX`。v1 仅用于兼容与开发工具的 `--minutes` 任意分钟模式，不是当前 UI 默认流程。

```text
payload: 60 bit
  version:    4 bit
  action:     4 bit
  minutes:   11 bit
  day_index: 16 bit
  nonce:     25 bit
mac:          20 bit truncated HMAC-SHA256
```

签名 transcript：`"PTC1" || device_id || NUL || payload_bits_as_bytes`。唯一支持 action 为 `1 = add_today_minutes`。

### 加时与 nonce

v1/v2 都把分钟数累加到当天有效有限额度；`unlimited` 或 `blocked` 从 0 起算，结果截断到 1440。可写模式把绝对结果持久化为 today override，防止 enforce 回到周模板。

nonce 仅在 PCTL 写入生效、规则和匹配 result 都持久化后追加到 `ledger/used_nonces.jsonl`。无效 token、observe dry-run、备份失败、写入失败、运行时效果未观察到、规则/result/ledger 失败都不得提前消费 nonce。result 写入失败时回滚规则；重试同一码重新应用相同绝对目标，不能再次叠加。

## 请求传输

### IPC v1

Switch 客户端默认连接 CMIF 服务 `pctc:u`；桌面工具只使用文件队列。接口版本 1，最多 8 个会话，请求 JSON 最大 4096 字节，result 缓冲最大 8192 字节。

`SubmitRequest` 返回 accepted 前必须原子持久化到 `inbox/pending/`。完成 Event 触发后客户端调用一次 `GetResult`。服务不可用时才回退文件队列；已 accepted 后 Event 失效时只能读取同一 request id 的 SD result，不得重复提交。`NotifyStorageChanged` 用于唤醒 worker。

### 文件队列

客户端发布：

1. 生成 `<unix_ms>-<random16>` request id。
2. 写 `inbox/pending/<id>.json.tmp`。
3. 原子 rename 为 `inbox/pending/<id>.json`。

sysmodule 处理：

1. rename 到 `inbox/processing/<id>.json` 取得处理权。
2. 解析并执行请求。
3. 原子写 `results/<id>.json`。
4. 将原请求移到 `inbox/done/<id>.json`。

request id 长 1–79，只允许 ASCII 字母、数字、`-`、`_`；文件 stem 与 JSON 内 id 必须相同。客户端只接受同名、同 id 且 schema 有效的 result。UI timeout 只表示截止时间前没看到 result，不能证明后台未执行。

Overlay 和 NRO 是独立客户端。Overlay 不得验证签名、读取 secret 或调用 PCTL。孩子界面只有在 `offline_code` result 同时满足 `status:"ok"`、`dry_run:false`、`state.play_timer_enabled:1`、`state.restricted_now:0` 时才认定真实解锁。

## Request 契约

```json
{
  "version": 1,
  "request_id": "1783526400123-a4f2",
  "type": "offline_code",
  "created_at": 1783526400,
  "payload": { "code": "12345678" }
}
```

解析器校验 `version`、`request_id`、`type`、`created_at`、`payload` 及请求专用字段。能够解析 request id 时，schema 错误也应生成结构化 result。

| type | payload |
| --- | --- |
| `offline_code` | `{ "code": "12345678" }`，也接受 v1 兼容码 |
| `status` | `{}` |
| `set_today_limit` | `{ "minutes": 45 }` |
| `add_today_minutes` | `{ "minutes": 15 }` |
| `disable_today_limit` | `{}` |
| `block_today` | `{}` |
| `restore_today_policy` | `{}` |
| `set_weekly_template` | `{ "days": [{ "mode": "limit", "minutes": 60 }, ...共 7 项] }` |
| `set_bedtime` | `{ "enabled": true, "start_min": 1260, "end_min": 480 }` |
| `set_limit_action` | `{ "action": "remind" }` |
| `parent_unlock_start` | `{ "duration_minutes": 15 }` |
| `parent_unlock_end` | `{}` |
| `probe_play_timer_write` | `{}` |
| `probe_apply_today_limit` | `{ "minutes": 1, "start_timer": true }` |
| `probe_play_timer_effect` | `{ "wait_for_expiry": false }` |
| `prepare_device_test` | `{}` |
| `probe_raw_block` | `{}` |
| `probe_suspend` | `{}` |

`parent_unlock_start` 必须使用 `duration_minutes`，误用 `minutes` 返回 `bad_request`。observe 下家长操作也是 dry-run，不持久化状态。`prepare_device_test` 不携带 token，不读取或消费 nonce；`probe_play_timer_effect` 继续保留“测试后恢复原设置”的兼容语义。

离线码处理顺序固定为：schema/config/disable 检查、token 与 nonce 验证、PCTL/模式/capability gate、计算绝对目标、备份、写入并启动计时器、最多 5 秒观察运行时效果、持久化规则和 result、最后消费 nonce。

## Result 契约

成功 result：

```json
{
  "version": 1,
  "request_id": "1783526400123-a4f2",
  "type": "offline_code",
  "status": "ok",
  "mode": "observe",
  "dry_run": true,
  "state": {
    "day_index": 2380,
    "limited_today": -1,
    "blocked_today": -1,
    "unrestricted_today": -1,
    "remaining_available": false,
    "remaining_minutes": -1,
    "played_minutes_available": false,
    "played_minutes": -1,
    "play_timer_enabled": -1,
    "restricted_now": -1,
    "bedtime_active": false,
    "parent_unlock_active": false
  },
  "capabilities": {
    "play_timer_write_verified": false,
    "play_timer_effect_verified": false,
    "raw_block_verified": false,
    "suspend_verified": false
  },
  "completed_at": 1783526401
}
```

错误 result：

```json
{
  "version": 1,
  "request_id": "1783526400123-a4f2",
  "type": "offline_code",
  "status": "error",
  "mode": "observe",
  "dry_run": true,
  "error": {
    "code": 203,
    "reason": "bad_signature",
    "message": "授权码签名不匹配"
  },
  "completed_at": 1783526401
}
```

`played_minutes_available` 和 `played_minutes` 是兼容性可选字段。仅在有限模式、剩余时间可读且 0x44 配置额度布局已验证时可用，计算为 `max(configured_minutes - remaining_minutes, 0)`；旧客户端可忽略，新客户端读取旧 result 时按不可用处理。

Switch adapter 在全局家长控制启用时，必须结合当天 0x44 slot 判定状态：当天 slot 为 unlimited 时报告 `unrestricted_today:1`，restricted 且分钟为 0 时报告 `blocked_today:1`，其余 restricted 有限目标报告 `limited_today:1`。不能只根据全局 enabled/unlocked 推断今日状态；今日 unlimited 的 remaining 统一按不可用处理。

探针扩展对象：

| 请求 | result 扩展 | 必须保留的证据 |
| --- | --- | --- |
| `probe_apply_today_limit` | `probe_apply` | 目标、是否 start、PCTL 错误、before/after 状态、raw hex/slots、hint |
| `probe_play_timer_effect` | `pctl_effect_probe` | verdict/failure_stage、before/active/restored、opaque snapshots、raw/timer/remaining/restore checks、IPC result |
| `prepare_device_test` | `device_test` | verdict/failure_stage、release/restored/ready 三阶段状态、before/restored opaque snapshots、最终测试额度、恢复/可用性/rules checks、IPC result |
| `probe_raw_block` | `pctl_raw_block_probe` | verdict/failure_stage、0 分钟目标、before/active/restored、blocked 与 restore checks、IPC result |

effect probe 的 fast 模式优先临时使用 1440 分钟；若与原值相同，可最多降低 10 分钟但必须保留至少 1 分钟剩余。无法选出安全目标时返回 `inconclusive`。任何写探针都必须恢复完整 opaque 0x44 snapshot 和原 timer enabled 状态。

`pctl_effect_probe.failure_stage` 的稳定值为 `none`、`observe`、`before_read`、`snapshot`、`backup`、`write`、`start_timer`、`raw_target`、`safe_target`、`runtime_status`、`expiry`、`restore`、`capability_persist`。`pctl_raw_block_probe.failure_stage` 使用同一集合中的 `none`、`observe`、`before_read`、`snapshot`、`backup`、`write`、`start_timer`、`raw_target`、`runtime_status`、`restore`、`capability_persist`。

`device_test.failure_stage` 成功时为 `none`，observe 演练时为 `observe`；稳定失败值为 `before_read`、`snapshot`、`backup`、`release_write`、`release_start`、`release_status`、`restore`、`ready_write`、`ready_start`、`ready_status`、`rules_persist`、`capability_persist`。result 自身无法持久化时内部记录 `result_persist` 并回滚，但不存在可供客户端读取的对应 result。

`prepare_device_test` 在 sysmodule 的单个事务内执行：捕获并备份原始 snapshot；写入当天 unlimited、启动 timer 并确认限制解除；精确恢复 snapshot 和原 timer 状态；写入有限测试额度并再次启动和确认可用；最后持久化今日 override 与 write/effect capability。额度优先为 `min(max(已玩分钟 + 30, 60), 1425)`，已玩时间不可用时为 1425；若该目标仍已到期则重试 1440，仍不可用就回滚。成功状态有意保留有限的今日 override，结束测试应提交 `restore_today_policy`。

## 模式与探针

| 模式 | 行为 |
| --- | --- |
| `disabled` | 拒绝请求，不读取或写入 PCTL |
| `observe` | 可读状态，返回 `dry_run:true`；不写 PCTL、不持久化规则/能力、不消费 nonce |
| `grant` | 通过备份和 capability gate 后执行显式加时及家长操作 |
| `enforce` | 包含 grant，并在分钟边界自动对账每日规则和 bedtime |

- `unlimited_not_allowed` 只适用于可写模式中 PCTL 当前无限且配置禁止转为有限的情况；observe 不以此拒绝有效码。
- 普通写入同时要求 `play_timer_write_verified` 与 `play_timer_effect_verified`。
- `probe_play_timer_write` 通过 `pctl:s` 做 read → same-value write → readback，成功后写入 `pctl-s-v2` capability。
- `probe_apply_today_limit` 是底层诊断，不要求或设置普通 capability，也不消费 token nonce；observe 只演练。
- `probe_play_timer_effect` 绕过 token/rules/普通 capability，但仍受 mode、`disable.flag` 和备份约束。恢复失败返回 `pctl_restore_failed`，清除 write/effect capability 并创建 `disable.flag`。
- `prepare_device_test` 在 `disabled` 或存在 `disable.flag` 时拒绝，在 observe 下只返回 dry-run，仅 grant/enforce 真正执行。写入、启动、状态确认、rules/capability/result 持久化任一步失败都回滚测试前 snapshot、timer、rules 和 capability；恢复无法证明时清除能力并创建 `disable.flag`。
- `disable_today_limit` 与一键测试共用 unlimited 生效语义：写入后必须启动 timer 并回读确认 `unrestricted_today:true` 且 `restricted_now:false`，确认后才保存 rules；PCTL、rules 或 result 失败时恢复请求前 snapshot 和 rules。
- `probe_raw_block` 在 write/effect 都已验证后，写入当天 0 分钟 restricted 目标、观察限制、恢复完整 snapshot。恢复失败清除 raw capability 并创建 `disable.flag`。
- `probe_suspend` 通过 `pctl:s` 检查 `IsPlayTimerAlarmDisabled (1458)` 并获取 `GetPlayTimerEventToRequestSuspension (1457)` 事件。实际暂停由 Horizon 执行，本项目不直接暂停或终止进程。
- adapter 只使用多会话 `pctl:s`，不得打开或回退到单会话 `pctl:a`。

## 日志与 PCTL 证据

`logs/YYYY-MM-DD/events.jsonl` 每行一个结构化事件，例如：

```json
{"ts":1783526401,"request_id":"1783526400123-a4f2","type":"set_today_limit","event":"pctl_apply","error":"ok","detail":"limit"}
```

稳定事件名为 `request_received`、`result_ok`、`result_error`、`result_write_failed`、`state_persisted`、`state_rollback_ok`、`state_rollback_failed`、`pctl_backup`、`pctl_backup_failed`、`pctl_apply`、`pctl_apply_failed`、`nonce_consumed`、`nonce_failed`、`v2_failures_cleared`、`probe_ok`、`probe_failed`、`pctl_start_timer`、`effect_observed`、`device_test_before`、`device_test_release`、`device_test_restore`、`device_test_restore_failed`、`device_test_ready`、`raw_block_before`、`raw_block_apply`、`raw_block_restore`、`raw_block_restore_failed`。新增或重命名稳定事件必须同步测试和本文档。

`pctl_debug.jsonl` 只供开发排障，不得包含 secret、PIN 或离线码。稳定 stage 为 `backup`、`probe_play_timer_write`、`probe_apply_before`、`probe_apply_write`、`probe_apply_after`、`probe_apply_start_timer`、`probe_raw_block`、`probe_suspend`、`apply_target`、`start_timer`。

0x44 play timer settings layout v2 只来自实现与匹配真机 A/B snapshot：words 0..6 为 header，day n 从 `7 + 4n` 开始，字段 `flag`、`enabled`、`minutes` 位于 +0、+1、+2。除 Saturday 外记录还有 padding。limited/blocked 写入 `flag=0x0600`、`enabled=0x0100`；unlimited 清零。写入必须保留所有无关 word，并拒绝超出已验证范围的 snapshot。

上游 libnx 未公开 `StartPlayTimer (1451)`、`GetPlayTimerRemainingTime (1454)`、`GetPlayTimerSettings (145601)` 或 `SetPlayTimerSettingsForDebug (195101)` 封装，因此不得从 libnx 缺失定义推断单位或布局。

真机 A/B 证据表明 `GetPlayTimerRemainingTime (1454)` 返回 inline signed `s64` 纳秒；过期值可为负。adapter 对正值使用 `remaining_ns / (60 * 10^9)`，零或负值钳制为 0；不得 dispatch 为 `u32`、按 unsigned 解释或把原始值当分钟。

## 错误契约

每个错误必须具有数字 code、稳定 reason、中文 message 和开发日志细节。

| Code | Reason | 中文消息 |
