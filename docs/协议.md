# 协议

本文是 Companion、Tesla Overlay、sysmodule 和开发工具之间的权威契约。文件协议版本为 v1，离线 token 同时支持 v1 和 v2；用户界面默认使用 v2 8 位数字短码。

## SD 卡布局

应用根目录：

```text
sdmc:/switch/playwise/
├── config.json
├── auth.json
├── rules.json
├── state.json
├── capabilities.json
├── setup.json
├── inbox/
│   ├── pending/
│   ├── processing/
│   └── done/
├── results/
├── logs/YYYY-MM-DD/
│   ├── sysmodule.log
│   ├── events.jsonl
│   └── pctl_debug.jsonl
├── ledger/used_nonces.jsonl
├── backups/
│   ├── last_pctl_backup.txt
│   └── install_pctl_snapshot.json
├── recovery/active/
│   ├── meta.json
│   ├── pctl_snapshot.json
│   └── *.before
└── flags/
    ├── disable.flag
    ├── reload.flag
    ├── retry_setup_release.flag
    └── restore_install_snapshot.flag
```

Overlay 位于 `sdmc:/switch/.overlays/pctc.ovl`，仍只通过相同 IPC/request/result 契约通信。五个配置文件及 request/result JSON 顶层必须包含 `"version": 1`；JSON Lines 日志和 ledger 使用各自下文定义的逐行契约。

恢复优先级依次为 `restore_install_snapshot.flag`、`retry_setup_release.flag`、未完成恢复事务、`disable.flag`、普通请求和 Enforce。`disable.flag` 仍阻止所有正常控制写入。

日志、day index 和清理日期统一使用 UTC+8。系统保留当天及之前 29 个自然日；第 30 天及更早的日志目录、`results/*.json` 和 `inbox/done/*.json` 才可清理。时间无效、日期在未来或文件名未知时必须保留。

## 配置文件

### `config.json`

```json
{
  "version": 1,
  "device_id": "kid-switch",
  "grant_secret": "replace-with-long-random-secret",
  "max_add_minutes": 120,
  "control_mode": "enforce",
  "allow_unlimited_to_limited": false,
  "default_request_timeout_ms": 60000
}
```

唯一 package 的初始模式为 `enforce`。`grant` 仍可运行时配置；`observe/disabled` 只保留旧配置的非写兼容行为。未知 `control_mode` 按 `observe` 处理。`grant_secret` 可在 Companion NRO 家长区“安全工具”页面通过系统软键盘（swkbd）直接编辑并持久化写回。

### `auth.json`

```json
{
  "version": 1,
  "pin_hash": "hex-encoded-hmac-sha256",
  "pin_salt": "hex-encoded-16-bytes",
  "hash": "hmac-sha256",
  "updated_at": 1783526400
}
```

- `pin_salt` 是 16 个随机字节的小写 hex。
- `pin_hash` 是 HMAC-SHA256 小写 hex，key 为 UTF-8 PIN，message 为 `"PTC-PIN1" || salt16`。
- `pin_hash` 和 `pin_salt` 同时为空表示尚未初始化。
- 该 PIN 只保护本地家长区，不是 Nintendo 系统 PIN。

### `rules.json`

```json
{
  "version": 1,
  "week": [
    { "mode": "unlimited", "minutes": 120 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "limit", "minutes": 60 },
    { "mode": "unlimited", "minutes": 120 }
  ],
  "today_override_present": false,
  "today_override_day_index": 0,
  "today_override_mode": "limit",
  "today_override_minutes": 60,
  "bedtime_enabled": false,
  "bedtime_start_min": 1260,
  "bedtime_end_min": 480,
  "limit_action": "remind"
}
```

星期顺序为 Sun=0 到 Sat=6。`mode` 取 `limit`、`unlimited`、`blocked`；`limit_action` 取 `remind`、`raw_block`、`suspend`。缺失文件使用上述默认值，版本或字段无效返回 `rules_invalid`。

`grant` 只保存 bedtime 和限制方式，不运行分钟边界自动控制。`enforce` 在有限额度剩余时间为 0 或进入 bedtime 时段时执行限制方式：

- `remind` 保持普通有限目标，系统提醒由官方设置决定。
- `raw_block` 要求有效 `raw_block_verified`，写入 `blocked`、0 分钟目标。
- `suspend` 要求有效 `suspend_verified`，写入有限模式、0 分钟目标，由 Horizon 暂停请求通道处理。
- bedtime 结束或本项目临时解锁生效时恢复当天规则。
- 能力未验证时保持 fail-open，记录稳定错误，不写 PCTL。

### `state.json`

```json
{
  "version": 1,
  "parent_unlock_until": 0,
  "last_enforced_day_index": 0,
  "last_enforced_mode": 0,
  "last_enforced_minutes": 0,
  "last_enforced_bedtime_active": false,
  "updated_at": 1783526400,
  "v2_failed_attempts": 0,
  "v2_cooldown_until": 0
}
```

缺失文件或新增字段使用零值。`parent_unlock_until` 为 Unix 秒，0 表示未启用；它只抑制项目本地规则，不解除已经生效的 Horizon/PCTL 限制。`last_enforced_*` 用于自动对账去重和 bedtime 恢复。

连续 5 次 v2 格式或签名失败触发 10 分钟冷却，并随 state 原子持久化。成功完成可写 v2 加时后清零。冷却不影响 v1、状态或家长区请求。

### `capabilities.json`

```json
{
  "version": 1,
  "raw_block_verified": false,
  "raw_block_backend": "pctl-s-rawblock-v1",
  "suspend_verified": false,
  "suspend_backend": "pctl-s-suspend-v1"
}
```

只有 `raw_block` 和 `suspend` 是需要持久化门禁的高风险能力。旧 `play_timer_write_*` 和 `play_timer_effect_*` 字段允许兼容读取，但不显示、不参与判断，也不会由新实现写回。

### `setup.json`

```json
{
  "version": 1,
  "phase": "pending",
  "restriction_cleared": false,
  "snapshot_available": false,
  "activate_after": 0,
  "last_error": ""
}
```

`phase` 只允许 `pending`、`released`、`active`、`failed`、`restored`。`released` 允许状态与引导操作，但阻止普通写入和 Enforce；`complete_setup` 设置 5 秒 `activate_after`，到期后进入 `active`。

`backups/install_pctl_snapshot.json` 保存完整 0x44 raw、长度、timer 状态、捕获时间和 SHA-256，首次写入后不得被重试覆盖。`recovery/active/meta.json` 是普通写入事务标记；同目录保存 PCTL snapshot 及 rules/state/ledger 前像。

## Token

### v2 8 位数字短码

纯 8 位 ASCII 数字按 v2 解析，允许前导零。固定动作为“今日加时”，分钟档位支持 1–4 分钟微调与 5–120 分钟（每 5 分钟一档，共 28 档）。

```text
tier_index: 5 bit    // 0..27 (共 28 档)
                     // 0..23:  minutes = (tier_index + 1) * 5 (5..120 分钟)
                     // 24..27: minutes = tier_index - 23 (1..4 分钟)
nonce:      9 bit    // 0..511
mac:       12 bit    // truncated HMAC-SHA256
value = (tier_index << 21) | (nonce << 12) | mac
```

签名 transcript 使用固定宽度大端整数：

```text
"PTC2" || device_id || NUL || day_index_u16 || tier_index_u8 || nonce_u16
```

日期和设备参与签名但不显示。超过 26 bit、长度错误或档位非法返回 `bad_code`。ledger 记录 `"token_version": 2`，与 v1 nonce 命名空间分离。

CLI 的 `--tier-minutes` 使用本地按设备/日期递增的 nonce 状态，达到 511 后拒绝继续签发。PWA 使用 Web Crypto 和 `crypto.getRandomValues()`，在当前 origin 的 `ptc.frontend.config.v1` 与 `ptc.frontend.nonces.v1` 保存配置和已签发 nonce；不同浏览器或 origin 不同步，碰撞由 Switch 以 `used_token` 拒绝。

### v1 兼容码

含连字符或 16 个 Crockford Base32 字符按 v1 解析，显示格式为 `XXXX-XXXX-XXXX-XXXX`。v1 仅用于兼容与开发工具的 `--minutes` 任意分钟模式，不是当前 UI 默认流程。

```text
payload: 60 bit
  version:    4 bit
  action:     4 bit
  minutes:   11 bit
  day_index: 16 bit
  nonce:     25 bit
mac:          20 bit truncated HMAC-SHA256
```

签名 transcript：`"PTC1" || device_id || NUL || payload_bits_as_bytes`。唯一支持 action 为 `1 = add_today_minutes`。

### 加时与 nonce

v1/v2 都把分钟数累加到当天有效有限额度；`unlimited` 或 `blocked` 从 0 起算，结果截断到 1440。可写模式把绝对结果持久化为 today override，防止 enforce 回到周模板。

nonce 仅在 PCTL 写入生效、规则和匹配 result 都持久化后追加到 `ledger/used_nonces.jsonl`。无效 token、observe dry-run、备份失败、写入失败、运行时效果未观察到、规则/result/ledger 失败都不得提前消费 nonce。result 写入失败时回滚规则；重试同一码重新应用相同绝对目标，不能再次叠加。

## 请求传输

### IPC v1

Switch 客户端默认连接 CMIF 服务 `pctc:u`；桌面工具只使用文件队列。接口版本 1，最多 8 个会话，请求 JSON 最大 4096 字节，result 缓冲最大 8192 字节。

`SubmitRequest` 返回 accepted 前必须原子持久化到 `inbox/pending/`。完成 Event 触发后客户端调用一次 `GetResult`。服务不可用时才回退文件队列；已 accepted 后 Event 失效时只能读取同一 request id 的 SD result，不得重复提交。`NotifyStorageChanged` 用于唤醒 worker。

### 文件队列

客户端发布：

1. 生成 `<unix_ms>-<random16>` request id。
2. 写 `inbox/pending/<id>.json.tmp`。
3. 原子 rename 为 `inbox/pending/<id>.json`。

sysmodule 处理：

1. rename 到 `inbox/processing/<id>.json` 取得处理权。
2. 解析并执行请求。
3. 原子写 `results/<id>.json`。
4. 将原请求移到 `inbox/done/<id>.json`。

request id 长 1–79，只允许 ASCII 字母、数字、`-`、`_`；文件 stem 与 JSON 内 id 必须相同。客户端只接受同名、同 id 且 schema 有效的 result。UI timeout 只表示截止时间前没看到 result，不能证明后台未执行。

Overlay 和 NRO 是独立客户端。Overlay 不得验证签名、读取 secret 或调用 PCTL。孩子界面只有在 `offline_code` result 同时满足 `status:"ok"`、`dry_run:false`、`state.play_timer_enabled:1`、`state.restricted_now:0` 时才认定真实解锁。

## Request 契约

请求顶层包含 `version`、`request_id`、`type`、`created_at` 和 `payload`。公共请求包括状态、离线码、今日/周计划/bedtime/限制方式、家长临时解锁、`probe_raw_block`、`probe_suspend`，以及：

| type | payload | 语义 |
| --- | --- | --- |
| `complete_setup` | `{}` | 完成首次引导并设置 5 秒激活宽限 |
| `retry_setup_release` | `{}` | 仅在 pending/failed 下重试解除，不覆盖安装 snapshot |
| `restore_install_snapshot` | `{}` | 恢复安装前 PCTL 设置并创建 `disable.flag` |

请求编号 15–18 保留但无公共名称：`probe_play_timer_write`、`probe_apply_today_limit`、`probe_play_timer_effect`、`prepare_device_test` 均返回 `unknown_request_type`。

普通写入顺序固定为：schema/config/setup/disable 检查，token 与 nonce 验证，持久化恢复事务，写 PCTL 并启动 timer，确认运行时目标，持久化 rules/state/result，最后提交 nonce 并清除事务。任一步失败立即回滚；无法证明恢复成功时创建 `disable.flag`。

## Result 契约

`status` 及正常 result 的稳定扩展：

```json
{
  "capabilities": {
    "raw_block_verified": false,
    "suspend_verified": false
  },
  "setup": {
    "phase": "released",
    "restriction_cleared": true,
    "snapshot_available": true,
    "activate_after": 0,
    "last_error": ""
  }
}
```

`state` 继续包含 day index、limited/blocked/unrestricted、remaining、played、timer、restricted、bedtime 和 parent unlock。`played_minutes_*` 为兼容性可选字段。`probe_raw_block` 可附带 `pctl_raw_block_probe` 证据；普通写入不再生成 write/effect probe 证据。

## 模式与探针

| 模式 | 行为 |
| --- | --- |
| `enforce` | 单包初始模式；setup active 后自动对账规则 |
| `grant` | 只执行显式加时和家长操作 |
| `observe` | 旧配置兼容，只读或 dry-run |
| `disabled` | 旧配置兼容，拒绝正常控制 |

- 普通 set limit、unlimited、加时、恢复规则和 Enforce 不要求 play-timer capability，也不受 `allow_unlimited_to_limited` 阻止。
- `probe_raw_block` 写入当天 0 分钟 restricted 目标、观察受限并恢复完整 snapshot；恢复失败清除能力并创建 `disable.flag`。
- `probe_suspend` 只验证 Horizon 暂停请求通道，本项目不直接终止进程。
- adapter 只使用短时 `pctl`/`pctl:s` 会话，不得打开或回退到单会话 `pctl:a`。

## 日志与 PCTL 证据

`logs/YYYY-MM-DD/events.jsonl` 每行一个结构化事件，例如：

```json
{"ts":1783526401,"request_id":"1783526400123-a4f2","type":"set_today_limit","event":"pctl_apply","error":"ok","detail":"limit"}
```

稳定事件名包括 `request_received`、`result_ok`、`result_error`、`result_write_failed`、`state_persisted`、`state_rollback_ok`、`state_rollback_failed`、`pctl_backup`、`pctl_backup_failed`、`pctl_apply`、`pctl_apply_failed`、`pctl_start_timer`、`effect_observed`、`nonce_consumed`、`nonce_failed`、`v2_failures_cleared`、`probe_ok`、`probe_failed`、`raw_block_before`、`raw_block_apply`、`raw_block_restore`、`raw_block_restore_failed`。新增或重命名稳定事件必须同步测试和本文档。

`pctl_debug.jsonl` 只供开发排障，不得包含 secret、PIN 或离线码。当前稳定 stage 为 `backup`、`setup_release`、`probe_raw_block`、`probe_suspend`、`apply_target`、`start_timer`。

0x44 play timer settings layout v2 只来自实现与匹配真机 A/B snapshot：words 0..6 为 header，day n 从 `7 + 4n` 开始，字段 `flag`、`enabled`、`minutes` 位于 +0、+1、+2。除 Saturday 外记录还有 padding。limited/blocked 写入 `flag=0x0600`、`enabled=0x0100`；unlimited 清零。写入必须保留所有无关 word，并拒绝超出已验证范围的 snapshot。

上游 libnx 未公开 `StartPlayTimer (1451)`、`GetPlayTimerRemainingTime (1454)`、`GetPlayTimerSettings (145601)` 或 `SetPlayTimerSettingsForDebug (195101)` 封装，因此不得从 libnx 缺失定义推断单位或布局。

真机 A/B 证据表明 `GetPlayTimerRemainingTime (1454)` 返回 inline signed `s64` 纳秒；过期值可为负。adapter 对正值使用 `remaining_ns / (60 * 10^9)`，零或负值钳制为 0；不得 dispatch 为 `u32`、按 unsigned 解释或把原始值当分钟。

## 错误契约

每个错误必须具有数字 code、稳定 reason、中文 message 和开发日志细节。

| Code | Reason | 中文消息 |
| ---: | --- | --- |
| 0 | `ok` | 成功 |
| 100 | `unsupported_version` | 不支持的协议版本 |
| 101 | `bad_request` | 请求格式无效 |
| 102 | `unknown_request_type` | 未知请求类型 |
| 103 | `request_expired` | 请求已过期 |
| 200 | `bad_code` | 授权码格式无效 |
| 201 | `bad_token_version` | 授权码版本不支持 |
| 202 | `unsupported_action` | 授权码动作不支持 |
| 203 | `bad_signature` | 授权码签名不匹配 |
| 204 | `bad_clock` | 系统时间不可用 |
| 205 | `wrong_date` | 授权码不是今天有效 |
| 206 | `used_token` | 授权码已经使用过 |
| 207 | `minutes_exceed_limit` | 授权分钟数超过上限 |
| 208 | `code_cooldown` | 短码错误次数过多，请稍后再试 |
| 300 | `disabled` | 后台当前已禁用 |
| 301 | `unlimited_not_allowed` | 当前无限制状态不允许改为有限制 |
| 302 | `raw_block_not_verified` | 禁玩能力尚未验证 |
| 303 | `suspend_not_verified` | 暂停能力尚未验证 |
| 304 | `pctl_write_not_verified` | 家长控制写入能力尚未验证 |
| 305 | `pctl_effect_not_verified` | 家长控制运行时生效能力尚未验证 |

写入模式的 `offline_code status:"ok"` 表示目标写入、timer 启动和运行时解除限制均已观察到。`observe status:"ok"` 始终只是演练，任何客户端都不得把它显示为真实解锁。

错误 301、304、305 保留为旧 result 的稳定兼容映射，新普通写入流程不再以 unlimited guard 或 play-timer capability gate 产生这些错误。
