# 协议

本文是标准分发 profile 的权威契约。文件 schema 为 v1；离线 token 可解码 v1/v2，用户界面使用 v2 8 位数字码。Device Lab 使用独立 profile 和根目录，其危险请求不属于标准分发协议。

## 运行目录

```text
sdmc:/switch/playwise/
├── build.json
├── config.json
├── credentials.json
├── auth.json
├── grant-issued.json
├── pending-redemption.json（仅在已确认兑换尚未处理完结果时存在）
├── rules.json
├── state.json
├── setup.json
├── compatibility.json
├── environment.json
├── inbox/{pending,processing,done}/
├── results/
├── ledger/used_nonces.jsonl
├── backups/install_pctl_snapshot.json
├── recovery/active/
├── flags/
├── logs/
│   ├── YYYY-MM-DD/
│   └── undated/<boot-id>/
└── support/
```

`build.json` 是随安装包写入的程序资产；其余 JSON 是运行数据或首次安装 seed。标准分发构建不创建 `capabilities.json`。

## 配置契约

### `build.json`

`release-manifest.json` 仅供打包门禁和组件一致性校验，不属于标准分发 Zip；Zip 内只保留运行时需要的 `build.json`。

```json
  "build": {

    "libnx": "<version>",
    "libtesla_commit": "<40-hex>"
  },
  "verified_environment": {

    "hos": "22.5.0",

```

同一紧凑 JSON 必须嵌入 sysmodule、NRO 和 Overlay。profile、版本或 release ID 不匹配返回 `504 release_manifest_invalid`。

### `config.json` 与 `credentials.json`

```json
{
  "version": 1,
  "device_id": "kid-switch",
  "max_add_minutes": 240,
  "default_request_timeout_ms": 60000,
  "pairing_base_url": "https://selfuppen.github.io/NX-PlayWise/",
  "parent_shortcut_mask": "c0",
  "custom_shortcut_enabled": false,
  "show_parent_shortcut_hint": true,
  "setup_wizard_step": 0,
  "setup_wizard_version": 2
}
```

`config.json` 中的后三个字段由 Companion 首次设置流程维护：

- `parent_shortcut_mask` 是小写十六进制的自定义组合掩码。示例 `c0` 表示 `L + R`，`300` 表示 `ZL + ZR`；只允许界面支持的手柄按键组合。预设列表覆盖两组肩键单独使用，以及分别搭配任一方向键、`Plus`、`Minus` 的 14 种组合，并保留录制其他组合。组合中的 `+` 只表示同时按键，按键名称本身不附加符号，避免把 `Plus` 误显示成尚未结束的组合。固定的家长区快捷键 `Minus` 不包含在此字段中，始终保留，因此自定义组合不会替换它。自定义组合需长按约 400ms 触发；固定 `Minus` 在按下后松开时进入家长区，无需长按。首次设置、区域选择摘要、孩子区入口提示和家长区快捷键管理都必须明确这一区别。字段缺失或无效时掩码回退到 `L + R`，但是否实际启用仍由下一字段决定。
- `custom_shortcut_enabled` 明确控制自定义组合是否生效。全新安装首次确认前默认为 `false`，此时只有固定 `Minus` 可进入家长区；选择或录制只更新界面草稿，家长明确确认后才同时保存掩码和启用状态。字段缺失但 `parent_shortcut_mask` 合法时按 `true` 解析。组合包含 `Plus` 或 `Minus` 时优先等待自定义组合的约 400ms 长按判定；单独按下并松开 `Minus` 仍进入家长区，单独按下并松开 `Plus` 仍退出 NRO。
- `show_parent_shortcut_hint` 控制孩子区是否显示进入家长区的快捷键说明，默认 `true`。关闭只隐藏提示，不会禁用 `Minus -` 或自定义组合。
- `setup_wizard_step` 保存首次设置向导的恢复位置：`0` 表示没有待恢复的向导，`1`–`5` 分别表示快捷键、PIN、确认接管系统控制、可选自制程序菜单入口保护、选择区域。`setup_wizard_version:2` 区分新版五步向导；缺少该字段的旧值 `4` 迁移为新版步骤 `5`。它只用于恢复界面进度，系统是否已接管仍以 `setup.json.phase` 为准。
  第 3 步已成功进入 `released` 或 `active` 后，即使家长从第 4 步返回查看，继续操作也只推进到第 4 步，不得再次执行接管或重置同步宽限。后台对 `active` 下重复到达的 `complete_setup` 幂等返回当前状态，不重复保存安装快照、写入 PCTL 或启动新的宽限。第 4 步失败可重试或跳过，不阻塞进入第 5 步。

### 自制程序菜单入口保护

该功能只在 PIN 认证后的家长区域和首次向导中出现，孩子区不得显示状态或快捷键。启用前必须完整备份 `/atmosphere/config/override_config.ini` 与 `/switch/.packages/More Menu/Photo Album/package.ini`（包括原本不存在的状态），随后把前者的全部 `[hbl_config]` 替换为 `override_any_app=false`、Controller applet program ID `0100000000001003`、`override_key_0=X` 和 `39_bit` address space，并删除后者。两个文件属于同一恢复事务；任一步失败必须按前像回滚。配置生效后，应在桌面“手柄设置”图标上按住 `X`，再按 `A`，进入自制程序菜单（hbmenu）；“手柄设置”只是该入口的启动载体。

可信备份、存在性、校验值和事务记录保存在 `switch/playwise/backups/album_restriction/`。升级、`-Clean` 和 `-Full` 均不得删除该目录。关闭时按备份字节级恢复；检测到外部改动时普通恢复拒绝覆盖，只有家长长按确认才能强制恢复。备份缺失或校验失败时不得猜测原始内容。配置保存后 UI 必须提示重启主机生效；卸载或删除 PlayWise 数据前必须先关闭限制。

这些字段不是秘密，也不是标准分发 IPC 请求的安全凭据；Companion 通过原子写入更新它们，字段缺失时使用上述默认值。

```json
{
  "version": 1,
  "grant_secret": "<sysmodule 首次启动生成的 64 位小写 hex>"
}
```

正式模式的 secret 不得进入模板、manifest、日志或支持包。首次启动仍由 sysmodule
使用 `randomGet` 生成设备唯一的 64 位小写十六进制 secret。管理界面允许保存 32–64
个非空白可打印 ASCII 字符；更新加时码密钥会使当前家长端配对和使用原密钥签发的代码失效。

家长可在再次验证 PlayWise PIN、查看具体风险并二次确认后，主动切换到公开演示密钥
`playwise-public-demo-secret-0001`。该值不是私密凭证，不得作为安装 seed；启用后任何知道
设备名的人均可签发多个 1–120 分钟码，并可将当日额度累计至 1440 分钟。家长页面必须
持续显示红色低安全警告。退出演示模式时生成新的随机 64 位密钥，不保存被替换的密钥。

### `auth.json`

```json
{
  "version": 1,
  "pin_hash": "<64-hex>",
  "pin_salt": "<32-hex>",
  "hash": "hmac-sha256",
  "updated_at": 1783526400,
  "failed_attempts": 0,
  "cooldown_until": 0
}
```

PIN 允许 1–64 位 ASCII 数字，长度由家长决定；选择过短 PIN 时界面必须提示弱保护风险。hash 的 key 为 PIN UTF-8，message 为 `"PTC-PIN1" || salt16`，所有合法长度均使用同一格式。空 hash/salt 表示首次设置未完成。连续第 5 次失败开始冷却 30 秒，后续失败依次为 60 秒、2 分钟、4 分钟并最长 10 分钟；`failed_attempts` 和 `cooldown_until` 跨重启保存，成功验证后清零。文件缺少这两个字段时按 0 处理。

家长区修改任我玩 PIN 时必须先按同一验证与冷却规则确认当前 PIN，成功后才可输入并确认新 PIN；取消、验证失败或两次新 PIN 不一致不得覆盖现有凭据。

### `rules.json`

```json
{
  "version": 1,
  "week": [
    {"mode": "unlimited", "minutes": 120},
    {"mode": "limit", "minutes": 60},
    {"mode": "limit", "minutes": 60},
    {"mode": "limit", "minutes": 60},
    {"mode": "limit", "minutes": 60},
    {"mode": "limit", "minutes": 60},
    {"mode": "unlimited", "minutes": 120}
  ],
  "today_override_present": false,
  "today_override_day_index": 0,
  "today_override_mode": "limit",
  "today_override_minutes": 60,
  "holiday_enabled": false,
  "holiday_mode": "unlimited",
  "holiday_minutes": 120,
  "makeup_workday_mode": "limit",
  "makeup_workday_minutes": 60
}
```

星期顺序为 Sun=0 到 Sat=6。mode 只允许 `limit` 和 `unlimited`；不存在 `blocked`、bedtime 或 `limit_action`。

国家节假日规则的优先级固定为：`today_override > statutory_holiday/makeup_workday > week`。`holiday_enabled:false`、日期不在日历覆盖年份内或日期属于普通日期时均回退自然星期计划。升级自旧版 `rules.json` 时缺失的新字段使用上述默认值，功能保持关闭，必须由家长确认两个额度后启用。

首版日历编译进平台无关规则核心，覆盖年份、版本、发布日期和权威来源见[节假日日历数据](节假日日历.md)。进入未覆盖年份时继续执行每周计划；覆盖终点前 30 天起 `calendar_update_warning:true`。

### `state.json`

关键字段：

```json
{
  "version": 1,
  "last_enforced_day_index": 0,
  "last_enforced_mode": 0,
  "last_enforced_minutes": 0,
  "apply_status": "idle",
  "apply_pending_confirmation": false,
  "apply_confirmation_deadline": 0,
  "pending_mode": 0,
  "pending_minutes": 0,
  "updated_at": 0,
  "v2_failed_attempts": 0,
  "v2_cooldown_until": 0
}
```

Enforce 写入后先保存 `apply_status:"applied_pending_confirmation"`。确认期限为写入后 30 秒；确认成功清空 pending，超时回滚。连续 5 次 v2 格式或签名失败触发 10 分钟冷却。

确认窗口内的 `recovery/active/` 属于当前 sysmodule 进程持有的活跃事务，普通 scheduler tick 不得执行启动恢复。只有每次 sysmodule 启动的首次 bootstrap 可以把启动前已存在的事务判定为遗留事务并回滚；恢复成功后写入 `disable.flag`，要求家长重新确认接管。

### setup、兼容与环境

`setup.json.phase` 允许 `unconfigured`、`pending`、`released`、`active`、`failed`、`protection`、`restored`。首次接管前，后台会只读采集今天的 PCTL 模式、配置总额度和剩余时长，并在 `setup.json` 暂存 `handover_*` 字段。对于限时日，优先保留已读取的“当天总额度”；只有总额度不可读但“已玩 + 剩余”均可读时才计算总额度。随后写入仅当天有效的 `today_override`，在 5 秒同步结束时重新应用并回读剩余时间（允许分钟向下取整带来的 1 分钟差）。这样已有的当天余额不会被默认周计划覆盖；次日仍按家长配置的周计划执行。不限时和已限制日也会作为当天临时规则保留。

若无法安全得到限时日的总额度或剩余时间，接管返回 `313 handover_state_unavailable`，不写入 PCTL、不保存安装快照，也不套用默认规则；家长可保留现有系统设置，稍后重新检测或次日再接管。接管后回读不符合预期时，后台恢复安装前 snapshot、创建 `disable.flag` 并进入 `restored`，不会把错误额度留在系统中。

`restored + disable.flag` 或自动事务恢复形成的 `active + disable.flag` 均显示“解除停用并重新接管”，由家长确认后提交 `complete_setup`。后台必须先重新执行只读安全预检，只有预检通过才删除 `disable.flag`、释放当前限制并继续接管；预检失败时保留原 phase 和停用标记，允许稍后重试。`compatibility_status` 使用 `pending`、`verified`、`accepted_unknown` 或 `protection`。

`environment.json` 记录 HOS、firmware hash/digest、产品型号和是否运行于 Atmosphère；精确 Atmosphère 版本只记录在资格 manifest，不作为严格运行时判定。

`compatibility.json` 保存家长接受的精确环境指纹和时间。未知兼容可由 PIN + 长按确认；snapshot、PCTL layout、启动遗留事务、PCTL 初始化/读取或 manifest 失败不可由标准分发构建绕过。

## Request

文件路径为 `inbox/pending/<request_id>.json`；IPC service 为 `pctc:u`。通用外壳：

```json
{
  "version": 1,
  "request_id": "client-unique-id",
  "type": "status",
  "created_at": 1783526400,
  "payload": {}
}
```

标准分发 profile 只接受：

| ID | type | payload |
| ---: | --- | --- |
| 1 | `offline_code` | `{"code":"12345678"}` |
| 2 | `status` | `{}` |
| 3 | `set_today_limit` | `{"minutes":60}` |
| 4 | `add_today_minutes` | `{"minutes":15}` |
| 5 | `disable_today_limit` | `{}` |
| 7 | `restore_today_policy` | `{}` |
| 8 | `set_weekly_template` | `{"days":[7 个 mode/minutes 对象]}` |
| 19 | `complete_setup` | `{}` |
| 20 | `retry_setup_release` | `{}` |
| 21 | `restore_install_snapshot` | `{}` |
| 22 | `preview_offline_code` | `{"code":"12345678"}` |
| 23 | `set_holiday_policy` | `{"enabled":true,"holiday_rule":{"mode":"unlimited","minutes":0},"makeup_workday_rule":{"mode":"limit","minutes":60}}` |

ID 6、9–18 不属于标准分发 profile；未列入表格的请求字符串返回 `102 unknown_request_type`。`disable.flag` 存在时 status 与 setup/recovery 请求仍可执行，普通控制写返回 `300 disabled`。

家长打开“设置今日额度”前，Companion 必须先刷新 status。`played_minutes` 可用时，编辑器默认值为当日已玩分钟数并限制到合法的 1–1440 分钟范围（已玩 0 分钟时从 1 分钟显示）；这只是初始显示值，不改变 1–1440 分钟的可选范围，也不禁止家长继续下调。`played_minutes` 不可用时，优先回退当前有效限时额度，否则使用 60 分钟，不得猜测已玩时间。低于或等于已玩时间的额度仍沿用手柄长按确认规则。

`preview_offline_code` 执行与正式兑换相同的 token、日期、设备、nonce、冷却和当前状态校验，但只计算结果，不写 PCTL、rules、state、result 之外的业务状态或 ledger，也不保留/消费 nonce。用户确认后，Companion 必须再次调用该预览；若“兑换后是否可用、是否为 0、是否截断、是否从不限时转限时”等安全语义变化，必须展示新预览并再次确认，不能直接提交 `offline_code`。

## Result

结果原子写入 `results/<request_id>.json`，并将请求移入 `inbox/done/`。成功结构：

```json
{
  "version": 1,
  "request_id": "client-unique-id",
  "type": "status",
  "status": "ok",
  "state": {
    "day_index": 2380,
    "restriction_enabled_available": true,
    "restriction_enabled": true,
    "temporary_unlocked_available": true,
    "temporary_unlocked": false,
    "limited_today": 1,
    "blocked_today": 0,
    "unrestricted_today": 0,
    "remaining_available": true,
    "remaining_minutes": 45,
    "played_minutes_available": true,
    "played_minutes": 15,
    "play_timer_enabled": 1,
    "restricted_now": 0,
    "rule_source": "weekly",
    "calendar_covered": true,
    "calendar_update_warning": false
  },
  "completed_at": 1783526400
}
```

`status` 同时承担家长区的组合只读检测：除计时实况外，结果中的 `setup` 提供兼容性、
写入确认、活跃恢复事务和脱敏停用原因，`environment` 提供运行时已记录的 HOS、机型及
是否运行于 Atmosphère。该检测不得删除 `disable.flag`、接管系统或写入 PCTL。旧版本的
`disable.flag` 只有存在性而没有原因时，`disable_reason` 为空，UI 必须显示“旧版本未记录”，
不得猜测原因。`restriction_enabled_available` 与 `temporary_unlocked_available` 区分真实的
`false` 和读取不可用；UI 不得用 `false` 代替失败。

成功写请求的 result 是该请求的提交记录。后台可在 result 持久化完成前继续保留该请求的
`recovery/active` 以支持写失败回滚，但 result 中必须返回 `recovery_active:false`；其它请求
持有的活跃事务（例如 Enforce 的确认窗口）仍返回 `true`。Companion 本地配置操作完成后也
必须重新读取真实恢复事务状态，不得沿用此前 result 中的缓存告警。

后台另以原子写入维护 `support/recent-events.jsonl`，最多保留 20 条脱敏关键事件；普通无变化
的 status 成功不写入。status 只读结果通过 `recent_events` 返回该摘要，支持页展示最近 3 条。
每条仅含时间、请求类型、稳定事件名、错误原因和脱敏 detail，不包含请求 payload、PIN、
离线码、密钥、nonce 或 recovery 原始内容。摘要损坏或写入失败不得阻断控制主流程。

失败将 `status` 改为 `error` 并增加：

```json
"error": {"code": 312, "reason": "protection_mode", "message": "安全前置检查失败，已进入保护模式"}
```

result 不输出控制模式或 dry-run 字段。

`rule_source` 是最终生效规则来源，只允许 `weekly`、`today_override`、`statutory_holiday`、`makeup_workday`。该字段由 sysmodule 与 PCTL 目标在同一次规则计算中生成，UI 不得自行根据日期猜测。日历更新或 `set_holiday_policy` 成功后立即重算当天规则；当天已有 `today_override` 时继续保留临时设置。

`preview_offline_code` 成功结果额外包含：

```json
"preview": {
  "grant_minutes": 30,
  "remaining_after_available": true,
  "remaining_after_minutes": 75,
  "effective_add_minutes": 30,
  "capped": false,
  "converts_unlimited_to_limited": false
}
```

NRO 和 Overlay 的兑换流程固定为“输入 → 非消费预览 → 确认 → 再校验 → 正式兑换 → 成功结果”。预览后取消、预览失败和同步提交失败都要清除界面中的完整代码，并明确说明代码未消费、仍可重新输入。兑换后剩余为 0、未知，或从不限时变为限时时，只接受手柄长按确认，触控不能绕过。

正式 `offline_code` 获得持久提交身份前，Companion 在根目录原子写入 `pending-redemption.json`。文件只保存版本、request ID、确认时间、是否已收到提交成功响应，以及兑换前/预览后的分钟快照；严禁保存完整加时码。同步提交失败时立即删除该文件。若进程在提交响应附近中断，重启后用 request ID 检查 `results/` 和 inbox 的 durable request 证据：没有提交证据的 prepared 标记按“未提交、未消费”处理；已有提交证据或 `submitted:true` 时持续读取同一 `results/<request_id>.json`，界面显示成功结果或“结果确认中”，绝不重新提交该码。终态结果展示并由用户处理后才删除恢复标记。

### 面向用户的错误处理

错误码 `306`（`pctl_effect_not_observed`）表示后台没有观察到家长控制设置按预期生效。可能原因包括主机家长控制尚未手动开启，或系统状态尚未同步。用户应先在主机打开“系统设置 → 家长控制 → 开启家长控制”，返回 PlayWise 后选择“重新检测”；仍失败时保留诊断信息，不要直接编辑 PCTL 原始数据。

错误码 `313`（`handover_state_unavailable`）表示首次接管无法同时可靠获得当前限时日的总额度与剩余时长。PlayWise 在此错误下没有改写 PCTL；应保留当前 Nintendo 家长控制设置，稍后重新检测或在次日再完成接管，不要为了继续设置而猜测“总额度”等于“剩余时长”。

`played_minutes` 优先来自 PCTL 私有命令 `1952 GetPlayTimerSpentTimeForTest` 的独立已用时；因此 `remaining_available:false` 的不限时日仍可能有 `played_minutes_available:true`。若该命令不可用，限时日回退到配置总分钟减 1454 剩余分钟，不限时日返回 `played_minutes_available:false` 与 `played_minutes:-1`，不会猜测或把不限时哨兵值当作已玩时间。

## 家长网页配对

Companion 使用当前 `device_id`、`grant_secret` 和可选 `config.json.pairing_base_url` 生成 fragment URL 的二维码。缺少自定义字段时使用默认地址：

```text
https://selfuppen.github.io/NX-PlayWise/#device_id=<url-encoded>&grant_secret=<url-encoded>
```

fragment 不随 HTTP 请求发送。PWA 读取后必须立即用 `history.replaceState` 清除地址栏参数，
验证设备名为 1–32 位 `[A-Za-z0-9_-]`、密钥为 32–64 个非空白可打印 ASCII 字符，并在
家长确认后才替换 `localStorage` 中的当前设备。取消、缺字段或验证失败不得改写当前保存的配对配置。

自定义根地址最长 256 个字符；只接受绝对 HTTPS，或用于本地调试的 `http://localhost`、回环地址和私有网 IP。地址不得包含 userinfo、控制字符、空白或已有 fragment，可以包含 path 和 query。Companion 始终自行追加 `#device_id=...&grant_secret=...`。编辑和恢复默认地址均需再次验证 PIN；界面必须警告自定义站点能读取配对密钥。

文件配对使用 `sdmc:/switch/playwise/parent-import.json`：

```json
{"version":1,"device_id":"kid-switch","grant_secret":"<32–64 chars>"}
```

家长网页同时提供 `playwise-offline.html` 单文件离线版。它必须内联全部运行资源、不得自动发起网络请求，并沿用上述文件配对 schema、字段校验、覆盖确认、v2 固定向量自检和 nonce 上限。普通用户的首选交付物 `playwise-complete-<版本>.zip` 必须且只能包含同版本标准安装包 `playwise-<版本>.zip` 和该离线网页；内嵌文件必须与分别验证的源产物字节一致，不得解开、重写或混入 Device Lab、安装脚本及额外说明文件。单文件从 `file://` 打开时不作为二维码跳转目标，不注册 Service Worker，也不宣称可安装为 PWA。Web Crypto 不可用时允许使用输出完全兼容的内置 HMAC-SHA256；安全随机源不可用时允许从浏览器当天尚未签发的 nonce 中顺序选择。浏览器拒绝持久存储时允许仅在内存中保存，但必须明确提示关闭页面后配置和 nonce 历史会丢失，以及发生 nonce 碰撞时重新生成。

二维码显示、导出文件、显示当前密钥、保存新密钥和本机生成加时码均需再次验证 PlayWise 管理 PIN。“加时码与安全”固定提供两个直接生成入口：“立即生成加时码”进入本机生成页，“手机/电脑生成加时码”进入二维码和手动导入说明页；两者按 `B` 直接返回安全页，不经过聚合中转层。

“加时码生成管理”集中提供“管理加时码设备名”“管理加时码密钥”“导出手机/电脑配置”“编辑二维码跳转地址”和“恢复二维码跳转默认地址”五项操作，使用两列卡片、方向键、`A` 和触摸统一操作，不提供隐藏上下文快捷键。子操作完成后回到或留在管理页；恢复默认地址须在 PIN 验证后再使用普通 `B 取消 / A 确认` 二次确认。设备名和密钥管理中的输入、随机生成和保存是分离操作；输入与随机生成只修改草稿，`+` 保存后才持久化，带草稿离开时必须确认继续编辑或放弃。

“手机/电脑生成加时码”同时展示两条路径，并主推从完整交付包取得 `playwise-offline.html`、导出 `sdmc:/switch/playwise/parent-import.json` 后手动导入；页面需提示手机先保存文件并交给系统浏览器打开，不要使用聊天软件或网盘内置预览器。扫描二维码自动导入降为网页可访问时的便捷方式，仍须动态完整显示当前 `pairing_base_url`，不得以省略号隐藏合法地址。两条路径均指导家长选择“导入配置文件”和“导入此设备”，并明确警告二维码和配置文件均包含加时码密钥。自定义地址的产品前提是官方 PWA，或完整部署仓库 `tools/ptc_frontend` 得到的兼容 PWA；Companion 只执行既有 URL 格式校验，不联网探测页面能力。

## Companion 本机生成加时码

家长区从“立即生成加时码”直接进入本机生成页面，使用当前设备密钥生成今天有效的 v2 8 位码。默认时长为 20 分钟；六个调整按钮、生成和返回均可由方向键选中并按 `A` 执行，`L/R` 约调整 ±15 分钟，`ZL/ZR` 约调整 ±30 分钟，`+` 生成。所有调整都吸附到 1–4 分钟、5–120 分钟（每 5 分钟一档）以及 150/180/210/240 分钟，并只显示不超过 `max_add_minutes` 的值。页面进入时主动请求 status，突出今天已玩、当前还能玩和兑换后预计还能玩，并显示状态更新时间；刷新失败时不得把缓存数字冒充实时值，但仍允许签发代码。预计剩余以当前剩余加本次时长计算，受每日 1440 分钟上限约束；不限时兑换会改为限时，已玩可用时预计剩余为本次时长，数据不足时显示暂不可用而不猜测。日期只使用 status 返回的 `day_index`；状态未加载时不得用 NRO 本地时钟猜测日期。

`grant-issued.json` 按 `day_index` 保存本机已签发 nonce。生成器同时排除该集合和 `ledger/used_nonces.jsonl` 中当天已消费的 v2 nonce，再从 `randomGet` 起点选择剩余值。生成动作不消费 ledger；只有兑换成功并完成 result/ledger 提交后才消费。生成新码、调整时长、刷新状态或离开页面均不会撤销已经签发的代码；代码只会因成功消费、日期变化、设备名变化或密钥变化而失效。界面必须保留当前显示代码的签发时长和生成时预计快照，并提示同日已签发代码可能仍可兑换，不得以隐藏代码暗示撤销。当天 512 个 nonce 均已签发或消费时必须拒绝继续生成，不得清空签发集合或复用 nonce。生成结果显示日期、分钟数、8 位码和“成功兑换后仅可使用一次”。

## 写入与恢复顺序

普通写入的提交顺序固定为：

1. 读取并验证 request、setup、配置、规则和 token；
2. 在 `recovery/active/` 原子保存 PCTL snapshot 及 rules/state/ledger 前像；
3. 应用 PCTL 目标并启动 timer；
4. 观察运行时目标；Enforce 允许短暂 pending，其余写请求失败即回滚；
5. 原子保存 rules/state/result；
6. 仅对成功 token 追加 nonce；
7. 清除恢复事务并归档 request。

无效 token、写失败、result 失败、ledger 失败和回滚路径不得提前消费 nonce。回滚无法精确证明时保留现场并创建 `disable.flag`。

## 日志与支持

有效 UTC+8 日期写入 `logs/YYYY-MM-DD/`；日期无效时写入 `logs/undated/<boot-id>/`。支持导出只允许 build/config/rules/state/setup/compatibility/environment 白名单字段，禁止 credentials、auth、离线码、完整 nonce 和原始 recovery 数据。导出文件额外包含导出瞬间的脱敏 `runtime_snapshot`：最近一次后台 status 的读取时间与数据年龄、计时模式、剩余/已玩可用性及分钟数、当前限制状态、规则来源、紧急停用标志、是否存在活跃恢复事务、请求是否处理中和传输类型。该快照明确标识缓存年龄，不直接读取 PCTL，也不包含私有 raw layout。诊断导出的进行中、成功和失败状态均显示在“支持与恢复”当前页面；成功状态固定展示完整保存路径、提交 GitHub Issue 时附加文件的说明，以及 `https://github.com/selfuppen/NX-PlayWise/issues`，离开该页或再次导出时清除或替换。

## Device Lab 协议边界
