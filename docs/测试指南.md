# 测试指南

测试是架构的一部分。项目必须先在 host 环境证明行为，再使用真实 Switch 服务。

## 当前可验证状态

已在本机验证通过：

- `python .\tests\mvp\test_token_v1.py`
- `python .\tests\observe\test_observe_queue.py`
- `protocol_probe.py` 的 init -> 生成离线码 -> 提交 `offline_code` / `status` request -> observe 处理 -> result 写出流程。
- `tools/package_sdmc.py` 可生成 safe SDMC 目录和 zip。

当前未在本机验证：

- C host 测试：需要本机具备 `make` 和 `gcc`，或使用远程 devkitPro 容器。
- 模拟器和真机：仓库当前还没有可启动 companion NRO、真实 boot2 sysmodule 二进制、真实 SDMC adapter 或 PCTL adapter。

重要边界：

- 当前 package 只能提供 `sdmc:/switch/play-time-control/` 配置和协议目录骨架。
- 模拟器/真机现阶段只能验证 SD 卡目录布局和后续二进制接入准备；不能声称已验证 PCTL、boot2 自启、play timer、raw block 或 suspend。

## 测试层次

单元测试：

- 面向纯 `common` 函数。
- 不使用文件系统。
- 不使用 libnx。
- 不依赖真实时间。

集成测试：

- 使用 `mem_storage`。
- 使用 `pctl_stub`。
- 使用 fake time。
- 端到端覆盖 request queue 和 control policy。

模拟器测试：

- 只验证 companion UI 和文件协议。
- 不声称验证真实 PCTL 行为。

真机测试：

- 验证 boot2、PCTL 读写、raw block、suspend 和 play timer 行为。

## 从零开始的本地测试

### 1. 检查环境和工作区

运行：

```powershell
git status --short
python --version
```

预期：

- Python 可用，建议 Python 3.12 或更新版本。
- 工作区只包含你确认要保留的本地改动。

### 2. 跑 Python host 快速回归

运行：

```powershell
python .\tests\mvp\test_token_v1.py
python .\tests\observe\test_observe_queue.py
```

预期输出：

```text
MVP token v1 tests passed
Observe queue tests passed
```

这两条测试覆盖：

- 离线加时代码的编码、解码、签名校验、错日期、重复 nonce 和超上限拒绝。
- observe 队列的 `offline_code`、`status`、坏签名、dry-run result、request 归档，以及 observe 模式不消费 nonce。

### 3. 跑 host observe 端到端 probe

初始化一个本地 SDMC 风格目录：

```powershell
python .\tools\protocol_probe.py init `
  --root .\.tmp\sdmc-observe `
  --device test-device `
  --secret test-secret
```

生成固定离线码：

```powershell
python .\tools\grant_code.py `
  --minutes 30 `
  --device test-device `
  --secret test-secret `
  --day-index 2380 `
  --nonce 4660
```

提交离线码请求，把 `<CODE>` 替换为上一步输出：

```powershell
python .\tools\protocol_probe.py request `
  --root .\.tmp\sdmc-observe `
  --type offline_code `
  --code <CODE>
```

处理 observe 请求：

```powershell
python .\tools\protocol_probe.py process-observe `
  --root .\.tmp\sdmc-observe `
  --day-index 2380
```

预期：

- 输出 `processed=1`。
- `.tmp\sdmc-observe\switch\play-time-control\results\` 下出现 result JSON。
- result 包含 `"status": "ok"`、`"mode": "observe"`、`"dry_run": true`。
- `.tmp\sdmc-observe\switch\play-time-control\ledger\` 保持为空，表示 observe 没有消费 nonce。

再提交并处理一个 status 请求：

```powershell
python .\tools\protocol_probe.py request `
  --root .\.tmp\sdmc-observe `
  --type status

python .\tools\protocol_probe.py process-observe `
  --root .\.tmp\sdmc-observe `
  --day-index 2380
```

预期 status result 同样包含 `"status": "ok"`、`"mode": "observe"`、`"dry_run": true`。

### 4. 生成可复制到 SD 卡根目录的 safe 包

运行：

```powershell
python .\tools\package_sdmc.py `
  --mode safe `
  --device-id kid-switch `
  --grant-secret replace-with-long-random-secret `
  --max-add-minutes 120 `
  --out .\build\packages\safe `
  --zip .\build\packages\safe.zip
```

预期：

- `build\packages\safe.zip` 解压后顶层直接是 `switch\play-time-control\...`。
- 不包含 `atmosphere\contents\...\flags\boot2.flag`。
- `switch\play-time-control\config.json` 中 `control_mode` 为 `observe`。

如果已经有 companion NRO，可以一起打包：

```powershell
python .\tools\package_sdmc.py `
  --mode safe `
  --out .\build\packages\safe-nro `
  --zip .\build\packages\safe-nro.zip `
  --nro .\path\to\pctc.nro
```

如果已经有 sysmodule `exefs.nsp`，并且准备测试 boot2，必须同时传入 `--sysmodule-exefs` 和 `--boot2`：

```powershell
python .\tools\package_sdmc.py `
  --mode disabled `
  --out .\build\packages\disabled-boot2 `
  --zip .\build\packages\disabled-boot2.zip `
  --sysmodule-exefs .\path\to\exefs.nsp `
  --toolbox .\path\to\toolbox.json `
  --boot2
```

脚本不会在缺少 sysmodule 二进制时生成 `boot2.flag`，避免做出一个看似能自启但实际没有后台程序的包。

## C host 测试入口

本机具备 `make` 和 `gcc` 时运行：

```sh
make
```

也可以拆开运行：

```sh
make test-host
make test-python
```

`make` 当前会编译并运行 `tests/c/test_host_core.c`，然后运行两个 Python 回归测试。

## 当前 C Host 覆盖

`tests/c/test_host_core.c` 当前覆盖：

- C token v1 与 Python fixture 一致。
- HMAC 校验、错密钥、错日期、重复 nonce、超上限。
- day index、weekday 和跨天 bedtime。
- 错误 reason 映射。
- observe dry-run 策略。
- grant 写入策略、backup gate 和 nonce 消费。
- raw block capability gate。
- `disable.flag` 优先级。
- status request pending -> processing -> done -> result。
- grant request 调用 `pctl_stub` 并写 backup/ledger。
- backup failure 阻止 PCTL 写入且不消费 nonce。
- stuck processing request 恢复。

## 仍需补充的覆盖

- 更完整的 request/result schema validation。
- `set_today_limit`、`add_today_minutes`、`disable_today_limit`。
- `restore_today_policy`、`set_weekly_template`、`set_bedtime`。
- `parent_unlock_start`、`parent_unlock_end` 和过期。
- `probe_raw_block`、`probe_suspend` 在 stub 中更新 capability。
- PCTL read/write failure 的更多 result 断言。
- storage failure 的可恢复路径。

## Fixture 要求

Fixture 应生成，不手写。

每个 fixture 应定义：

- case name。
- device id。
- grant secret。
- date 或 day index。
- nonce。
- minutes。
- expected token。
- expected result。

`tools/make_fixtures.py` 必须从与 `tools/grant_code.py` 相同的协议规则生成 deterministic fixture。

## 验收门槛

启用真实 PCTL 写入前：

- 所有 host 单元测试通过。
- 所有 host 集成测试通过。
- `observe` 验证有效码但不消费 nonce。
- 坏码路径从不消费 nonce。
- backup failure 阻止写入。
- capability gates 在 probe 前拒绝 raw block 和 suspend。

启用 `enforce` 前：

- `grant` 阶段已经通过真机最小写入测试。
- 拒绝用例在真实硬件通过。
- backup 文件可读且有恢复价值。
- event log 能记录成功和失败路径。

## 远程容器验证

共享 devkitPro 容器通过本地 SSH 别名访问：

```text
249-nintendo-switch-dev
```

远程仓库路径：

```text
/ws/switch-play-time-control-local
```

本地和远程都使用 `master` 分支。远程不会自动同步本地工作区；必须先本地提交并推送，再让远程 `git pull --ff-only origin master`。

当前远程完整验证命令：

```sh
ssh 249-nintendo-switch-dev 'cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make'
```

需要显式设置 devkitPro 环境变量时使用：

```sh
ssh 249-nintendo-switch-dev 'export DEVKITPRO=/opt/devkitpro; export DEVKITARM=/opt/devkitpro/devkitARM; export DEVKITA64=/opt/devkitpro/devkitA64; export PATH=$DEVKITA64/bin:$PATH; cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make'
```

Package 验证示例：

```sh
ssh 249-nintendo-switch-dev 'cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make package-safe package-observe'
```

默认 package 不应包含 `boot2.flag`。只有已经有 sysmodule `exefs.nsp`，并且显式传入 `--boot2` 时才应生成 boot2 flag：

```sh
python3 tools/package_sdmc.py --mode disabled --sysmodule-exefs path/to/exefs.nsp --boot2 --out build/packages/disabled-boot2
```

当前 package 不会自动包含真实 companion NRO 或 sysmodule 二进制；需要通过 `--nro`、`--sysmodule-exefs` 和 `--toolbox` 显式传入。
