# 测试指南

本文说明测试为什么分层，以及不同改动应执行哪些步骤。普通改动先跑自动化测试；只有自动化测试无法证明的 Switch 官方家长控制服务（PCTL）运行时行为和真实手柄/触摸输入链路才上 Switch 实机验证。

## 测试原理

### 分层验证

测试分为三层：

1. **本地代码自动化测试（Python 回归）**：验证 8 位加时码协议（token）、请求队列（queue）、防重复标记（nonce）、首次设置流程（setup）、恢复事务（recovery transaction）以及安装包（package）安全规则。
2. **容器编译验证（C/C++ 构建）**：在隔离容器中验证 C 语言核心代码、构建文件（Makefile）、主程序界面（Companion NRO）、快捷悬浮窗（Tesla Overlay）、后台服务程序（sysmodule）以及最终生成的单个安装包 Zip。
3. **实机验收测试（Switch 真机）**：在真实 Switch 主机上验证官方控制服务（PCTL）行为、系统开机流程（boot lifecycle）以及手柄/触摸屏输入响应。

本地自动化测试和容器构建测试必须具有确定性且可重复，不依赖真实时间或 Switch 官方网络服务。真机实机测试根据修改范围触发，不作为日常代码修改的默认步骤。

### 安全与恢复

每次向官方控制服务（PCTL）写入规则前，必须先在磁盘上保存恢复事务记录（recovery transaction），写入后确认真实控制目标已生效，最后提交规则文件（rules）、状态文件（state）、结果文件（result）和防重复标记（nonce）。任何阶段发生错误都会触发回滚机制；若无法明确证明恢复成功，系统必须自动创建紧急停用标记文件（`disable.flag`）。

启动恢复机制的优先级如下：

1. 恢复初始官方快照标记（`restore_install_snapshot.flag`）
2. 重试解除限制标记（`retry_setup_release.flag`，仅在未完成 pending 或失败 failed 阶段有效）
3. 未完成的恢复事务记录（`recovery/active/meta.json`）
4. 紧急停用标记（`disable.flag`）
5. 普通加时请求与自动规则控制（Enforce）

“强行封锁”（`raw_block`）和“暂停游戏”（`suspend`）属于独立的高风险控制能力，仅在开发或发布相关功能时进行专项实机验证。

## 测试步骤

### 1. 运行本地自动化测试

在仓库根目录执行命令：

```powershell
python .\tools\test.py
```

当终端显示 `PASS: local tests` 时表示测试通过。该入口覆盖以下逻辑：

- 8 位加时码协议（token v1/v2）、北京时间格式（UTC+8 日期）、防止重复播放（replay）、防重标记提交顺序（nonce submit order）以及 v2 加时码冷却判定。
- 请求与结果结构规范（request/result schema）、队列操作原子性（queue atomicity）、IPC 通信去重（IPC deduplication）和卡顿请求恢复（stuck processing recovery）。
- 首次设置状态机（setup state machine）、前置解限失败回滚（setup release rollback）、5 秒激活宽限期（5s grace period）和恢复标记优先级（recovery flag priority）。
- 普通官方控制写入事务（PCTL write transaction）、运行时效果确认（runtime confirmation）、结果/防重标记失败回滚（result/nonce failure rollback）和开机崩溃恢复（boot crash recovery）。
- 规则控制去重（Enforce deduplication）、规则与状态管理（rules/state）、强行封锁与暂停游戏门禁（raw block/suspend gate）。
- 家长网页控制台（PWA）、单安装包目录布局（single-package layout）、升级数据保留（update retention）以及安装脚本安全规则。

说明：普通控制探针矩阵、observe 全路径模式、旧版五包构建矩阵、一键基础测试（self-check）和重复 UI 卡片断言等已不再作为测试范围。

### 2. 编译并校验安装包（Package）

当修改涉及 C 代码、Makefile、主程序界面（Companion NRO）、快捷悬浮窗（Tesla Overlay）、后台服务程序（sysmodule）或安装包打包逻辑时，执行命令：

```powershell
python .\tools\package_remote.py
```

该脚本会在隔离容器 SSH 会话中自动清理旧产物、运行 C/Python 单元测试、编译三类二进制文件，并最终在 `build/packages/` 下生成单一压缩包 `playwise-<timestamp>.zip`。容器会自动挂载并读取当前工作区代码，未提交的更改也会参与编译。

编译完成后，脚本会自动校验以下项目：

| 检查项目 | 合格标准（通过条件） |
| --- | --- |
| 单包输出 | `build/packages/` 下仅存在一个最新的 PlayWise Zip 压缩包 |
| 完整文件布局 | Zip 内部包含后台服务（sysmodule）、主程序界面（NRO）、快捷悬浮窗（Overlay）以及开机自启标记（`boot2.flag`） |
| 初始配置状态 | 默认开启规则控制（`control_mode=enforce`），初始化阶段为未完成（`setup.json.phase=pending`） |
| 升级数据保留 | 安装脚本在覆盖安装时保留授权密钥（`grant_secret`）、PIN 密码、规则（rules）、状态（state）、审计日志（ledger）、日志与备份 |
| 干净构建 | 构建前会自动清理先前产物，若编译失败不会遗留伪造的半成品包 |

请勿使用手工 SSH、`docker exec` 或人工复制产物等旁路手段替代该权威编译入口。

### 3. 界面与交互实机验收

当修改涉及 Switch 主程序界面（Companion NRO）或快捷悬浮窗（Tesla Overlay）时，请按页面逐项确认：

1. 首次打开主程序时，优先展示“首次设置引导页”，并清晰标记初始化阶段（phase）、限制解除状态、官方快照（snapshot）状态和倒计时激活时间。
2. “家长区” -> “安全工具”页面包含：启用自动控制、重试前置解限、恢复安装前状态、紧急停用控制，以及强行封锁探针（raw block probe）和暂停游戏探针（suspend probe）。
3. 页面中不应显示旧版一键基础测试或普通控制写能力探针。
4. 孩子页、PIN 密码输入框、8 位加时码界面、分钟调节、周计划设置、就寝时间（bedtime）设置和确认弹窗无文字/控件重叠，手柄按键与触摸屏均能顺畅操作。
5. 界面通信状态能准确区分：内存快速通道（IPC）、SD 卡文件队列（SD queue）、IPC 已接收但仍在读取 SD 结果（IPC accepted / SD result backread），以及本地 SD 标记文件（SD flag）。
6. 首次设置/恢复失败时，界面展示稳定的错误码与具体原因说明（code/reason），且失败的结果不会抹掉最近一次有效的系统状态。

### 4. 验收新设备或新的系统版本（HOS/PCTL）

每当遇到新的 Switch 机型或新的系统固件（HOS）组合时，执行一次完整流程验收：

1. 先让 Switch 主机进入官方受限状态，安装最新的唯一 Package 压缩包，然后重启主机。
2. **不使用** Nintendo 官方 PIN 密码或手机 App 解锁。直接打开主程序界面（Companion NRO），确认首次设置引导页显示“官方控制快照（snapshot）可用”，且“当前限制已自动解除”。
3. 在主程序界面中设置或验证 PIN 密码，进入“家长区”点击“启用自动控制”。确认页面展示 5 秒倒计时，倒计时期间无需手动刷新；倒计时结束后自动跳转到孩子页，界面显示“自动控制：已启用”。
4. 输入并提交一个 15 分钟 v2 加时码，确认 Switch 系统的真实可玩额度增加、计时器启用（timer enabled）、限制阻断解除（restricted false），并确认后台防重标记（nonce）仅被提交了一次。
5. 重启 Switch 主机，确认初始化状态（setup）、控制规则（rules）、可玩额度（limits）和审计日志（ledger）在重启后依然持久化保存。
6. 在首次验收时，额外在 SD 卡创建恢复标记文件 `flags/restore_install_snapshot.flag`，确认系统的原始官方控制设置和计时器状态被完整恢复，初始化阶段进入“已恢复快照”（`restored`），且系统自动生成了紧急停用标记文件（`disable.flag`）。

注意：任何一步出现失败，都应立刻停止规则控制（Enforce）和高风险能力探针测试，并按“失败后取证”章节保留日志与数据。

### 5. 按修改模块追加实机测试

根据你的修改范围，选择对应的模块执行详细实机验收测试。

#### 5.1 PCTL 写入与恢复模块

**触发条件**：修改 `sysmodule_core.c` 中的 PCTL 读写逻辑、0x44 字节快照布局、写操作事务恢复逻辑。
**前置条件**：主机已安装测试包并重启，位于 phase=active 阶段。
**测试步骤**：
1. 在 Companion 安全工具页，观察“强制阻止”和“暂停软件”能力状态。
2. 执行“验证强制阻止能力”探针。
3. 再次观察能力状态，确认是否变更为“已验证”。
**预期结果**：探针写入完成，无崩溃，UI 更新为已验证（成功）或显示具体的错误反馈码（适配层未实现）。
**失败排查**：
- **UI 显示**：错误码 300+ 表示 PCTL 写入阶段错误。
- **自动暴露**：`pctl_debug.jsonl` 中记录具体的 0x44 读写偏移和报错内容。
- **取证清单**：`sysmodule.log`、`backups/last_pctl_backup.txt`。

#### 5.2 开机引导与初始化模块

**触发条件**：修改 `sysmodule.json`、系统初始化时序或 `setup_phase` 状态转移逻辑。
**前置条件**：清理 SD 卡 `setup.json`，在官方受限状态下覆盖安装。
**测试步骤**：
1. 开机后立即打开 Companion NRO。
2. 观察引导页的阶段显示与倒计时。
3. 如果停留在 pending 阶段，按 Minus 键进入安全工具尝试“重试前置解限”。
**预期结果**：系统能正确检测官方限制，5秒倒计时后自动激活进入 active。如果前置解限受阻，重试后能继续。
**失败排查**：
- **UI 显示**：安全工具页会高亮提示“等待前置解限”或“解限失败”。
- **取证清单**：`setup.json`、`sysmodule.log`。

#### 5.3 界面交互与输入模块

**触发条件**：修改 Companion NRO 渲染、UI 状态机、Overlay 画图代码。
**前置条件**：主机正常运行，位于 active 阶段。
**测试步骤**：
1. 打开 NRO，测试摇杆、十字键、触摸屏切换各个 Tab。
2. 在孩子页输入 8 位加时码，尝试故意输错一次，再输对一次。
3. 打开左侧快捷菜单（Tesla Overlay），测试快速加时与状态折叠。
**预期结果**：手柄与触摸均无死区，输入框无重叠，加时反馈及时（SD/IPC 同步无明显延迟）。Overlay 能正常覆盖游戏画面和系统级阻断弹窗。
**失败排查**：
- **表现**：如果输入无响应，可能是 libnx/libtesla 事件丢失。
- **取证清单**：排查修改点前后的事件处理循环逻辑。如果死机请提取对应的 `crash_reports`。

#### 5.4 规则与控制模块

**触发条件**：修改周计划、就寝时间、额度结算逻辑。
**前置条件**：设备时间设置在测试时段。
**测试步骤**：
1. 在家长区修改当日规则为限时，剩余时间设为 1 分钟。
2. 游玩任意游戏 1 分钟，观察是否触发限制。
3. 在限制生效状态下，通过 Overlay 提交家长临时解锁，观察游戏是否恢复。
4. 测试就寝时间拦截：将系统时间调至设定的就寝时段内，观察是否立即被阻断。
**预期结果**：额度耗尽与就寝时段触发立即被系统拦截（取决于控制方式）；临时解锁能顺利绕过当前限制。
**失败排查**：
- **UI 显示**：如果额度未生效，安全工具页状态面板可能会显示“状态异常”或未更新。
- **自动暴露**：`events.jsonl` 会记录每次时间跳变的校准事件。
- **取证清单**：`state.json`、`rules.json`、`events.jsonl`。

#### 5.5 高风险能力专项测试（强行封锁与暂停软件）

**触发条件**：修改 `PTC_LIMIT_ACTION_RAW_BLOCK` 或 `PTC_LIMIT_ACTION_SUSPEND` 实施细节。
**测试步骤**：
1. 在安全工具页执行对应探针并确保成功验证。
2. 在家长区“时间计划” -> “限制方式”中选择对应方式。
3. 消耗时间至限时触发。
**预期结果**：触发时，强行封锁应直接拉起不可消除的官方全屏阻断；暂停软件应无缝暂停当前应用并弹窗。
**失败排查**：
- 如果系统死机或无限黑屏，说明 0x44 写入严重错误。
- 强制重启后应自动触发 `disable.flag` 保护。

### 6. 安全工具页可用性说明

NRO 家长区“安全工具”提供了六种应急和测试操作，各操作均有内置的**可用性门禁**和**自动上下文引导**，以减少误操作：
- **启用自动控制**：仅在“限制已解除”（phase=released）时才允许点击。
- **重试前置解限**：仅在 pending 或 failed 阶段时高亮并推荐点击。
- **恢复安装前状态**：如果官方快照文件存在且完整才允许点击，用于完全回退。
- **紧急停用控制**：始终可用，点击后将立即写入 `disable.flag` 停止后台写操作。
- **能力探针**：仅在 active 阶段开放点击，验证成功后将置灰防止重复写入真机。
操作失败时，界面底部将自动显示排查建议及错误码。

## 失败后取证

如果由于严重故障导致无法打开 Switch 主程序（Companion NRO），可以直接在 SD 卡中创建对应的恢复标记文件（flag）。若要彻底禁止后台服务程序（sysmodule）随开机启动，可直接删除 Atmosphere 系统目录中的开机自启标记文件 `boot2.flag`。

在排查定位问题前，请务必保留以下关键文件：

- 初始化配置文件：`setup.json`
- 初始官方快照备份：`backups/install_pctl_snapshot.json`
- 未完成的恢复事务目录：`recovery/active/`
- 请求处理结果文件：`results/*.json`
- 当天的系统日志目录：`logs/`
- 系统能力配置文件：`capabilities.json`

如果后台服务程序（sysmodule）发生崩溃，崩溃报告文件位于 SD 卡路径：

```text
sdmc:/atmosphere/crash_reports/<tick>_4200000000bd2300.log
```

请结合编译产物中的符号映射表 `sysmodule/build/pctc-sysmodule.map` 和当天的系统日志定位崩溃代码行。
