# 测试指南

本项目使用一个本地测试入口、一个容器构建入口和分阶段真机验收。协议拒绝、nonce、backup gate、PCTL 失败和恢复由自动测试覆盖；真机测试集中证明系统服务、运行时效果和恢复能力。

请求字段、result 和错误语义以[协议](协议.md)为准；安装与日常操作见[使用指南](使用指南.md)。

## 本地回归

Windows PowerShell：

```powershell
python .\tools\test.py
```

成功时输出：

```text
PASS: local tests
```

该入口无第三方 Python 依赖，覆盖：

- token v1/v2、固定向量、UTC+8 日期、分钟档位、nonce 和 v2 冷却。
- request/result schema、observe 队列、stuck recovery、匹配 id 和原子写入。
- IPC accepted-before-execute、SD fallback 不重复提交、扫描退避和分钟调度。
- PWA Web Crypto parity、离线缓存、CSP、MIME 和路径穿越防护。
- package 默认 `observe`、`boot2.flag` 规则、NRO/Overlay 元数据和 zip 布局。
- UTC+8 日志目录及 30 天保留策略。

control mode、backup gate、nonce 消费时机、rules、enforce、Companion UI 状态和 PCTL/capability 失败注入属于 C host 测试，由下一节的容器入口统一编译执行。

只有排查具体失败时才单独执行 `tests/` 下的脚本。

### PWA 验收

```powershell
python .\tools\ptc_frontend_server.py
```

在 `http://127.0.0.1:8765` 验证：生成与复制 8 位码、刷新恢复配置、清除本机配置、安装 PWA、断网重开、移动端单列布局，以及浏览器 Network 中没有外部请求。正式手机场景必须使用可信 HTTPS origin。

## 容器构建与 Package

涉及 C、Makefile、Companion NRO、Overlay、sysmodule 或 package 的改动，运行：

```powershell
python .\tools\package_remote.py
```

默认环境为 `root@127.0.0.1:1888`，仓库挂载到 `/ws/playwise`。脚本通过一次 SSH 会话：

1. 清理旧 `build/packages/`。
2. 在挂载工作区运行 C/Python 测试。
3. 构建 NRO、Overlay 和 sysmodule NSP。
4. 生成并校验 `safe-nro`、`disabled-boot2`、`observe-boot2`、`grant-boot2`、`enforce-boot2` 五个 zip。

通过条件：

| 检查 | 判据 |
| --- | --- |
| 安全默认值 | `safe-nro` 为 observe，无 `boot2.flag`，不含 Overlay |
| boot2 包 | 包含 sysmodule、NRO、Overlay、对应模式和显式 `boot2.flag` |
| 元数据 | NRO/Overlay 可被相册、Tesla/Ultrahand 正确枚举，标题和版本有效 |
| 旧产物 | 构建前清理；失败时不得留下伪完整 package 集合 |
| 安装脚本 | 复制后哈希一致，切换 safe 包只移除本项目 Overlay |

容器直接读取未提交工作区。不要用本机缺少 make/gcc 或 WSL 作为跳过 C 验证的理由，也不要绕过该入口维护旁路命令。

## 图形界面验收

在模拟器或真机以 1280×720 检查：

| 区域 | 验收重点 |
| --- | --- |
| 孩子首页 | 今日状态、剩余/已玩时间、模式、计时器、bedtime、临时解锁、限制方式和最近结果完整；不显示 id、路径或原始 JSON |
| 8 位码 | 数字键盘、退格/清空/提交、取消和错误页正确；失败不清除最近有效状态 |
| 家长入口 | 页面不显示快捷入口；`Minus` 或肩键组合后仍必须验证本地 PIN |
| 家长区 | 今日管理 6 张、时间计划 5 张、安全工具 5 张卡片全部可达，三页两列布局无重叠 |
| 输入方式 | 手柄和触摸命中一致；分钟、周计划、bedtime、限制方式和确认弹窗取消时不提交请求 |
| 风险确认 | 可能立即受限的设置显示已玩时间和待保存内容，并要求二次确认 |
| 传输状态 | 区分 IPC、SD 文件队列、IPC → SD 结果回读；accepted 后不得重复提交 |
| 能力状态 | 显示 write、effect、raw block、suspend；反馈包含中文原因和必要的 code/reason/failure_stage |
| 布局稳定性 | 中文无乱码，焦点清晰，等待/成功/拒绝/超时不引发布局跳动 |
| 恢复页 | 图形、字体或 FreeType 初始化失败时只显示最小中文恢复页并可退出 |

`disable.flag` 的创建/删除必须显示“本地 SD 标志文件”，不能沿用此前 IPC 标签。模拟器只能证明 UI 和请求流程，不能证明共享字体兼容性、PCTL 效果或真机恢复。

## 真机启用顺序

1. `safe-nro`：验证 UI、PIN、输入和 SD 文件，不启动 sysmodule。
2. `disabled-boot2`：验证 boot2、日志和结构化拒绝，不触碰 PCTL。
3. `observe-boot2`：验证状态、有效/无效 token 和 `dry_run:true`，确认 PCTL 与 nonce 不变。
4. `grant-boot2`：先执行快速设备测试，再验证显式业务请求。
5. 按需执行 raw block/suspend 独立探针。
6. `enforce-boot2`：仅在 grant 业务链路稳定后验证自动规则。

每阶段失败时停止升级，保留 result、日志、capability 和 backup。

## 快速设备测试

前置条件：已掌握 SD 卡恢复和官方 PIN/App；容器构建通过；安装最新 `grant-boot2`；不存在 `flags/disable.flag`。

进入 Companion“安全工具”，选择“快速设备测试”并二次确认。通过信息必须为“快速设备测试通过，设置已自动恢复”。

一次测试覆盖 request queue、真实 `pctl:s` 会话、写前备份、目标写入、`StartPlayTimer`、运行时状态、capability 持久化和 opaque snapshot 恢复。PASS 同时要求：

- result 类型为 `probe_play_timer_effect`、非 dry-run，`verdict` 为 `pass`。
- raw settings 和原 timer enabled 状态全部恢复。
- write/effect capability 分别持久化为 `pctl-s-v2` 和 `pctl-s-runtime-v2`。
- backup、effect before/active/restore 证据存在。
- active 只改变目标日期，restored 与 before 完全一致。
- 已有累计游玩时间时仍选择不会立即到期的安全临时目标。

旧 v1 capability 会自动失效。backup slot 摘要不符合 `h:...;d0:flag=...,enabled=...,m=...` 时说明仍在运行旧 sysmodule，应停止并重新安装。

失败、超时或 self-check 不通过时，Companion 自动创建 `disable.flag`。记录页面上的 code/reason/failure_stage 和测试时间，不继续 grant、enforce 或高风险探针。

## Grant 业务验收

前置条件：快速测试通过，write/effect capability 有效，不存在 `disable.flag`。

| 场景 | 通过判据 |
| --- | --- |
| 设置今日额度为 40 | result 非 dry-run 成功；today override=40；官方界面同步 |
| 使用 v2 15 分钟码 | `python .\tools\grant_code.py --tier-minutes 15 --device <id> --secret <secret>`；额度变为 55，ledger 追加一次 |
| 重复同一码 | `used_token`；ledger、rules 和 PCTL 不再变化；错误页返回后状态仍有效 |
| v2 连续错误 | 第 5 次后 `code_cooldown`；重启仍有效；成功兑换后清零 |
| 超上限 v1 兼容码 | 使用 `--minutes` 生成超过 `max_add_minutes` 的码；`minutes_exceed_limit` 且不消费 nonce |
| 昨日码 | `wrong_date`，不写 PCTL、不消费 nonce |
| 今日操作 | 临时加时、今日不限、恢复周计划均成功且 rules 对应变化 |
| 重启 | 今日 override 和 nonce ledger 保持一致 |

随后在 grant 模式验证不触碰 PCTL 的规则请求：每周计划、bedtime、`remind`、临时解锁和结束解锁。rules/state 必须更新；`grant` 保存 bedtime 但不自动到点限制，这是预期行为。

`raw_block`、`suspend` 和“今日禁玩”在对应能力未验证时必须返回 `*_not_verified`。

## 独立能力探针

仅在快速测试和 Grant 业务验收通过后按需执行。模式必须为 grant/enforce；observe 只能得到 `dry_run:true`、`verdict:"not_run"`。

### 暂停软件

“验证暂停软件”只读，不改变设置。通过要求 `suspend_verified:true`、backend 为 `pctl-s-suspend-v1` 且事件日志有 `probe_ok`。

- `suspension event unavailable`：当前系统没有可用事件，保持关闭。
- `suspension event ok but play timer alarm is disabled`：先在官方家长控制中启用游玩时间提醒后重测。

capability 只证明 Horizon 暂停请求通道可用，不证明本项目直接暂停软件。

### 强制阻止

“验证强制阻止”会把当天临时写成 restricted 0 分钟，观察运行时受限，再恢复完整 0x44 snapshot 和原 timer 状态。应在无人使用主机且官方 PIN 可用时执行。

PASS 要求：

- `pctl_raw_block_probe.verdict:"pass"`，非 dry-run。
- `raw_target_written`、`blocked_observed`、`raw_restored`、`timer_restored` 全为 true。
- active 只把目标日期分钟改为 0；restored 与 before 完全一致。
- `raw_block_verified:true`，backend 为 `pctl-s-rawblock-v1`。
- 日志包含 before/apply/restore，backup 已更新，不存在 `disable.flag`。

`write` 表示主机拒绝 raw 0；`runtime_status` 表示写入后未观察到受限；`restore` 表示恢复失败。恢复失败必须返回 `pctl_restore_failed`、清除能力并创建 `disable.flag`，随后立即执行恢复流程。

不得手工编辑 capability 绕过任何探针。

## Enforce 验收

完成 Grant 业务验收后安装 `enforce-boot2`：

1. 启动约 15 秒后，在分钟边界写入当天规则并 `start_timer`；event 和 `last_enforced_*` 同步更新。
2. 无配置变化时观察数分钟，不得重复写相同目标或重复增长成功日志。
3. 修改今日额度，下一轮对账到新值。
4. 跨本地零点后应用新一天周计划，day index 递增。
5. 创建 `disable.flag` 后立即停止对账；删除后恢复。
6. 有限额度到 0 时，`remind` 保持普通目标；已验证的 `raw_block`/`suspend` 使用各自目标；未验证时 fail-open。
7. bedtime 进入时执行所选限制，结束时恢复当天规则；`last_enforced_bedtime_active` 正确切换。
8. bedtime 期间开始本地临时解锁应恢复当天规则，结束解锁且仍在时段内应重新执行限制。

出现重复写入或跨日错误时保留 `state.json` 和 `events.jsonl`；出现 `pctl_apply_failed` 时同时保留 `pctl_debug.jsonl`。

## Tesla 硬限制验收

在目标 HOS、Atmosphere、nx-ovlloader 和 Tesla Menu 组合上执行：

1. 正常状态打开“任你玩”，检查中文、8 位槽、3×4 数字键盘、方向键连移、A/X/Y/Plus/B 和禁用提交状态；当前版本不验收触摸。
2. 触发官方游玩时间硬限制弹窗，确认 Tesla Menu 和 Overlay 仍能显示并接收输入；任一失败即停止该方案，不修改 qlaunch。
3. 提交有效码，必须得到真实非 dry-run offline-code 成功、timer enabled=1、restricted=0、剩余时间增加；官方弹窗消失并返回原游戏。
4. 无效、过期、重复、冷却、后台不可用、disabled 和 PCTL 失败均显示中文错误，不消费 nonce；observe 只显示演练。
5. 分别验证 IPC、SD fallback 和 accepted 后 SD 结果回读，三种路径均不得重复提交。
6. 重复掌机/底座、睡眠唤醒和重启；相关版本变化后重做本节。

## 恢复与取证

1. 能进入 Companion 时，在“安全工具”创建 `disable.flag`。
2. Companion 不可用时，从 SD 卡创建 `sdmc:/switch/playwise/flags/disable.flag` 并重启。
3. 完全停止 boot2 时删除 `sdmc:/atmosphere/contents/4200000000BD2300/flags/boot2.flag`，或安装 `disabled-boot2`。
4. 官方限制已经生效时使用官方 PIN 或 Nintendo Parental Controls App 解除。
5. 保留对应 `results/`、当天 `logs/`、`capabilities.json` 和 `backups/last_pctl_backup.txt`；确认恢复后才删除 `disable.flag`。

sysmodule 崩溃报告位于 `sdmc:/atmosphere/crash_reports/<tick>_4200000000bd2300.log`。使用 `Module Info` 偏移和 `sysmodule/build/pctc-sysmodule.map` 定位符号；结合当天 `sysmodule.log` 最后一行判断启动阶段。若 `SP` 低于 `Stack Region` 下界，应优先按栈溢出分析。

栈预算不变量：`main` 中的大型 `PtcIpcServer`、`PtcSysmodule` 保持 `static`；cleanup 流程共用调用方传入的 `PtcStorageEntry[256]`，不得在嵌套函数各声明一份。
