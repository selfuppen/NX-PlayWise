# 测试指南

测试分为确定性 host 回归、devkitPro 容器构建和真机资格验证。公开 Release 的自动测试保留完整安全与恢复能力，但设备端不运行循环写入/回滚式 self-test。

## 本地回归

```powershell
python .\tools\test.py
```

通过标志为 `PASS: local tests`。该入口覆盖：

- token v1/v2、8 位码、日期、签名、replay、nonce 提交顺序和冷却；
- request/result schema、原子队列、IPC 去重、stuck request 恢复；
- setup 预检、snapshot、5 秒宽限、兼容状态和恢复优先级；
- 普通 PCTL 事务、失败注入、rollback、result/ledger 失败；
- Enforce 去重、`applied_pending_confirmation`、30 秒确认/回滚；
- PIN、规则、安装器、升级保留和诊断脱敏；
- Release/Device Lab 契约隔离和 package helper 失败路径。

测试必须使用固定时间、固定 fixture 和 host adapter，不依赖真实 Switch 服务。

## 权威容器验证

涉及 C、C++、Makefile、NRO、Overlay、sysmodule 或 package 时必须执行：

```powershell
python .\tools\package_remote.py
```

脚本在单次 SSH 会话中清理旧产物，运行 C host、UI 和 Python 回归，编译三个 Release 组件并生成唯一公开 Zip。

发布门禁断言：

- `build/packages/` 只有 `playwise-0.1.2.zip`；
- Zip 包含 Release sysmodule、NRO、Overlay 和 `boot2.flag`；
- `build.json` 与安装 manifest 完全一致，profile 为 `release`；
- 三个二进制都嵌入同一 manifest，NRO/Overlay 显示版本均为 `0.1.2`；
- 无 LAB handler、旧请求、旧控制模式、`capabilities.json` 或占位 secret；
- 不 seed `credentials.json`，首次启动必须生成唯一 secret；
- 安装脚本升级时替换程序和 build manifest，但保留 credentials、PIN、rules、state、ledger、logs 和 backups。

禁止用手工 SSH、`docker exec` 或复制回本地代替该入口。

## Device Lab 隔离验证

内部人员在 devkitPro 环境显式运行：

```sh
make device-lab-package
```

检查：

- 输出只在 `build/device-lab/`，不会出现在 `build/packages/`；
- Title ID 为 `4200000000BD23F0`，IPC 为 `pwtl:u`，SD 根目录为 `switch/playwise-device-lab`；
- manifest profile 为 `device-lab`；
- NRO 持续显示 DEVICE LAB 危险水印，操作要求 ZL+ZR+A；
- 包默认不含 `boot2.flag`；
- `make packages` 不会构建或携带任何 LAB 产物。

## UI 实机验收

修改 NRO 或 Overlay 后，至少验证：

1. 首次设置按“环境与兼容状态 → 1–64 位数字 PIN → 加时码设置 → 周计划 → 接管确认”推进，未完成前不允许普通写入；旧 6 位 PIN 可继续验证。
2. 孩子首页只展示今日已玩/总额度/剩余时间、8 位数字键盘和简明状态。
3. 家长区只有今日额度、周计划、加时码与安全、支持与恢复四类页面；周计划直接展示七日编辑器，没有功能卡或二级菜单，也没有探针、能力矩阵、后端或 raw layout 文案。
4. 手柄和触摸均可操作数字键盘、额度和周计划；弹窗输入不穿透。
5. 状态语言一致：绿色“正常运行”、蓝色“正在同步”、黄色“兼容性待确认”、橙色“保护模式”；红色表示需要家长关注且会阻止正常控制的状态。保护模式显示“安全保护已触发”，主动停用显示“紧急停用已开启”，两者可并列。
6. `disable.flag` 下孩子页和全部家长页持续显示红色停用状态；status、诊断导出、解除停用和恢复仍可用，额度、周计划和加时码写入在 UI 与后台均被拒绝。
7. 支持包中搜索 secret、PIN、已提交 8 位码和完整 nonce 均无匹配。
8. 进入/重新进入孩子页、切换到家长区“今日额度”页以及每个时间调整入口都会主动刷新状态；页面显示 UTC+8 日期、当前已玩、当前剩余、调整后可玩和“上次同步 X 秒/分钟前”。超过 30 秒应能明显看出数据可能过期；不限时无法可靠读取已玩时显示“暂不可用”，且“临时加时”不可提交。
9. “今日额度”和“临时加时”页面不应有文字互相覆盖；大号分钟数同时显示小时/分钟换算，点击分钟数可进入数字输入，快捷调整提供 ±5/±15，并明确提示只影响今天。不限时改限时、减少可玩时间、恢复周计划和会影响今天的周计划保存均显示二次确认；恢复周计划清除今日额度与不限时 override，并展示恢复前后的剩余时间对比。
10. 周计划未保存时，离开提供“保存并离开 / 放弃并离开 / 继续编辑”，保存计划不清除今日 override。
11. 显示密钥、二维码、导出配置和保存密钥均重新验证 PlayWise PIN；演示密钥启用时持续显示红色警告，退出后生成新的 64 位随机密钥。
12. 扫码配对覆盖成功、缺少 fragment 参数、非法密钥、取消导入、已有配置覆盖，以及 `parent-import.json` 成功/失败路径都有确定性前端测试。
13. PIN 覆盖 1 位、64 位、65 位、非数字、旧 6 位兼容，以及第 5 次失败后 30 秒至最长 10 分钟的持久冷却。
14. 本机生成器默认 20 分钟，左右只遍历合法且不超过设备上限的档位；未加载日期时拒绝生成，并排除当天 ledger 与本机已签发 nonce。
15. 二维码自定义地址覆盖 HTTPS、localhost/回环/私有 IP HTTP、path/query、恢复默认，以及 public HTTP、userinfo、控制字符、超长和已有 fragment 的拒绝路径。
16. PWA 离线页面包含配对、码无效、日期、设备无响应、紧急停用和高级诊断排错说明。

## 资格验证

`0.1.2` 的目标基线：

- Nintendo Switch OLED；
- HOS 22.5.0；
- 资格测试环境 Atmosphère 1.11.2。

必须使用最终 `build/packages/playwise-0.1.2.zip` 重新执行，旧包结果不能继承：

1. 在已启用官方时间限制的主机上安装并重启。
2. 确认首次只读预检完成，未确认前没有 PCTL 写入。
3. 创建一个自选长度的数字 PIN，确认自动生成的 secret 不等于任何公开占位值，确认一周规则。
4. 家长确认接管后，验证安装 snapshot、解除当前限制、5 秒同步和 Active 状态。
5. 分别测试 status、设置今日总额度、增加分钟、今日不限时、恢复周计划和周计划保存。
6. 使用一个最终生成的 15 分钟 v2 加时码，确认 timer、剩余时间和 nonce 仅提交一次。
7. 制造一次状态传播延迟，确认显示“正在同步”；30 秒内确认成功或按契约回滚。
8. 重启验证 setup、rules、state、ledger 和未完成事务恢复。
9. 创建 `disable.flag`，确认只熔断写入；再验证诊断和安装快照恢复。
10. 恢复安装前 snapshot，确认原始 raw/timer 状态可被精确证明，并进入 `restored`。

截至 2026-08-07，最终 `0.1.2` 产物的上述真机资格验证仍待执行；manifest 必须保持 `requires-requalification-for-final-artifact`，不得宣称已发布验证。

## 失败取证

优先从 Release 支持页导出脱敏诊断。若 NRO 无法启动，保留：

- `build.json`、`setup.json`、`compatibility.json`、`environment.json`；
- `backups/install_pctl_snapshot.json`；
- `recovery/active/`；
- `results/`、`logs/` 和相关 crash report。

不要对外发送 `credentials.json`、`auth.json`、完整 ledger 或原始离线码。要停止自动启动，可移除 `atmosphere/contents/4200000000BD2300/flags/boot2.flag`。
