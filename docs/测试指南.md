# 测试指南

本文档是项目测试入口。所有改动先用 host 自动验证证明协议、队列、结果和安全 package 行为，再进入远程 devkitPro 构建、模拟器辅助验证和真实 Switch 分阶段验证。

## 1. 可自动验证

### 1.1 本地一键自动验证

Windows 10 / PowerShell：

```powershell
python .\tools\verify_auto_tests.py
```

预期输出形态：

```text
[RUN ] existing Python regressions
[PASS] existing Python regressions
[RUN ] host protocol probe
[PASS] host protocol probe
[RUN ] safe package layout
[PASS] safe package layout
[RUN ] boot2 packaging guard
[PASS] boot2 packaging guard
summary: 4/4 automatic verification steps passed
```

该脚本无第三方依赖，不要求真实 Switch、模拟器或 devkitPro。它会使用临时目录完成以下断言：

- 运行 `tests/mvp/test_token_v1.py` 和 `tests/observe/test_observe_queue.py`。
- 执行 `protocol_probe init -> grant_code -> offline_code/status request -> process-observe`。
- 校验 result 为 `status: ok`、`mode: observe`、`dry_run: true`。
- 校验 request 已从 `inbox/pending/` 归档到 `inbox/done/`。
- 校验 observe 模式不创建 `ledger/used_nonces.jsonl`，即不消费 nonce。
- 生成 safe SDMC package 和 zip，校验目录完整、`control_mode=observe`、zip 顶层为 `switch/`。
- 校验 safe package 不包含 `boot2.flag`。
- 校验 `package_sdmc.py --boot2` 在缺少 `--sysmodule-exefs` 时失败，避免生成空 boot2 包。

失败时脚本会打印失败步骤、命令、stdout 和 stderr。成功时只输出 PASS 汇总。

### 1.2 拆分运行

调试具体失败时可以拆开运行：

```powershell
python .\tests\mvp\test_token_v1.py
python .\tests\observe\test_observe_queue.py
```

预期输出：

```text
MVP token v1 tests passed
Observe queue tests passed
```

常用 host probe 命令如下；一键脚本已经覆盖这些路径，手工运行主要用于排查：

```powershell
python .\tools\protocol_probe.py init `
  --root .\.tmp\sdmc-observe `
  --device test-device `
  --secret test-secret

python .\tools\grant_code.py `
  --minutes 30 `
  --device test-device `
  --secret test-secret `
  --day-index 2380 `
  --nonce 4660

python .\tools\protocol_probe.py request `
  --root .\.tmp\sdmc-observe `
  --type offline_code `
  --code <CODE>

python .\tools\protocol_probe.py process-observe `
  --root .\.tmp\sdmc-observe `
  --day-index 2380
```

手工为 Companion 测试生成匹配 result 时：

```powershell
python .\tools\make_result.py `
  --root .\.tmp\sdmc-observe `
  --request-id <REQUEST_ID> `
  --status ok `
  --day-index 2381
```

`make_result.py` 只写 `results/<request_id>.json`，不会移动 `inbox/pending/` 里的 request；完整队列处理仍使用 `protocol_probe.py process-observe`。

### 1.3 当前 C Host 覆盖

`tools/verify_auto_tests.py` 不编译或运行 C host 测试；它只覆盖 Python 回归、host protocol probe 和 package 安全规则。C host 覆盖需要远程环境，应使用专门脚本通过 SSH 执行：

```powershell
python .\tools\verify_c_host_tests.py
```

预期输出形态：

```text
[RUN ] remote C host core
[PASS] remote C host core
summary: 1/1 C host verification steps passed
```

该脚本会通过 SSH 访问 `249-nintendo-switch-dev`，进入 `/ws/switch-play-time-control-local`，执行 `git pull --ff-only origin master && make test-host`，并校验输出包含 `C host core tests passed`。远程仓库不会自动同步本地未提交改动；需要验证本地改动时，先提交并推送 `master`。

只有在本机有可用 C 编译器并需要调试脚本时，才使用本地模式：

```powershell
python .\tools\verify_c_host_tests.py --local
```

`tests/c/test_host_core.c` 当前覆盖：

- C token v1 与 Python fixture 一致。
- HMAC 校验、错密钥、错日期、重复 nonce、超上限。
- day index、weekday 和跨天 bedtime。
- 错误 reason 映射。
- observe dry-run 策略。
- grant 写入策略、backup gate 和 nonce 消费。
- raw block capability gate。
- `disable.flag` 优先级。
- status request pending -> processing -> done -> result。
- grant request 调用 `pctl_stub` 并写 backup/ledger。
- backup failure 阻止 PCTL 写入且不消费 nonce。
- stuck processing request 恢复。
- C 侧 request schema parser 和 result schema validator。
- `observe` 下规则请求保持 dry-run，不写 rules/state/capabilities，不触碰 PCTL。
- `grant` 下今日规则、周模板、bedtime、limit action、parent unlock、probe capability 的成功/失败路径。
- PCTL write failure、result write failure 和 ledger append failure 不提前消费 nonce。
- request queue 文件路径拼接长度检查。

仍需补充：

- PCTL read failure 的更多 result 断言。
- 更细粒度 storage failure 的可恢复路径。
- Switch `fs_storage`、time provider 和 PCTL adapter 的真机行为验证。
- Companion 家长区/PIN 流程的 UI 层测试。

## 2. 远程 devkitPro 自动构建验证

C host、Companion NRO、sysmodule NSP 和 package 生成的权威验证默认走远程 devkitPro 容器。本机缺少 `make`、`gcc` 或 WSL 发行版不是跳过 C host 验证的理由。

远程信息：

```text
SSH alias: 249-nintendo-switch-dev
remote path: /ws/switch-play-time-control-local
branch: master
```

远程不会自动同步本地工作区。涉及 C 代码、Makefile、NRO、sysmodule 或 package 的改动，应先本地运行快速验证、提交并推送 `master`，再让远程仓库快进拉取。

完整远程验证应使用脚本自动运行并检查构建产物：

```powershell
python .\tools\verify_devkitpro_build.py
```

预期输出形态：

```text
[RUN ] remote devkitPro build
[PASS] remote devkitPro build
[RUN ] remote build artifacts
[PASS] remote build artifacts
summary: 2/2 devkitPro verification steps passed
```

脚本默认通过 SSH 访问 `249-nintendo-switch-dev`，进入 `/ws/switch-play-time-control-local`，执行 `git pull --ff-only origin master` 后运行完整构建目标，并验证：

- C host core 和 Python 回归通过。
- `build/switch/pctc.nro` 存在。
- `build/switch/exefs.nsp` 存在。
- `build/packages/safe` 和 `build/packages/observe` 不包含 `boot2.flag`。
- `build/packages/safe-nro.zip` 包含 Companion NRO 且不包含 `boot2.flag`。
- `build/packages/disabled-boot2.zip` 和 `build/packages/observe-boot2.zip` 包含 sysmodule `exefs.nsp` 和 `boot2.flag`。

只有在本机已配置 devkitPro、`make` 和 Switch 工具链时，才使用本地模式：

```powershell
python .\tools\verify_devkitpro_build.py --local
```

需要显式指定 SSH 模式时，也可以使用：

```powershell
python .\tools\verify_devkitpro_build.py --ssh
```

构建并自动安装 `safe-nro.zip` 到 Eden 模拟器 SD 根目录：

```powershell
python .\tools\verify_devkitpro_build.py --install-safe-nro
```

默认会从远端拉取 `/ws/switch-play-time-control-local/build/packages/safe-nro.zip` 到本机 `build/downloads/safe-nro.zip`，并解压到：

```text
C:\Users\YeguoqiangTHPC\AppData\Roaming\eden\sdmc\
```

脚本会校验 `safe-nro.zip` 不包含 `boot2.flag`，解压后也会检查模拟器 SD 根目录没有本项目的 `atmosphere/contents/010000000000BD23/flags/boot2.flag` 残留。若需要指定其他模拟器 SD 根目录：

```powershell
python .\tools\verify_devkitpro_build.py --install-safe-nro --sdmc-root <sdmc-root>
```

如果只想远程构建 `safe-nro.zip`，可运行：

```sh
ssh 249-nintendo-switch-dev 'export DEVKITPRO=/opt/devkitpro; export DEVKITARM=/opt/devkitpro/devkitARM; export DEVKITA64=/opt/devkitpro/devkitA64; export PATH=$DEVKITA64/bin:$PATH; cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make package-safe-nro'
```

排查时也可以手工运行等价远程命令：

```sh
ssh 249-nintendo-switch-dev 'export DEVKITPRO=/opt/devkitpro; export DEVKITARM=/opt/devkitpro/devkitARM; export DEVKITA64=/opt/devkitpro/devkitA64; export PATH=$DEVKITA64/bin:$PATH; cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make && make companion-nro && make sysmodule-nsp && make package-safe package-observe package-safe-nro package-disabled-boot2 package-observe-boot2'
```

只验证 host C 和 Python 回归：

```sh
ssh 249-nintendo-switch-dev 'cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make'
```

远端完整验证覆盖：

- C host core 编译与测试。
- Python token / observe 回归。
- Companion NRO 构建，输出 `build/switch/pctc.nro`。
- Sysmodule NSP 构建，输出 `build/switch/exefs.nsp`。
- safe、observe、safe NRO、disabled boot2 和 observe boot2 package 生成。

package 安全规则：

- 默认 package 不包含 `boot2.flag`。
- 只有显式传入 sysmodule `exefs.nsp` 并指定 `--boot2` 时才生成 boot2 package。
- disabled/observe boot2 package 只是进入真机分阶段验证的输入，不能声明 boot2 自启、PCTL 写入、raw block 或 suspend 已验证。

## 3. 需要手动验证

### 3.1 模拟器辅助验证

Ryujinx/Eden 等 Switch 模拟器可在 Windows 10 上降低 Companion NRO 文件协议测试风险，但模拟器结论不能替代真机系统能力验证。

模拟器可验证：

- Companion NRO 是否启动。
- 输入、菜单、按键、软键盘和超时显示。
- request JSON 是否写入模拟器 SD 卡的 `switch/play-time-control/inbox/pending/`。
- 使用 `tools/make_result.py` 或 host `process-observe` 写出 result 后，NRO 是否读取并展示匹配 result。
- 家长区 UI 完成后，各操作是否写出预期 request type。

模拟器不可声明验证：

- Atmosphere boot2 sysmodule 自动启动。
- Nintendo PCTL IPC。
- play timer 真实读写。
- raw block。
- suspend。
- 真机恢复路径。

推荐模拟器流程：

1. 运行 `python .\tools\verify_devkitpro_build.py --install-safe-nro`，远程构建 `safe-nro.zip` 并解压到 Eden 模拟器 SD 根目录。
2. 如需手工排查，也可先远程构建 `safe-nro.zip`，再将 safe NRO package 解压或挂载到模拟器 SD 卡根目录。
3. 启动 Companion NRO。
4. 在 UI 中提交 `status` 或 `offline_code` request。
5. 用 `python .\tools\make_result.py --root C:\Users\YeguoqiangTHPC\AppData\Roaming\eden\sdmc` 生成匹配 result，或把同一 SDMC 目录交给 `protocol_probe.py process-observe` 处理。
6. 确认 NRO 展示匹配 result；没有 result 时应显示后端未响应或超时，而不是业务失败。

### 3.2 真实 Switch 分阶段验证

真实 Switch 测试必须从低风险到高风险推进，不要直接进入 `grant` 或 `enforce`。

阶段顺序：

1. Safe SDMC layout：只检查 SD 卡目录和配置，不安装 boot2。
2. NRO-only：只验证 Companion 读写文件协议，不安装 boot2。
3. Disabled boot2：验证 sysmodule 启动、日志和结构化 `disabled` result，不访问 PCTL。
4. Observe boot2：验证真实 sysmodule request 处理和 PCTL 只读路径，result 必须 `dry_run: true`，不消费 nonce。
5. Grant 最小写入：使用 1 分钟有效码，确认写入前备份、成功后消费 nonce。
6. Enforce：在 grant 稳定后验证开机启用或刷新 play timer。
7. Raw block / suspend probe：只在 grant/enforce 基础能力和恢复路径全部通过后单独验证。

真机前置条件：

- 真实 Nintendo Switch。
- Atmosphere CFW。
- 可写 SD 卡。
- Homebrew Menu。
- 已知恢复方式：能移除 `boot2.flag`，或能创建 `sdmc:/switch/play-time-control/flags/disable.flag`。
- 在强控制测试前，已经实测 `disable.flag` 行为。

当前能力边界：

- 当前真实 PCTL adapter 只使用 libnx 公开 API 读取 restriction 状态并生成备份文本。
- play timer 写入、raw block 和 suspend probe 在 raw layout 真机验证前返回稳定错误。
- disabled/observe boot2 package 已可远程构建，但 boot2 自启、真实 SDMC 持久化、PCTL 读状态仍需真机确认。

详细分阶段清单见 `docs/真机测试指南.md`。

## 4. 验收门槛

启用真实 PCTL 写入前：

- `python .\tools\verify_auto_tests.py` 通过。
- 远程 `make` 通过。
- disabled boot2 和 observe boot2 已在真机通过。
- `disable.flag` 恢复路径已实测。
- `observe` 验证有效码但不消费 nonce。
- 坏码路径从不消费 nonce。
- backup failure 阻止写入。
- capability gates 在 probe 前拒绝 raw block 和 suspend。

启用 `enforce` 前：

- `grant` 阶段已经通过真机最小写入测试。
- grant 拒绝用例在真实硬件通过。
- backup 文件可读且有恢复价值。
- event log 能记录成功和失败路径。

## 5. Fixture 要求

Fixture 应生成，不手写。

每个 fixture 应定义：

- case name。
- device id。
- grant secret。
- date 或 day index。
- nonce。
- minutes。
- expected token。
- expected result。

`tools/make_fixtures.py` 必须从与 `tools/grant_code.py` 相同的协议规则生成 deterministic fixture。
