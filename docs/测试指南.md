# 测试指南

项目只保留一个本地测试入口、一个远程打包入口和一次真机快速测试。协议拒绝路径、nonce、backup gate、PCTL 失败和恢复细节由自动测试覆盖，不再要求每次在真机逐项重做。

## 本地测试

Windows PowerShell：

```powershell
python .\tools\test.py
```

成功时只输出：

```text
PASS: local tests
```

该命令无第三方依赖，覆盖：

- token v1、observe queue、Web 辅助界面和远程打包工具回归。
- `protocol_probe` 的 init、离线码、observe 处理、result 和队列归档。
- observe 不消费 nonce。
- safe package 布局、默认 observe 和无 `boot2.flag`。
- 缺少 sysmodule 时禁止生成 boot2 package。

只有排查具体失败时才直接运行 `tests/` 下的单个脚本。

## 远程打包

涉及 C、Makefile、Companion NRO、sysmodule 或 package 的改动，先提交并推送 `master`，然后运行：

```powershell
python .\tools\package_remote.py
```

脚本通过一次 SSH 会话完成以下工作：

1. 宿主机仓库快进到 `origin/master`。
2. devkitPro 容器运行完整 C/Python 测试。
3. 构建 Companion NRO、sysmodule NSP 和全部 package。
4. 校验并下载五个 zip：`safe-nro`、`disabled-boot2`、`observe-boot2`、`grant-boot2`、`enforce-boot2`。
5. 将 zip 解压到同名目录。

Windows 默认输出目录：

```text
D:\switch\play-time-controll\download
```

需要其他目录时使用：

```powershell
python .\tools\package_remote.py --output <目录>
```

下载先写入临时目录。构建、传输或校验失败时，上一次成功下载的 package 保持不变。

## 图形界面验收

在模拟器或真机以 1280×720 检查以下内容：

- 孩子首页能显示今日状态、剩余时间、控制模式、计时器、就寝限制、临时解锁和最近反馈，且不暴露 request id、路径或原始 JSON。
- “今日管理、时间计划、安全工具”三页共 16 张操作卡完整可达，分别为 6、5、5 张，两列网格；`L/R` 切页、方向键选卡、`A` 执行、`B` 返回、`Y` 刷新。
- 触摸点按与手柄等价：标签页切页、卡片直接执行、弹窗确认取消、分钟加减、七日编辑器的星期与模式、就寝字段与增减、限制方式三选项。绘制与命中测试共用同一套控件几何，点击区域与显示控件一致。
- 今日管理页展示今日状态面板；安全工具页展示写入验证、效果验证、强制阻止和暂停软件四项能力状态。
- 点按“验证强制阻止”或“验证暂停软件”当前必然返回失败反馈，且不产生 `flags/disable.flag`。这可用于区分能力探针失败与快速设备测试失败。
- 分钟步进器、七日编辑器、就寝时间编辑器、限制方式三段选择器和全部确认弹窗没有文字越界、焦点不清或控件重叠。
- PIN 使用密码软键盘，离线码使用下载码软键盘；取消软键盘、编辑器或危险确认均不创建请求。
- 简体中文共享字体正常加载，所有中文无乱码；等待、成功、拒绝和超时状态不会引发布局跳动。
- 后台超时、坏授权码、缺少状态和快速设备测试失败均显示简短中文反馈；快速设备测试失败后存在 `flags/disable.flag`。
- 图形、共享字体或 FreeType 初始化失败时只显示最小中文恢复页，并可从该页退出。

模拟器可验证页面和请求流程，但共享字体兼容性、PCTL 效果及快速测试后的真实恢复仍以真机结果为准。

## 真机快速测试

日常真机验收只运行快速 PCTL effect probe，不再执行 A-F 阶段、拒绝用例矩阵、手工 1 分钟授权码或 enforce snapshot。

前置条件：

- 已掌握 SD 卡读写方式和官方家长控制 PIN/App。
- 知道如何创建 `sdmc:/switch/play-time-control/flags/disable.flag` 和移除 `boot2.flag`。
- 远程打包已通过。

操作：

1. 将最新 `grant-boot2-<timestamp>.zip` 解压到 SD 卡根目录并重启进入 Atmosphere。
2. 启动 Companion，进入“安全工具”，选择“快速设备测试”，阅读风险说明后按 `A` 二次确认。
3. 等待最近反馈显示“快速设备测试通过，设置已自动恢复”。

一次快速测试自动覆盖 request queue、真实 PCTL 会话、写前备份、目标写入、StartPlayTimer、运行时状态读取、能力持久化和原始设置恢复。PASS 必须同时满足：

- result 为 `probe_play_timer_effect`、写入模式、非 dry-run。
- `pctl_effect_probe.verdict` 为 `pass`。
- raw settings 和 timer enabled 状态均已恢复。
- `play_timer_write_verified` 与 `play_timer_effect_verified` 均已持久化。
- backup、`effect_before` 和 `effect_restore` 证据存在。
- `opaque_snapshots` 显示 active 只改变目标日期的分钟字段，restored 与 before 完全一致。
- 当天已有累计游玩时间时，快速探针仍应使用 1440 分钟或保留至少 1 分钟剩余的安全临时目标，不应短暂触发“限制时间到期”。

Layout v2 真机复测必须使用全新的 `grant-boot2` package。旧 `pctl-s-v1` / `pctl-s-runtime-v1` capability 会自动失效，不得手工改回 true。若 backup 的 slot 摘要不是 `h:...;d0:flag=...,enabled=...,m=...` 格式，说明仍在运行旧 sysmodule，应停止测试并重新安装 package。

失败、超时或自检不通过时，Companion 自动创建 `disable.flag` 并显示 `FAIL`。不要继续 grant、enforce、raw block 或 suspend；保留 result、logs、capabilities 和 backup 排障。

## 快速测试之后的功能验证

快速设备测试只证明底层写入被 PCTL runtime 采纳，不证明业务链路。确认快速测试通过后，按下面三个阶段依次验证，任一阶段不通过就停在该阶段排查，不要跳到下一阶段。

### 阶段 1：grant 模式基础功能

沿用已安装的 `grant-boot2` package，不需要换包。

前置条件：

- `capabilities.json` 中 `play_timer_write_verified` 与 `play_timer_effect_verified` 均为 `true`，且 backend 分别为 `pctl-s-v2` 与 `pctl-s-runtime-v2`。
- 不存在 `flags/disable.flag`。

操作与通过判据：

1. 家长区“今日管理”选择“设置今日额度”，设为一个明确值（例如 40 分钟）。result 为 `status: ok`、`dry_run: false`；`rules.json` 中 `today_override_present: true`、`today_override_minutes` 等于该值；主机系统设置或 Nintendo Parental Controls App 中当天限额同步变化。
2. 在 PC 生成离线加时码，当天使用可省略 `--date`：

   ```powershell
   python .\tools\grant_code.py --minutes 15 --device <device_id> --secret <grant_secret>
   ```

   `--device` 和 `--secret` 必须与 SD 卡 `config.json` 一致。在孩子首页按 `A` 或点按输入按钮录入该码。判据：`today_override_minutes` 变为 `40 + 15 = 55`，即在当日额度上**累加**而不是覆盖；官方界面同步；`ledger/used_nonces.jsonl` 追加一条记录。
3. 把同一个码再输入一次。必须被拒绝，错误 reason 为 `used_token`；`ledger/used_nonces.jsonl` 不再新增，`rules.json` 不变。
4. 生成一个 `--minutes` 大于 `config.json` 中 `max_add_minutes` 的码并输入。必须被拒绝，reason 为 `minutes_exceed_limit`，且不消费 nonce。
5. 生成一个 `--date` 为昨天的码并输入。必须被拒绝，reason 为 `wrong_date`。
6. 依次执行“临时加时”“今日不限”“恢复周计划”。三者 result 均为 ok；`rules.json` 中 `today_override_mode` 相应变为 `limit` 与 `unlimited`；执行“恢复周计划”后 `today_override_present` 变为 `false`。
7. 重启主机后再次查看孩子首页。今日额度与重启前一致，确认 SDMC 持久化生效。

失败处理：任一步 result 不为 ok 时，保留 `results/`、`logs/events.jsonl`、`logs/pctl_debug.jsonl` 和 `backups/`，按 reason 对照 `docs/协议.md` 的错误契约。出现 `pctl_write_not_verified` 或 `pctl_effect_not_verified` 说明对应 capability 已失效，需要重新运行快速设备测试。

### 阶段 2：不写 PCTL 的规则类功能

仍在 `grant` 模式。这些请求只更新本地规则，不经过 PCTL 写入路径，因此可用于区分故障出在 PCTL 层还是规则层。

操作：设置每周计划、设置就寝时间、限制方式选择“仅提醒”、执行“临时解锁”后再“结束解锁”。

通过判据：

- 全部返回 ok。
- `rules.json` 中 `week`、`bedtime_enabled`、`bedtime_start_min`、`bedtime_end_min`、`limit_action` 相应更新。
- `state.json` 中 `parent_unlock_until` 在解锁后为未来时间戳，结束解锁后回到 `0`。
- 解锁生效期间孩子首页显示“临时解锁：已开启”，结束后显示“未开启”。

当前能力边界，属于预期行为而不是缺陷：

- 限制方式选择“强制阻止”或“暂停软件”会被拒绝，reason 分别为 `raw_block_not_verified` 和 `suspend_not_verified`。
- “今日禁玩”会被拒绝，reason 为 `raw_block_not_verified`。该 gate 位于控制模式判断之前，因此在 `observe` 模式下同样拒绝。

这三项都需要 `platform/switch/pctl_adapter.c` 补齐真实探针实现，不是配置问题，也无法通过运行能力探针解锁。

### 阶段 3：enforce 模式自动对账

前置条件：阶段 1 和阶段 2 全部通过。将 `enforce-boot2` package 解压到 SD 卡根目录并重启。

操作与通过判据：

1. 启动后等待约 15 秒启动延迟加若干轮询周期。后台自动把当天规则写入 PCTL 并调用 `start_timer`，不需要提交任何 request。`logs/events.jsonl` 出现 `pctl_start_timer` 和 `state_persisted`；`state.json` 中 `last_enforced_day_index`、`last_enforced_mode`、`last_enforced_minutes` 被填入。
2. 保持不操作继续观察数分钟。去重生效，不应重复写入，`events.jsonl` 不再出现相同的 `pctl_start_timer`。
3. 在家长区修改今日额度。下一轮 tick 自动对账到新值，`last_enforced_minutes` 跟随更新。
4. 跨日验证：次日首次启动或跨过本地 0 点后，自动按新一天的周计划重新写入，`last_enforced_day_index` 递增。
5. 创建 `flags/disable.flag`。tick 立即停止对账，`events.jsonl` 无新增写入；删除该文件后恢复对账。

失败处理：出现重复写入或跨日不切换时，保留 `state.json` 与对应时间段的 `logs/events.jsonl` 片段。出现 `pctl_apply_failed` 时保留 `logs/pctl_debug.jsonl`。

## 恢复

按以下顺序处理：

1. Companion 家长区“安全工具”选择“紧急停用控制”，二次确认后创建 `disable.flag`。
2. Companion 无法启动时，从 SD 卡创建 `sdmc:/switch/play-time-control/flags/disable.flag`，然后重启。
3. 需要完全停止 boot2 时，删除 `sdmc:/atmosphere/contents/4200000000BD2300/flags/boot2.flag`，或安装 `disabled-boot2` 包。
4. 官方游玩时间限制或暂停软件已生效时，使用官方 PIN 或 Nintendo Parental Controls App 解除。

恢复期间不要删除 `backups/last_pctl_backup.txt`、`results/` 或 `logs/`。确认问题解决且目标模式正确后，才能在 Companion 的“安全工具”中选择“恢复控制”并二次确认删除 `disable.flag`。

## 能力边界

- 快速测试是日常真机权威入口，但不验证 raw block 或 suspend；两者继续受 capability gate 保护。
- 快速测试通过只解锁 play timer 限额写入路径，即离线加时码和今日额度类操作。`raw_block`、`suspend` 和 `block_today` 需要先在 `platform/switch/pctl_adapter.c` 补齐真实探针实现；当前运行“验证强制阻止”或“验证暂停软件”无法解锁这些能力。
- expiry probe 仅用于专项排障，不是普通验收项。
- `safe-nro` 和 `observe-boot2` 保留用于 UI 或只读专项排障，不属于日常流程。
- 请求字段、错误码和结果结构以 `docs/协议.md` 为准。
