# 测试指南

测试分为确定性 host 回归、devkitPro 容器构建和真机资格验证。标准分发构建的自动测试覆盖完整安全与恢复能力，但设备端不运行循环写入/回滚式 self-test。

## 本地回归

```text
python tools/test.py
```

通过标志为 `PASS: local tests`。该入口覆盖：

- token v1/v2、8 位码、日期、签名、replay、nonce 提交顺序和冷却；
- request/result schema、原子队列、IPC 去重、stuck request 恢复；
- setup 预检、snapshot、5 秒宽限、兼容状态和恢复优先级；
- 普通 PCTL 事务、失败注入、rollback、result/ledger 失败；
- Enforce 去重、`applied_pending_confirmation`、30 秒确认/回滚，以及活跃 recovery 与启动遗留事务的区分；
- PIN、规则、安装器数据保留和诊断脱敏；
- 标准安装包/完整交付包/Device Lab 契约隔离和 package helper 失败路径。
- `version.h`/`version.mk` 一致性，以及 PWA 官方链接和外链安全属性。
- 单文件离线版与模块化源码的一致性、内联 CSP、零运行时网络依赖、Web Crypto/内置 HMAC 固定向量和无持久存储降级。

测试必须使用固定时间、固定 fixture 和 host adapter，不依赖真实 Switch 服务。

## 权威容器验证

涉及 C、C++、Makefile、NRO、Overlay、sysmodule 或 package 时必须执行：

```text
python tools/package_remote.py
```

脚本在单次 SSH 会话中清理现有构建产物，运行 C host、UI 和 Python 回归，编译三个标准分发组件并生成标准安装包与完整交付包。

分发门禁断言：

- `build/packages/` 只有当前版本的标准安装包 `playwise-v<当前版本>.zip` 和完整交付包 `playwise-complete-v<当前版本>.zip`；
- 标准安装 Zip 只包含标准分发 sysmodule、NRO、Overlay、`boot2.flag` 及运行时目录，不包含安装器、离线网页或校验专用文件；
- 完整交付 Zip 只包含字节一致的当前版本标准安装包与 `playwise-offline.html`，拒绝缺失、重复、额外、路径穿越或内容不一致的成员；
- Zip 内 `build.json` 与构建阶段外部生成的 release manifest 完全一致，profile 为 `release`；
- 三个二进制都嵌入同一 manifest，NRO/Overlay 均显示当前构建版本；NRO 还必须嵌入项目仓库和 PWA 地址；
- 无 LAB handler、标准协议外请求、运行时控制模式、`capabilities.json` 或占位 secret；
- 不 seed `credentials.json`，首次启动必须生成唯一 secret；
- `tools/install_package_to_sd.ps1` 替换程序和 build manifest，但保留 credentials、PIN、rules、state、ledger、logs 和 backups；该脚本不打入运行时 Zip。

禁止用手工 SSH、`docker exec` 或复制回本地代替该入口。

## Device Lab 隔离验证

内部人员在 devkitPro 环境显式运行：

```sh
make device-lab-package
```

检查：

- 输出只在 `build/device-lab/`，不会出现在 `build/packages/`；
- Title ID 为 `4200000000BD23F0`，IPC 为 `pwtl:u`，SD 根目录为 `switch/playwise-device-lab`；
- manifest profile 为 `device-lab`；
- NRO 持续显示 DEVICE LAB 危险水印，操作要求 ZL+ZR+A；
- 包默认不含 `boot2.flag`；
- `make packages` 不会构建或携带任何 LAB 产物。

## UI 实机验收

修改 NRO 或 Overlay 后，至少验证：

- 主题专项：在家长区“加时码与安全 → 外观主题”分别选择“跟随系统 / 浅色 / 暗色”，确认立即完整重绘且重启后保留；配置写入失败时恢复原主题并提示。旧 `config.json` 缺少 `theme` 或值无效时按“跟随系统”处理，系统主题读取失败则安全回退浅色，不能阻止 NRO 启动或改变任何控制状态。“跟随系统”在启动和从 HOME 菜单恢复后重新读取系统设置。OLED Hybrid 暗色逐页覆盖孩子页、首次设置、家长页、错误页和全部弹层；正文/次文字至少 4.5:1，焦点/功能边框至少 3:1；成功、警告、危险和中性状态同时使用几何符号、颜色与文字；二维码保持白底黑码且可扫码。Overlay 继续使用自己的固定深色受限色板，不读取 NRO 的主题偏好。

1. 使用没有 `config.json` 向导字段的全新配置，确认首次设置按“快捷键 → PIN → 确认接管系统控制 → 可选自制程序菜单入口保护 → 选择区域”推进；中途退出后重启会恢复到已保存步骤，旧版步骤 `4` 会迁移到新版步骤 `5`，未完成前不允许普通写入。
2. 快捷键页固定显示 `Minus`，并提供 `L + R`、`ZL + ZR` 分别搭配四个方向键、`Plus`、`Minus` 在内的 14 项列表及“录制其他组合”。组合文案中的 `+` 只作为按键分隔符，例如必须显示 `L + R + Plus`，不得显示歧义形式 `L + R + Plus +`。选择/录制只更新草稿，按 `+` 确认后才生效；未确认或明确关闭时仅保留 `Minus`。首次快捷键页、区域选择摘要、孩子区页脚和家长区快捷键管理均须说明自定义组合需长按约 400ms，固定 `Minus` 松开即可进入且无需长按。分别真机验证 `L+R+下`、包含 `Plus` 和包含 `Minus` 的组合可长按约 400ms 触发，单独按下并松开 `Minus` 仍能进入，重启后状态不变。
3. PIN 覆盖 1 位、6 位、64 位、65 位、非数字、两次输入不一致，以及少于 4 位只提示风险；所有 PIN 入口的错误都使用最上层“重试 / 取消”弹窗，错误后清空当前输入，两次不一致时清空两次输入。冷却弹窗逐秒更新剩余秒数并禁用重试，取消不计失败。“修改任我玩PIN”必须先验证当前 PIN，取消、错误和冷却状态都不得进入新 PIN 覆盖流程。
4. 接管确认前只做只读预检；确认后验证安装 snapshot、解除当前限制、约 5 秒同步宽限，并在宽限结束后进入第 4 步。第 4 步分别验证启用成功、失败后重试和暂时跳过；成功后提示重启生效。对已有官方限时日，记录“总 180 分钟、已玩 60 分钟、剩余 120 分钟”向量：完成接管后必须仍剩余约 120 分钟（允许显示值相差 1 分钟），不得套用工作日默认 60 分钟；次日才切回 PlayWise 周计划。无法读取总额度且无法由已玩加剩余计算时必须返回 313、不得写 PCTL。
5. 第 5 步默认选中家长区，孩子区和家长区选项都显示简短切换说明；手柄或触摸选择区域后均不得立即进入，必须再触发独立的“确认进入家长区/孩子区”按钮。首次确认进入家长区不重复验证 PIN，之后从孩子区进入家长区需要 PIN。
6. 家长区“加时码与安全”页面存在“家长区快捷键管理”下级页，可选择/录制/关闭自定义组合，并显示孩子区提示开关和当前状态。关闭提示后孩子区不得显示固定 `Minus -`，也不得禁用任何已启用入口；右侧“加时码如何生成”不得再混入进入家长区或 PIN 说明。
7. 孩子首页以“自律小达人 · 加时奖励”和“遵守约定、合理安排时间”为标题；顶部的“系统计时器”与“运行状态”同列。加时码输入框默认以大字显示“输入加时码”，并显示护眼提醒；输入后以大字显示 8 位码。游戏时间统计在按游戏数据不可用时必须明确显示“游戏明细暂不可用”和真实的今日累计已玩时间，不得伪造前 3 名游戏排行；最近执行区域保持紧凑且不遮挡页脚操作。孩子区只使用 `B` 或触摸退出，`+` 不得作为退出快捷键，以免与家长区自定义组合冲突；图形初始化失败的备用界面可保留 `+` 退出。
8. 家长区只有今日额度、周计划、国家节假日、加时码与安全、支持与恢复五类页面；三个重构页仍须显示与其他家长页一致的完整“最近执行”卡，正文、触控区域、状态卡和页脚不得重叠。国家节假日页使用左侧 760px 控制区和右侧 384px 状态区，总开关关闭时仍可编辑并保存两套未启用预设；关闭状态保存后不得声称今天已应用节假日规则。唯一的保存按钮横跨左侧控制区；无修改和保存中均不可重复提交。日历使用当前草稿预览并标明尚未保存，切页、返回孩子区或退出前默认聚焦“继续编辑”，放弃后才丢弃草稿。方向键必须与二维布局一致，并提供按节日分组的内置安排分页查看；未覆盖年份不得显示伪造安排。孩子区完全不显示自制程序菜单入口保护状态或快捷键 `X`。
9. “支持与恢复”的六张卡始终显示；当前无需执行的“确认接管系统控制”和“重试修复”等操作使用禁用样式且不可触发，并解释禁用原因。右侧状态详情不得重复全局底栏的控制状态、系统限制和今日计时；系统版本、主机型号、Atmosphère 检测结果分行显示。最近三条事件不得与排障摘要重叠或被截掉，手柄和触摸均可打开详情；PIN 认证后的家长区详情可展示设备标识、路径、原始事件名、请求 ID、错误码与内部状态，但任何页面仍不得显示完整 `grant_secret`、PIN、令牌签名材料或其他可复用秘密。无事件和读取失败必须分别提示。第六张卡为“软件信息”；手柄和触摸均可打开只读弹层，显示 `PlayWise（任我玩）`、当前构建版本、`https://github.com/selfuppen/NX-PlayWise` 和 `https://selfuppen.github.io/NX-PlayWise/`，按 `A`、`B` 或触摸关闭按钮均可返回。不得显示内部 Device Lab 信息。
10. 手柄和触摸均可操作数字键盘、额度和周计划；弹窗输入不穿透。
11. 状态语言一致：绿色“正常运行”、蓝色“正在同步”、黄色“兼容性待确认”、橙色“保护模式”；红色表示需要家长关注且会阻止正常控制的状态。保护模式显示“安全保护已触发”，主动停用显示“紧急停用已开启”，两者可并列。
12. `disable.flag` 下孩子页和全部家长页持续显示红色停用状态；status、诊断导出、解除停用和恢复仍可用，额度、周计划和加时码写入在 UI 与后台均被拒绝。分别以 `restored + disable.flag` 和 `active + disable.flag` 验证支持页显示“解除停用并重新接管”；预检失败保留 phase 与 flag，成功后才删除 flag 并进入 5 秒宽限。
13. 家长区所有页面底栏显示独立的 `Y 刷新` 与全局状态摘要；前四个按钮宽度为 `130 / 130 / 170 / 130px`，右侧状态栏从 `x=662` 延伸至主内容右边界 `x=1226`，不得与按钮重叠。两者均可触摸或从正文底部按方向键到达。正常、未加载、过期和普通读取失败状态按 `A` 或触摸状态摘要会刷新；保护、停用、临时解除或恢复事务按 `A` 进入“支持与恢复”。家长主页面的 `Y` 始终只刷新，弹层中的 `Y` 保留输入清空等上下文语义，`L/R` 与 `B` 保持原导航语义。
14. 成功刷新超过 2 分钟后隐藏旧剩余分钟数并显示“状态待确认”；Nintendo 家长控制未启用、临时解除和读取不可用必须分别显示，不能把未知值显示成“否”。支持页不得再硬编码“到期行为：系统提醒”。
13. “导出诊断包”先提醒文件可能包含设备标识和文件路径，只应发送给可信支持人员；确认后的进行中、成功和失败状态均留在“支持与恢复”当前页，不得打开结果弹层。成功状态分三行完整显示导出路径、提交 GitHub Issue 时附加文件的说明和 `https://github.com/selfuppen/NX-PlayWise/issues`；离开支持页后清除。导出前刷新一次状态，确认 `runtime_snapshot` 包含 status 时间与年龄、计时/限制读数及其可用性、规则来源、紧急停用、活跃恢复事务、请求处理中和传输类型；未刷新时必须明确 `status_loaded:false`，不得把默认数字冒充实时读数。支持包中搜索 secret、PIN、已提交 8 位码、完整 nonce、私有 raw layout 和 recovery 原始内容均无匹配。
14. 进入/重新进入孩子页、切换到家长区“今日额度”页以及每个时间调整入口都会主动刷新状态；页面显示 UTC+8 日期、当前已玩、当前剩余、调整后可玩和“上次同步 X 秒/分钟前”。超过 30 秒应能明显看出数据可能过期；若真机已验证 PCTL 1952，则不限时也应显示独立已玩时间并允许后续状态判断；1952 不可用时才显示“暂不可用”，且依赖已玩时间的“临时加时”不可提交。
15. “设置今日额度”、周计划额度、法定休假日额度和调休工作日额度共用 `920×620` 紧凑分钟编辑框：左侧提供数字键盘与 ±5/±15，右侧用大号分钟值突出当前输入并显示对应信息；所有可见按钮支持手柄和触控且不得文字重叠。今日额度显示今天已玩、当前还能玩、修改后预计和刷新时间；周计划编辑今天时显示保存后预计，编辑其他星期时突出所选星期草稿额度并明确今天不受影响；节假日编辑显示规则类型、启用状态、今日命中或下一次对应安排，今日日期命中但预设未开启或被临时设置覆盖时不得误报为正在生效。编辑框打开时预选完整当前值，首次输入数字替换原值；今日额度完成后提交或进入安全确认，其余页面完成后只更新草稿。默认值优先使用当前有效限时规则总额度；规则不可得且已玩与剩余均可靠时使用两者之和并钳制到 1–1440；不限时或仍不可确定时使用 60。恢复周计划确认框使用并列状态卡突出“当前还能玩 / 恢复后还能玩”；不限时改限时使用状态卡突出“今天已玩 / 当前还能玩 / 修改后还能玩”。剩余 1–15 分钟使用黄色、0 分钟使用红色、不限时使用绿色，并始终保留文字标签。操作后为 0 或已玩不可用、无法判断是否立即限制时，触控不得绕过手柄长按 `A`；未知状态只说明无法判断，不得伪造立即限制结论。

## 资格验证

当前版本的资格验证基线：

- Nintendo Switch OLED；
- HOS 22.5.0；
- 资格测试环境 Atmosphère 1.11.2。

必须使用 `build/packages/` 中当前版本的标准安装包执行：

1. 在已启用官方时间限制的主机上安装并重启。
2. 确认首次只读预检完成，未确认前没有 PCTL 写入。
3. 创建一个自选长度的数字 PIN，确认自动生成的 secret 不等于任何公开占位值，确认一周规则。
4. 家长确认接管后，验证安装 snapshot、解除当前限制、5 秒同步和 Active 状态。
5. 分别测试 status、设置今日总额度、增加分钟、今日不限时、恢复周计划和周计划保存。
6. 使用一个由当前候选环境生成的 15 分钟 v2 加时码，确认 timer、剩余时间和 nonce 仅提交一次。
7. 制造一次状态传播延迟，确认显示“正在同步”；30 秒内确认成功或按契约回滚。
8. 重启验证 setup、rules、state、ledger 和未完成事务恢复。
9. 创建 `disable.flag`，确认只熔断写入；再验证诊断和安装快照恢复。
10. 恢复安装前 snapshot，确认原始 raw/timer 状态可被精确证明，并进入 `restored`。
11. 确认 `restored` 下首次设置第 3 步显示“解除停用并重新接管”；确认后必须先重新经过预检，成功时才解除 `disable.flag` 并在 5 秒宽限后进入 `active`，失败时必须保留停用标记和 `restored`，且安装 snapshot 不得被覆盖。
12. 制造一次 Enforce 状态传播延迟，确认 30 秒窗口内同一进程的 scheduler 不会把活跃 recovery 误判为启动遗留事务；随后在窗口内真实重启，确认遗留事务被恢复、创建 `disable.flag`，并可从 `active` 状态通过“解除停用并重新接管”安全恢复。

当前版本已于 2026-08-10 在上述环境完成资格验证；manifest 的 `verified_environment.result` 为 `verified`。

## 失败取证

优先从标准分发构建的支持页导出脱敏诊断。若 NRO 无法启动，保留：

- `build.json`、`setup.json`、`compatibility.json`、`environment.json`；
- `backups/install_pctl_snapshot.json`；
- `recovery/active/`；
- `results/`、`logs/` 和相关 crash report。

不要对外发送 `credentials.json`、`auth.json`、完整 ledger 或原始离线码。要停止自动启动，可移除 `atmosphere/contents/4200000000BD2300/flags/boot2.flag`。
