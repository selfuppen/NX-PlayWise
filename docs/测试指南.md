# 测试指南

测试分为确定性 host 回归、devkitPro 容器构建和真机资格验证。公开 Release 的自动测试保留完整安全与恢复能力，但设备端不运行循环写入/回滚式 self-test。

## 本地回归

```powershell
python .\tools\test.py
```

通过标志为 `PASS: local tests`。该入口覆盖：

- token v1/v2、8 位码、日期、签名、replay、nonce 提交顺序和冷却；
- request/result schema、原子队列、IPC 去重、stuck request 恢复；
- setup 预检、snapshot、5 秒宽限、兼容状态和恢复优先级；
- 普通 PCTL 事务、失败注入、rollback、result/ledger 失败；
- Enforce 去重、`applied_pending_confirmation`、30 秒确认/回滚；
- PIN、规则、安装器、升级保留和诊断脱敏；
- Release/Device Lab 契约隔离和 package helper 失败路径。

测试必须使用固定时间、固定 fixture 和 host adapter，不依赖真实 Switch 服务。

## 权威容器验证

涉及 C、C++、Makefile、NRO、Overlay、sysmodule 或 package 时必须执行：

```powershell
python .\tools\package_remote.py
```

脚本在单次 SSH 会话中清理旧产物，运行 C host、UI 和 Python 回归，编译三个 Release 组件并生成唯一公开 Zip。

发布门禁断言：

- `build/packages/` 只有 `playwise-0.1.2-alpha.zip`；
- Zip 包含 Release sysmodule、NRO、Overlay 和 `boot2.flag`；
- `build.json` 与安装 manifest 完全一致，profile 为 `release`；
- 三个二进制都嵌入同一 manifest，NRO/Overlay 显示版本均为 `0.1.2-alpha`；
- 无 LAB handler、旧请求、旧控制模式、`capabilities.json` 或占位 secret；
- 不 seed `credentials.json`，首次启动必须生成唯一 secret；
- 安装脚本升级时替换程序和 build manifest，但保留 credentials、PIN、rules、state、ledger、logs 和 backups。

禁止用手工 SSH、`docker exec` 或复制回本地代替该入口。

## Device Lab 隔离验证

内部人员在 devkitPro 环境显式运行：

```sh
make device-lab-package
```

检查：

- 输出只在 `build/device-lab/`，不会出现在 `build/packages/`；
- Title ID 为 `4200000000BD23F0`，IPC 为 `pwtl:u`，SD 根目录为 `switch/playwise-device-lab`；
- manifest profile 为 `device-lab`；
- NRO 持续显示 DEVICE LAB 危险水印，操作要求 ZL+ZR+A；
- 包默认不含 `boot2.flag`；
- `make packages` 不会构建或携带任何 LAB 产物。

## UI 实机验收

修改 NRO 或 Overlay 后，至少验证：

1. 使用没有 `config.json` 向导字段的全新配置，确认首次设置按“快捷键 → PIN → 确认接管系统控制 → 选择区域”推进；中途退出后重启会恢复到已保存步骤，未完成前不允许普通写入。
2. 快捷键页固定显示 `Minus -`，并提供 `L + R`、`ZL + ZR` 分别搭配四个方向键、`Plus +`、`Minus -` 在内的 14 项列表及“录制其他组合”。选择/录制只更新草稿，按 `+` 确认后才生效；未确认或明确关闭时仅保留 `Minus -`。分别真机验证 `L+R+下`、包含 `Plus +` 和包含 `Minus -` 的组合可长按约 400ms 触发，单独按下并松开 `Minus -` 仍能进入，重启后状态不变。
3. PIN 覆盖 1 位、64 位、65 位、非数字、两次输入不一致、少于 4 位只提示风险，以及旧 6 位兼容；“修改任我玩PIN”必须先验证当前 PIN，取消、错误和冷却状态都不得进入新 PIN 覆盖流程。
4. 接管确认前只做只读预检；确认后验证安装 snapshot、解除当前限制、约 5 秒同步宽限，并在宽限结束后进入第 4 步。若返回 306，页面必须显示“系统设置 → 家长控制 → 开启家长控制”和“重新检测”。
5. 第 4 步默认选中家长区，孩子区和家长区选项都显示简短切换说明；手柄或触摸选择区域后均不得立即进入，必须再触发独立的“确认进入家长区/孩子区”按钮。首次确认进入家长区不重复验证 PIN，之后从孩子区按 `Minus -` 或自定义组合进入家长区需要 PIN，家长区按 `B` 返回孩子区。
6. 家长区“加时码与安全”页面存在“家长区快捷键管理”下级页，可选择/录制/关闭自定义组合，并显示孩子区提示开关和当前状态。关闭提示后孩子区不得显示固定 `Minus -`，也不得禁用任何已启用入口；右侧“加时码如何生成”不得再混入进入家长区或 PIN 说明。
7. 孩子首页以“自律小达人 · 加时奖励”和“遵守约定、合理安排时间”为标题；顶部的“系统计时器”与“运行状态”同列。加时码输入框默认以大字显示“输入加时码”，并显示护眼提醒；输入后以大字显示 8 位码。游戏时间统计在按游戏数据不可用时必须明确显示“游戏明细暂不可用”和真实的今日累计已玩时间，不得伪造前 3 名游戏排行；最近执行区域保持紧凑且不遮挡页脚操作。
8. 家长区只有今日额度、周计划、加时码与安全、支持与恢复四类页面；周计划直接展示七日编辑器，没有功能卡或二级菜单，也没有探针、能力矩阵、后端或 raw layout 文案。
9. 手柄和触摸均可操作数字键盘、额度和周计划；弹窗输入不穿透。
10. 状态语言一致：绿色“正常运行”、蓝色“正在同步”、黄色“兼容性待确认”、橙色“保护模式”；红色表示需要家长关注且会阻止正常控制的状态。保护模式显示“安全保护已触发”，主动停用显示“紧急停用已开启”，两者可并列。
11. `disable.flag` 下孩子页和全部家长页持续显示红色停用状态；status、诊断导出、解除停用和恢复仍可用，额度、周计划和加时码写入在 UI 与后台均被拒绝。
12. 支持包中搜索 secret、PIN、已提交 8 位码和完整 nonce 均无匹配。
13. 进入/重新进入孩子页、切换到家长区“今日额度”页以及每个时间调整入口都会主动刷新状态；页面显示 UTC+8 日期、当前已玩、当前剩余、调整后可玩和“上次同步 X 秒/分钟前”。超过 30 秒应能明显看出数据可能过期；若真机已验证 PCTL 1952，则不限时也应显示独立已玩时间并允许后续状态判断；1952 不可用时才显示“暂不可用”，且依赖已玩时间的“临时加时”不可提交。
14. “今日额度”和“临时加时”页面不应有文字互相覆盖；大号分钟数同时显示小时/分钟换算，点击分钟数可进入数字输入，快捷调整提供 ±5/±15，并明确提示只影响今天。恢复周计划确认框的四行对比不得进入或覆盖确认区域。不限时改限时时突出已玩和修改后剩余；新额度小于或等于当前已玩时，必须用大号红字并排显示“已玩 / 还剩 0 分钟”和“保存后会马上限制儿童使用”，触控不能绕过手柄长按 `A`；已玩不可用时明确无法估算，不得显示无法证实的立即限制断言。
15. 周计划显示顺序固定为周一到周日，周六浅橙、周日浅红、今天使用更粗的当前日边框；整张限时卡可触摸并进入编辑，选中日期后 `A` 也可编辑。分钟输入页显示 `L/R ±5`、`ZL/ZR ±15`，页面按钮显示 `X` 切换模式与 `ZL` 放弃修改。主保存按钮带 `A` 标记，页脚不重复“保存计划”，`B 返回孩子页`位于第三格。`Y` 刷新并显示动态上次刷新时间；有草稿时提供“保存并刷新 / 放弃并刷新 / 继续编辑”，默认选中继续编辑，左右移动、`A` 确认，并保留 `+ / X / B` 直达键。保存计划不清除今日 override。
16. “加时码生成”首先显示占据主要区域的“扫二维码生成加时码”；“在本机生成 8 位码”进入独立下级页面，“更多设置”仍在主弹层展开。安全页右侧帮助框不得与最近执行框重叠，动作卡小字不得越界；显示密钥、二维码、导出配置和保存密钥均重新验证 PlayWise PIN，64 字符密钥必须在框内完整分行显示；演示密钥启用时持续显示红色警告，退出后生成新的 64 位随机密钥。
17. 扫码配对覆盖成功、缺少 fragment 参数、非法密钥、取消导入、已有配置覆盖，以及 `parent-import.json` 成功/失败路径都有确定性前端测试。
18. 二维码页提示收藏扫码后打开的地址，并明确说明拍照保存的二维码包含生成加时码的权限、需要保护相册；页面不得使用共享中文字体缺失的 emoji。
19. 本机生成器默认 20 分钟，左右用代码绘制的三角箭头提示上/下一合法档位，不得依赖 `‹`、`›` 等缺失字形；`L/R` 约 ±15、`ZL/ZR` 约 ±30，并全部吸附到合法且不超过设备上限的档位。未加载日期时拒绝生成，并排除当天 ledger 与本机已签发 nonce。
20. “更多设置”中保留导出配置、编辑跳转地址和恢复官方地址；二维码自定义地址覆盖 HTTPS、localhost/回环/私有 IP HTTP、path/query、恢复默认，以及 public HTTP、userinfo、控制字符、超长和已有 fragment 的拒绝路径。
21. PWA 离线页面包含配对、码无效、日期、设备无响应、紧急停用和高级诊断排错说明。
22. Overlay 提交前显示“当前还剩可玩”，兑换成功后改为“修改后可玩”；8 位输入槽与“已输入位数”之间至少留出一个完整小字号高度，触摸命中区域必须与上移后的键盘、提交栏和状态栏一致，展开状态栏不得超出可视区域。打开时自动读取状态；空闲时 `Y` 和顶部触摸按钮可刷新，刷新期间保留输入和上一次成功状态，成功后保持页面打开。刷新时间显示“刚刚刷新 / N 秒前”，30 秒后警示数据可能过期；不得用本地倒计时猜测剩余时间。status 成功不能按 `unlock_observed` 判为加时失败，错误态 `Y` 仍重试最近请求。

## 资格验证

`0.1.2-alpha` 的目标基线：

- Nintendo Switch OLED；
- HOS 22.5.0；
- 资格测试环境 Atmosphère 1.11.2。

必须使用最终 `build/packages/playwise-0.1.2-alpha.zip` 重新执行，旧包结果不能继承：

1. 在已启用官方时间限制的主机上安装并重启。
2. 确认首次只读预检完成，未确认前没有 PCTL 写入。
3. 创建一个自选长度的数字 PIN，确认自动生成的 secret 不等于任何公开占位值，确认一周规则。
4. 家长确认接管后，验证安装 snapshot、解除当前限制、5 秒同步和 Active 状态。
5. 分别测试 status、设置今日总额度、增加分钟、今日不限时、恢复周计划和周计划保存。
6. 使用一个最终生成的 15 分钟 v2 加时码，确认 timer、剩余时间和 nonce 仅提交一次。
7. 制造一次状态传播延迟，确认显示“正在同步”；30 秒内确认成功或按契约回滚。
8. 重启验证 setup、rules、state、ledger 和未完成事务恢复。
9. 创建 `disable.flag`，确认只熔断写入；再验证诊断和安装快照恢复。
10. 恢复安装前 snapshot，确认原始 raw/timer 状态可被精确证明，并进入 `restored`。
11. 确认 `restored` 下首次设置第 3 步显示“解除停用并重新接管”；确认后必须先重新经过预检，成功时才解除 `disable.flag` 并在 5 秒宽限后进入 `active`，失败时必须保留停用标记和 `restored`，且安装 snapshot 不得被覆盖。

截至 2026-08-07，最终 `0.1.2-alpha` 产物的上述真机资格验证仍待执行；manifest 必须保持 `requires-requalification-for-final-artifact`，不得宣称已发布验证。

## 失败取证

优先从 Release 支持页导出脱敏诊断。若 NRO 无法启动，保留：

- `build.json`、`setup.json`、`compatibility.json`、`environment.json`；
- `backups/install_pctl_snapshot.json`；
- `recovery/active/`；
- `results/`、`logs/` 和相关 crash report。

不要对外发送 `credentials.json`、`auth.json`、完整 ledger 或原始离线码。要停止自动启动，可移除 `atmosphere/contents/4200000000BD2300/flags/boot2.flag`。
