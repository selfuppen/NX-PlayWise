# 测试指南

测试分为确定性 host 回归、devkitPro 容器构建和真机资格验证。标准分发构建的自动测试覆盖完整安全与恢复能力，但设备端不运行循环写入/回滚式 self-test。

## 本地回归

```text
python tools/test.py
```

通过标志为 `PASS: local tests`。该入口覆盖：

- token v1/v2、8 位码、日期、签名、replay、nonce 提交顺序和冷却；
- request/result schema、原子队列、IPC 去重、stuck request 恢复；
- setup 预检、snapshot、5 秒宽限、兼容状态和恢复优先级；
- 普通 PCTL 事务、失败注入、rollback、result/ledger 失败；
- 日期计划 1/366 天边界、跨周/月/年、规则优先级和 7 天预览；每日自主缓冲的关闭/不限时拒绝、一次领取、换日、1440 截断，以及 PCTL/state/activity/result 失败回滚；
- 家庭活动最多 200 条、清空 result 失败回滚、活动写失败不消费离线码 nonce；每日摘要的可靠剩余、7/30 天唯一日期聚合、缺失不插值、未来/重复/乱序与时钟回拨；
- 独立只读统计 adapter 在证据门禁前固定 unavailable、保持本机范围且不产生伪造游戏条目；
- Enforce 去重、`applied_pending_confirmation`、30 秒确认/回滚、已耗时长超过恢复后周额度且 1455 已恢复 false 时按精确设置回读提交、306 错误结果真实运行时快照的 UI/诊断保留，以及活跃 recovery 与启动遗留事务的区分；
- PIN、规则、安装模板幂等初始化、直接覆盖升级的数据保留和诊断脱敏；
- 标准安装包/完整交付包/Device Lab 契约隔离和 package helper 失败路径。
- `version.h`/`version.mk` 一致性，以及 PWA 官方链接和外链安全属性。
- 单文件离线版与模块化源码的一致性、内联 CSP、零运行时网络依赖、Web Crypto/内置 HMAC 固定向量和无持久存储降级。

测试必须使用固定时间、固定 fixture 和 host adapter，不依赖真实 Switch 服务。

## 权威容器验证

涉及 C、C++、Makefile、NRO、Overlay、sysmodule 或 package 时必须执行：

```text
python tools/package_remote.py
```

脚本在单次 SSH 会话中清理现有构建产物，运行 C host、UI 和 Python 回归，编译三个标准分发组件并生成标准安装包与完整交付包。

分发门禁断言：

- `build/packages/` 只有当前版本的标准安装包 `playwise-v<当前版本>.zip` 和完整交付包 `playwise-complete-v<当前版本>.zip`；
- 标准安装 Zip 只包含标准分发 sysmodule、NRO、Overlay、`boot2.flag`、`build.json`、不可变 `defaults/*.json` 及空运行目录，不包含六个根目录可变 seed、安装器、离线网页或校验专用文件；
- Device Lab Zip 保留 `atmosphere/contents/4200000000BD23F0/flags/` 目录项但不包含 `boot2.flag`；首次长按切换必须在目录原先不存在时也能原子创建 Lab flag。模拟 `standard_disabled` journal、标准 flag 已暂存且 Lab flag 尚未创建的中断态时，Lab NRO 不连接 `pwtl:u`、可显示恢复页，标准 NRO 在自身 flag 缺失时也不连接 `pctc:u`；两者均不得黑屏。
- 完整交付 Zip 只包含字节一致的当前版本标准安装包与 `playwise-offline.html`，拒绝缺失、重复、额外、路径穿越或内容不一致的成员；
- Zip 内 `build.json` 与构建阶段外部生成的 release manifest 完全一致，profile 为 `release`；
- 三个二进制都嵌入同一 manifest，NRO/Overlay 均显示当前构建版本；NRO 还必须嵌入项目仓库和 PWA 地址；
- 无 LAB handler、标准协议外请求、运行时控制模式、`capabilities.json` 或占位 secret；
- 不 seed `credentials.json`，首次启动必须生成唯一 secret；缺失运行文件只从 `defaults/` 原子创建，已有文件即使无效也不得覆盖；
- 直接把新版安装包合并到已有目录以及使用 `tools/install_package_to_sd.ps1`，都必须替换程序和 build manifest，同时逐字节保留 credentials、PIN、rules、state、ledger、logs 和 backups；该脚本不打入运行时 Zip。

禁止用手工 SSH、`docker exec` 或复制回本地代替该入口。

## Device Lab 隔离验证

内部人员在 devkitPro 环境显式运行：

```sh
make device-lab-package
```

检查：

- 输出只在 `build/device-lab/`，不会出现在 `build/packages/`；
- Title ID 为 `4200000000BD23F0`，IPC 为 `pwtl:u`，SD 根目录为 `switch/playwise-device-lab`；
- manifest profile 为 `device-lab`；
- NRO 使用中文卡片式三步向导，根据 boot journal、Lab 服务、session 和报告自动推荐“启用实验后台”“继续浮窗取证”“恢复正常后台”或恢复处理；所有 boot flag 切换要求长按 ZL+ZR+A，恢复等待期间页面持续刷新；boot flag 切换有持久化 journal，重复执行幂等，冲突时不覆盖未知文件；host 测试还须模拟 Switch `rename` 不覆盖已有目标，以及旧 journal/完整 `.tmp` 并存、仅剩完整 `.tmp` 和未完整 `.tmp` 三种中断恢复；
- 首次打开 NRO 时，在 Lab boot flag 尚未启用的状态不得查询 `pwtl:u`，首屏必须可以立即绘制；Lab Overlay 从启动起固定使用持久化 SD 请求队列，不因实验后台尚未注册服务而阻塞；
- Overlay 使用固定深色中文页面，提供“聚焦限制复测”“Timer 激活 A/B（七阶段）”和“高级完整取证（六阶段）”；显示模式、阶段进度、下一动作、倒计时、自动结论、恢复状态和报告路径。普通操作、两层人工观察和恢复支持触摸，可能写入限制的阶段仍只接受实体手柄长按 A 两秒；非中文系统语言下也必须使用简体中文共享字体；
- Zip 同时包含 `switch/playwise-device-lab/playwise-device-lab.nro`、`switch/.overlays/playwise-device-lab.ovl`、Lab sysmodule 和 device-lab manifest；
- 包默认不含 `boot2.flag`；
- `make packages` 不会构建或携带任何 LAB 产物。

### 引导式真机取证

验收环境为 Nintendo Switch OLED、HOS 22.5.0、Atmosphère 1.11.2，并已安装 Tesla/Ultrahand。先在官方家长控制中配置当天正在生效的非空计划，确认剩余至少 10 分钟；准备两个允许短暂中断、没有未保存进度的非关键游戏：

1. 安装 Device Lab Zip，运行 `playwise-device-lab.nro`。确认首页自动显示“准备启用实验后台”，长按 `ZL+ZR+A` 一秒。NRO 会先通过 `pm:shell` 只读确认源进程；安全交接可用时直接零重启进入 Lab，不可用时自动准备 boot flag 并只要求重启一次。若提示冲突或中断，只按页面引导恢复，不要手工覆盖 flag/backup。
2. 从 Tesla/Ultrahand 打开 `playwise-device-lab.ovl`。默认选择“资格批次”，用左右键确认并记录官方“时间到了暂停软件”的原始开关状态。自由聚焦、Timer 激活 A/B 和高级完整取证仍可单独选择。批次开始后 Overlay 显示四项进度、匿名游戏 A/B、下一动作、倒计时、判定/恢复状态和报告路径；按 `Minus` 可展开英文机器值、请求 ID 与错误码。
3. 聚焦模式直接进入 `restriction_effect`。完整模式才依次完成 `home_stopped`、`home_started`、`game_foreground`、`game_suspended`、`sleep_wake`，每个普通阶段自动采样 75 秒；若原始 0x44 全零，界面和报告会提示第 3–5 阶段前提不足，不得据此声称生命周期已验证。完整生命周期复测应先配置非空的 Nintendo 周计划。
4. 在安全游戏中进入“观察时间限制效果”，确认无未保存进度后使用实体手柄长按 `A` 两秒；触摸只能看到安全提示，不能开始该阶段。关闭 Overlay，观察约 15 秒内是否出现时间限制提示，以及游戏实际是继续、暂停/挂起还是退出；后台会自行恢复，不要求 Overlay 保持打开。随后必须重新打开 Overlay，先记录提示可见性，再单独记录游戏实际行为。等待人工观察时不显示“立即恢复”，从 NRO 进入也只会提示返回 Overlay。
5. 只有 Overlay 显示 `exact_restore_proved` 才算恢复得到证明。若显示 `restore_required`，立即按 `A` 重试恢复；Lab `disable.flag` 会阻止任何后续取证写入。
6. 人工观察完成前只会生成 `lab/report-<run-id>.draft.json`。每项 final 且 `exact_restore_proved` 后直接选择“继续下一项”；结果与槽位预期不符时报告仍保留，但批次停在原槽位等待重试。四项依次为 Timer A/B、暂停开启的游戏 A、暂停开启的游戏 B、暂停关闭且继续运行的游戏 B。完成后恢复批次开始时记录的官方暂停开关，并保留四份 accepted 报告及 `reports/<campaign-id>.campaign.json`。关闭 Overlay、睡眠或提前退出不会丢失进度；放弃只归档，不删除证据。最后从 NRO 恢复正常后台：热切换成功时无需重启，回退路径只在末尾再重启一次，并验证标准 PlayWise 正常读写。

A/B 模式开始前必须在 Nintendo 官方家长控制中配置非空且正在生效的周计划，并确认至少 10 分钟剩余。HOME 保持亮屏至少 90 秒；待机至少 90 秒，唤醒后立即重新打开 Overlay。随后按顺序执行限时、限制后加时和限制后不限时的 settings-only 目标；只有当前目标未达到运行条件时，后台才重新确认同一目标、调用一次 `1451` 并复读。报告按目标保存前置状态、settings-only 结果、是否调用 fallback、调用前后读数和不能判断原因；不得把相关性写成“settings-only 启动了计时器”等因果结论。无法排除唤醒后的亮屏时间时，待机结论必须为 `inconclusive`。

另覆盖 SD 挂载或目录创建失败、`pm:shell` 不可用、源进程拒绝退出、NRO 中断、目标启动失败、runtime-ready 陈旧或身份不匹配、恢复请求超时、报告不存在、结果码失败、`session.json` 损坏、v1/v2 journal 各中断点和未知 flag/backup 冲突。每个故障注入都必须断言未启动第二个 PCTL owner；无法证明热切换时应进入整批最多两次重启的回退，且已完成报告和 `campaign.json` 不丢失。

新报告必须为 `schema_version:2`（并保留 `version:2`），应包含当前模式所需阶段的 `1453/1454/1455/1952` 原始纳秒/布尔值与 Result、阶段前后完整 `0x44` hex/hash、`1006/1031/1035/1457/1458` raw/libnx 对照及 `comparable`、目标绑定 fallback、限制事件辅助证据、实际 environment/build 身份和逐字节恢复证明；聚焦/完整模式另含两层人工观察。0x44 变化分别列出实现预期头部、当日和意外 offset。任一 raw/libnx 调用失败时不得输出为相等；新 HOME 结论使用事实性的 `home_usage_counted`，`unsafe_for_home_start` 仅解析旧 JSON。完整模式全零基线即使最终发布报告，也必须同时给出 `complete=true` 与 `lifecycle_evidence_complete=false`，不得再输出误导性的 `activation_evidence_complete=true`。1457 不参与完整性、提示可见性或产品资格，结果也不得自动提升 `1952`、暂停、退出或禁玩为标准能力。schema v1 只保留为历史证据，资格工具必须拒绝用它晋级。

## Eden 模拟器快速测试

只想在 Eden 里快速看 UI 和业务流程时，在 devkitPro 环境显式运行：

```sh
make eden-test-nro
```

产物为 `build/eden-test/pctc-eden.nro`。Eden 只需加载该单个 NRO，不需要预先铺开安装包：首次运行会在 `sdmc:/switch/playwise-eden` 自行创建独立测试数据（含 `build.json`、`defaults` 之外的六个运行文件、固定测试 `credentials.json` 和假 `environment.json`），并在 NRO 进程内用模拟 PCTL 运行真实的 `sysmodule_core`。Eden 的 Windows 虚拟 SD 不保证跨目录 `rename` 的队列语义，因此该 profile 通过进程内 IPC 桥同步提交请求并照常持久化 result JSON；PIN 等模态界面不会阻塞处理，`status` 和 `complete_setup` 都会及时返回。真实 SD 原子队列仍由 host 测试和真机路径覆盖。

固定测试参数：设备 ID `eden-switch`，grant secret `playwise-eden-test-secret-00000001`。生成可兑换的加时码：

```sh
python tools/grant_code.py --tier-minutes 30 --device eden-switch --secret playwise-eden-test-secret-00000001
```

界面持续显示红色 `EDEN TEST` 角标，传输行固定显示"传输：Eden 模拟后台"。测试状态跨启动保留；需要重新走首次设置时只删除 `sdmc:/switch/playwise-eden`，不得删除或覆盖 `sdmc:/switch/playwise`。

该入口只覆盖初始化、PIN、页面导航、规则、离线码、nonce 和恢复流程；**不作为真实 PCTL 私有命令、0x44 layout 或计时效果的证据，也不替代真机资格验证。** Overlay 需要 Tesla，Eden 无法加载，因此浮窗仍只能在真机验证。

隔离断言：产物只在 `build/eden-test/`，`make packages` 与 `make device-lab-package` 均不构建也不携带该目标；`python tools/package_remote.py` 无条件扫描标准分发与 Device Lab 二进制，拒绝任何 Eden marker。需要顺带构建并校验该 NRO 时使用 `python tools/package_remote.py --with-eden`；不加该开关时默认构建的命令、耗时和产物集合完全不变。

## UI 实机验收

修改 NRO 或 Overlay 后，至少验证：

- 主题专项：在家长区“设置 → 外观主题”分别选择“跟随系统 / 浅色 / 暗色”，确认立即完整重绘且重启后保留；配置写入失败时恢复原主题并提示。旧 `config.json` 缺少 `theme` 或值无效时按“跟随系统”处理，系统主题读取失败则安全回退浅色，不能阻止 NRO 启动或改变任何控制状态。“跟随系统”在启动和从 HOME 菜单恢复后重新读取系统设置。OLED Hybrid 暗色逐页覆盖孩子页、首次设置、家长页、错误页和全部弹层；正文/次文字至少 4.5:1，焦点/功能边框至少 3:1；成功、警告、危险和中性状态同时使用几何符号、颜色与文字；二维码保持白底黑码且可扫码。Overlay 继续使用自己的固定深色受限色板，不读取 NRO 的主题偏好。

## PDM 与 Bedtime 证据门禁

按游戏统计发布前，独立只读 `pdm:qry` 实验必须对应用启动、前后台和退出事件执行 HOME、游戏前台、挂起、待机、换日、手工改时钟、多账号和未知软件 A/B。报告需证明事件去重、乱序、缺失和时钟回拨的降级语义，并明确统计为本机使用；证据不足时 Release adapter 保持 unavailable，不能显示今日/七日 Top 3。整个实验不能调用 PCTL `1952`，不能写 rules/state 或改变控制状态。

Bedtime 只允许在 Device Lab 中验证每周各日单个跨夜窗口。发布门禁必须证明到点限制真实可见、普通加时码在窗口内不兑换也不消费、次日规则与余额正确、重启继续生效，并覆盖 HOME、游戏前台、挂起、待机和跨日恢复。raw block 或恢复任一项不能逐字节证明时，标准包不得出现 bedtime 字段、请求或 UI，禁止用 0 分钟规则代替。

## 资格验证

当前候选唯一资格目标：

- Nintendo Switch OLED；
- HOS 22.5.0；
- 资格测试环境 Atmosphère 1.11.2。

候选构建、SD 准备、报告验证和原包晋级的权威命令为：

```powershell
python tools/test.py
python tools/package_remote.py
.\tools\prepare_device_lab_sd.ps1 -SourceFolder .\build\packages -Drive E -WipeAll
.\tools\prepare_device_lab_sd.ps1 -SourceFolder .\build\packages -Drive E -WipeAll -Apply
python tools/verify_device_qualification.py `
  --packages .\build\packages `
  --reports .\device-reports `
  --expected-model oled `

python tools/promote_qualified_build.py `
  --packages .\build\packages `
  --verification .\build\qualification\verification.json `

```

SD 脚本默认只预演；`-Apply` 前必须核对盘符和主机备份目录。Device Lab 资格输入是一个完整 campaign：Timer A/B、游戏 A 暂停开启、游戏 B 暂停开启、游戏 B 暂停关闭且继续运行。工具只有发现一个完整批次时才自动选择；多个批次必须增加 `--campaign <campaign-id>`。失败尝试和自由会话不会混入 accepted 集合；`hot_switch` 与 `reboot` 均可通过，但每份报告必须记录实际方式。任一 accepted 报告缺失人工观察、环境来源/版本、公开命令对照、目标绑定 fallback、意外 offset 检查或 `exact_restore_proved` 都会失败。晋级工具只复制验证时计算哈希的原 Zip，不重新编译。

随后必须使用同一标准安装包执行：

1. 在已启用官方时间限制的主机上安装并重启。
2. 确认首次只读预检完成，未确认前没有 PCTL 写入。
3. 创建一个自选长度的数字 PIN，确认自动生成的 secret 不等于任何公开占位值，确认一周规则。
4. 家长确认接管后，验证安装 snapshot、解除当前限制、5 秒同步和 Active 状态。
5. 分别测试 status、设置今日总额度、增加分钟、今日不限时、恢复周计划和周计划保存；另在额度已耗约 745 分钟时恢复 60 分钟周计划，确认系统限制出现后即使 1455 不再保持 true，请求仍成功、当天设置保持 60 分钟且不会回滚到原临时额度。随后从 Nintendo 系统临时解除限制，确认状态仍为限时 60 分钟、额度剩余 0，临时解除和计时器未计时单独展示；进入睡眠并唤醒后确认临时解除消失、原限制继续生效，期间不得出现新的 PlayWise `pctl_apply`。
6. 使用一个由当前候选环境生成的 15 分钟 v2 加时码，确认 timer、剩余时间和 nonce 仅提交一次。
7. 制造一次状态传播延迟，确认显示“正在同步”；30 秒内确认成功或按契约回滚。
8. 重启验证 setup、rules、state、ledger 和未完成事务恢复。
9. 创建 `disable.flag`，确认只熔断写入；再验证诊断和安装快照恢复。
10. 恢复安装前 snapshot，确认原始 raw/timer 状态可被精确证明，并进入 `restored`。
11. 确认 `restored` 下首次设置第 3 步显示“解除停用并重新接管”；确认后必须先重新经过预检，成功时才解除 `disable.flag` 并在 5 秒宽限后进入 `active`，失败时必须保留停用标记和 `restored`，且安装 snapshot 不得被覆盖。
12. 制造一次 Enforce 状态传播延迟，确认 30 秒窗口内同一进程的 scheduler 不会把活跃 recovery 误判为启动遗留事务；随后在窗口内真实重启，确认遗留事务被恢复、创建 `disable.flag`，并可从 `active` 状态通过“解除停用并重新接管”安全恢复。
13. 设置次日为 60 分钟限时，在当天结束前让主机停留 HOME 后进入待机；次日保持屏幕和游戏未打开至少 90 分钟。确认 `pctl_debug.jsonl` 只有 Enforce 的 `apply_target`，没有 `stage:"start_timer"`，唤醒后 1454 剩余时间没有因后台跨日同步而减少，界面也不得显示虚假的 60 分钟额度消耗。
14. 分别记录 HOME、系统设置、游戏前台、游戏挂起、待机和唤醒后的 1454/1952 A/B。确认 HOME、系统设置等亮屏使用按 Nintendo 官方主机使用语义累计，待机期间不累计，唤醒后恢复累计；不得再要求“进入真实游戏才开始计时”或“返回 HOME 不消耗”。若候选环境不能满足此项，不得把它标为新的资格基线。
15. 配置跨周、跨月和跨年的日期计划，逐日核对 7 天预览及“今日临时设置 > 日期计划 > 国家节假日 > 周计划”；重启后规则不丢失，计划结束首日恢复下级来源。
16. 在限时日通过手柄和触摸各领取一次自主缓冲，核对第二次拒绝、换日恢复和 1440 分钟截断；在 PCTL 写入、SD 状态保存和 result 提交失败的注入包中确认资格与 PCTL 前像均恢复。
17. 在浅/暗主题中检查家庭活动翻页与清空、7/30 天可靠天数、孩子区今天/明天来源和中性文案；随后覆盖 HOME、前台、挂起、待机和换日，确认统计失败或文件损坏不影响时间控制。

2026-08-10 的结论是早于当前 PCTL 改动的历史证据，不能资格化当前候选。所有新 manifest 的 `verified_environment.result` 和 `qualification.status` 默认均为 `pending`；只有来源于无 tracked 修改 commit 且哈希匹配的 `build/qualified/qualification.json` 才表示该原包已通过。

## 失败取证

优先从标准分发构建的支持页导出脱敏诊断。若 NRO 无法启动，保留：

- `build.json`、`setup.json`、`compatibility.json`、`environment.json`；
- `backups/install_pctl_snapshot.json`；
- `recovery/active/`；
- `results/`、`logs/` 和相关 crash report。
- Overlay 或 NRO 显示 SD 传输时，检查当日 `logs/YYYY-MM-DD/ipc-client.log`；确认记录包含 `client`、`stage`、`rc`、`module`、`description`、`version` 和 `expected`，相同连接失败不会随每次刷新重复写入，且日志中不含请求正文、PIN、密钥或 8 位码。Overlay 进程启动后再提交一次状态刷新，正常连接必须记录 `client=overlay stage=connected`（此前发生过连接失败时）并在界面显示“传输：IPC”；退出并重新打开 Overlay 后重复验证，排除 SM 会话只在初始化阶段短暂有效。

不要对外发送 `credentials.json`、`auth.json`、完整 ledger 或原始离线码。要停止自动启动，可移除 `atmosphere/contents/4200000000BD2300/flags/boot2.flag`。
