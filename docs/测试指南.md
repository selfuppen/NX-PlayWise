# 测试指南

本项目使用一个本地测试入口、一个容器构建入口和按改动范围触发的真机验收。自动测试覆盖协议、队列、nonce、setup、恢复事务和 package；真机只证明目标 HOS 上的 PCTL 运行时行为和输入链路。

## 本地回归

```powershell
python .\tools\test.py
```

成功输出 `PASS: local tests`。该入口覆盖：

- token v1/v2、UTC+8 日期、replay、nonce 提交顺序和 v2 冷却。
- request/result schema、队列原子性、IPC 去重和 stuck processing 恢复。
- setup 状态机、前置解除失败回滚、60 秒激活宽限和恢复 flag 优先级。
- 普通 PCTL 写入事务、运行时确认、result/nonce 失败回滚和启动崩溃恢复。
- Enforce 去重、rules/state、raw block/suspend 门禁。
- PWA、单包布局、更新保留数据和安装脚本安全规则。

普通 play-timer capability 探针矩阵、observe 全路径、五包矩阵、一键基础测试 self-check 和重复 UI 卡片数量断言不再属于测试范围。

## 容器构建与 Package

涉及 C、Makefile、Companion NRO、Overlay、sysmodule 或 package 的改动，运行：

```powershell
python .\tools\package_remote.py
```

脚本通过一次 SSH 会话清理旧产物、运行 C/Python 测试、构建三类二进制，并只生成 `playwise-<timestamp>.zip`。

| 检查 | 判据 |
| --- | --- |
| 单包 | 只存在一个最新 playwise zip |
| 完整布局 | 包含 sysmodule、NRO、Overlay 和 `boot2.flag` |
| 初始配置 | `control_mode=enforce`，`setup.json.phase=pending` |
| 更新保留 | 安装脚本不删除 `switch/playwise`，保留 secret、PIN、rules、state、ledger、日志和备份 |
| 旧产物 | 构建前清理，失败时不留下伪完整产物 |

容器直接读取未提交工作区。不要绕过该入口维护旁路 SSH、`docker exec` 或复制构建命令。

## 图形界面验收

- 首次启动优先显示 setup 页面，展示 phase、限制是否解除、snapshot 是否可用和激活时间。
- 家长安全页包含启用自动控制、重试前置解限、恢复安装前状态、紧急停用、raw block 探针和 suspend 探针。
- 不显示一键基础测试或普通 write/effect capability。
- 孩子页、PIN、8 位码、分钟、周计划、bedtime、限制方式、确认弹窗和触摸/手柄输入无重叠。
- 传输状态区分 IPC、SD 队列、IPC accepted 后 SD result 回读，以及本地 SD flag。
- setup/recovery 错误显示稳定 code/reason，且错误结果不清除最近一次有效状态。

## 新设备或 HOS/PCTL 变化

每个设备/HOS 组合只需完成一次：

1. 先让主机处于当前受限状态，安装唯一 package 并重启。
2. 不使用 Nintendo 官方解锁，确认 Companion 可启动，setup 显示 snapshot 可用且限制已解除。
3. 设置或验证 PIN，点击“启用自动控制”，等待 60 秒进入 `active`。
4. 使用一个 15 分钟 v2 码，确认真实额度变化、timer enabled、restricted false 和 nonce 只提交一次。
5. 重启，确认 setup、规则、额度和 ledger 持久化。
6. 首次额外创建一次 `flags/restore_install_snapshot.flag`，确认原始 raw settings 与 timer 状态恢复，setup 为 `restored` 且 `disable.flag` 存在。

任一步失败时保留 setup、安装 snapshot、result 和当天日志，不继续 Enforce 或高风险探针。

## 按改动范围验收

普通代码回归默认不做真机测试。

| 改动范围 | 追加真机场景 |
| --- | --- |
| PCTL layout/status/write/restore | 前置解除或普通写入事务对应单项 |
| setup/boot lifecycle | 受限安装、重试解除、60 秒激活或启动崩溃恢复 |
| Companion/Overlay 输入 | 对应输入链路；Overlay 变更再测官方硬限制弹窗 |
| Enforce/rules/bedtime | 去重、规则变化、跨日或 bedtime 单项 |
| raw block | 独立 raw block 探针及精确恢复 |
| suspend | 独立 suspend 探针 |

## 高风险能力

`raw_block` 探针临时写入 0 分钟 restricted 目标，观察受限后恢复完整 0x44 snapshot 和 timer。PASS 要求 raw target、运行时阻止、raw 恢复和 timer 恢复全部成立；恢复失败必须清除能力并创建 `disable.flag`。

`suspend` 探针只验证 Horizon 暂停请求通道，成功后保存 `pctl-s-suspend-v1` backend。两项能力都不进入基础安装流程，只在相关功能开发或发布时专项验证。

## 恢复与取证

恢复优先级：

1. `restore_install_snapshot.flag`
2. `retry_setup_release.flag`
3. 启动时未完成 `recovery/active/meta.json`
4. `disable.flag`
5. 普通请求和 Enforce

无法进入 Companion 时可直接在 SD 卡创建恢复 flag。完全停止 boot2 时删除 Atmosphere 内容目录下的 `boot2.flag`。

保留 `setup.json`、`backups/install_pctl_snapshot.json`、未完成时的 `recovery/active/`、对应 result、当天日志和 `capabilities.json`。

sysmodule 崩溃报告位于 `sdmc:/atmosphere/crash_reports/<tick>_4200000000bd2300.log`。结合 `sysmodule/build/pctc-sysmodule.map` 和当天日志定位。
