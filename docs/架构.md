# 架构

项目分为四层，用来隔离高风险 Switch 行为，并让大部分逻辑可以在桌面 host 环境测试。

## 第一层：Common Core

Common core 是纯 C 逻辑。

职责：

- 16 字符 token 编码、解码。
- HMAC-SHA256 20-bit 截断校验。
- day index 和 weekday 计算。
- bedtime 跨天判断。
- request/result schema 常量。
- 错误码、reason 和中文 message 映射。
- 规则引擎。
- 控制策略。
- nonce 消费时机判断。

Common core 不得：

- include libnx 头文件。
- 读写文件。
- 知道 SD 卡路径。
- 调真实 PCTL IPC。
- 渲染 UI。
- 直接依赖真实当前时间。

当前已实现：

- `common/token/token_v1.c`
- `common/protocol/error_code.c`
- `common/protocol/result_builder.c`
- `common/time/ptc_time.c`
- `common/rules/rules.c`
- `common/policy/control_policy.c`

## 第二层：Platform Adapters

平台层用 C vtable 隔离环境相关操作。

所需 adapter：

- Storage：read、atomic write、append、rename、remove、exists、metadata、完整目录遍历和安全目录删除。
- PCTL：read status、backup、apply target、start timer、stop timer、probe raw block、probe suspend。
- Time：向编排层提供 Unix time、day index 和 minute of day。
- Logging：写人类日志和结构化 event。

Host 测试替身：

- `mem_storage`
- `pctl_stub`
- fake time provider

真实 Switch 实现应只替换 adapter，不改变 common core 或策略逻辑。

## 第三层：Sysmodule Orchestration

Sysmodule 编排层连接文件协议、common core 决策、平台 adapter 和 result 写入。

职责：

- boot 后初始化服务。
- 加载 config、rules、state 和 capabilities。
- 启动时恢复 stuck `processing` request。
- 推动 request 的 pending -> processing -> done 状态迁移。
- 调 token verifier 和 control policy。
- PCTL 写入前创建 backup。
- 写 event 和 result。

当前 `sysmodule/sysmodule_core.c` 已实现 host-testable 编排核心，包括 request queue、status、offline_code、backup gate、grant nonce ledger 和 stuck processing 恢复。真实 boot2 lifecycle、SDMC adapter 和 libnx PCTL adapter 仍需后续补齐。

## 第四层：Companion UI 与 Tesla Overlay

Companion UI 是 request queue 的前台客户端，不是安全边界。

职责：

- 显示当前状态和最近 result。
- 接收孩子输入的离线码。
- 使用本地 PIN 保护家长区。
- 提交家长区管理 request。
- 等待 matching result id。
- 超时显示“后台未响应”，不能当作业务失败。
- `companion/result_summary.*` 提供 NRO 与 overlay 共用的 `PtcCompanionResultSummary`，统一解释 status、dry-run、错误、剩余分钟、计时器和限制状态。
- `companion/overlay/` 输出 `pctc.ovl`。它使用方向键和 A/X/Y/Plus/B 输入 16 个 Crockford Base32 符号；方向键支持按住连续移动，界面固定显示 16 个输入槽、当前输入位置、高对比键盘焦点和可用状态明确的 Plus 提交按钮。当前版本不处理触摸输入，不调用 `swkbdShow()`，不直接访问 PCTL，也不持有 `grant_secret`。
- 官方硬限制弹窗没有第三方扩展点；Tesla 是否能在该弹窗之上显示并接收输入是 HOS/Atmosphere/nx-ovlloader 组合的真机验收门槛，不属于 host 测试可以证明的性质。

### Companion NRO、Tesla Overlay 与 Sysmodule 的关系

Companion NRO 和 Tesla Overlay 是两个彼此独立、地位相同的前台客户端。两者使用 `PtcCompanionTransportClient`，在 Switch 上优先走 `pctc:u` IPC；桌面工具保留 `PtcCompanionFileClient`。

```text
Companion NRO ─┐             ┌─ persist inbox/pending ─┐
               ├─ pctc:u ────┤                        ├─ worker ─> PCTL
Tesla Overlay ─┘             └─ completion Event/result┘
Desktop tools ───── SD file queue ──────────────────────┘
```

Tesla Overlay 输入离线码后的运行时链路为：

1. Overlay 在本地输入模型中收集 16 个 Crockford Base32 符号，格式化为 `XXXX-XXXX-XXXX-XXXX`。
2. Overlay 生成 request id 并优先用 IPC 提交；服务端持久化成功后返回完成 Event。IPC 不可用时才写入文件队列。
3. IPC 路径只等待 Event 并调用一次 `GetResult`；文件 fallback 按 250ms、500ms、1s 退避读取 result。
4. 常驻 sysmodule 扫描队列，将请求从 `pending` rename 到 `processing` 取得处理权，解析请求并执行 token、模式、能力、备份和 PCTL 流程，最后将原请求移到 `done`。
5. Overlay 校验 result schema 和 request id，只在 `offline_code` 返回 `status: "ok"`、`dry_run: false`、`play_timer_enabled: 1` 且 `restricted_now: 0` 时认为真实解锁已经观察到；随后显示剩余时间并自动关闭。`observe` 的成功 result 仍是演练，不能显示为已解锁。

安全边界始终在 sysmodule：只有 sysmodule 读取 `grant_secret`、验证 token、检查 nonce 和调用 PCTL。Overlay 只持有孩子刚输入的码及对应 request id；普通 Companion NRO 虽然还提供家长区功能，但提交离线码时走的是完全相同的后台路径。

边界：

- Companion PIN 只保护本项目家长区，不是 Switch 系统级 PIN。
- Atmosphere 不提供替代 Nintendo 家长控制 PIN 的通用解锁入口；官方临时解除仍依赖 Horizon 系统的家长控制 PIN 或 Nintendo Parental Controls App。
- 相册中的 Companion NRO 不是到时后的可靠入口。部署 boot2 包时同时安装 `switch/.overlays/pctc.ovl`，但 nx-ovlloader 与 Tesla Menu 由用户按当前 Atmosphere/HOS 版本另行安装；若 Tesla 热键在官方弹窗中不可达，停止本方案并使用官方 PIN/App 或外部 SD request。

当前 `companion/request_client.c` 已提供 request JSON 构建函数，`companion/file_protocol.c` 保留桌面文件协议；`companion/transport_client.c` 封装 IPC 优先与 fallback。家长区界面和完整规则编辑仍待实现。

Sysmodule worker 使用 wake Event 与超时驱动。文件扫描空闲时按 500ms、1s、2s、5s 退避；enforce 只在 UTC+8 分钟边界、reload 或显式唤醒时对账。目标未变化时不访问 PCTL、不写 state、不增长成功日志。

## 控制模式

`disabled`：

- 拒绝请求。
- 不读 PCTL。
- 不写 PCTL。

`observe`：

- 可读取状态。
- 验证请求并计算预期结果。
- 不写 PCTL。
- 不消费 nonce。
- result 标记 `dry_run: true`。

`grant`：

- 允许有效离线加时和家长区操作写 PCTL。
- 写入前要求 backup。
- 只有成功写入并持久化 result 后才消费 nonce。

`enforce`：

- 包含 `grant` 能力。
- 可启用或刷新 play timer。
- capability gate 通过后可执行 bedtime/suspend 等强控制行为。

## 高风险 Capability Gate

Raw block 和 suspend 纳入 v1 架构，但默认 gate。

执行条件：

- control mode 允许该操作。
- `capabilities.json` 标记对应 capability 已验证。
- backup 成功。
- PCTL adapter 成功。

Host tests 只能验证 gating 逻辑，真实能力验证必须在硬件上完成。
