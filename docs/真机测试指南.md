# 真机测试指南

真机测试必须分阶段进行，不要直接跳到 `enforce`。

## 前置条件

- 真实 Nintendo Switch 硬件。
- Atmosphere CFW。
- 可写 SD 卡。
- 用于启动 companion NRO 的 Homebrew Menu。
- sysmodule 行为异常时有已知恢复路径。
- 在强控制测试前，已经验证 `disable.flag` 行为。

## 当前边界

当前仓库已有最小 companion NRO 源码和构建目标，但仍没有 boot2 sysmodule 二进制、sysmodule 侧真实 SDMC adapter 或真实 PCTL adapter。因此现阶段不要把 SD 卡 package 当成完整可运行包；safe NRO package 只能验证前台 NRO 与 `sdmc:/switch/play-time-control/` 文件协议。

构建和 package 生成默认通过 SSH 远程 devkitPro 容器执行。本地改动必须先提交并推送到 `master`，再让远程仓库快进拉取：

```sh
ssh 249-nintendo-switch-dev 'export DEVKITPRO=/opt/devkitpro; export DEVKITARM=/opt/devkitpro/devkitARM; export DEVKITA64=/opt/devkitpro/devkitA64; export PATH=$DEVKITA64/bin:$PATH; cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make && make package-safe package-observe package-safe-nro'
```

阶段 A/B 使用远端生成的 `build/packages/safe.zip` 或 `build/packages/safe-nro.zip` 作为 SD 卡输入。

以下能力还不能通过当前 package 验证：

- boot2 sysmodule 是否真实启动。
- PCTL 读取或写入。
- play timer 行为。
- raw block。
- suspend。

## 阶段 A：Safe SDMC 目录布局

目标：

- 只验证 SD 卡根目录解压后的文件布局正确。
- 不安装 boot2，不触碰 PCTL。

命令必须按所在环境选择。Windows host / PowerShell 使用反引号 `` ` `` 续行和 `.\` 路径；remote devkitPro / bash 使用反斜杠 `\` 续行、`./` 路径和 `python3`。

Windows host / PowerShell：

```powershell
python .\tools\package_sdmc.py `
  --mode safe `
  --device-id kid-switch `
  --grant-secret replace-with-long-random-secret `
  --max-add-minutes 120 `
  --out .\build\packages\safe `
  --zip .\build\packages\safe.zip
```

remote devkitPro / bash：

```sh
python3 ./tools/package_sdmc.py \
  --mode safe \
  --device-id kid-switch \
  --grant-secret replace-with-long-random-secret \
  --max-add-minutes 120 \
  --out ./build/packages/safe \
  --zip ./build/packages/safe.zip
```

手动操作：

1. 将 `build\packages\safe.zip` 解压到 SD 卡根目录。
2. 确认 SD 卡上存在 `sdmc:/switch/play-time-control/config.json`。
3. 确认 SD 卡上存在 `inbox/pending/`、`inbox/processing/`、`inbox/done/`、`results/`、`logs/`、`ledger/`、`backups/`、`flags/`。
4. 确认没有 `sdmc:/atmosphere/contents/010000000000BD23/flags/boot2.flag`。
5. 打开 `config.json`，确认 `control_mode` 为 `observe`。

通过标准：

- 目录结构完整。
- safe 包没有 Atmosphere boot2 自动启动项。
- `config.json` 中的 `device_id`、`grant_secret`、`max_add_minutes` 与生成命令一致。

## 阶段 B：Companion NRO 文件协议

目标：

- 在有 companion NRO 后验证 UI 能读写同一套 SDMC 文件协议。
- 仍然不安装 boot2，不验证 PCTL。

在 companion NRO 可用后生成带 NRO 的 safe zip。推荐使用远程 devkitPro 容器直接生成 `safe-nro.zip`：

```sh
ssh 249-nintendo-switch-dev 'export DEVKITPRO=/opt/devkitpro; export DEVKITARM=/opt/devkitpro/devkitARM; export DEVKITA64=/opt/devkitpro/devkitA64; export PATH=$DEVKITA64/bin:$PATH; cd /ws/switch-play-time-control-local && git pull --ff-only origin master && make package-safe-nro'
```

没有真实 `.nro` 文件时不要执行本段，停在阶段 A。

Windows host / PowerShell：

```powershell
$nro = ".\build\switch\pctc.nro"
if (-not (Test-Path $nro)) { throw "missing NRO: update `$nro to the real companion .nro path" }

python .\tools\package_sdmc.py `
  --mode safe `
  --out .\build\packages\safe-nro `
  --zip .\build\packages\safe-nro.zip `
  --nro $nro
```

remote devkitPro / bash：

```sh
make companion-nro

NRO=./build/switch/pctc.nro
test -f "$NRO" || { echo "missing NRO: update NRO to the real companion .nro path"; exit 1; }

python3 ./tools/package_sdmc.py \
  --mode safe \
  --out ./build/packages/safe-nro \
  --zip ./build/packages/safe-nro.zip \
  --nro "$NRO"
```

也可以直接使用快捷目标：

```sh
make package-safe-nro
```

手动操作：

1. 将 `safe-nro.zip` 解压到 SD 卡根目录。
2. 从 Homebrew Menu 启动 `switch/play-time-control/` 下的 NRO。
3. 在 UI 中提交 status 请求。
4. 确认 `sdmc:/switch/play-time-control/inbox/pending/` 出现 request JSON。
5. 手工放入匹配 result，或把 SD 卡目录复制回 PC 后用 host `process-observe` 处理，再放回 SD 卡。
6. 确认 companion 能显示匹配 result；没有 result 时应显示后端未响应或超时，而不是业务失败。

通过标准：

- Companion 可以启动。
- Companion 可以写入 request。
- Companion 可以读取匹配 result。
- 未安装 boot2 sysmodule。

## 阶段 C：Disabled / Observe Boot2

目标：

- 只有在 sysmodule 二进制、日志路径和恢复路径都准备好后，才验证 boot2。
- 先跑 `disabled`，再跑 `observe`。

必须先满足：

- 已有真实 sysmodule `exefs.nsp`。
- 已有可用恢复方式：能移除 `boot2.flag`，或能创建 `sdmc:/switch/play-time-control/flags/disable.flag`。
- 已经完成阶段 A；如果涉及 UI，也已经完成阶段 B。

生成 disabled boot2 包：

Windows host / PowerShell：

```powershell
python .\tools\package_sdmc.py `
  --mode disabled `
  --out .\build\packages\disabled-boot2 `
  --zip .\build\packages\disabled-boot2.zip `
  --sysmodule-exefs .\path\to\exefs.nsp `
  --toolbox .\path\to\toolbox.json `
  --boot2
```

remote devkitPro / bash：

```sh
python3 ./tools/package_sdmc.py \
  --mode disabled \
  --out ./build/packages/disabled-boot2 \
  --zip ./build/packages/disabled-boot2.zip \
  --sysmodule-exefs ./path/to/exefs.nsp \
  --toolbox ./path/to/toolbox.json \
  --boot2
```

手动操作：

1. 解压 `disabled-boot2.zip` 到 SD 卡根目录。
2. 启动或重启进入 Atmosphere。
3. 检查 `sdmc:/switch/play-time-control/logs/` 下是否有 sysmodule 日志。
4. 提交一个 request。
5. 确认 result reason 为 `disabled`。

通过标准：

- sysmodule 能启动并写日志。
- request 能得到结构化 disabled result。
- 不读取、不写入 PCTL。

disabled 阶段通过后，才生成 observe boot2 包：

Windows host / PowerShell：

```powershell
python .\tools\package_sdmc.py `
  --mode observe `
  --out .\build\packages\observe-boot2 `
  --zip .\build\packages\observe-boot2.zip `
  --sysmodule-exefs .\path\to\exefs.nsp `
  --toolbox .\path\to\toolbox.json `
  --boot2
```

remote devkitPro / bash：

```sh
python3 ./tools/package_sdmc.py \
  --mode observe \
  --out ./build/packages/observe-boot2 \
  --zip ./build/packages/observe-boot2.zip \
  --sysmodule-exefs ./path/to/exefs.nsp \
  --toolbox ./path/to/toolbox.json \
  --boot2
```

observe 手动操作：

1. 解压 `observe-boot2.zip` 到 SD 卡根目录。
2. 启动或重启进入 Atmosphere。
3. 生成当天有效离线码。
4. 通过 companion 或 request 文件提交 `offline_code`。
5. 检查 `results/<request_id>.json`。
6. 检查日志和 ledger。

observe 通过标准：

- result 包含 `status: "ok"`。
- result 包含 `mode: "observe"`。
- result 包含 `dry_run: true`。
- 不写入 PCTL。
- 不消费 nonce。
- PCTL 读取失败时也必须返回结构化 result。

## 阶段 D：Grant / Enforce / Raw Block / Suspend

目标：

- 在真实 PCTL adapter、备份文件和失败路径全部通过后，再开放写入和强控制能力。

进入本阶段前必须满足：

- C host tests 全部通过。
- disabled boot2 和 observe boot2 已在真机通过。
- `disable.flag` 恢复路径已实测。
- 写入前 backup 可读且有恢复价值。
- PCTL 写失败、backup 失败、坏 token、重复 token 都不会消费 nonce。

Grant 最小写入通过标准：

- 使用 1 分钟的有效加时代码。
- 写入前创建 backup 文件。
- 今日限制按预期变化。
- Result 为成功。
- 成功后消费 nonce。
- Event log 记录本次写入。

Grant 拒绝用例：

- 重复代码。
- 错误日期。
- 错误 secret。
- 加时时长超过上限。
- Unlimited guard。
- Backup failure，如果可测试。

拒绝用例通过标准：

- 写出稳定 error result。
- PCTL 目标保持不变。
- 除非原始成功 grant 已消费 nonce，否则不消费 nonce。

Weekly、Bedtime、Parent Unlock 通过标准：

- Weekly template 会应用预期的今日目标。
- Bedtime state 在预期时间变化。
- Parent unlock 可以开始、结束和过期。
- Event log 记录状态转换。

Enforce 通过标准：

- Enforce 按设计启动或刷新 play timer。
- 写入仍然要求 backup。
- Results 保持结构化。
- `disable.flag` 仍会强制 fail-open。

Raw Block 与 Suspend Probe 规则：

- 仅在 grant/enforce 基础能力全部通过后运行。
- 每次只运行一种能力。
- 保持恢复路径可用。
- 记录人工观察结果。

Raw Block 与 Suspend Probe 通过标准：

- Probe result 被记录到日志。
- 只有成功验证后，capability 才能标记为 true。
- Probe 前普通 raw block/suspend 请求会被拒绝，probe 后才允许。
