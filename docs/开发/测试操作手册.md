# 测试操作手册

本手册只维护可复用步骤，具体候选、批次进度及后续安排放在所属任务的阶段文档中。详细安全边界以[真机稳定探测方法](真机稳定探测方法.md)、[无人值守更新与测试指南](无人值守更新与测试指南.md)、[标准采集](PCTL1952标准采集.md)和[协议](../设计/协议.md)为准。历史脚本留作审计，不是可直接重放的日常入口。

## 选择最小验证层

功能的分层责任和去重依据见[分层测试策略](分层测试策略.md)；发版前最小端到端集合见[Eden主流程场景](Eden主流程场景.md)。入口烟测7项与核心主流程集合分别报告。

| 改动／问题 | 首选验证 | 能支持的结论 |
| --- | --- | --- |
| 文档分类、链接、只读索引 | 文件清单完整性、相对链接、前后哈希 | 目录完整和引用可达，无新硬件结论 |
| Python、协议工具、报告 | 确定性成功／失败fixture，CLI及完整Python回归 | 软件行为；首次和重复离线核验须一致 |
| C／NRO／Overlay／package | 统一devkitPro入口，保留默认Eden NRO构建／校验，不启动模拟器 | C及产物门禁；Eden不证明真实PCTL |
| 日常NRO页面、交互与本地业务流程 | Host边界／失败回归和按需UI预览 | 确定性软件行为；不执行Eden场景或稳定性回归 |
| 发版前交互与本地业务验收 | 候选身份固定后，执行一批Eden最小回归及受变更影响的场景 | 模拟环境中的交互、回执和持久化；不覆盖真实IPC／SD队列、Overlay或系统限制 |
| 实际控制、计数或恢复 | 冻结生产候选、标准raw、原队列回执、完整恢复 | 指定候选／环境／场景的真机结论 |
| 真正可见、可继续使用、休眠和底座 | 对应实体动作及集中观察，独立于机器断言 | 对应画面／实物效果，不能自动推广 |

日常基础测试不运行Eden；交互和本地业务的模拟器回归只在发版前集中执行。名称含Eden的Host单元测试没有启动模拟器，仍保留在日常入口。发版前默认一批最小回归及受变更影响的场景，不固定重复多批稳定性探测；有独立稳定性验证目标时再制定有界计划。真机操作集中到系统服务、实际阻断／解除、Overlay与生命周期。Eden的范围、场景和证据要求见[测试指南](测试指南.md#eden-模拟器快速测试)；不因已有模拟结果省略受改动影响的真机集成或资格检查。分别记录NRO构建／校验、模拟器启动和场景断言结果，统一构建不会自动启动Eden。

Windows回归显式使用UTF-8，避免主进程正常、子进程中文解码失败：

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONIOENCODING = 'utf-8'
python -X utf8 tools/test.py
if ($LASTEXITCODE -ne 0) { throw 'Python regression failed' }
python -X utf8 tools/package_remote.py --port 18881 --docker-container playwise-explain-build
if ($LASTEXITCODE -ne 0) { throw 'Unified build failed' }
```

统一构建仅在本批涉及C或产物验证时执行；上述端口／容器为维护者profile，按现场覆盖。普通门禁不得加 `--skip-tests` 或关闭Eden；正式交付才按需要使用 `--release`。命令失败后不继续提交、部署或签署，PowerShell分号不会自动实现该停止条件。

## 一批测试的执行步骤

1. **固定问题和通过条件**。写出已证事实、真实缺口、变更影响、适用候选／环境、最少阶段和预期拒绝。只因版本变化不必重做全部旧实验；也不能把旧结果直接改成新候选通过。
2. **冻结可核验材料**。核对clean源码、实际Zip／NSP／NRO／Overlay／Eden哈希、manifest与runtime；前像包括规则、完整0x44／timer、启动项和恢复材料。当前不需要的新服务不初始化。
3. **准备有界计划**。使用全新目录和run；租期覆盖导航／交接、使用窗口、逐段恢复、拉回和余量。租期从设备进程启动加载，不是Host脚本启动计时；运行中改配置不能续租。先检查是否能复用现有稳定进程，再考虑已验证同候选安全交接，避免无意义更新和反复整机重启。
4. **集中必要的人为步骤**。只提出本批确实需要的PIN、真实休眠／底座或观察。已有正常PIN和导航授权按原范围使用；凭据仅内存隐藏输入，不放命令、环境、源码、摘要或日志。不用自动任务代替用户尚未给出的时间窗口。
5. **先确认导航，再进入危险窗口**。必要的只读页面预检绑定前台、boot、截图哈希和短时效；过期只刷新只读预检，不重放已开始事务。远程输入使用 `bounded_input_batch.py` 限时限次，收尾释放并detach；输入失败不靠重复按键碰运气。
6. **队列请求只发布一次**。UUID和完整请求先保存，再提交；只等同ID/type回执。成功、明确拒绝和未知分别处理。超时不是失败，不能换ID重发或猜回滚；明确重复领取拒绝测试使用另一个有意的业务请求，不能冒充原请求网络重试。
7. **采集以设备证据为准**。保留Unix、本地day、run／boot、tick、完整0x44、各Result、1952及带符号1454。实际使用窗口必须达到设备端点时长；Host等60秒可能只跨57秒。跨boot不相减tick，原始跨界／失败行保留，不修成成功零。
8. **逐段恢复，不等人工答复**。每个危险窗口即时恢复策略和应恢复的完整设置／timer。只有本批拥有的标记可以归档；未知写入先查现场。真实消费、已领取缓冲、nonce、账本和活动继续保留，不能回写旧state以伪造“完全恢复”。
9. **证明停采和健康收尾**。归档本批配置，间隔大于采样周期两次拉回相等，检查stop计数、保存失败、队列、fatal/crash、身份、候选清单中的全部安装文件及规则。区分“SD原像恢复”和“当前进程已加载原像”，不能只验文件就声称运行恢复。
10. **离线核验两次，再封存和提交**。先跑业务与恢复断言，JSON写入后再从磁盘读回比较；7／30日等键在schema中统一使用字符串。输出独占创建、失败不覆盖；两次相同后保存逐文件索引。封存后发现派生核验缺陷，另建补充目录修正并绑定原哈希，不改旧raw、截图或封存脚本。每批核验通过再提交。

## 常见误判与本轮经验

| 易错点 | 正确处理 |
| --- | --- |
| 不限时也用1440来“让计数工作” | 新v2目标真正不限时，累计独立来自1952；错误读数保持unknown |
| 用额度减钳制余额反算真实已用 | 只有可信限额才交叉校验，保留负余额；不限时、BLOCKED和业务额度分开 |
| 自动休息结束后两个端点必须完全相等 | 按真实期限扣除恢复后的可用后缀；使用契约规定的配对容差，不拿全受限区间或固定Host等待代替 |
| timer=false就认定不限时不应增长 | 按真实目标和直接累计判断；Host覆盖不等于timer=false硬件已测 |
| 真休眠也要求timer全程不变 | 保留实际timer生命周期与同期累计，分别核对休眠排除、唤醒增长和前后恢复；不能用全程常量断言抹去有效观测，也不能把timer=false单独当作真实休眠证明 |
| 规则恢复就清掉正常领取／消费 | 策略恢复与正常业务痕迹分开，资格和nonce不得回退 |
| 7／30日一样就认为窗口完整 | 当前样本可能都在7日内；仍需窗口边缘和完整全天的独立证据 |
| 逐日取整再求和／混加v1与v2 | 直接累计先求纳秒和再取整；旧估算与直接来源各算各的，未知不补零 |
| 刷新请求让旧历史变“刚刚采集” | 保留captured_at；observed_at和本次完成时间另记，不刷新历史可靠下界的原时间 |
| 把旧日加时汇总当作今日增量基数 | 先核对`summary_day_index`与实际采样日；比较本次授权增量时，旧日汇总的今日有效基数为0，原值和所属日继续保留，不能回写state或把历史样本改成0 |
| 第一遍报告成功就能重复跑 | JSON整数键会变字符串；必须验证序列化往返及重复输出不变，再封存 |
| Shell中核验失败仍继续commit | 显式检查退出码；构建、核验、变更和提交按依赖顺序执行 |
| 错误回执`restricted_now=-1`被转成true或当作当前限制事实 | -1是未知；使用成功状态/同期标准raw核对上下文，保留配对时钟精度，不用错误回执补造真实状态 |
| 把孩子页可用时间快照120秒门槛套给Overlay家长动作 | 分别核对候选源码契约；Overlay普通家长动作状态达30秒即要求刷新，完整安装快照恢复另有豁免。预先验证导航，在单次动作前取得同实例新状态；刷新不代替正常PIN，也不延续已消费的一次授权 |
| 危险窗口内等待代理逐张读图导致租期耗尽 | 先在健康状态证明必要导航；有界脚本执行与即时恢复，画面最后集中确认，超时按原停止条件收尾 |
| 恢复回执成功或第一条timer样本就宣称完整恢复 | 保留原始端点，预留有限只读复查预算；完整0x44/timer与规则核对通过才宣称恢复。早期不一致不能用额外计时写入掩盖，原收尾失败与后续独立收尾分别记录 |
| 正确PIN后认证计数未变就认定已拒绝 | 认证记录不变也可能是没有进入PIN页或未提交。先证明实际输入页、提交前提和结果提示，再区分拒绝、未执行与未知；导航失败停止依赖输入，文件名及按键发送成功不能替代页面回执 |
| 正数`time()`就当作Unix时间写共享期限 | Overlay的未初始化libc时钟可能是uptime；跨客户端认证等持久化期限须统一时钟域并核对。页面投影修复不代表PIN调用也已修复；发现不一致先停止，不只修改脚本接受该数字或直接清计数 |

## 机器结论与人工结论分开

截图默认只用pixelPeek，采集失败单记且不阻塞可靠读数。按阶段／时间／SHA整理HTML，几批之后一次集中复核必要画面，回复保存在独立人工目录并绑定原图及机器索引。机器restricted=false不证明提示已消失，半透明过渡图不证明完全恢复；导航所需的少量代理读图也不能代替用户最终效果确认。

受限阶段保留原生提示后，按[稳定探测方法](真机稳定探测方法.md#画面最后统一确认)有界打开PlayWise Overlay，补拍当前限制原因；并发及原因交接分别留图。先核实当前快捷键和导航健康，打开失败停止输入并记录缺口，不重复碰运气、不延迟恢复。查看原因不附带任何业务操作，截图仍只用pixelPeek。

用户主动指出具体画廊并确认时，直接保存该原话，逐项绑定该版画廊索引和全部所含原图，不再重复提问或逐张重读。先复核封存附件未变，再新增独立人工记录，更新所属批次的待确认项；原机器报告中的manual=null保持原始状态。后续新增画面、候选变化或确认范围不足时，另列对应缺口，不将一次确认外推为所有UI入口或完整资格。

报告统一区分“通过／部分证明／未执行／前提不满足／恢复未证实”；软件回归、旧能力、标准候选短链、人工可见性和完整资格是不同层次。不用大量复选框或文档提交数量代替真正缺口盘点。

## 可复制的批次计划

```text
问题与变更影响：
已证事实／本批缺口：
候选commit、release、三组件及Zip哈希：
环境、run、源boot、日期：
阶段与每阶段通过／拒绝条件：
租期、动作数、失败上限、恢复余量：
原规则／0x44／timer／启动项前像：
最小人为步骤及集中观察项：
各请求原UUID／内容／回执位置：
未知事务／fatal／恢复不明时停止规则：
实际端点、原raw及恢复／停采断言：
两次离线核验、附件索引、人工待确认项：
正常业务痕迹保留及最终现场：
```

工具按[tools分类](../../tools/README.md)选择。临时脚本／日志属于独立 `build/<批次>/`；若封存报告依赖脚本，则它已是证据的一部分，不能当临时垃圾删除。通用能力经回归后才能沉淀进 `tools/`，避免把某一次设备身份、绝对路径、PIN或一次性run写成公共默认流程。
