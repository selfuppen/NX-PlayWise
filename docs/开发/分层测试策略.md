# 分层测试策略与覆盖分工

[开发入口](README.md) · [测试操作手册](测试操作手册.md) · [主流程场景](Eden主流程场景.md)

测试按“规则正确 → 组件接通 → 产物可交付 → 用户任务完成 → 真机效果成立”逐层收敛。下层覆盖枚举、边界和故障，上层只验证跨边界的代表性旅程。通过数量、截图数量和重复批次数不能当作功能覆盖率；没有覆盖率采集时不报告代码覆盖百分比。

## 各层负责什么

| 层 | 目标与现有入口 | 保留的断言 | 不向上重复的内容 |
| --- | --- | --- | --- |
| L1 确定性单元／组件 | `tests/c/test_host_core.c`、`test_control_safety.c`、`test_ui_state.c`；Python／前端固定向量 | token、四级额度优先级、纳秒累计、时钟、nonce、边界、UI投影与命中 | 不在Eden枚举512个nonce、所有分钟值、日期组合或错误码 |
| L2 Host集成与故障 | `tests/nro_setup/test.c`、真实文件系统／adapter shim、`test_config_backup.inc`、执行器门禁 | 真正NRO编排、请求/结果解析、事务提交点、失败回滚、重启恢复、输入及证据停止条件 | 不在Eden制造每一种I/O/PCTL失败，不以真实等待代替固定时钟边界 |
| L3 构建与产物 | `python tools/package_remote.py` | C/Python/UI门禁、标准三组件与Zip、Eden NRO及marker隔离 | 不把NRO生成成功算作启动／业务通过；发布包组另按release要求 |
| L4 Eden端到端 | [执行入口](Eden自动化测试.md)、[场景规格](Eden主流程场景.md) | 实际输入→页面→请求回执→状态/文件→下游入口与重开；只验证模拟业务 | 不承担真实PCTL、跨进程IPC、真实SD原子性、Tesla或CFW生命周期 |
| L5 真机集成／资格 | 冻结候选、标准取证、Device Lab及集中画面复核 | 原生阻断/解除、游戏实际效果、Overlay、休眠/底座、自启动/热更新、完整恢复 | 不重新枚举可由Host证明的纯规则；不能省略真实硬件边界 |

`tools/test.py` 是Python／协议／前端／打包工具门禁，不等于全部C测试入口。C安全、NRO编排和adapter等由统一devkitPro入口执行。名称包含Eden的Host测试仍属于L1/L2。

## 从功能到场景的映射

| 功能 | 下层主要来源 | Eden只补的接线风险 | 真机独有风险 |
| --- | --- | --- | --- |
| 首次设置与PIN | `tests/nro_setup/test.c`、`test_auth_clock.c`、`test_ui_state.c` | 首次进入、取消/错误/成功、真实页面与文件、重开不重走向导 | 共享认证时钟权限、NRO/Overlay并发、真实重启冷却 |
| 离线码与快速加时 | token v1/v2、`test_direct_grants`、`test_direct_grant_rollbacks` | 预览→取消/确认→结果→额度、nonce与活动一致；家长快捷加时入口 | 新鲜1952读数、超额加时后的原生恢复与游戏可用 |
| 长期计划 | rules纯函数、`test_today_decision_and_plan_review` | 草稿丢弃不落盘，保存后孩子/今日安排与下次启动一致 | 实际PCTL写入、日期／时区与环境 |
| 四级优先级 | rules及forecast固定向量 | 一组可区分的180/90/60/150额度，逐层覆盖和撤销时UI与后台一致 | 真机只补受改动影响的控制集成，不重测整张优先级真值表 |
| 自主缓冲 | C成功/拒绝/回滚 | 家长开启→孩子领取→按钮禁用→重开仍不可领；活动与资格不重复 | 原生限制下Overlay领取与实际解除 |
| 护眼/就寝/电视 | `test_control_safety.c`、`test_policy_status.inc`、`test_direct_unlimited.inc` | 一次自然休息/恢复、PIN跳过就寝、总额与电视原因交接 | PCTL计数、真实阻断、POWER休眠、底座与跨日 |
| 备份与导入 | `test_config_backup.inc`、NRO备份编排、布局回归 | 创建→改规则→选择恢复→PIN/长按→重开；正常业务痕迹保留 | 跨进程恢复与真实PCTL原像，设备资格 |
| 语言/主题 | 文案catalog、palette、生产绘制三语/双主题 | 实际选择会重绘并持久化，切换后仍能导航 | 真机字形、电视距离阅读和实际输入体验 |
| 家长网页／配对 | `tests/frontend/`、HMAC固定向量、离线包门禁 | 网页真实导入→发码→NRO兑换属于受改动触发的扩展场景 | 手机摄像头扫码、真实浏览器存储/网络环境 |
| 支持与升级恢复 | 热加载Host集成、诊断脱敏与package测试 | 软件信息/只读支持页面可按变更补交互 | 标准后台交接、自启动、完整安装原像恢复 |

## 发版前最小集合

入口烟测 `--suite smoke` 保留7项，适合单独诊断自动化通路；它不能代表核心功能验收。发版前主流程最小集合使用 `--suite main`：包含同一批7项前置，再串行执行10项旅程，前置只执行一次。具体步骤与验收数值以[主流程场景](Eden主流程场景.md)为准。

最小集合保证主要业务链每类有一条代表路径，不承诺全部功能、语言/主题笛卡尔积或异常穷举。地区日历导入/应用、PWA真实配对、完整安装恢复、热更新等按相应变更选择扩展场景。对这些功能做了修改时，不能以未修改范围的最小集合代替受影响测试。

## 执行顺序与停止条件

1. 根据改动列出风险及其最低验证层；先补下层可确定的问题，再扩展Eden。
2. 日常运行Host回归；C/NRO/Overlay/package改动走统一入口并保留默认Eden NRO构建／校验。日常不启动模拟器。
3. 发版前固定实际NRO与manifest，运行一次主流程集合，加上受影响扩展场景。需要稳定性验证时另定目标、样本数和停止上限。
4. 构建／启动／场景／画面复核／真机资格分别记录。前置失败阻止依赖输入；超时保持未知，不换ID重放。
5. 场景结束正常退出自建进程并审计同PID崩溃；JSON写盘后读回，离线复核两次。失败批次原件保留，修复后使用新目录。

明确安排的Eden专项按约定范围执行到修复后候选验证完成；“日常默认不启动”不取消已授权的专项。独立支持/恢复专项使用`--suite support`，复用必要前置，不为单个扩展重复整套入口认证或main计时旅程。

Eden模拟后台随NRO退出；“重开应用持久化”不证明后台独立运行、主机重启或关闭期间累计。模拟限制页仍能打开NRO，不是生产受限自救路径的证据。

## 如何报告成绩

以“功能×层×候选×环境”为一条结论：标明已设计、已实现自动化、实际通过/失败/未知/未执行、原件位置和仍欠证据。旧候选通过保留原范围；不得把“有测试文件”写成当前源码通过，也不把新补的用例立即计入历史成功数量。阶段成绩和剩余工作放验收记录，不在本策略中累计。
