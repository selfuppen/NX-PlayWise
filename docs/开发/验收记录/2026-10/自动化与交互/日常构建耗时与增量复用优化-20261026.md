# 日常构建耗时与增量复用优化（2026-10-26）

本批针对统一构建做本机前后测量。相同默认门禁下，无变化重复构建由 63.66 秒降至 35.79／30.49 秒，两次均值 33.14 秒，减少约 48%。测试未跳过，标准包与默认 Eden NRO 构建／校验通过；没有部署或执行模拟器业务场景。

## 口径与实际数据

环境为共享工作区、`devkitpro-ssh-v1`、SSH `31888`、默认 `-j8`。默认 `1888` 未监听的首次尝试退出 255，未进入构建，日志 `build/build-opt-baseline-20261026.log`；读取实际 Docker 端口后改用统一入口的参数覆盖，没有修改维护者默认配置。

| --- | ---: | --- |
| 原流程首轮 | 237.31 | 发生组件重编译；不是 `--clean` 基准 |
| 原流程无变化复跑 | 63.66 | 标准包＋Eden，完整测试，18 次 Host 编译，2 次身份扫描 |

原流程只有一个无变化样本，优化后为两个；文件系统缓存、系统负载与磁盘读取均会影响结果，不能据此承诺每次固定 33 秒。首轮优化后耗时更长，本批不宣称全清理／全编译加速。日常重复构建的收益来自消除工作，而非关闭测试或 Eden。

基线原始文件为 `build/build-opt-baseline-20261026-{01,02}.log` 及对应 `-timing.json`；优化后为 `build/build-opt-after-20261026-{01,02,03}.log` 及对应 `-timing.json`。源码／工具链身份副本为 `build/build-opt-after-20261026-manifest.json`。本记录在性能样本之后编写，构建身份以该副本为准；这些工作区产物不是 clean 冻结生产候选或设备资格。

## 已落地的去重

- Host 测试和 UI 预览程序不再无条件重编译；对应源码、保守的头／`.hpp`／`.inc` 依赖、Makefile、编译命令／版本与 flags 会使缓存失效。测试本身每次执行。
- 同一次 Make 为所选 profile 采集一次源码／工具链身份，分别写独立清单；后续调用重新采集，不读取旧身份缓存。未知 libnx 的批量输出在写文件前拒绝。
- Switch 编译器 `.d` 保留真实清单引用关系，不再强迫无关单元因清单改变而编译；NACP 只依赖组件 Makefile 与版本文件。
- 完整 Python 回归已经在统一构建内执行，不再把外部先跑同一全量套件列为固定前置。修复中的定向测试仍可用于提前反馈。
- 补齐 Host 编译和 UI 检查计时，按阶段汇总；计时自测隔离输出，移除把累计计时／挂钟比值写成实测加速与节省时间的结论。

日常最小流程、专项参数和复用边界已整理到[构建与测试分层](../../../构建与测试分层.md)，并同步开发入口、环境指南和测试操作手册。

## 验证与边界

实际执行：

```text
python -X utf8 tests/devkit/test_release_manifest.py
python -X utf8 tests/devkit/test_stage_timer.py
python -X utf8 tests/devkit/test_package_remote.py
python tools/package_remote.py --port 31888
python -X utf8 tools/package_remote.py --port 31888
python -X utf8 tools/package_remote.py --port 31888 --previews
```

前三项定向回归通过；Windows 上的 Make 集成按设计转交统一 devkitPro 门禁，其后已在容器完整 Python 回归中执行通过。隔离 Make 回归覆盖无变化复用、源码与嵌套 include 修改、flags 变化、删除 include、编译失败拒绝旧产物，以及三 profile 只生成一次身份的选择逻辑。清理 profile 回归继续使用真实 Make 清理规则。

两轮无变化日志均确认：完整 Python 与 C／UI 检查存在、清单生成一次、没有 Host 编译、Switch `-c` 或 `nacptool --create`。实际 `.d` 另核对 sysmodule／Overlay／NRO main 与 Eden runtime 仍依赖清单，cJSON 与 UI 状态等无关单元不依赖清单。

Eden NRO 构建及产物校验：通过。Eden 模拟器启动／场景：按日常策略未执行。Complete、Device Lab 二进制、独立探测和正式资格：未执行，不以本次默认构建代表这些专项通过。
