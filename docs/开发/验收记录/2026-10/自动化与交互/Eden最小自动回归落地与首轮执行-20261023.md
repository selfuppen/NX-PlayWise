# Eden 最小自动回归落地与首轮执行（2026-10-23）

本批已落地首套隔离 Eden UI／业务自动测试入口。第7批 OpenGL 七项全部通过，但第8／9批独立重复均在game_ready前崩溃，启动稳定性未通过。已证明的业务能力只覆盖模拟前端及进程内模拟后台，不资格化真实 IPC、SD 队列原子移动、PCTL／1952、系统阻断、Tesla、休眠、底座或标准生产候选。

## 实现与门禁

入口为 [eden_runner.py](../../../../../tools/automation/eden_runner.py)，操作方法及只读 UI 快照 v1 见 [Eden自动化测试](../../../Eden自动化测试.md)。执行器通过 Eden MCP stdio／eden-control 驱动真实 NRO 输入，点击中心由生产布局函数导出；只读快照不含 PIN／加时码正文。隔离 profile、固定120分钟规则、300秒／180次输入上限、逐位输入断言、新回执 ID/type、同PID退出审计及哈希封存共同构成通过条件。失败阻止依赖步骤，不自动补发业务请求。

发现并修正三个执行问题：动画帧由0递增至上限，初版观察条件写反；Windows 原子替换快照期间的短暂读占用需有界重读；Eden 会先回工具回应再定时释放触摸，100毫秒输入可能漏采，改为400毫秒触摸／200毫秒按钮并等待1.2秒。新 Host 回归覆盖启动假成功、退出码被崩溃事件否决、回执身份、快照占用及封存往返／篡改拒绝。

此外定位到原 Eden 模拟后台的跨秒加时读问题：页面轮询更新的 usage_captured_at 早于确认时的新请求起点，核心正确返回401。修复仅在 Eden 模拟适配器实际 read_grant_status 时推进累计时间并采样时间戳；生产核心的新鲜度检查未放宽。C 回归证明旧缓存拒绝、新采样通过、注入读失败保留及跨日累计重置。
