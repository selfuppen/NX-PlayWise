## 证据与原因

只读拉回最后 65 个结果目录条目中的 59 件本 boot 时段 status/overlay_ready 回执，全部带有效 usage；完成减原捕获范围为 -1 到 5 秒。负差仍属于未来捕获，按既有规则保守不可用，不能为了通过测试放宽它。另核对最后 8 件 status 的原 `inbox/done` 请求：客户端 `created_at` 为 759–772 秒，后台捕获/完成是约 `1791991936` 的 Unix 秒。例如 `772000-0039` 的请求时间 772，捕获 `1791991936`、完成 `1791991938`，并非过期回执。

Overlay 在请求派发时直接把 `std::time(nullptr)` 传给 bridge，bridge 用 `created_at * 1000` 形成请求 ID。原始请求因此提供了正数客户端时间的证据，而不只是根据截图猜测。r4 的逐帧更新把任何 `wall_now > 0` 当作有效墙钟，直接与后台 Unix 捕获相减；772 小于捕获日期，会立即清除有效分钟。请求成功的同一帧先显示刚解析数值，下一帧失效，与用户观察一致。

本机 libnx checkout 为 `feebd026ca0f5dcc2119f46ad8e0d16ad3dd4973` / `v4.12.0-25-gfeebd026`，工作树 clean；同时保存实际构建 libnx 4.12.0 对应本地 tag 的已跟踪 `init.c`、`newlib.c` 及哈希。默认弱 `__appInit` 调用 `timeInitialize` 和 `__libnx_init_time`，但仓库固定 Tesla `f766e9b607a05e9756843cbd62b3bfb98be1646c` 提供自己的 `__appInit`，没有这两步。newlib 时间基数是静态变量，未初始化可保持 0，系统 tick 换算随后得到正数启动后秒数。此前“初始化失败返回非正时间”的回退只覆盖一种情况，遗漏了初始化根本没有执行的正数情况。这里没有额外初始化服务或直接探测进程内 libc 变量。
