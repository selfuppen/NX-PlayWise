## Eden 覆盖盘点与执行计划

**结论**：已有套件覆盖多数可模拟业务的主路径。六批 UI 新增或改变了实际输入与页面状态，旧套件和 Host 布局检查只能提供部分基础，现有回归尚未覆盖全部可模拟功能。优先扩展原专题，每个新能力保留一个代表成功和必要的取消、无效或拒绝路径。

| 合并后的功能 | 历史套件能证明的部分 | 应补的 Eden 断言 |
| --- | --- | --- |
| ① 儿童首页、家长今日安排；② 今日详情双时间轴 | main／refresh 显示余额、限制、刷新与业务结果；Host 有新几何和并发投影 | 用手柄和触控验证普通／受限右列顺序、首项、禁用和刷新时映射；走家长快捷卡、守护入口和返回；对照双时间轴、独立余额、过期／并发／待生效，以及倒计时归零待确认 |
| ② 七日总览；③ 地区日历、指定日期和就寝 | main 走每周取消／保存及四级覆盖；plans 走地区日历导入／应用、就寝分区／持久化 | 从新七日卡选两个不同日期，再编辑字段；断言选卡本身不改草稿，保存只影响目标日；用不同日程确认指定日期、日历和逐日跨夜窗口的保存、放弃及重开。在线导入的网络边界交给 Host 和真机 |
| ④ 护眼、电视模式、自主缓冲 | 模拟自然休息和恢复、手动电视／掌机切换、非电视累计与 PIN 豁免、单次缓冲领取 | 护眼档位与跳过本次、电视快捷档和放弃草稿、缓冲档与孩子端预览进入实际触控／手柄链；确认保存／取消效果及只解除目标限制。实体底座和 Switch Lite 兼容性另验 |

发版前集中为三个执行单元：

1. **先跑一轮主流程**。冻结当前 Eden NRO 与 manifest；复用 `main` 的 7 项前置和 10 项旅程。先检验新交互的客体快照、当前命中区域与等待条件，再判定后端回执和落盘。尤其复核新的选中日与就寝编辑入口、`backup_*` 区域和三合一入口的 `web`／`safeguards` 路径。将旧导航断言移到新控件后保留原业务断言。
2. **补两组专题**。规划和状态合在 `plans`、`dock`、`refresh`、`notifications`；家长凭据、安全和恢复用 `web`、`safeguards`、`support` 及必要的长按／三语 `input`。按改动选择受影响路径，Host 继续承担全组合的文本布局和故障边界。三语选代表页复核真实渲染与输入。
3. **统一证据与停止条件**。使用 shared 模式、独立 profile、受控输入和正常退出，分别记构建、启动、场景与画面。回执超时或输入未释放时停止依赖动作。汇总绑定实载 NRO、Eden 版本／渲染器、前置数据和各原件；JSON 读回、离线核验两次后清理成功批次。变更仅属执行器时仍记录执行器和产物各自的身份。

## 真机覆盖盘点与执行计划
