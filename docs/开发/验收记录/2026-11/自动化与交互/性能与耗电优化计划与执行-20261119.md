## 审核口径

原报告发现了真实的重复读取、解析与绘制工作，但不能从调用次数推出物理 SD 访问、磨损、CPU 100%、实际帧率或省电百分比。严重度按可证明影响重排，不沿用原报告的 P0。

- NRO 动画期固定累加 20ms、实际只睡眠 5ms 属于计时错误；请求超时同样不能按轮询次数累计。
- 输入所有权每次物理输入前的新鲜检查是防串键边界，最多读取 runtime 和两个租约文件，并非 13 个。释放记录服务于晚到读者，不能删除；不得用 mtime 缓存放行输入。
- 后台 1Hz 电视规则与空闲检查存在，但并非每轮必做全部控制 IPC；内置日历也不等同于导入日历的文件读取。跨轮校验导入数据、身份、采样时间和写后确认均有正确性目的。
- 通知 ready 是短租约握手；短通知发布者已有清理。不能仅延长租约或停止隐藏轮询来规避 I/O。
- Result 校验函数不是一次 cJSON 解析；实际重复树构建可合并，但校验必须保留。
- 静止 UI 仍有呼吸、秒钟、主题和页面过渡，不能仅比较 model 就跳帧。

## 本批不直接实施的建议

- 后台跨轮日历／身份 mtime 缓存、降低 PCTL 采样、忽略 captured_at、移除释放记录、放宽 ready 租约：会改变已确认的安全／故障发现边界，当前建议不采纳。
- 全局静态跳帧、阴影／光晕重设计、热更新哈希移入线程：需完整的动画失效机制或更新事务生命周期设计，列为后续专项；本批不以不完整实现宣称解决。
- 缓存 GET_VERSION、按回执类别跳过草稿加载：须先界定重连身份与外部规则修改的刷新边界，暂不改变协议行为。
- 隐藏输入仅对快捷键子集提速：需验证多键按下顺序和呼出响应，不依据静态报告改动。

## 实施结果

1. `loop_clock.h` 对真实间隔做饱和累计，回退不产生巨大差值。主循环和 PIN 页不再因动画改用 5ms 睡眠，依赖采样次数的快捷键／PIN 长按／方向连发不会在动画期加速；慢 I/O 仍可能延长其实际响应。动画本身继续用既有单调时钟推进。请求等待单独记录上次轮询时刻，传输累计也防整数溢出。Eden 只有发现同一请求的实际回执文件才可提前越过文件轮询间隔，不伪造经过时间。
2. 所有权缓存只保留成功匹配的原字节与解析值，约增加 1.9 KiB／context；没有减少新鲜读取次数。固定工作负载首次 reader 解析为 52 次 cJSON 分配，100 组 reader／writer 检查为 0 次分配、400 次读取。读取失败、同长度 boot 替换、租约释放及损坏后的拒绝测试通过。
3. 文本引用使用 64 槽有界缓存，保存目录内稳定指针与 ID，冲突回到原查找，三语逐项测试通过。每周预览规则构建从七次合并为一次；NRO 应用 Result 的摘要与详情共用一棵已校验的树，局部树构建从两次降为一次，传输层校验保留。
4. audout 初始化不启动输出；首次有效声音才启动，播放完成后在约 100ms 轮询中停止。禁音／取消停止并清空，失败保留待清理状态，确认旧缓冲释放前不启动新声音。空闲已停止时不查询服务。三缓冲、启动／停止／清空／查询／追加失败路径通过假服务测试；并未证明硬件管线休眠。
5. Tesla 完全不透明像素直接写入已检查的 swizzle 地址；部分透明保留原公式，消除第二次地址／裁剪计算。65,536 组通道与 alpha 组合等价检查通过。没有改变列遍历顺序、卡片描边或淡入淡出；上游固定 commit 不变，新增本地补丁登记。

协议总览另修正旧描述：自动详情写入达到五次失败后停止写协作，但简要提示只读接收继续。这是文档纠错，不是本批改变隐藏接收行为。
