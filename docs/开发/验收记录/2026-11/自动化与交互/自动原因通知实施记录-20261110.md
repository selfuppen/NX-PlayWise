| 情况 | 固定接收者行为 / 本项目承诺 |
| --- | --- |
| 格式 | UTF-8 JSON；title、text、font_size=26、duration=10000、show_time="false"（字符串）、priority=30。只写本项目独占文件，临时文件不以 .notify 结尾 |
| 轮询及排序 | 接收者约每300ms扫描；文件候选优先级数值较大优先，同级mtime较旧优先；常规每轮至多选一个，首次扫描可填空槽。满槽可推迟读取，不保证2秒内读取 |
| 读取与删除 | show把文字复制入内存，文件通常直到槽驱逐才删除；通知关闭分支直接删除全部.notify。消失只能记为消失、显示未确认 |
| 同名覆盖 | 活动槽同名被跳过，旧槽驱逐会按文件名删除。为避免旧槽误删新事件，采用每boot/序号唯一文件名，最多一份本项目待消费文件，不复用活动文件名 |
| 原因交接／解除 | 发布端核对原字节后删除旧待消费文件；不能撤回已复制的活动槽。短句明确为发生过的事件，不显示实时倒计时、不宣称已解除 |
| 正常发布 | 发布端待消费目标窗口2秒，接收端请求显示10秒；10秒从接收者放入槽开始，并含其动画／调度边界，不是发布起算的硬期限 |
| 额外延迟 | 接收者画面越界会延长expireNs，启动浮窗时update可暂停，满槽／内部队列也可延迟；不得承诺活动通知的严格10秒墙钟上限 |
| 接收者缺席／其他浮窗 | 驻留状态unknown；发布方到期尽力清理，不把输入owner租约当接收者证明。PlayWise详情有效租约仅供自身抑制 |
| 后台退出／休眠／SD错误 | 正常交接撤销待消费；异常退出、线程被阻塞、真实休眠或SD删除失败会越过2秒窗口，可能被旧接收者补播。失败退避并停止新发布，启动先处理持久所有权记录 |
| 第三方设置 | 只读Ultrahand全局通知及PlayWise条目快捷键；缺失／非法降级为打开任我玩查看详情；不修改INI、loader、OVL或全局组合键 |

时序：完成原有策略处理和可靠观察 → 生成当前实例事件 → 确认本项目旧材料已清理 → 原子发布 → 至多2秒后核对原字节清理。期间原因变更、未知状态、禁用或交接优先清理；10秒限频内合并最新原因，只有新鲜可靠快照才允许发布。文件I/O安排在主循环原控制锁外，不能改变原控制返回值或消费记录。
