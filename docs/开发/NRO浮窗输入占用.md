# NRO与浮窗的输入占用

标准manifest的`nro_overlay_input_owner_version:1`表示生产NRO与Overlay实现协作输入占用；Eden和Device Lab不声明该能力。它防止同一按键在PlayWise浮窗显示期间同时触发底层PlayWise图形NRO，包含其内部PIN页。它不是HID系统权限、请求鉴权或游戏侧隔离证明，也不覆盖系统软件键盘等外部applet；真实游戏效果仍须单独验证。

## 生命周期与记录

实现位于`companion/input_owner.*`，只使用现有SD存储和设备单调时钟，不新增HID/AM/PM服务、线程或控制请求，不反复申请系统前台。只在标准profile、实际runtime的release与编译release一致时启用Overlay输入。正常热更新中新NRO面对已知旧release时仍可输入PIN完成原交接；初始后台明确不存在也保留恢复UI。读取失败不能冒充已知缺失。

Overlay正常显示时，在support目录写入并回读两个槽：

```text
overlay-input-<实际后台boot_id>-0.json
overlay-input-<实际后台boot_id>-1.json
```

每个文件恰含7个唯一键：

```json
{
  "schema_version": 1,
  "release_id": "<实际编译release>",
  "backend_boot_id": "<16位小写hex>",
  "owner_id": "<32位小写hex>",
  "issued_mono_ns": "<正十进制纳秒>",
  "expires_mono_ns": "<正十进制纳秒>",
  "visible": true
}
```

owner由本Overlay实例开始tick和本次显示tick组成，不含PIN、按键、令牌或密钥。同一进程每次重新显示使用新epoch。有效期最多30秒、每10秒交替续一个槽；两槽在替换单文件时仍有另一个有效租约，避免现有FS原子写实现中remove/rename之间的空档。空闲绘制不每帧写SD。输入及其松开事件在提交动作前还重新核对后台身份，不等下一次续约。

正常隐藏及退出写入同epoch的`visible:false`记录，退出不重复延长已释放记录。保留释放记录是为了让晚恢复的NRO也能识别跨界长按；它们不是活跃占用。每个boot最多两个槽，后续正常显示可替换同身份的已释放/已到期记录。未知、损坏或其他仍有效owner不能被覆盖。

任何初始写入、回读、续约、时钟或身份核验失败，Overlay停止处理输入并沿原Tesla路径正常隐藏；不强杀后台、不重放已提交请求、不续租一个已经到期的显示实例。释放只处理本owner，存储失败时已有有效租约最多保留至原绝对期限。若释放也失败，不能假报文件已清除。

首次已有业务恢复/`overlay_ready`握手也在成功占用后才开始，同一backend boot只开始一次；正常隐藏/重新显示不重复握手。这样占用失败时不会先向后台报告恢复通道就绪。原有待确认业务仍只按原ID恢复，不用新的请求重放。

## NRO入口保护

NRO在解释物理输入前查询两个槽，覆盖普通页面、触摸、摇杆、快捷键、内部PIN、长按和松开确认。空闲查询最多每250毫秒一次；有输入时立即查询，不使用缓存放行。任一有效visible租约或未知记录都抑制操作，同时取消待处理减号、快捷键和确认长按状态。

占用结束/租约到期后，必须先观察中性输入帧，才接收新的动作，避免Overlay关闭时仍按住的键或触摸变成NRO确认。释放记录即使先前未被NRO看到，也会触发此保护。读取持续未知时保持不放行，不能用到期猜测修复损坏记录；明确有效但因进程异常留下的租约则在30秒后经中性帧恢复。只删除/归档确已绑定到本批且已释放的记录，不清理未知文件。

不同backend boot使用不同路径，跨boot不比较tick。租约只是两客户端的协作协议，依赖单个正常显示的PlayWise Overlay和受信SD环境，不代替平台级独占或安全认证。NRO自动status不属于物理输入动作，仍沿原协议运行；成功回执来源继续用[UI状态来源取证](UI状态来源取证.md)核验，不能只按数量推断按键接收。

## 验证与收尾

C回归覆盖默认无owner、显示/释放/重显、中性释放、晚读者、两槽替换空档、租期、失败锁存、部分写入、其他owner保护、身份变化、未知存储、损坏/越界时间和业务状态不变。涉及C/NRO/Overlay的验证必须使用统一构建入口并保留默认Eden；Eden不证明本机协作或系统输入行为。

真机按实际clean候选绑定标准raw与两端status来源，留存限制前、休息中、自然解除后及正常隐藏/退出的槽原字节。自然解除段不主动提交业务；验证NRO没有直接Y提交、Overlay正常响应，以及退出后NRO刷新恢复。游戏侧效果、系统软件键盘和并发显示等不据此外推。

先完成策略/完整PCTL设置恢复与标准采集停采，再关闭前端并核对来源日志终末。检查两槽均已释放且属于本epoch；需要归档时，先证明Overlay已正常退出、原字节及owner不变，记录意图并只处理本批文件。保留原样本/已提交业务活动，报告可离线重复核验。
