# 真机稳定探测方法

本方法来自2026-10-13至14日使用时间能力探测，目标是减少值守、避免已知故障路径，并让结论能追溯到原始证据。它是本机实践出的优先路线，不保证任意固件、服务或环境都稳定。已验证事实见[主线记录](../调研/PCTL1952主线探测计划.md)，后续功能影响见[分析交接](../调研/PCTL1952功能影响分析交接.md)。

## 先固定统计口径与验证边界

本轮接受游戏、HOME、系统设置正常可用期间计时；限制使机器无法正常使用时允许停表，即使仍亮屏。不能将总累计解释成纯游戏前台、所有亮屏、小屏用量或某个护眼周期。

开始前列出已验证项、缺口、通过标准和执行顺序。引用已经充分验证的原始记录，不为新报告重复跑同一实验。每项明确为通过、部分证明、未执行或前提不满足；计划、宿主回归、故障后的非零累计均不能自动变成真机通过。

## 优先沿用已有稳定进程

当前PCTL读取路线使用标准后台`4200000000BD2300`的编译期旁路：标准控制逻辑不改，新增采集函数不写PCTL、不初始化输入，不调用电源、PM或PDM，不增加独立sysmodule或线程。仅诊断构建定义`PLAYWISE_PCTL_CAPTURE`，正常标准二进制不含采集标记。

每5秒读取1453、1454、1455、1952和145601，保存各自Result与完整0x44。每次采样的所有退出路径都关闭子服务和工厂；会话释放、失败和停采由真实C路径测试覆盖。不要因为函数是只读就假设没有资源代价；同一进程仍需限定频率、租期、失败次数并验证长期稳定性。

本机此前观察到HID和AM的LimitReached fatal、ams_mitm abort。模块和错误可绑定证据，但具体资源耗尽及崩溃根因未完全证明。当前不要重复旧BD23F1自启动、hbmenu/Controllers X+A、第二游戏切换、远程输入初始化或旧BPC/PM电源路径。`usage_probe/`及旧自启动脚本保留为历史实验实现，不是推荐稳定部署入口；构建通过不代表可以重新启用。

如果新能力必须引入额外服务，先单独核验权限、会话生命周期与资源影响，再将最小探测接入稳定进程；不能把当前PCTL成功外推到PDM或其他服务。

## 绑定正在测试的实际二进制

保存实际SD后台NSP、公用build.json、runtime-ready、原启动标记状态、相关公共规则和恢复前像。实际安装包的manifest含dirty标记时，不能只凭commit名字重建并声称等价。

本轮控制重建绑定本地commit `df104d86b8c300cc9654dde4449df445b2ec4045`。仅允许规范化已验证唯一且与NSO标头绑定的20字节GNU build-id；加载段布局、代码/数据、模块和NPDM必须匹配实际原像。NSP的字节SHA不同仍应如实保留，不能称完全相同。

调查上游按仓库约定固定commit并记录工作树状态。私有PCTL命令单位与0x44布局以协议及真机A/B为准，不能从libnx没有公开封装推断。机器、HOS、Atmosphère、libnx、源码哈希、包哈希和采集run_id都要可追溯。

统一构建入口示例（端口18881为本机profile）：

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
python -X utf8 tools/package_remote.py --with-pctl-capture --port 18881
```

入口执行C/Python门禁，并生成校验标准包、内部惰性采集包及默认Eden NRO。Eden不能证明真实PCTL语义；不要通过手工SSH/Docker旁路构建，也不要因测试通过自动提高产品资格。

## 将准备、实体操作、采集和收尾分开

`tools/pctl_capture.py`的`stage/activate/collect/restore`负责映像与采集配置事务，内部Zip只含暂存映像和身份，没有boot flag或自动激活。对一个新目录执行stage，检查前像和运行身份后才activate；命令仍会改变专用测试机，必须处于用户授权范围。

```text
python tools/pctl_capture.py stage --out device-reports/<独立批次>
python tools/pctl_capture.py activate --out device-reports/<独立批次>
# 完成正常重启并确认新runtime/boot后：
python tools/pctl_capture.py collect --out device-reports/<独立批次>
# 操作已知、规则已恢复后：
python tools/pctl_capture.py restore --out device-reports/<独立批次>
```

已有backup或配置会拒绝覆盖。先核对它所属run、前像哈希和结束状态，再以原run身份归档，不能直接删除未知恢复材料。

**租期只在启动读取。** 有效范围300–7200秒，默认activate配置3600秒。长时间预使用或自然午夜前，先算好真实结束时间、设置足够租期并回读，再一次正常重启加载。进程运行中修改租期不能延长已加载租期；过期或配置删除后旁路锁存停用，重新配置仍需重启。先检查完整准备状态再请用户重启，避免反复请求。

稳定接口无法可靠替代实体真休眠或正常重启。把确实需要人的操作合并成一批：正常启动后保持可用、短按POWER真休眠至少120秒、唤醒保持可用、最后正常重启联网；只在整组完成后统一回复。休眠窗口宿主仅取日志，不提交status/控制请求。不要以断网、Stop计时或关显示冒充休眠。

无需人的独立项目继续执行。截图失败、画面待确认不阻塞计数采集；不可自动完成的事项明确留待确认。若机器fatal或写入回执未知，则该设备上的依赖操作必须停下核对，不能用“不阻塞”理由继续猜测写入。

## 操作只提交一次，原始证据只追加

通过现有标准文件队列进行显式规则操作，UUID和请求内容先落宿主日志再发布；只等待同一ID/type回执。成功、拒绝和未知是不同结果。超时不代表失败，未知原请求不能换ID重发；先找原回执和真实状态，再决定恢复。

`tools/pctl_usage_scenarios.py`在追加操作前读取已有journal，避免后续status查询覆盖此前动作汇总。raw JSONL、请求/回执、source/run/boot身份、设备Unix秒、本地day_index、tick纳秒、全部Result、带符号剩余和原始设置必须保留。下载尾行不完整时保存原始字节并标记，不静默修复。

只有读取有效、实际配置可信时才交叉验证`额度纳秒 − 带符号1454剩余 = 1952累计`。负剩余保留符号，不能先钳成0再反推累计。无额度、显式不限时和临时BLOCKED分别记录；失败保持未知，不用默认0代替。

普通窗口用同boot设备tick计算间隔。宿主等待60秒时，最新周期日志可能只跨57秒；必须要求设备端点本身达到时长，或用已保存的连续原始记录补齐并单独列出处。缺样、错误、中途规则变化或计数倒退不能隐藏。跨boot只比较同日有界Unix端点与累计，不能相减不同启动的tick。

不要更改旧raw来使派生结论一致。重建缺失汇总时标明重建依据，把原动作端点和相邻额度变化样本分开；旧bootstrap前、已过期和其他进程的读数不能冒充新窗口基线。

## 新安装首次分支的专门前置条件

完整新PlayWise安装不等于全新主机，更不等于追溯原始反馈现场。原生家长控制须已开启、当天无额度且真实使用超过60分钟。整体隔离旧数据目录并保留所有私密文件，由不可变安装默认模板和正常启动生成新setup；不手写setup字段模拟首次。

必须准备有效的独立测试PIN，使用Companion的HMAC-SHA256格式；标准后台正常启动自行生成新加时密钥。原PIN/credentials不读取或复制到新现场。本轮遗漏测试PIN导致308 setup_pending，只有接管前累计读取通过；修正后另run重试，不将拒绝批次改为成功。真实预使用已经满足且原生累计未丢失时，不必重复一小时，但新boot的实际1952仍须大于3600秒。

记录标准bootstrap之前的1952、正常生成的unconfigured/setup无快照和原生设置，首次complete_setup成功后再核对历史保留。超过默认额度而立刻受限是有效场景；先保留这个结果，再显式加时验证连续增长。不能在拍摄首次结果前偷偷放宽额度。

`tools/pctl_fresh_takeover.py isolate/finish/report`要求调用方先准备计划、模板哈希和公共前像，**不是从任意设备一键运行的通用入口**。本轮准备脚本位于被忽略的build目录，仅为现场脚本；后续按明确计划重建，不把未提交脚本当固定工具依赖。原目录归档路径与run严格绑定，已有归档不得覆盖。

## 收尾必须有可核验结果

已知操作才按本次前像恢复，未知写入保持待核对。只清除本次拥有、原因匹配的停用或就寝跳过标记，不清其他人的保护状态。

首次安装试验结束后，先归档测试目录、恢复完整旧目录和公共策略前像，保留当前进程真实生成的runtime身份，通过reload.flag清除缓存，最后移除本次停用标记。不能把旧进程的PID/boot复制成当前身份。旧凭据始终留在原目录。

核验原规则语义、setup、就寝跳过、限制状态、标准启动项以及原NSP SHA。归档采集配置使旁路停用，间隔超过采样周期再次拉取，核对不再追加。本轮6秒检查通过；运行中仍可能是已停采的诊断构建，下次正常启动才加载SD上的原二进制。

最终报告分别列能力结论、三个生命周期场景、原问题链路、恢复状态、仍未验证事项和最后画面。保存最终输入哈希、服务错误/累计倒退/带符号交叉失配数；报告生成必须可离线重跑，不能隐式重新操作设备。

## 本轮事实与后续推论的分界

|事实|可以支持|不能直接推出|
|---|---|---|
|游戏、HOME、设置约1:1累计|主机正常可用总时间来源|纯游戏前台或全部亮屏时间|
|受限、真休眠冻结，唤醒恢复|当前接受口径下的累计连续性|护眼休息判定、PIN临时解锁的全部语义|
|正常同日重启保留、新安装可读此前累计|读取和接管不应假设从0开始|此前使用归属于哪个护眼周期或屏幕模式|
|加时不跳涨，负剩余交叉吻合|定位当前额度减钳制剩余的估算问题|所有配置切换、写入失败、回滚均无计数影响|
|本次自然午夜归零、次日增长|已测日切窗口及规则组合|改日期、跨时区、多日休眠或历史日期查询|
|1952为主机总累计|用于研究稳定的总用量差分|小屏累计直接等于1952，或电视/掌机切换已验收|

护眼、就寝和电视模式仍须结合各自状态机、策略基线、临时0分钟配置、跨日恢复及资格门禁全面分析；不要因为主线读取可行就宣布三个功能完整合格。
