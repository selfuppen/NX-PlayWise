身份检查完成后，以下示例创建新冻结目录。批次名须唯一；该示例不能代替 P0-3 的身份核验。复制前先保存构建日志；不要在后续流水线写入 `build/packages` 时同时复制。

```powershell
$batch = 'pctl1952-20261014-r1' # 按实际日期/轮次更换
$candidateRoot = Join-Path (Get-Location).Path "build/qualification/candidates/$batch"
if (Test-Path -LiteralPath $candidateRoot) { throw '批次目录已存在，请使用新批次名' }
New-Item -ItemType Directory -Path $candidateRoot -ErrorAction Stop | Out-Null
Copy-Item -LiteralPath 'build/packages' -Destination (Join-Path $candidateRoot 'packages') -Recurse -ErrorAction Stop
Copy-Item -LiteralPath 'build/eden-test/pctc-eden.nro' -Destination $candidateRoot -ErrorAction Stop
$candidatePackages = Join-Path $candidateRoot 'packages'
Get-ChildItem -LiteralPath $candidatePackages -Filter '*.zip' | Get-FileHash -Algorithm SHA256
$reports = Join-Path (Get-Location).Path "device-reports/$batch"
python -X utf8 tools/pctl_usage_qualification.py --packages "$candidatePackages" --output "$reports/pctl-usage-qualification.json" --model mariko-oled --hos 22.5.0 --atmosphere 1.11.2
```

四条短链的字段、数值容差和严格校验以[候选验收契约](PCTL1952候选验收.md)为准，不在本清单另造协议。

| case | 必需顺序 | 验收重点 |
| --- | --- | --- |
| `usage_live` | `before → after` | 正常可用至少 60 秒，1952 累计与单调时间一致增长，timer 已确认且没有官方 PIN 临时解除 |
| `grant_recovery` | `before → after → active_end` | 已用超过业务额度，保留负的 signed 1454；按新鲜累计向上取整加时，实际授权正确，解除后至少 60 秒继续计时并实际可用 |
| `proxy_cycle` | `unlimited → proxy → blocked → proxy_restored → unlimited_restored` | 不限时/1440/BLOCKED/1440/不限时配置正确，累计无写入跳变，自动休息恢复不新增 1451 |

产品补充复测：

- [ ] **展示与加时**：NRO/Overlay 本机累计、原捕获时间与未知状态正确；正剩余不足一分钟不被当成真实耗尽；快速加时、离线码预览/兑换、自主缓冲使用新鲜累计，实际授权不包含基数修正量。读取未知、零增量、写入或提交失败不消耗 nonce/缓冲资格；失败证据不足时明确记为未覆盖。
- [ ] **护眼周期**：触发、正常休息完成、跳过本次、关闭恢复分别观察；未知/午夜边界不凭空证明已休息；旧周期迁移及重启不能退还已用量。自动后台写入/恢复不启动 1451。
- [ ] **非电视模式**：真实 TV → 掌机/桌面 → TV 拔插；稳定电视区间不计小屏，端点模式未知和重启缺口按保守规则处理；读取中断/禁用再启用不能退款或悄悄恢复资格。
- [ ] **组合限制**：就寝、护眼、非电视与每日额度的关键组合，移除一个原因不能解除另一个仍有效的限制；分别核对可用性、配置、剩余与累计。
- [ ] **历史记录**：v1/v2 同日共存且分开显示；失败/BLOCKED/不限时不能把未知变为已知零；保留原可靠 capture 和累计下界。自然换日与重启后的日期/来源正确，7/30 日汇总不混合旧估算；完整全天覆盖仍不承诺。
- [ ] **恢复与现场留存**：限制后入口、Overlay 恢复与原设置恢复按正式测试步骤核验。若出现 `restore_required` 或不能证明精确恢复，先执行已有恢复流程，保留草稿与失败材料，停止后续写入验收；不手工擦除保护标记继续测试。

执行时在批次记录中填写下表，完成后再更新本清单勾选状态；不在正在运行的构建中编辑 tracked 文档。计划日期不能代替实际完成时间。

| 字段 | 填写内容 |

| 偏差 / 未覆盖 | 不能解释的变化、缺失事实、独立资格限制 |
