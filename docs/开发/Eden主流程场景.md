# Eden主流程端到端场景

[分层策略](分层测试策略.md) · [运行与证据](Eden自动化测试.md)

## 目标与数据

本套检查真实NRO操作是否正确串起后台结果、页面投影、文件和后续入口。执行 `eden_runner.py run --suite main --timeout 1200 ...`，一次使用全新私有profile；入口烟测7项前置只跑一次，随后按下表顺序执行10项旅程。默认入口烟测仍可用 `--suite smoke` 单独运行。

准备期写入每周每日120分钟、关闭的护眼1/1分钟周期、关闭的就寝00:01–次日00:00窗口，以及明确标为测试数据的EDEN地区当年全年假日。日历catalog/library/active在启动前作为fixture准备，本套不声称覆盖日历导入/应用UI。就寝窗口不能用于证明真实跨午夜，00:00的空窗或跨年导致fixture不匹配应记录前提不满足。当前NRO须提供完成帧v1及独立输入采样v2；驱动按一次down→观察已采样→一次up→观察已释放执行，不依靠定时tap或重发保证操作。

PIN由正常设置创建测试默认110；离线码固定测试设备和公开测试secret，实际日期取新鲜后台结果。所有规则变化都从正常NRO UI发起，不向队列或业务state注入成功结果，不修改生产目录。主流程最长1200秒、最多500次输入，无自动重试；护眼进入最多205秒、退出和就寝自然分钟调度各最多85秒，业务回执最多20秒，输入或观察失败停止后续依赖。护眼开启后的首次分钟调度建立基线，累计刚低于60秒时还需下一分钟判断，因此不能用85秒覆盖最坏调度位置。进程内桥保存就寝规则的成功回执不代表已到下一分钟调度，必须继续观察实际限制值。

## 最小场景与通过条件

| 顺序/自动化ID | 操作与检查点 | 端到端通过条件 |
| --- | --- | --- |
| 前置 `setup/reopen` | 完成三步设置，关闭并重开 | 新`complete_setup`回执成功，设置完成落盘；新实例进入孩子区，不重复接管 |
| 前置 `pin_cancel/pin_wrong/pin_correct` | 正常页面取消、错误一次、正确进入 | 取消认证文件字节不变；错误计数1；正确进入家长页并清零；不测试完整冷却阶梯 |
| 前置 `code_success/code_replay` | 30分钟码预览并确认，再次输入同码 | 120→150；新`offline_code`成功，nonce0只消费一次、活动一次；新预览206，规则/账本不变 |
| M01 `code_cancel_journey` | 未使用的nonce1码预览成功，在确认页取消 | 返回孩子页；不提交兑换，不增加额度、不消费nonce。区别于“输入框直接取消” |
| M02 `plan_journey` | 清除今日调整；修改周计划后丢弃；再次编辑当天为180分钟并保存 | 丢弃不落盘；保存有同ID/type成功结果；今日安排显示180，非仅草稿显示 |
| M03 `priority_journey` | 启用90分钟测试假日；启用今天60分钟日期计划；设今日150；逐层撤销 | 依次180→90→60→150→60→90→180；持久规则与forecast来源相符，不破坏底层计划 |
| M04 `buffer_journey` | 家长快捷加15；启用5分钟缓冲；孩子领取；再次触摸已领取入口 | 180→195→200；一次领取回执，资格已领且入口禁用；再次操作无新领取请求、不增加额度 |
| M05 `eye_journey` | 留存护眼说明页；正常保存开启1/1周期；观察自然休息和自然恢复；关闭规则 | 有真实输入提交的policy回执；运行中自然进入模拟resting并留图；自然期限后恢复可用；关闭落盘。不开加速时钟 |
| M06 `bedtime_journey` | 开启预置窗口并长按确认；家长PIN跳过当前实例；关闭计划 | 模拟就寝原因生效；正常PIN/确认后的skip成功且恢复可用；关闭成功，无恢复错误。只证明本地模拟链 |
| M07 `dock_journey` | 先设今日不限时，再开启仅电视；今日限额设1；经额度编辑器尝试不限时；设每日180；Eden页模拟电视/掌机；PIN豁免；关闭规则 | 不限时也受电视限制；每日/电视并发；受电视限制时不限时请求明确326且规则不变；设180仅移除每日原因；模拟电视解除、掌机再次限制；PIN豁免解除；关闭后清除今日调整。各段留图/回执，326来源见[协议](../设计/协议.md) |
| M08 `backup_journey` | PIN创建完整备份；周额度改240；只勾选周计划；PIN并长按导入 | 创建/恢复分别成功；240恢复180；未选缓冲仍5；已用nonce不退。十一组组合/归档损坏留Host |
| M09 `preferences_journey` | 安全与偏好打开外观主题；模式选浅色、风格选雾青，先确认配置未写；A提交后返回；再改暗色提交；最后改动后B放弃；语言改英文 | 两组单选只预览不改`config.json`；A一次保存`theme`与`theme_style`（light/teal、dark/teal）并关闭页面；B放弃草稿后配置仍为dark；语言切换后可继续导航。留图`preference-light`/`preference-dark`，不重复三语全部页面的绘制矩阵 |
| M10 `business_reopen` | 完成所有业务后正常关闭并重开 | 新实例孩子页七日预览的今日总额度为180（大号剩余时间扣除模拟已用量，不要求等于180）；周计划/关闭的规则保持；缓冲仍已领不可再领；nonce账本不变；dark/en保留 |

每段必须同时核对页面、对应业务结果及文件/下游效果；只有`status:ok`不能通过。进入模拟受限态仍能操作NRO只是Eden豁免；真实受限后的入口和恢复必须在真机Overlay验证。

## 按变更选择的扩展场景

这些是可执行验收步骤，尚未由 `--suite main` 自动执行。报告单独标明选中/未选中、人工执行或工具缺口，不能计入17项通过：

X03已有独立`--suite support --timeout 600`自动化入口，6项包含必要前置、诊断、停用、恢复及重开。它仍不属于main；实际成绩按候选和批次单独记录。

X02使用`--suite web --timeout 600`及[浏览器交接步骤](Eden自动化测试.md#x02网页配对与发码扩展)，共5项（含必要前置）。它从正常UI导出配对文件，用独立真实浏览器上下文完成导入、存储重载和发码，再输入DOM中的码并核对消费／活动及重开；不以CLI发码代替网页。共享资源运行与成功自动清理按[Eden运行指南](Eden自动化测试.md#准备与运行)执行。

| ID/触发变更 | 前提与最短步骤 | 必需结果 |
| --- | --- | --- |
| X01 日历管理 | 私有profile放一份有效地区JSON到calendar-import；UI导入；先看当前计划；再选择导入地区并长按应用 | 导入成功时active不变；应用后active/hash及七日预览改变；清除今日/日期覆盖后实际来源正确；重开仍保留。无效字段/重复日期留Host |
| X02 PWA/配对/发码 | 使用独立浏览器测试存储；NRO经PIN显示测试配对信息；网页导入并生成当天30分钟码；孩子输入并确认 | 浏览器→码→NRO→回执/活动/nonce闭环；日期以主机为准。现有CLI发码兑换不能代替此场景；二维码光学扫码真机另验 |
| X03 支持入口/恢复 | 新profile完成设置；进入只读支持与诊断导出；返回；经家长PIN紧急停用→恢复安装前设置 | 诊断脱敏且可读；停用禁写但状态/恢复可达；完整恢复使用同事务回执及模拟原像。文件损坏/所有回滚阶段留Host；原生恢复真机另验 |
| X04 指定日期就寝/草稿导航 | 当前日期的自定义窗口；分别编辑周/节假日/指定日期；切页取消、放弃，再保存单页 | 不误保存未确认草稿；只合入当前页，其他已存分区保留；自然时间边界留Host/真机，不在Eden跨夜等候 |
| X05 输入/页面布局 | 受改页面用触摸打开→手柄完成→触摸返回，含一条长按及一条取消 | 焦点/滚动/返回来源正确，弹层不穿透；只选择受影响语言/主题。真实短触/摇杆/Tesla仍单列真机 |

支持专项的诊断在启用和停用状态各导出一次，核对新文件、脱敏字段和成功页；紧急停用先取消再确认，检查禁用的加时入口不发新写请求，而status/诊断仍可达。完整恢复先取消再确认，核对唯一回执、`restored`阶段、停用标记和无活跃事务；重开后再次经正常家长PIN进入支持页。恢复前后保留已消费nonce、正常兑换活动和业务规则，模拟剩余与已用之和回到安装前可观察额度（允许分钟截断差1）。不从这些投影宣称真实0x44、原生阻断或生产后台重启已验证。

## 记录与复用

`summary.json`的suite与scenario键必须匹配；main整体通过还要求三次自建进程健康退出（含两次重开）、同PID事件审计通过。每项保存检查点和截图；业务回执绑定新ID/type，最终规则/state、活动、nonce与只含计数的认证摘要归档。保留NRO、manifest、当批runner/bridge/main模块，JSON落盘后连续离线复核两次。

护眼说明页的`eye-policy-guide`和最终英文孩子页的`business_reopen`截图用于独立画面复核：确认不限时日说明完整可读，以及七日预览标题与摘要没有重叠。机器业务断言不自动证明文案或布局正确；三语双主题的文字测量边界继续由Host生产绘制回归负责。

前置失败时后续标为未执行，不把多个候选的零散成功拼成同一轮通过。修复后新建批次；需要只复核材料时用`verify`，不重复启动模拟器。阶段成绩另放验收记录；本规格中列出用例不等于已执行。
