# 同候选采集安全重启

2026-10-16 为避免反复整机重启，新增有明确采集用途的后台安全重启。它是真实功能变更，不能将新组件冒充旧冻结 `0ce2e11`。后续已从clean `501647c` 冻结并完成首次升级、同候选采集重启及PIN／长按业务机器核验，规则恢复与停采通过；17张画面待集中人工复核，原件与精确边界见[真机实测记录](同候选采集重启与敏感业务实测-20261016.md)。

## 已实现的边界

- 新标准manifest明确声明 `capture_restart_version:1`，旧候选没有该能力时仍拒绝；不更改普通更新的同release与不限时门禁。
- `auto_update prepare --capture-plan` 离线冻结当前clean原包与全新标准采集计划，校验原Zip、三个生产组件及配置原字节。run要求实际安装文件全部等于该原包、旧采集已停、无未解决事务和无配置冲突；原生未受限且有限余额须可靠覆盖整个run租期加60秒，工具不自动改变规则。
- 新分支仅上传采集配置与源boot／run／配置SHA-256绑定的用途请求，不上传NSP/NRO/Overlay。正常家长PIN后只确认一次，NRO领取请求并复用原有安全静默、IPC关闭、flag暂存、三次源不存在证明、flag恢复及有界目标就绪；同release也必须新PID和新boot。
- 用途与配置绑定持久化到journal、领取原件和追加事件；变更、重放、身份矛盾或结果未知不猜测恢复。主机必须拿到新boot实际有效raw才允许后续测试，不能只凭runtime-ready通过。
- 成功后继续新run原始租期，后续危险窗口保留独立前像、恢复与停采。已有raw只追加，不续租，不清理其他操作者标记。
