# 无人值守更新与测试指南

本文说明标准包免系统重启更新的自动化入口。它用于已授权的专用测试机，替换 SD 安装文件、通过正常家长 PIN 确认加载后台、核验接管状态，并保存可离线重跑的证据。入口为 `tools/device/auto_update.py`，不安装 NSP forwarder，不升级 Atmosphère、HOS 或其他 sysmodule。

## 能力与验收边界

2026-10-15 的[探索记录](../调研/历史调查/2026-10/免系统重启更新与自动化测试-20261015.md)证明了指定机器上的免系统重启路径，并保留一次中断与恢复。原始 26 张集中画面已由操作者统一确认符合标题；该证据没有覆盖本文新增协调器、故障重试和构建身份实现。新实现的测试状态见[测试指南](测试指南.md)。旧报告保持封存，不能用它替代新候选验收。

工具区分四种事实：安装文件回读一致、目标进程身份就绪、接管恢复为 active、`ready_for_tests`。最后一种只是允许后续测试的机器前置条件，所有报告仍写 `qualified:false`。真实提示可见性、游戏效果、POWER 真休眠、实体底座操作及生产候选资格必须各自验证；机器状态不能替代人工观察。

新包必须包含 `hot_reload_events_version:1` 和 `build.source_fingerprint`。允许从支持既有安全交接的旧后台首次升级到新包；旧版本没有持久事件，不作为自动化降级的目标。Overlay 的输入隔离已由操作者确认；本工具不重复该实验，也不驱动已打开的 Overlay。

Overlay快捷键按当前管理器/PlayWise配置读取并核实，不将历史机器配置作为固定入口。历史↓管理器入口/返回HOME、PlayWise入口/刷新/过期/详情/PIN页及指定图对输入隔离已分别留存独立人工确认，见[人工复核](验收记录/2026-10/自动化与交互/人工画面复核与快捷键更正-20261015.md)及[管理器补测](验收记录/2026-10/自动化与交互/管理器正确快捷键补测-20261015.md)。旧↑试验条件作废，不重跑已确认的隔离场景；新更新批的截图仍需独立集中复核。受限阶段按[稳定探测方法](真机稳定探测方法.md#画面最后统一确认)有界打开Overlay采集当前原因；普通更新/采集重启仍须先关闭Overlay，不能将原因观察入口用于绕过更新前提。

## 一次准备

1. 按[开发环境指南](开发环境指南.md)配置 Python、devkitPro、FTP 和已有 sys-botbase。sys-botbase 不随 PlayWise 包交付。先完成构建，冻结实际 Zip，保持测试期间没有其他部署者、按键注入者或请求生产者。
2. 使用已有的 NRO forwarder 打开 PlayWise，停在**孩子区、无弹窗、无 Overlay**。运行时后台与 SD 上的 build/artifacts 必须一致；不能从任意 HOME 位置直接运行。更新过程中 B 关闭 NRO，HOME 的最近应用仍应是刚关闭的同一 forwarder，A 重新打开它。不得重排 HOME 或切换用户、游戏。
3. 保持标准空 `boot2.flag`、setup active、无 disable/recovery、请求 pending/processing 空。当天须不限时且未受限，护眼、就寝、强制电视和非电视额度均关闭；工具检查这些条件，**不会为了通过检查修改规则**。设备本地午夜前须留出整轮租期及额外 60 秒。
4. 确认已安装 forwarder 的应用 ID。NRO 位于前台时可用 `python tools/automation/sys_botbase_client.py --host <IP> title` 查询。探索机的 ID 为 `058C622F470EC000`，不能直接套用到别的机器。
5. 无人值守环境通过进程环境变量注入已授权的测试 PIN，命令行仅传变量名。手工启动也可使用隐藏交互输入。当前已验证按键映射仅支持数字 `0、1、3、5、7、9`，长度 1–16；不支持的 PIN 会在任何设备操作前拒绝。工具不提供跳过 PIN 的生产开关，也不把 PIN 写入命令、报告或按键日志。环境变量由外部凭据管理注入，任务后清除。

构建示例（仓库根目录）：

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONIOENCODING = 'utf-8'
python tools/test.py
python tools/package_remote.py --port 18881
```

`18881` 是本次维护者机器已验证的 SSH 映射；脚本默认仍为 `1888`，其他机器按实际 profile 覆盖。统一入口默认构建和校验 Eden `build/eden-test/pctc-eden.nro`，不得用旁路构建替代。包路径以构建输出为准。

## 每轮命令

每轮使用**新的**报告目录。`prepare` 仅离线验证和复制候选，不连接设备：

```powershell
python tools/device/auto_update.py prepare --package <标准分发Zip> --out device-reports/update-run-001 --host <IP> --forwarder <已核实应用ID> --duration-s 300
python tools/device/auto_update.py run --out device-reports/update-run-001 --apply --pin-env PLAYWISE_TEST_PIN
python tools/device/auto_update.py report --out device-reports/update-run-001
```

不传 `--pin-env` 时使用隐藏交互输入。FTP、sys-botbase 端口默认分别 21、6000，可在 prepare 时覆盖。`run` 要求显式 `--apply`；出现 `run.json` 后禁止重放同一轮，包括进程崩溃或网络超时。新的目录也不能用来绕过未解决的原事务。先检查原始 UUID、回执与设备现场，再决定后续动作。

成功后 NRO 留在孩子区，报告 `phase:ready_for_tests`，可接下一批有独立租期的测试。不要直接循环调用更新来掩盖失败，也不要把更新成功等同于后续测试通过。同一候选已经加载时会拒绝无意义重载。

更新和采集重启均从孩子页用独立减号键松开进入正常家长PIN。隐藏L+R入口要求两秒长按，不能用650毫秒短按替代；否则后续敏感输入可能落在普通页面。输入命令没有UI回执，必须从已核实孩子页开始，授权后的界面与原交接事件仍需核对。2026-10-18短按失败与恢复见[工具导航修复记录](验收记录/2026-10/自动化与交互/更新导航失败恢复与工具修复-20261018.md)。

后续重新开启标准采集，先检查原租期能否继续复用。[有目的同候选采集重启](同候选采集安全重启-20261016.md)由新标准manifest的 `capture_restart_version:1` 明确声明，只有完整已安装候选与冻结Zip逐文件一致、旧采集已停止、全新采集run及配置一致时，才可在正常PIN和一次确认后复用安全交接。旧候选没有该声明仍拒绝；不能只移除原同release检查。该新分支的软件回归与生产/Eden构建通过不等于真机已验证。

离线激活检查可加 `--manifest <实际build.json>`；与runtime/raw候选一致且声明新能力时返回 `capture_restart_preflight_required`，没有声明仍为不支持，任何结果都不授权激活或整机重启。普通更新仍要求当天不限时、未受限；采集重启分支允许原生未受限且可靠带符号剩余量足以覆盖整轮租期另加60秒的限时窗口，禁止官方临时解锁、其他限制和不可信余额。工具不为满足前提自动修改规则。

新分支的离线准备示例：

```text
python tools/device/auto_update.py prepare --package <当前clean标准Zip> --capture-plan <全新采集目录/plan.json> --out <全新重启目录> --host <IP> --forwarder <已核实ID> --duration-s 300
python tools/device/auto_update.py run --out <重启目录> --apply
python tools/device/auto_update.py report --out <重启目录>
```

仍须从指定forwarder孩子区、无Overlay开始，不能从任意HOME调用。省略 `--capture-plan` 时保持原升级行为；重启分支不上传生产组件，只在源未变时准备新采集配置和boot/run/hash绑定的专用请求。NRO领取请求一次后执行既有静默、IPC关闭、三次源不存在证明、flag恢复及有界启动；主机要求同release的新PID/boot、原回执、完整有序交接事件及新boot实际有效raw。成功后保留原采集配置继续原租期，后续测试仍需独立前像与停采收尾。失败不重放，不猜测回滚或自动改规则。

导航就绪应在控制事务前确认，不能在等待代理读图时先放宽规则。只读截图预检应绑定实际boot、前台、画面哈希和短时效；过期预检可以重新只读取图，不能重放已启动控制事务或延长后台已加载租期。进入危险窗口后仍保留原来的超时、原ID回执和逐段恢复边界。

独立停采任务不得仅因配置已移除就把claim归档为completed。先保留归档配置的所有权和原像证据，再用 `tools.device.auto_update.capture_stop_proof` 核验同候选/run/boot的完整原流、正常终末原因，以及三次逐字相同且相邻至少7秒的宿主单调时间拉取。缺终末、仍追加、尾行不完整、外来身份或失败终末均保留claim不确定状态；该纯证据函数不发设备命令、不替代健康/所有权检查，也不授予资格。已开始的失败任务不重放，另立补充恢复材料。

后续采集不要假设返回孩子区与打开Overlay只新增固定两件回执；页面返回可能额外刷新。应先保存完整新增ID集合，按当前marker、release/boot/环境与原ID/type回执确认真实握手，Unix毫秒和单调时钟ID不能混筛。正常complete_setup的ok回执也可能先为released并带activate_after，等待其正常转为active，不重复按确认。第五轮的终末事件缺口、原请求恢复及租期到期收尾见[标准采集首批记录](验收记录/2026-10/自动化与交互/标准采集首批与第五轮更新恢复-20261015.md)；原stopped更新记录不因独立恢复而改写成功。

2026-10-16 clean `501647c` 的首次正常升级和显式同候选采集重启已实际执行，随后复用同boot原租期完成敏感PIN／长按业务机器核验与恢复停采，详见[真机记录及附件哈希](验收记录/2026-10/自动化与交互/同候选采集重启与敏感业务实测-20261016.md)。首次升级前的临时不限时是用户授权的独立有界策略窗口，更新工具未自动改规则；两次交接前后各自规则字节一致不等于整批零策略写入。操作者已确认17张画面“全部符合描述”，不扩展为故障注入、游戏或完整候选资格。

## 实际顺序与证据

- 冻结 `candidate.zip`、`plan.json` 与逐文件哈希；运行前再次验证冻结包。只允许标准不可变安装文件，拒绝 live auth、credentials、rules、state 等可变路径及未知文件。
- 保存 `before/`、`preimages.json`、源 PID/boot/release、原规则和新鲜 status；只有正常 status 请求经标准队列提交。没有保存或重写真实 PIN、grant secret、nonce/ledger。
- 关闭 NRO，逐文件保存检查点、上传并回读，最后发布 `build.json`。每个文件更新有临时文件事务；**整包不是跨文件原子事务**。`.tmp/.previous` 或未知 flag/journal 冲突会停止，不覆盖他人事务。
- 打开新 NRO，按正常 PIN 进入家长区并只确认一次。NRO 完成静默、关闭 IPC、暂存启动 flag、证明源退出、恢复 flag、启动目标和验证新身份。
- 主机只轮询 `handover/events/<transaction_id>.jsonl`。不在交接窗口并发读取、复制或改写 `reload.json` / `.tmp`；早期中断中存在读者竞争假设，尚无足够 errno 证据证明它是根因。
- 匹配 target PID/release、新 boot、原 status ID/type 回执。只有保护原因为 `runtime_fingerprint_changed` 时，允许在正常家长页面确认一次 `complete_setup`，保存该原始回执；其他保护原因停止。
- 最后核验 active、无 disable/recovery、同一设备日、规则不变、完整安装文件哈希、空 flag、无本轮交接残留及无待处理请求。截图失败单独记录，不阻止可靠状态采集。

`events.jsonl` 是主机检查点；`audit/*.raw` 保留设备追加事件的不同字节快照，包括末尾不完整行；`requests/` 与 `receipts/` 保存原 ID 请求/回执；`verification.json` 为离线文件索引。`report` 不连接设备，重复运行结果应相同；封存后改动证据会拒绝。人工画面结论另存独立材料，不覆盖机器记录或已封存索引。报告目录含设备状态与安装前像，应按内部测试材料管理。

封存后定位缺失事件使用独立的只读诊断，不重跑`run`或回写旧报告：

```text
python tools/device/auto_update.py diagnose --out <原封存更新目录> --diagnostics-out <独立诊断目录>
```

`diagnose`先核对原目录全部文件及索引、raw文件名中的哈希，再分别列出每个快照的完整事件、缺失/重复事件、顺序、来源与用途绑定、损坏完整行和不完整尾行。快照按文件名排列，不声称时间先后；不完整尾行不能充当终末事件。输出必须位于原目录之外，首次独占创建，重复运行只核对原输出和JSON读回，原件变化或输出被改动即拒绝。该命令不连接设备、不把新进程实际存在推定为完整交接、不推断缺失根因，不授权恢复或重新执行；原`stopped`结论保持不变。

## 期限与失败处理

FTP `450/550` 只有明确包含“No such file or directory”时才视为缺失；权限拒绝、忙或不明确失败均停止。不能把无法读取保护文件当作保护不存在。

整轮租期默认 300 秒，允许 60–600 秒。每组按键另有限定时长与次数，前后检查新增 fatal/crash 和前台身份；设备调用自身仍有 socket 超时，因此租期是停止发起下一操作的上限，不是硬实时断电保证。主机等交接最多 90 秒；NRO 交接/退出/目标就绪期限分别为 10/10/30 秒，只在证明目标不存在时最多再启动一次。短暂 `EBUSY/EACCES/EAGAIN` 的 journal/flag 变更最多等待 500ms，持续失败保留恢复材料并记录 errno/Result。

NRO交接事件追加复用生产FS的有界append路径：仅在尚未打开文件、未写任何字节时，对`EBUSY/EACCES/EAGAIN`及已观察到的`EIO + FS Result 0xE02`最多等待50次、每次10ms；其它EIO立即失败，write/close失败不重放整行。追加仍属best effort，持久失败仍可能缺事件；它不改变交接状态机或原始完整事件门禁，也不能据宿主注入通过推定某次真机终末缺失的根因。

| 停止位置 | 后续处理 |
| --- | --- |
| 前置检查失败 | 查看 `run.json`，一般未上传安装文件；status 本身可能已有原 UUID 回执。解决前提后重新准备一轮。 |
| `installing` / 回读失败 | 按 `current_file`、`installed`、前像与设备 `.tmp/.previous` 判读最后一文件是否已发布。先确认当前运行身份；完整恢复原包或完整补齐冻结候选，再回读全部组件。不能仅替换 build.json，也不能假定 FTP 异常等于未写入。 |
| 交接前失败，源仍在 | 核对原事务与空 flag 已恢复、intent 已撤销、源身份未变。不得强杀源或换 ID 重发业务请求。新 NRO 失败页暂停 IPC/SD 提交，正常重开后重新检查。 |
| 源已退出，目标未就绪 | 保留原 journal/events。新版 NRO 重开时先恢复本事务原 flag，仅在候选字节完整、目标身份匹配且连续三次证明无人运行时进入有界启动等待。未知 PID、其他 release、矛盾记录一律停止。不要通过反复开关 sysmodule 管理器碰运气。 |
| `reconfirm_pending` 超时 | 原 `complete_setup` 可能已执行；查原请求/回执与 setup，不再次按确认，不新建同类 UUID。 |
| 新 fatal、未知写入、身份冲突或恢复未证实 | 停止该设备依赖操作，保存现场。只读排查后再执行明确恢复；不能自动重启、清全目录或回写旧 raw。 |

工具目前**不提供通用自动回滚命令**。不能把旧安装文件覆盖回 SD 就声称旧进程已恢复；运行身份与文件身份必须分别核验。恢复只处理本轮拥有的标记和不可变文件，不能回滚自然增长的使用状态、nonce、ledger、实时 PCTL `0x44` 或其他操作者数据。需要原包回退时先冻结恢复计划，使用整包、正常授权交接并验证；旧包缺少事件版本时不走本自动入口。既有 sysmodule 管理器只保留为单独核实“确实无进程”后的人工应急手段，不能自动停止一个活跃 owner。

独立停采不能只依赖主任务写出的`target-runtime.json`：主机观察中断后，用户正常确认的同候选交接仍可能完成。`auto_update.capture_recovery_target`提供纯离线绑定检查，要求原source、用途请求/配置字节哈希、唯一新增完整有序事件链、当前target、新boot实际raw、claimed与同ID/type成功status原回执全部匹配，pending必须不存在；拒绝不完整尾行、错误Result、多事务和冲突身份。它不连接设备、不修改原报告、不授权规则回滚。独立收尾仍须先核对健康、交接已结束、安装字节和本批配置归属，再仅归档自身配置，取得stop及两次不追加后归档claim；无法证实时保留未知，依赖已加载的有限租期停止。下一轮排程前必须用主任务中断/无target文件的故障回归验证该路径，不能将宿主硬截止当成设备已停采。

## 构建身份与后续测试

`release_id` 新格式为 `playwise-<版本>+<commit前12位>.<generation前16位>`。generation 绑定 Git 跟踪及非忽略未跟踪文件的路径/原始字节指纹和编译器、libnx、libtesla、容器镜像信息；忽略的构建产物和时间戳不参与，同一源码的 release/Lab/Eden 共用 generation。Git 无法读取时构建失败；同一 commit 下改动源码也能区分。它是源码/工具链身份，**不能替代 Zip、NRO、Overlay、NSP 的精确 SHA-256，也不证明 clean 或生产资格**。
