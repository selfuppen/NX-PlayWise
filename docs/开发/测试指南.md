# 测试指南

本指南聚焦 PlayWise 的测试门禁、权威构建入口、Eden 模拟器策略、Device Lab 隔离验证与候选资格流程。逐功能／专项 Host 回归明细已按主题拆分为[功能回归明细与专题检查清单](测试与模拟器/功能回归明细.md)，UI 真机观察项见[UI 实机验收清单](真机与专题/UI实机验收清单.md)。

> 维护约定：新增功能或修复的细项回归请补充到[功能回归明细与专题检查清单](测试与模拟器/功能回归明细.md)对应小节，不再在本文顶部堆叠更新段落；单批实测成绩按月记录在[验收记录](验收记录/README.md)。

## 分批执行与证据记录

按改动范围选择下文回归，执行与恢复按[测试操作手册](测试操作手册.md)，真机安全边界按[稳定探测方法](真机与专题/真机稳定探测方法.md)。具体阶段的进度、执行安排和待确认项放在所属任务的阶段文档中；历史记录保持原候选范围。

| 检查点 | 长期要求 |
| --- | --- |
| 失败传播 | 构建／核验未通过就停止后续部署、签署或提交；显式检查原生命令退出码 |
| 报告重复执行 | 固定输入、JSON落盘后读回，检查schema键与类型符合对应契约、重复结果一致，不以首跑成功代替复跑 |
| 原件与补充 | 封存前两次离线结果一致；之后修正比较器、派生结论或补充观察，另存材料并绑定原哈希，不修改旧raw／脚本 |
| 人工复核 | 保存用户原话、画廊／原图／机器索引哈希，结论只覆盖所确认画面；来源不变不重复询问，机器状态不替代真实可见性 |
| 恢复与业务痕迹 | 原策略、完整0x44／timer、启动项和运行身份按本批前像核对；正常消费、成功领取、nonce及活动保留，不回写旧state制造恢复 |
| 验证层次 | Host、Eden、旧能力、标准候选短链、人工效果和完整资格分别记范围；文档提交不触发无业务变化的新候选部署 |

批次结论与具体人工答复进入对应阶段文档及验收记录，通用步骤只在稳定手册维护。具体批次用量不作为未来fixture或设备默认值。

## 回归覆盖与原适用边界

NRO预览生成器对简体、繁体和英文均运行完整场景；独立规则说明弹窗、规则页过期和1/1分钟密集推演也输出浅暗两主题。真实渲染检查规则汇聚条可用／unknown／受限的三种语义背景，防止四卡待确认但总闸放行的回归。复核规则页顶部不得与受限／未知投影矛盾，并检查16:25恢复与16:28停止、长英文及密集周期的测量排布和省略标记。旧输出目录可能残留已移除场景，覆盖清单应绑定本轮生成器及原图哈希，不能按目录PNG总数声称全部是当前候选。

孩子页七日预览标题与摘要按实际文本宽度两端对齐，预览回归记录生产`draw_text`的坐标和测量宽度，断言三语、浅暗主题的两段文字均完整出现、间隔至少12px且落在标题栏内；记录钩子仅由Host预览的Switch stub启用。护眼不限时日说明保持“不改变全天额度、读数不可用显示未知”，文案目录回归拒绝说明标题/正文重新出现1440计数代理。此处不禁止真实每日额度上限1440或历史兼容材料中的有效说明。

支持页签有状态时，标题与徽标上下排布，徽标宽度来自实际文字测量。`test-ui-primitives`使用固定字体调用`ui_preview <font> --check-parent-tabs`，对三语、浅暗主题、正常/停用/恢复/待完成/失败五种状态和五个根页面加一个计划子页，共180种组合记录生产文字坐标。标题和状态全文须各出现一次、均在页签内且上下至少相隔2px；正常状态不出现徽标，计划子页不残留根页签或徽标。该检查属于日常Host绘制回归，不启动Eden；完整预览另保留`support-incomplete`场景。

实用文档按[预览场景清单](../images/README.md)选择正常使用、休息、不限时、限制并发、过期与浮窗验证/用量场景；`--with-previews` 从当前代码生成后同步到中英文使用指南，不读取历史画廊。运行 `python tools/package_remote.py --with-previews`（默认含 Eden），再用 `python tools/build/sync_doc_previews.py --check` 检查图片一致性；复核文档图片路径、语言与配文对应，示例分钟数不作为真机断言。

标准后台无代理自然换日的Host核验入口为 `tools/device/pctl_production_midnight.py`，专项回归 `tests/devkit/test_pctl_production_midnight.py` 纳入 `tools/test.py`：保留真实跨界无效行，核对同boot相邻日、原追加诊断、午夜低值和两侧60秒增长、无1440／自动1451及每条0x44无关字节保持；拒绝服务失败、时钟／累计跳变、短窗口、断档、混boot、保存失败和覆盖旧输出。旧午夜报告入口保持原兼容，详见[历史核验范围](验收记录/2026-10/1952去代理/1952无代理自然换日离线核验-20261016.md)。

`test_home_details_status` 覆盖三语的健康策略关闭、不限时wire零、已知0与未知累计、120/121秒边界、跨日/回拨/未来捕获、刷新失败/等待与恢复、真实休息期限及电视模式，并验证投影不修改模型。生产绘制使用相同详情投影，预览增加 `today-policies-off` 与 `today-policies-off-stale`；真机以新clean候选另做不刷新过期/Y恢复链。

Overlay 清单容量回归在 `tests/c/test_host_core.c:test_overlay_handshake_large_manifest`：4095 字节完整清单必须同时通过握手及持久 ready 状态验证；release 不匹配和 4096 字节超限均拒绝并保留原 ready，PCTL 写入/1451 次数不变。C 权威验证执行 `python tools/package_remote.py`，保留默认 Eden。真机触发及新候选补测分别记录。

`test_policy_status`另覆盖Overlay未初始化墙钟的正数uptime：后台本地日期/日内秒随回执往返解析，关闭就寝可正确投影；29秒有效、30秒和缺失单调起点无效，跨午夜须刷新。分数/越界日内秒、日期不匹配、捕获不属于同一`completed_at`及旧结果缺clock均保持未知；默认结果清旧时刻、Host时间provider秒值确定性初始化。恢复路径的回执读取使用协议规定容量，不因新增可选元数据截断测试。权威验证仍走统一构建并默认打包/校验Eden，真机显示另绑定新候选。

`test_ui_state` 的直接累计用例另覆盖Overlay无本地墙钟时：后台完成时间投影、原捕获年龄加整个请求耗时的120秒边界、已过期回复、完成时间早于捕获、缺失完成时间及缺失单调起点。未知只清累计可用性，保留原捕获和业务额度；持久旧结果不获得新鲜起点。此回退不新增时间服务，真机复测另绑定新候选。

Overlay标准预览的 `overlay-console-details` 与 `overlay-console-details-unknown` 覆盖就寝期间详情的独立累计、原捕获UTC时间和未知展示，三语共用生产绘制代码并断言不伪造累计或刷新时间；冻结r2已发现的详情缺口见[浮窗补证](验收记录/2026-10/1952迁移/PCTL1952-P1浮窗展示补证-20261014.md)。

回执容量回归 `tests/c/test_result_capacity.inc` 通过真实标准队列覆盖超过旧6144字节缓冲区的状态回执、近期事件满容量轮换及不完整尾行，逐次用 JSON 解析核验完整 `completed_at`；构造器分别验证完整成功和不足容量失败。环境重新接管回归在同一分钟内先启动宽限，再推进五秒，确认无新请求/通知/停用变化时也立即施加原周规则。权威验证使用 `python tools/package_remote.py`，默认含 Eden 构建校验。

NRO 家长区入口 PIN 回归使用固定时间与内存存储，覆盖错误后停留弹窗、连续错误、正确重试、取消恢复焦点、主动进入只读支持及脱敏诊断；验证第 5 次失败的 30 秒冷却、重试禁用、关闭重进不能绕过冷却、到期不自动打开输入框，以及凭据损坏和写失败保留原支持路径。三个按钮的手柄与触摸共用动作并检查命中区域不重叠；重试输入复用忽略原触摸直至抬起的 PIN 流程。`python tools/package_remote.py --with-previews` 生成简体、繁体、英文及浅暗主题的今日安排、密码错误与冷却预览，核对文案和按钮无溢出，并同步使用指南截图。

独立使用时间能力探测使用单独后台和原始证据流，不沿用 Device Lab 阶段或资格流程。入口、原始字段、无人值守边界和快速批次见[独立使用时间能力探测](../调研/历史调查/2026-10/独立使用时间能力探测.md)。构建使用 `python tools/package_remote.py --with-usage-probe`，保留标准包与 Eden 应用门禁；读取失败、超额连续加时、改时和报告未知状态的回归位于 `tests/devkit/test_usage_probe.py`。

分区卡片 UI 回归：`python tools/package_remote.py --with-previews` 覆盖正式 NRO、Overlay 与 Eden 测试应用，并生成三语浅暗主题截图。Host UI 测试覆盖今日三个状态卡的触摸命中、手柄列间移动、返回焦点、草稿保留，以及等待中和儿童界面的拒绝路径；备份恢复勾选项须位于分组标题下方且恢复按钮不覆盖分组。Overlay 以稳定 action enum 映射视觉顺序，验证八项遍历可逆、电视解除与危险恢复的顺序和共享触摸布局。截图人工检查额度页、两种调度详情、恢复页及浮窗的文字换行、状态与用量区分。

## 持续集成门禁

`.github/workflows/ci.yml` 在 push 与 Pull Request 时于 `ubuntu-latest` 运行 `make test`：`test-host` 全程使用 gcc/g++（不依赖 devkitPro），编译并运行四个 C host 套件与 `ui_preview --check-primitives`；`test-python` 执行 `tools/test.py` 的全部 Python 回归。另有可选 UI 黄金图 job：`make ui-previews` 后用 `python3 tools/build/sync_doc_previews.py --check` 与已提交预览图做字节级比对。CI 不含 devkitPro 容器，因此 NRO、Overlay、sysmodule、标准安装包、完整交付包与 Device Lab 包的权威门禁仍必须在本地通过 `python tools/package_remote.py` 执行。

## 权威容器验证

涉及 C、C++、Makefile、NRO、Overlay、sysmodule 或 package 时必须执行：

```text
python tools/package_remote.py
```

脚本在单次 SSH 会话中清理现有构建产物，运行 C host、UI 和 Python 回归，编译三个标准分发组件并生成标准安装包与完整交付包。

分发门禁断言：

- `build/packages/` 只有当前版本的标准安装包 `playwise-v<当前版本>.zip` 和完整交付包 `playwise-complete-v<当前版本>.zip`；
- 标准安装 Zip 只包含标准分发 sysmodule、NRO、Overlay、`boot2.flag`、`build.json`、`package-artifacts.json`、不可变 `defaults/*.json` 及空运行目录，不包含六个根目录可变 seed、安装器或离线网页；组件清单必须与包内三个运行文件的大小和 SHA-256 完全一致；
- Device Lab Zip 保留 `atmosphere/contents/4200000000BD23F0/flags/` 目录项但不包含 `boot2.flag`；首次长按切换必须在目录原先不存在时也能原子创建 Lab flag。模拟 `standard_disabled` journal、标准 flag 已暂存且 Lab flag 尚未创建的中断态时，Lab NRO 不连接 `pwtl:u`、可显示恢复页，标准 NRO 在自身 flag 缺失时也不连接 `pctc:u`；两者均不得黑屏。
- 完整交付 Zip 只包含字节一致的当前版本标准安装包与 `playwise-offline.html`，拒绝缺失、重复、额外、路径穿越或内容不一致的成员；
- Zip 内 `build.json` 与构建阶段外部生成的 release manifest 完全一致，profile 为 `release`；
- 三个二进制都嵌入同一 manifest，NRO/Overlay 均显示当前构建版本；NRO 还必须嵌入项目仓库和 PWA 地址；
- 无 LAB handler、标准协议外请求、运行时控制模式、`capabilities.json` 或占位 secret；
- 不 seed `credentials.json`，首次启动必须生成唯一 secret；缺失运行文件只从 `defaults/` 原子创建，已有文件即使无效也不得覆盖；
- 直接把新版安装包合并到已有目录，以及使用盘符脚本 `tools/install/install_package_to_sd.ps1` 或 DBI MTP 脚本 `tools/install/install_package_via_dbi_mtp.ps1`，都必须替换程序和 build manifest，同时逐字节保留 credentials、PIN、rules、state、ledger、logs 和 backups；安装脚本不打入运行时 Zip。DBI MTP 脚本必须拒绝名称含 `install` 的 NSP/XCI 安装入口，并在复制后通过 MTP 读回逐文件校验 SHA-256。
- Switch 状态适配器必须先在 `pctl` 查询 `1455 restricted_now`；仅当该字段不可用时，才允许复用读取私有设置的短时 `pctl:s` 会话补读。不得因第一条通道失败而把未知值当成 `false`，也不得跳过即时写入后的运行时确认与回滚。

禁止用手工 SSH、`docker exec` 或复制回本地代替该入口。

## 标准版在线覆盖与热加载

Host C/UI/包测试至少覆盖：相同与不同 `release_id`、目标 profile/PID/boot ID 不匹配、家长确认操作只消费一次、非待加载状态没有隐藏按钮、孩子区无触发入口、等待态阻止其他设置、活跃 recovery、交接超时、源 PID 未消失、flag/backup 冲突、各 journal 阶段恢复、组件缺失/哈希不符以及目标不存在时至多一次重试。源码契约必须确认不存在 `pmshellTerminateProcess`，且证明源 PID 消失、恢复 flag 的顺序早于目标启动。

真机在 OLED / HOS 22.5.0 / Atmosphère 1.11.2 上使用与候选 Zip 哈希绑定的在线安装验证：

1. 关闭 NRO 和 Overlay，但保持主机开机；通过 DBI/MTP、FTP 或 USB 完整覆盖标准包的 `atmosphere` 与 `switch`。
2. 重新打开 NRO，确认孩子区只能看到“进入家长区处理”；验证 PIN 后出现热加载确认，取消后可从“软件信息”再次进入。
3. 确认后记录旧/新 PID、release ID 和 boot ID；交接期间并行提交返回 `QUIESCING`，UI 持续显示 1/4～4/4 阶段且其他设置不可提交。
4. 成功后核对配置、PIN、密钥、规则、nonce、额度、历史和 recovery 数据未丢失，再重新打开 Overlay 并确认自动连接新版 IPC。
5. 在 `prepared`、`boot_disabled`、`boot_restored`、`target_launched` 各阶段中断 NRO，重新打开后确认空 flag 恢复、当前安装后台可启动、始终只有一个 PCTL owner。
6. 注入不支持 quiesce、源进程不退出、目标身份不匹配和目标启动失败。旧进程仍在时必须继续可用；退出后的失败必须保留空 boot flag，只提示完整重启，不自动重启、不强杀。

电脑读卡器拔卡流程仍使用关机覆盖并重启，不属于热加载验收。Device Lab 继续按下节独立验证，不纳入标准控制器重构。

### 构建与运行

发版前可通过统一入口单独准备并校验 Eden 应用：

```powershell
python -X utf8 tools/package_remote.py --only eden
```

已在 devkitPro 环境中时，可用底层构建目标快速迭代：

```sh
make eden-test-nro
```

产物为 `build/eden-test/pctc-eden.nro`。Eden 只需加载该单个 NRO，不需要预先铺开安装包：首次运行会在 `sdmc:/switch/playwise-eden` 自行创建独立测试数据（含 `build.json`、`defaults` 之外的六个运行文件、固定测试 `credentials.json` 和假 `environment.json`），并在 NRO 进程内用模拟 PCTL 运行真实的 `sysmodule_core`。Eden 的 Windows 虚拟 SD 不保证跨目录 `rename` 的队列语义，因此该 profile 通过进程内 IPC 桥同步提交请求并照常持久化 result JSON；PIN 等模态界面不会阻塞处理，`status` 和 `complete_setup` 都会及时返回。真实 SD 原子队列仍由 host 测试和真机路径覆盖。

```sh
python tools/grant_code.py --tier-minutes 30 --device eden-switch --secret playwise-eden-test-secret-00000001
```

界面持续显示红色 `EDEN TEST` 角标，传输行固定显示"传输：Eden 模拟后台"。测试状态跨启动保留；需要重新走首次设置时只删除 `sdmc:/switch/playwise-eden`，不得删除或覆盖 `sdmc:/switch/playwise`。

该入口覆盖初始化、PIN、页面导航、规则、离线码、nonce 和 bedtime 模拟限制。家长区“时间计划 → 就寝时间”与标准 NRO 共用完整策略编辑；开始与结束时间使用小时/分钟双栏，L/R 选栏、右摇杆上下调整、ZL/ZR 前后 15 分钟，按 `+` 完成后再保存并让模拟后台重算。Eden 中开启交互音效后，危险确认按满 1 秒必须播放独立完成音效；关闭正在生效的 bedtime 必须恢复进入窗口前的模拟 PCTL 快照并清除恢复事务，不得产生 `310 recovery_failed` 或 `transaction_restore_failed`。Eden 不会阻断 NRO，且不要求 Tesla Overlay、官方设置确认或 Overlay 握手；这些仅是 `PLAYWISE_EDEN` 的测试豁免。**该结果不作为真实 PCTL 私有命令、0x44 layout、入口阻断或计时效果的证据，也不替代真机资格验证。** `python tools/package_remote.py --only eden` 只执行所选目标的构建与产物校验，不启动 Eden、不注入操作，也不自动证明 UI 或业务场景通过；它不构建生产 Sysmodule 与 Overlay。提交 C／NRO／Overlay／package 改动的最终验证仍须执行默认 `python tools/package_remote.py`，保留标准包和 Eden 的全部必要门禁。

模拟 PCTL 无当日可恢复基线时从今日已用 `min(30, 当日已过分钟)` 开始，避免 00:10 注入 30 分钟。存在当日电视模式采样基线时，重启恢复其总用量（含不足一分钟部分）与已确认控制目标，并取当日已知护眼／电视累计的可靠高水位；关闭 NRO 的间隔不累计。规则或状态读取失败不猜测恢复。设置有限额度且计时开启时，NRO 运行期间每满 60 秒增加 1 分钟已用、减少 1 分钟剩余，界面自动刷新，到额度耗尽后停止增加。当前 Eden 启用直接累计模型：真正不限时下即使 timer=false 仍累计，用于模拟护眼／非电视业务；累计最多为 1440 分钟，这只是模拟计数上限，不是安装 1440 分钟限额。BLOCKED 和临时解锁时冻结累计，普通限时下计时停止也不累计；跨日重置模拟已用时间。以上均为本地模型行为，不是 Horizon 计时证据。

按本次改动选择适用场景，保留成功路径和对应拒绝／失败路径；错误与存储故障注入优先放在 Host，未支持的 Eden 故障注入不算已执行：

1. 首次设置、PIN 进入／错误、取消与长按确认；页面三语、双主题和焦点／触控反馈。
2. 离线码预览、兑换成功、重复兑换拒绝和自主缓冲领取；同时核对回执、余额、nonce／领取资格与活动记录。
3. 每周／节假日／指定日期／今日调整的优先级、模拟护眼／就寝／电视限制、并发原因及解除单个原因后保留其他限制。
4. 保存规则、备份与导入、正常关闭后重开，核对持久化结果；不得将重开 NRO 解释成生产后台重启或主机重启。

构建／产物校验通过、模拟器启动成功和业务场景通过必须分别记录。每批绑定实际加载的 NRO SHA-256、对应生成 manifest 的源码／release 身份、Eden 版本、隔离数据前提、操作及预期、同 ID/type 回执和持久化断言；可见效果另留必要截图。仅有 `status:ok`、启动日志或历史回执数量不证明完整场景通过。Eden 只在文件缺失时写入 `build.json`，虚拟 SD 中的旧文件不能单独证明当前 NRO 身份；不要为了记录新身份覆盖待测业务数据。结果区分通过、失败、未执行与前提不满足，按实际覆盖范围表述，不转为真机资格。

当前统一构建没有 Eden 场景自动驱动。要声明无人值守回归通过，须另有隔离数据准备、输入驱动、超时／失败上限、JSON 断言、必要截图和有界收尾，并执行上述场景；仅生成 NRO 不满足这些条件。测试数据只操作 `playwise-eden` 隔离目录，不修改生产 `playwise` 数据；封存原件与离线复核遵守本指南的分批记录要求。

`test_dock_midnight_allowance_change` 覆盖 00:10、非电视额度 1410、总额度 120 换为 60 的可靠换日与读取失败；`test_eden_timer_restart` 覆盖同日重启纳秒基线、状态读取失败与次日 00:10 启动。UI 三语回归核对已用 10、草稿 1410 得到非电视预计余额 1400，以及耗尽、未知与过期状态；备份入口回归固定默认创建页和创建按钮焦点。

隔离断言：统一入口交付的 Eden NRO 位于 `build/eden-test/`，`make packages` 与 `make device-lab-package` 均不构建也不携带该目标；`python tools/package_remote.py` 无条件扫描标准分发与 Device Lab 二进制，拒绝任何 Eden marker。普通构建回归保留默认 `--with-eden`，构建并校验 `build/eden-test/pctc-eden.nro`；不得用 `--only eden`、`--skip-tests` 或 `--no-eden` 替代生产标准构建门禁。

### 引导式真机取证

验收环境为 Nintendo Switch OLED、HOS 22.5.0、Atmosphère 1.11.2，并已安装 Tesla/Ultrahand。先在官方家长控制中配置当天正在生效的非空计划，确认剩余至少 10 分钟；准备两个允许短暂中断、没有未保存进度的非关键游戏：

1. 安装 Device Lab Zip，运行 `playwise-device-lab.nro`。确认首页自动显示“准备启用实验后台”，长按 `ZL+ZR+A` 一秒。NRO 会先通过 `pm:shell` 只读确认源进程；安全交接可用时直接零重启进入 Lab，不可用时自动准备 boot flag 并只要求重启一次。若提示冲突或中断，只按页面引导恢复，不要手工覆盖 flag/backup。
2. 从 Tesla/Ultrahand 打开 `playwise-device-lab.ovl`。默认选择“资格批次”，用左右键记录旧实验字段 `original_pause_state` 的取值（见本节历史假设说明）。自由聚焦、Timer 激活 A/B 和高级完整取证仍可单独选择。批次开始后 Overlay 显示四项进度、匿名游戏 A/B、下一动作、倒计时、判定/恢复状态和报告路径；按 `Minus` 可展开英文机器值、请求 ID 与错误码。
3. 聚焦模式直接进入 `restriction_effect`。完整模式才依次完成 `home_stopped`、`home_started`、`game_foreground`、`game_suspended`、`sleep_wake`，每个普通阶段自动采样 75 秒；若原始 0x44 全零，界面和报告会提示第 3–5 阶段前提不足，不得据此声称生命周期已验证。完整生命周期复测应先配置非空的 Nintendo 周计划。
4. 在安全游戏中进入“观察时间限制效果”，确认无未保存进度后使用实体手柄长按 `A` 两秒；触摸只能看到安全提示，不能开始该阶段。关闭 Overlay，观察约 15 秒内是否出现时间限制提示，以及游戏实际是继续、暂停/挂起还是退出；后台会自行恢复，不要求 Overlay 保持打开。随后必须重新打开 Overlay，先记录提示可见性，再单独记录游戏实际行为。等待人工观察时不显示“立即恢复”，从 NRO 进入也只会提示返回 Overlay。
5. 只有 Overlay 显示 `exact_restore_proved` 才算恢复得到证明。若显示 `restore_required`，立即按 `A` 重试恢复；Lab `disable.flag` 会阻止任何后续取证写入。
6. 人工观察完成前只会生成 `lab/report-<run-id>.draft.json`。每项 final 且 `exact_restore_proved` 后直接选择“继续下一项”；结果与槽位预期不符时报告仍保留，但批次停在原槽位等待重试。四项依次为 Timer A/B、暂停开启的游戏 A、暂停开启的游戏 B、暂停关闭且继续运行的游戏 B。完成后核对官方家长控制状态与原始设置一致，并保留四份 accepted 报告及 `reports/<campaign-id>.campaign.json`。关闭 Overlay、睡眠或提前退出不会丢失进度；放弃只归档，不删除证据。最后从 NRO 恢复正常后台：热切换成功时无需重启，回退路径只在末尾再重启一次，并验证标准 PlayWise 正常读写。

## 截图视觉验证（权威，替代 campaign 人工肉眼层）

campaign 限制矩阵的人工肉眼层（关 Overlay 肉眼看限制提示 + 游戏暂停/挂起/退出，再到设备观察 UI 点选）由「sys-botbase 抓图 + Claude Code 本地判读」替代，并成为放行 `promote` 的**权威**证据——截图留存且 SHA-256 绑定，比一次性的人工肉眼更可审计。机器 SD 取证、campaign 四槽结构、哈希绑定与发布隔离保持不变；bedtime/eye-care 的视觉项仍人工（后续迭代纳入同一框架）。

4. `python tools/automation/vision_capture_driver.py submit --host <ip> --run-id <run_id>`：按已封存判定点选设备观察 UI，设备 app 写出完整 schema-v2 报告。

## 能力探测（capability_probe，只采集不判读）

`tools/lab/capability_probe.py` 是真机**能力探测**工具，用于快速弄清某能力在真机上到底怎样，而非产出可晋级的资格。它经 FTP 把 `lab_*` 请求写进 Lab sysmodule 的 `inbox/pending`（与 Overlay 提交等价）驱动整条会话，sys-botbase 只用于 `pixelPeek` 抓图；零 C 改动，不需要 Overlay 导航或物理长按。运行期**绝不**提交 `lab_observation`、不封存判定、不走资格门禁——只采集，判读推迟到最后由人工（或人工决定交给 AI）读。因此它是探测/排障通道，不替代 `verify_device_qualification` 的权威资格。

- 自检：`python tools/lab/capability_probe.py preflight --host <ip> --url ftp://<ip>:21/`——校验 FTP、sys-botbase、Lab sysmodule 是否已 booted 且在认领 inbox、`pixelPeek` 是否可用（依赖 Atmosphère debug/debugunit flag），以及前台是否有游戏。

## PDM 与 Bedtime 证据门禁

按游戏统计发布前，独立只读 `pdm:qry` 实验必须对应用启动、前后台和退出事件执行 HOME、游戏前台、挂起、待机、换日、手工改时钟、多账号和未知软件 A/B。报告需证明事件去重、乱序、缺失和时钟回拨的降级语义，并明确统计为本机使用；证据不足时 Release adapter 保持 unavailable，不能显示今日/七日 Top 3。整个实验不能调用 PCTL `1952`，不能写 rules/state 或改变控制状态。

Bedtime 已进入默认关闭的标准包，但只允许用 Device Lab 形成资格证据。资格门禁必须证明：到点和窗口内唤醒均在 60 秒内触发；弹窗期间游戏、Homebrew、HOME、系统设置和 PlayWise NRO 五类入口全部被阻断；Overlay 仍能打开、共享 NRO 的 PIN/错误次数/冷却、执行单次授权，并分别完成跳过当前实例、关闭 bedtime 和完整安装快照恢复。每个恢复动作都必须提交请求、重读 PCTL 并解除弹窗；若每日额度仍耗尽，应显示“仍受每日额度限制”而不是误判失败或完全解除。

还必须验证普通加时与自主缓冲在窗口内被拒绝且不消费 nonce/资格、同日可靠余额恢复、跨日新额度、重启继续执行、改时钟立即重算、进入/退出写失败、`disable.flag` 下恢复白名单。后台失联时 Overlay 只能显示“请求未确认”和外部恢复说明，且 `restore_install_snapshot.flag` 不得出现。Overlay 缺失或未握手时，标准 NRO 必须在首次启用前确认 Nintendo 官方家长控制已开启并清楚提示风险；接受后允许启用，后续无握手仍继续计划以防绕过。raw block、恢复或任一入口矩阵不能证明时，候选不能晋级完整资格，禁止用普通 0 分钟额度代替。

Bedtime 时间边界还必须在已启用 Nintendo 官方家长控制的真机上验证。状态确认只检查官方家长控制是否开启；记录限制提示和软件实际行为，不要求额外的暂停软件开关。PlayWise PIN 不能替代 Nintendo 官方 PIN。使用正确的官方 PIN 把时间调整到窗口开始前、窗口内、窗口结束后和跨日一侧，确认后台记录时间异常并立即重算；报告必须注明首版不维护独立可信时钟，也不承诺防止改时钟绕过。

SD 脚本默认只预演；`-Apply` 前必须核对盘符和主机备份目录。Device Lab 资格输入包括原有完整 campaign，以及同目录 final `bedtime-qualification.json`。模板中的 `null` 必须由本次候选真机事实替换，不能凭推断填写。工具只有发现一个完整批次时才自动选择；多个批次必须增加 `--campaign <campaign-id>`。任一 accepted 报告或 bedtime 报告缺少环境/构建身份、入口阻断、Overlay PIN 与三级恢复、生命周期、raw offset 或精确恢复证据都会失败。晋级工具只复制验证时计算哈希的原 Zip，不重新编译。要把护眼纳入标准包时，另生成 final `eye-care-qualification.json` 并给 `verify_device_qualification.py` 加 `--require-eye-care`；门禁要求休息开始/恢复在 60 秒内触发、全部护眼观察为真，且护眼休息的 0 分钟 BLOCKED 不计入每日额度（`eye_care_consumed_daily_allowance==false`）与 0x44 精确恢复。护眼属候选 pending，默认不要求；但报告若存在，无论是否 `--require-eye-care` 都会被 fail-closed 校验。

可用 `python tools/lab/device_lab_roundtrip.py` 把上述步骤串成免拔卡的 FTP/MTP 往返：`push` 复用 FTP 安装器推候选包（`--mode preserve` 覆盖写、逐字节保留运行时数据），`pull` 幂等拉回设备 `switch/playwise-device-lab/{reports,lab,logs,results}` 到扁平 `device-reports/`（正是 `--reports` 期望布局）与 `switch/playwise/{logs,results,ledger,support}` 到 `device-reports/standard/`，`verify`/`promote` 再串联既有门禁与晋级；`all` 子命令在 push 后打印必须手动完成的真机核心清单，等操作者回车再拉取。拉回后用 `python tools/lab/assert_device_evidence.py --evidence device-reports/standard` 机器核验标准包验收的可判项（步骤 13 无 `start_timer`、`ipc-client.log` 八字段与脱敏、nonce 单次消费、result 状态），属 advisory，不改变权威门禁。人工观察用 `python tools/lab/capture_device_observations.py bedtime|eye-care|standard` 引导录入：bedtime 直接生成可被 `verify_device_qualification.py` 接受的 `bedtime-qualification.json`；eye-care 同样生成权威的 `eye-care-qualification.json`（模板 `make_eye_care_qualification_template.py`，校验器 `verify_eye_care_report`，opt-in 于 `--require-eye-care`）。真机核心——限制提示可见性与游戏暂停/挂起、长按 `ZL+ZR+A` 与 `A` 两秒、物理拔插底座、官方 PIN 改钟——无法远程，自动化只负责搬字节、机器断言与引导录入。

随后必须使用同一标准安装包执行：

1. 在已启用官方时间限制的主机上安装并重启。
2. 确认首次只读预检完成，未确认前没有 PCTL 写入。
3. 创建一个自选长度的数字 PIN，确认自动生成的 secret 不等于任何公开占位值，确认一周规则。
4. 家长确认接管后，验证安装 snapshot、解除当前限制、5 秒同步和 Active 状态。
5. 分别测试 status、设置今日总额度、快速加时固定/自定义值、今日不限时、清除今日额度调整和周计划保存；确认清除操作只移除 `today_override`，指定日期额度、bedtime 跳过及长期规则不变。随后从 Nintendo 系统临时解除限制，确认原限时规则和额度读数保持，睡眠唤醒后原限制继续生效。
6. 使用一个由当前候选环境生成的 15 分钟 v2 加时码，确认 timer、剩余时间和 nonce 仅提交一次。
7. 制造一次状态传播延迟，确认显示“正在同步”；30 秒内确认成功或按契约回滚。
8. 重启验证 setup、rules、state、ledger 和未完成事务恢复。
9. 创建 `disable.flag`，确认只熔断写入；再验证诊断和安装快照恢复。
10. 恢复安装前 snapshot，确认原始 raw/timer 状态可被精确证明，并进入 `restored`。
11. 确认 `restored` 下首次设置第 3 步显示“解除停用并重新接管”；确认后必须先重新经过预检，成功时才解除 `disable.flag` 并在 5 秒宽限后进入 `active`，失败时必须保留停用标记和 `restored`，且安装 snapshot 不得被覆盖。
12. 制造一次 Enforce 状态传播延迟，确认 30 秒窗口内同一进程的 scheduler 不会把活跃 recovery 误判为启动遗留事务；随后在窗口内真实重启，确认遗留事务被恢复、创建 `disable.flag`，并可从 `active` 状态通过“解除停用并重新接管”安全恢复。
13. 设置次日为 60 分钟限时，在当天结束前让主机停留 HOME 后进入待机；次日保持屏幕和游戏未打开至少 90 分钟。确认 `pctl_debug.jsonl` 只有 Enforce 的 `apply_target`，没有 `stage:"start_timer"`，唤醒后 1454 剩余时间没有因后台跨日同步而减少，界面也不得显示虚假的 60 分钟额度消耗。
14. 分别记录 HOME、系统设置、游戏前台、游戏挂起、待机和唤醒后的 1454/1952 A/B。确认 HOME、系统设置等亮屏使用按 Nintendo 官方主机使用语义累计，待机期间不累计，唤醒后恢复累计；不得再要求“进入真实游戏才开始计时”或“返回 HOME 不消耗”。若候选环境不能满足此项，不得把它标为新的资格基线。
15. 配置跨周、跨月和跨年的指定日期额度，逐日核对 7 天预览及“今日额度调整 > 指定日期额度 > 国家节假日 > 周计划”；重启后规则不丢失，计划结束首日恢复下级来源。
16. 在限时日通过手柄和触摸各领取一次自主缓冲，核对第二次拒绝、换日恢复和 1440 分钟截断；在 PCTL 写入、SD 状态保存和 result 提交失败的注入包中确认资格与 PCTL 前像均恢复。
17. 在浅/暗主题中检查家庭活动翻页与清空、7/30 天可靠天数、孩子区今天/明天来源和中性文案；随后覆盖 HOME、前台、挂起、待机和换日，确认统计失败或文件损坏不影响时间控制。

2026-08-10 的结论是早于当前 PCTL 改动的历史证据，不能资格化当前候选。新 manifest 的 `verified_environment.result` 和 `qualification.status` 默认均为 `pending`；打包时显式提供 `--manual-device-verified` 和三个验机环境参数，则标准包记录 `manual_verified`，范围为主要功能人工验机。完整资格工具接受这两种候选状态，但仍要求无 tracked 修改、完整报告和原包哈希匹配。只有 `build/qualified/qualification.json` 才表示该原包已通过完整资格验证。

## 失败取证

优先从标准分发构建的支持页导出脱敏诊断。若 NRO 无法启动，保留：

- `build.json`、`setup.json`、`compatibility.json`、`environment.json`；
- `backups/install_pctl_snapshot.json`；
- `recovery/active/`；
- `results/`、`logs/` 和相关 crash report。
- Overlay 或 NRO 显示 SD 传输时，检查当日 `logs/YYYY-MM-DD/ipc-client.log`；确认记录包含 `client`、`stage`、`rc`、`module`、`description`、`version` 和 `expected`，相同连接失败不会随每次刷新重复写入，且日志中不含请求正文、PIN、密钥或 8 位码。Overlay 进程启动后再提交一次状态刷新，正常连接必须记录 `client=overlay stage=connected`（此前发生过连接失败时）并在界面显示“传输：IPC”；退出并重新打开 Overlay 后重复验证，排除 SM 会话只在初始化阶段短暂有效。
- Overlay 分别在正常、每日额度耗尽、就寝生效及解除就寝后仍受每日额度限制时打开：每次都先显示加时码页；`L` 只在缓冲可领取且未受就寝限制时提交，`R`/触摸可进入 PIN 页，`-` 展开状态；就寝期间可编辑代码但不能提交。就寝页 `Y/X` 与触摸可跳过或恢复本次窗口；当前窗口恢复需 PIN 和长按，失败保留跳过，成功后立即复读限制状态。PIN 页验证左右摇杆八方向 `1`–`8`、摇杆死区和单次锁存、十字键四方向、`X/Y` 输入 `0/9`、`ZL` 退格、`+` 验证和 `B` 返回；触摸不能直接输入数字，只能退格、验证或返回。页面仅显示静态方向示意、掩码和位数，不随输入高亮真实数字；往返家长区保留未提交代码，输错与冷却正确执行。家长区六项动作始终可见，不适用项禁用并解释；成功一次后再次执行须重新验证 PIN。动作页摇杆首次移动一步，持续推动约 400ms 后以约 180ms 重复，长帧不跳过多项。确认浮窗引导文案没有 emoji 乱码，特别是“额度玩完后将暂停”。

不要对外发送 `credentials.json`、`auth.json`、完整 ledger 或原始离线码。要停止自动启动，可移除 `atmosphere/contents/4200000000BD2300/flags/boot2.flag`。
