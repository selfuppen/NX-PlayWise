## 一、性能、资源与基础设施回归

### 导航快照、回执降频、性能与渲染优化

`tests/nro_setup/test.c`链接生产导航代码，验证50次同日有效快照的页面往返不读写存储、不提交status、不重置时间；覆盖120／121秒、跨日、回拨、读取失败状态、过期用量、未决请求／兑换、恢复焦点、手动刷新、PIN和未保存草稿。`tests/c/test_input_owner.c`对50个20ms持续按键帧统计已阻止输入时只复查4次（12次全文读取及12次metadata），并核对首次输入即时检查、松键恢复、未知存储重试、轮询间时钟回退和租约续期／到期；统一构建保留全部C/Python/UI及默认Eden产物校验。

空闲功耗调查与同条件真机复测方法见[耗电与空闲性能排查](../真机与专题/耗电与空闲性能排查.md)。Host 的 Overlay resource/memory 测试覆盖后台1000/250ms等待及更近期限优先、可见／持键20ms与隐藏空闲50ms输入节奏、HOME／POWER禁止自动打开后的无限等待，以及隐藏UI线程5秒／250ms节奏与后台身份10秒缓存；Python生命周期契约检查生产调用接线（仅待处理通知加速、采样合并落盘30秒及其交接前／退出补写、Device Lab保持逐次写入、冻结账本复用主循环读数、隐藏浮窗偏好检查不依赖输入而ready租约仍为每秒续写／1500ms且只在输入中立时续写）。控制安全回归的采样合并落盘用例覆盖：未开启时逐次写入、开启后只在30秒边界写一次且内存读取始终最新、模式变化立即落盘、恢复事务前像先补写且回滚不退还消耗、重载前补写、停用后到期补写、写失败保留并重试、重启后按保守口径衔接不丢用量。通知回归覆盖开启但空闲时不加速也不读取接收者配置、待处理与限频期间保持加速、ready租约仍受1500ms／2000ms上限约束，以及无人应答且观察已过期的提议不会产生任何通知（这是租约不能延长的原因）。冻结账本回归按2026-10-20真机POWER休眠原始流的形态（常规轮次加一次138秒冻结）覆盖阈值、写出时机、失败退避、环形上限、墙钟与单调差异及单调回退。原控制安全测试继续覆盖SD队列、停用／恢复、护眼期限、setup宽限与交接。真机需另验短按快捷键、HOME／POWER、通知撤回、休眠唤醒与计时恢复。

回执降频回归位于 `tests/c/test_result_polling.inc`，直接调用生产传输与恢复读取器并统计存储调用：20ms假时钟驱动、30秒无回执窗口，普通SD请求32次回执读取／done检查（原299次），中断兑换恢复33次（含首次立即读取），只允许原请求的一次提交。覆盖首次100ms、退避边界、迟到成功、done但无回执、损坏／错ID、真实超时、整型饱和、IPC受理未知／事件失败／结果失联、无SD的IPC事件成功、重开／切换ID／单调回退和读失败后恢复。Switch接线由 `test_switch_ipc_lifecycle.py` 核对两客户端共享恢复读取器、通知偏好5秒定时重读及IPC提前读取、浮窗导航复用既有新鲜度且显式刷新／归零复查仍独立。

性能优化的确定性边界：`test-loop-clock` 覆盖快速／慢速循环、时钟回退和饱和计时；NRO setup 回归验证同 tick 重复轮询不提前超时，以及真实 30 秒后仍接收原激活请求的迟到回执。`test_input_owner` 计数确认 100 组相同文件的 reader／writer 检查保持 400 次新鲜读取且零 JSON 分配，并覆盖缓存后失败、释放和换 boot。`test-audio-lifecycle` 使用假 audout 验证按需启动、空闲不查询、队列耗尽／禁音／取消停止及服务失败；`test-runtime-resources` 增加 65,536 组通道／alpha 组合与原 Tesla 混合公式等价比较。文本测试逐项遍历三语，Result 测试保留无效输入与树所有权检查。

运行资源回归由 `test-runtime-resources` 纳入统一 `test-host`，执行生产缓存／日历、NRO 图元及 Overlay 换行代码。检查 10KiB 文本缓存替换后至少节省 8KiB、连续缓存命中零解析、保存 JSON 往返、元数据／存储／损坏失败、跨年及远期日历损坏；对照冻结的旧算法检查阴影像素、文本换行、居中和按钮省略，记录字体操作、测量字节、临时分配及五组 Host 耗时。同时对比常驻后台的空闲轮次：同一 fixture 上“每次唤醒都执行完整轮次”与“先做到期探测、再按需执行”的存储调用次数，要求探测节奏至少减半、跳过的轮次零写入、唤醒计算不触碰存储，并记录完整轮次数量。计数和故障注入仅在 Host 测试编译中启用。输出为 `build/host/runtime-resources.json`，参考实现仅用于测试，不进入生产组件。

NRO 像素混合回归遍历 256×256 个源／目标通道值与 alpha 0／1／127／254／255，对照标量公式检查 RGB、输出 alpha、裁剪边界及非默认行跨度；全不透明路径必须强制输出 alpha 255，完全透明路径保持目标原值。

NRO 提前裁剪回归将完整绘制后遮罩与裁剪绘制逐像素比较，覆盖圆角矩形、描边、渐变、圆圈、粗线及三语灰度／粗体／固定 BGRA 字形，包含越界位置、空／反向窗口和 stride padding。测试字形仅在 `PTC_RESOURCE_TEST` 下启用；字形获取、位置推进及分配失败重试仍遵守原契约。

NRO 换行回归使用冻结的旧拆行策略，比较实际行尾和下一行的字节边界及行数上限；覆盖三语、空文本、连续换行、空格回退、长单词、4,000 字节长文本、emoji 和零／负宽。参考实现只用于 Host，不进入生产构建。

热更新确认回归 `test_handoff_ready` 检查 120 次相同轮询只写一次且每轮新读，覆盖事务变化、删除、坏文件／超长、读失败和写失败重试；特别注入“新字节已可读但提交失败”，相同内容不得掩盖待重试的持久化失败。该去重只适用于冻结事务确认，不得复用于短期 ready 租约。

详情 JSON 序列化回归对照旧构造器逐字节检查字段顺序、最大数值、转义及 UTF-8，通过 cJSON 分配钩子断言零分配，并覆盖 ready/request/ACK 往返、1,023／1,024／1,025 字节边界、存储失败与恢复。打印器额外缓冲余量不扩大原协议容量；现有 transient ready／持久化 request 与 ACK 选择以及租约／续期门禁继续执行。

涉及这些绘制路径时，通过 `python tools/package_remote.py --with-previews --preview-scope all` 完成全矩阵门禁。优化前构建完成后，用 `python tools/build/runtime_resource_report.py --capture-baseline <全新JSON路径>` 保存基线；优化后用该工具的 `--baseline <基线JSON> --out <全新报告目录>` 封存对比，`--build-command` 记录实际统一构建命令，`--verify <报告目录>` 从已写入 JSON 和附件哈希重复离线核验。PPM 哈希逐文件相等才说明固定字体／时钟下像素未变。

控制路径回归包含同次Enforce状态共享：电视／护眼／未变化目标只做一次完整读取，失败不按消费者重试、不伪造用量或控制写入；下一次调用、设备秒变化、时钟回拨与跨日重新读取。目标修改后的确认必须取得新设置，disable期间不进行Enforce读写；既有跨日、模式切换、并发限制和事务回滚继续执行。

后台空闲到期探测由 `test_control_safety.c` 的 `test_scheduler_idle_probe` 覆盖：待处理队列、停用标志出现与移除、reload／retry 恢复标志、分钟变化、扫描退避到期、护眼休息期限与 setup 宽限分别要求完整轮次；静默唤醒与静默时的完整轮次不产生任何存储写入或 PCTL 调用；`quiescing` 期间挂起完整轮次。该探测不加载规则、状态或 setup，完整轮次仍重读并校验全部输入。

全量截图不是日常集成测试前置。`python tools/package_remote.py` 默认运行全部 Host／UI 布局门禁及 Eden NRO 构建校验，不生成文档图片；`--with-previews`／`--previews` 默认仅处理中文文档引用图（当前 114 张），并行与增量启用。中英文文档图用 `--preview-scope docs`，完整三语、四风格与全部状态用 `--preview-scope all`，发版 `--release` 保留完整矩阵。跨语言／风格的绘制修改按影响显式选择完整矩阵。缓存、范围与串行开关见[构建与测试分层](构建与测试分层.md)。

`tools/test.py`对子命令使用命令私有的UTF-8环境，先收集stdout/stderr原始字节，再在调用线程严格解码。任一通道含无效UTF-8必须显式失败，不能让Windows读取线程异常后仍以子进程exit=0记为通过；`test_test_runner.py`覆盖中文输出、两通道坏字节、非零退出及`check=False`，并确认调用者环境不被修改。

`tests/devkit/test_package_remote.py` 在 devkitPro 的 GNU Make 环境用隔离目录执行实际根目录及后台 `clean` 配方：植入旧绝对路径的 Lab 依赖和生产/Lab输出，核对全部清除、重复清理成功、源码/配置/设备证据保留及 `CLEAN_EDEN` 两种模式。Windows 本地 Python 回归明确将此集成项交给统一 `python tools/package_remote.py` 门禁执行。

`tests/c/test_input_owner.c`通过统一C门禁验证NRO/Overlay输入占用、双槽替换空档、中性释放及写入/身份/时钟/未知存储失败收尾；生产NRO主入口与内部PIN使用同一保护，Eden不声明该生产能力。真机需绑定clean候选、原始占用记录、标准raw及两端status来源，并验证退出后NRO刷新恢复，详见[NRO浮窗输入占用](../真机与专题/NRO浮窗输入占用.md)。

### 自动更新、远端输入、兼容与协议安全边界

免系统重启自动化入口与恢复步骤见[无人值守更新与测试指南](../真机与专题/无人值守更新与测试指南.md)。`test_auto_update.py` 用假设备/输入/时钟覆盖完整更新、一次接管确认、读回失败、前台或恢复状态不符、超时不重放、截图不可用不阻塞、PIN 脱敏和离线索引防篡改；`test_release_manifest.py` 覆盖同 commit 内容变化、未跟踪源码、忽略产物及跨 profile 身份。C host 故障注入覆盖 journal 短暂/持续占用、commit 失败、静默期间原 SD 请求保留及客户端同时禁止 IPC/SD；生命周期检查约束恢复走三次不存在证明与有界就绪等待。`python tools/test.py` 和 `python tools/package_remote.py`（默认 Eden）是软件门禁，新增协调器的真机运行另行保存证据。

`test_auto_update.py` 的停采完成证明另覆盖完整终末成功、JSON读回/重复结果、缺终末、仍追加、残尾、run/boot/release不符、等待不足、布尔或回退单调时间、缺拉取、失败终末和计数矛盾。只有完整正常终末及两个至少7秒的稳定间隔才允许调用者继续claim完成归档。

`tests/c/test_firmware_compatibility.inc` 通过标准 Host C 入口覆盖 19 组首次启用、升降版本、AMS 或固件 hash 变化、旧 `read_ok=false`、机型未知、环境文件缺失、AMS 版本为 null、启动宽限及既有停用状态；部分环境的 pending 接管另验证家长重试的成功与失败。版本和环境元数据只提示，实际 PCTL 读取、布局、兼容记录写入、构建身份错误仍保护；不改额度、不启停计时、不覆盖安装快照，不在周期内重复读 PCTL。`tests/environment/test.c` 编译调用生产环境采集代码，注入摘要、机型、固件及服务初始化失败，验证独立查询、真实版本保留、原始 Result、JSON 读回和资源释放；NRO 集成测试读回诊断的真实停用原因与 setup 错误。统一验证使用 `python tools/package_remote.py`，默认保留 Eden NRO 构建与校验。

## 二、协议与业务功能回归
