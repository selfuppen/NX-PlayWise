# UI 实机验收清单

[测试指南](../测试指南.md) · [开发文档入口](../README.md) · [功能回归明细](../测试与模拟器/功能回归明细.md)

本清单承接自[测试指南](../测试指南.md)原「UI 实机验收」章节，集中记录主机应用、浮窗与多场景的真机可见性及交互验收项；单批真机结论与截图索引按月归档于[验收记录](../验收记录/README.md)。


修改 NRO 或 Overlay 后，至少验证：

- Overlay 儿童概览验证 30 秒边界、刷新中、刷新失败、就寝与每日额度并发、跨日和新回执恢复可用。自动弹出在真机上观察首个可见画面及后续原因，按本次 status 对齐通知实例和 ACK，单独覆盖撤回和超时。

- 主题专项：在家长区“设置 → 外观主题”中，“跟随系统 / 浅色 / 暗色”与四套设计风格各自是一组单选，选中项以圆环和实心圆点标出；方向键、触摸移动只改草稿并即时完整重绘，按 `A` 或底栏“确认保存”才把主题模式与设计风格一次写入 `config.json`，按 `B` 放弃草稿并恢复已保存外观。页脚在底栏上方同一行显示“已保存”和“待保存”两组取值，未改动时只显示已保存项；重启后两项同时保留；配置写入失败时恢复原主题与风格、保留页面并提示未保存。旧 `config.json` 缺少 `theme` 或值无效时按“跟随系统”处理，缺少 `theme_style` 时按石墨风格处理，系统主题读取失败则安全回退浅色，不能阻止 NRO 启动或改变任何控制状态。“跟随系统”在启动和从 HOME 菜单恢复后重新读取系统设置。OLED Hybrid 暗色逐页覆盖孩子页、首次设置、家长页、错误页和全部弹层；正文/次文字至少 4.5:1，焦点/功能边框至少 3:1；成功、警告、危险和中性状态同时使用几何符号、颜色与文字；二维码保持白底黑码且可扫码。Overlay 继续使用自己的固定深色受限色板，不读取 NRO 的主题偏好。

1. 使用没有 `config.json` 向导字段的全新配置，确认首次设置按“快捷键 → PIN → 外观主题 → 接管 → 进入区域”推进；中途退出后重启会恢复到已保存步骤。旧版未完成向导从第一步安全重启，已完成安装的步骤 `0` 保持不变；已经完成接管时不得重复提交接管请求，未完成前不允许普通写入。
2. 快捷键页固定显示 `Minus`，并提供 `L + R`、`ZL + ZR` 分别搭配四个方向键、`Plus`、`Minus` 在内的 14 项预设，不显示“录制其他组合”、录制触摸区域或 `X` 录制入口。选择只更新草稿，按 `+` 确认后才生效；未确认或明确关闭时仅保留 `Minus`。升级前已保存的合法非预设掩码不得被清除，且仍能解析和触发。首次快捷键页、区域选择摘要、孩子区页脚和家长区快捷键管理均须说明自定义组合需连续长按约 400ms，固定 `Minus` 松开即可进入且无需长按。分别真机验证 `L + R + 右` 的方向键和左摇杆右推连续按住约 400ms 后只触发一次、提前松开不触发、完全松开后可再次触发；组合候选按住期间不得穿透为孩子区普通输入。另验证固定 `Minus`、包含 `Plus`/`Minus` 的已保存组合及重启后的配置恢复。
3. 全新安装在认证状态合法且为空时自动创建默认 PIN `110`，认证文件只包含随机盐和哈希，不得保存明文；PIN 页明确提示弱保护，并提供“继续使用”和“修改 PIN”。覆盖修改默认 PIN、保留已有 PIN、已完成安装不覆盖、异常认证文件不覆盖和认证写入失败时停留本页并可重试。向导外的“修改任我玩PIN”仍必须先验证当前 PIN。PIN 输入另覆盖 1 位、6 位、64 位、65 位、非数字、两次输入不一致，以及少于 4 位只提示风险；所有 PIN 入口的错误都使用最上层“重试 / 取消”弹窗，错误后清空当前输入，两次不一致时清空两次输入。冷却弹窗逐秒更新剩余秒数并禁用重试，取消不计失败。摇杆 PIN 还需验证顺时针八方向映射、左右摇杆死区与单次锁存、十字键四方向、`X/Y` 的 0/9、触摸数字键盘、`ZL` 退格、`B` 取消以及短按/长按 `+` 的确认与临时系统键盘切换；方向示意中的 1 到 8 使用一致的主题强调色，不随数字键盘焦点产生异常变色，右侧四键圆阵列把 `X/0` 与 `Y/9` 标在对应圆内；已输入 PIN 只能显示掩码圆点。
4. 第 3 步可直接选择“跟随系统 / 浅色 / 暗色”，默认跟随系统并立即应用；原子保存失败时恢复原主题、显示错误并停留当前页。
5. 第 4 步接管确认前只做只读预检；确认后保存安装 snapshot，再次核对 `0x44`、timer、今日总额度和剩余时长，匹配时不写 PCTL、不调用 `1451`，直接保留现状并进入第 5 步。对已有官方限时日，记录“总 180 分钟、额度已耗（估算）60 分钟、剩余 120 分钟”向量：完成接管后必须仍剩余约 120 分钟（允许显示值相差 1 分钟），不得套用工作日默认 60 分钟；另覆盖“总 31 分钟、剩余 0、1455 不可用”，必须直接进入 active 且不临时解限。用 `failed + setup_release_failed + handover_today_pending` 复现旧版现场，重新接管不得返回 300；验证全部匹配后才删除 flag。若核对期间额度或 snapshot 改变，必须返回 313、保留 flag 且不得写 PCTL。无法读取总额度且无法由消耗估算加剩余计算时同样返回 313。制造旧后台与新版构建清单不一致的 `504 release_manifest_invalid`，确认向导提示完整重启主机后再试，并在仍失败时引导到 GitHub 项目 Issue 页反馈且包含致谢。
6. 第 5 步默认选中家长区，孩子区和家长区选项都显示简短切换说明；手柄或触摸选择区域后均不得立即进入，必须再触发独立的“确认进入家长区/孩子区”按钮。首次确认进入家长区不重复验证 PIN，之后从孩子区进入家长区需要 PIN。
7. 家长区“设置”页面存在“家长区快捷键管理”下级页，可选择预设或关闭自定义组合，并显示孩子区提示开关和当前状态；不得显示任意组合录制入口。关闭提示后孩子区不得显示固定 `Minus -`，也不得禁用任何已启用入口；“加时码”右侧帮助不得混入进入家长区或 PIN 说明。
8. 孩子首页使用等宽双栏“今日任务板”：左侧第一眼可读剩余时间、环形进度、今天与明天安排、已玩与剩余用时；右侧依次显示加时码、自主缓冲、使用详情和固定同步/异常状态卡。主进度槽下的“已玩”和“还剩”必须同字号（16px）且剩余分钟加粗，英文长标签先裁剪“已玩”而不是缩小字号；右列守护卡标题 16px、说明 15px，电视模式规则卡须同时容纳状态、模式与估算用量、规则摘要三行，且与护眼、就寝卡不重叠。调度看板（120–420）、七日预测（434–644）与右侧动作栏（状态卡底边 644）必须共用同一条内容底边，列间 14px 间距一致，动作栏各项不重叠且不压到底栏；“使用详情”按钮内的说明按当前语言实测行数整块居中，最多三行且不得溢出按钮。孩子区“使用详情”在标题与首排卡片之间显示 32px 导读条，只说明阅读顺序与“就寝、护眼、电视规则各自独立”，三语均须单行放下且不遮挡首排卡片；家长区今日详情不得出现该条，两个入口的“查看决策与规则”入口保持同一底边和同宽命中矩形。状态过期时剩余、用时条和两日规则都显示待确认，不得继续使用旧 forecast；不限时、0 分钟、1440 分钟、就寝生效、缓冲关闭/可领取/已领取、停用、等待和失败状态在浅暗主题下均不得重叠或越界。加时码输入弹层必须显示“主机今天 YYYY-MM-DD”和“生成加时码请选这一天”，日期只能来自 status 的 `day_index`；status 未加载时显示“主机日期待刷新”，不得改用 NRO 本地时钟推断。游戏内浮窗的加时码页在“已输入 X/8 位”同一行显示同样的主机日期与待刷新文案。游戏时间统计在按游戏数据不可用时必须明确显示“游戏明细暂不可用”，并把兼容字段只展示为“额度已耗（估算）”，不得伪造真实游戏时长或前 3 名游戏排行；孩子区只使用 `B` 或触摸退出，`+` 不得作为退出快捷键，以免与家长区自定义组合冲突；图形初始化失败的备用界面可保留 `+` 退出。
9. 家长区顶级页固定为“今日安排、时间计划、离线加时、安全与偏好、支持与恢复”。时间计划根页提供七张直达卡与七日预览；周计划、国家节假日和 bedtime 进入一级全屏编辑页，隐藏顶级页签并显示“时间计划 / 当前编辑项”，B 和触摸返回中枢并恢复来源卡焦点。安全与偏好直接提供外观、PIN、快捷键、hbmenu 入口和家庭活动；支持与恢复保留六项安全操作并可由 L/R 直达。紧急停用、恢复事务、protection 或 failed 时只在支持页签显示“需处理”，全局异常入口直接跳转支持页。正文、触控区域、状态卡和页脚不得重叠；弹层必须阻止输入穿透。
10. 顶级“支持与恢复”的六张卡始终显示，并保留五个页签与 `L/R` 循环；操作卡不得与右侧状态详情或最近执行重叠。当前无需执行的“确认接管系统控制”和“重试修复”等操作使用禁用样式且不可触发，并解释禁用原因。右侧状态详情不得重复全局底栏的控制状态、系统限制和今日计时；系统版本、主机型号、Atmosphère 检测结果分行显示。最近三条事件不得与排障摘要重叠或被截掉，手柄和触摸均可打开详情；PIN 认证后的家长区详情可展示设备标识、路径、原始事件名、请求 ID、错误码与内部状态，但任何页面仍不得显示完整 `grant_secret`、PIN、令牌签名材料或其他可复用秘密。无事件和读取失败必须分别提示。第六张卡为“软件信息”；手柄和触摸均可打开弹层，显示应用版本/`release_id`、当前后台 `release_id`、已加载/待加载/热加载不可用/安装不完整状态、项目仓库和家长网页。待加载时显示“暂不/加载新版”，确认只在 PIN 保护的家长区可达；其他状态按 `A`、`B` 或触摸关闭。不得显示内部 Device Lab 信息。
11. 手柄和触摸均可操作数字键盘、额度和周计划；弹窗输入不穿透。触摸打开 PIN 验证时，原触摸必须先完全抬起，不能串入 PIN 数字、退格、取消、确认或传统键盘；抬起后的下一次独立触摸正常生效。NRO 以高频输入循环采样触摸，并把后台结果轮询和绘制节奏独立限频；连续快速点击不得因旧的 100ms 采样间隔漏掉。分别验证约 50ms、80ms 和 120ms 的短触碰、按钮边缘触碰、完全抬起后的连续触碰，以及触摸危险确认按钮约 1 秒；快捷键约 400ms、危险确认约 1 秒和 PIN 长按 `+` 调出系统键盘约 1 秒的真实时长不得随输入采样频率变化。快捷键预设、最近事件、节假日开关与模式等紧凑行的整行间隙应归入相邻可见控件，不得形成细小的不可触碰区域。
固定家长入口补充：`Minus` 仅由独立按下／松开触发。回归须覆盖 `ZR＋Minus` 同时按下、两种释放顺序、Minus先按再加入修饰键、修饰键先按、组合取消后的下一次独立Minus、自定义组合长按仍正常，以及失去／恢复焦点、恢复应用或弹层切换后不补发旧释放。真机应在NRO儿童页打开再关闭真实浮窗，底层保持儿童页且无额外空PIN框；再单独Minus进入一次空PIN框、B取消返回，集中确认。Host通过不替代该真机交互观察。

12. 状态语言一致：绿色“正常运行”、蓝色“正在同步”、黄色“兼容性待确认”、橙色“保护模式”；红色表示需要家长关注且会阻止正常控制的状态。保护模式显示“安全保护已触发”，主动停用显示“紧急停用已开启”，两者可并列。
13. `disable.flag` 下孩子页和全部家长页持续显示红色停用状态；status、诊断导出、解除停用和恢复仍可用，额度、周计划和加时码写入在 UI 与后台均被拒绝。分别以 `restored + disable.flag` 和 `active + disable.flag` 验证支持页显示“解除停用并重新接管”；以系统从旧 HOS 升级到新 HOS 形成的 `protection + runtime_fingerprint_changed` 验证引导页和支持页显示“系统环境已变化，重新检测并接管”，家长确认且只读预检通过后更新兼容指纹、保留现有配置和安装快照、删除 flag 并进入 5 秒宽限。其它 protection 停用原因仍不得由该入口穿透；预检失败保留 phase 与 flag。
14. 家长区底栏高度为 44px；健康状态只显示稳定页面操作，时间计划一级编辑页固定显示 `B 返回计划 / Y 刷新`，右侧不绘制全局健康摘要。只有 protection、failed、停用、临时解除或恢复事务显示可聚焦、可触摸并可按 `A` 进入“支持与恢复”的右侧告警入口；超过 120 秒的陈旧状态只更新右上角状态条，不产生底栏告警。今日安排、时间计划、离线加时、安全与偏好、支持与恢复及计划子页的操作反馈统一显示为与底栏按键平齐的右下角状态胶囊，防止悬浮遮挡上方内容，不得使用横跨主体的反馈条。仅有错误原因或处理建议时显示 `X 详情`，按钮触摸区域必须与绘制区域一致；无详情时不得留下隐藏命中区，状态变化不得自动打开弹窗。验证隐藏入口没有命中区，告警出现和消失时焦点不会停在不可见目标。
15. 成功刷新超过 2 分钟后隐藏旧剩余分钟数并显示“状态待确认”；Nintendo 家长控制未启用、临时解除和读取不可用必须分别显示，不能把未知值显示成“否”。对“当天限时 60 分钟、额度剩余 0、系统临时解除、计时器已确认停止”向量，首页必须仍显示限时规则和 0 分钟额度，另行提示“临时解除期间不计时，进入睡眠后恢复限制”，计时器显示“未计时”而不是“未确认”。临时解除期间修改今日额度或领取缓冲必须保存设置但不得调用 `1451`。支持页不得再硬编码“到期行为：系统提醒”。
16. “导出诊断包”先提醒文件可能包含设备标识和文件路径，只应发送给可信支持人员；确认后的进行中、成功和失败状态均留在“支持与恢复”当前页，不得打开结果弹层。成功状态分三行完整显示导出路径、提交 GitHub / Gitee Issue 时附加文件的说明和 `https://github.com/selfuppen/NX-PlayWise/issues` / `https://gitee.com/selfuppen/nx-playwise/issues`；离开支持页后清除。导出前刷新一次状态，确认 `runtime_snapshot` 包含 status 时间与年龄、计时/限制读数及其可用性、规则来源、紧急停用、活跃恢复事务、请求处理中和传输类型；未刷新时必须明确 `status_loaded:false`，不得把默认数字冒充实时读数。支持包中搜索 secret、PIN、已提交 8 位码、完整 nonce、私有 raw layout 和 recovery 原始内容均无匹配。
17. 进入/重新进入孩子页、切换到家长区“今日安排”以及每个今日写入入口都会主动刷新状态；休眠解除或切回前台后同样刷新状态并同步安全标志。状态在 120 秒内（含边界）视为新鲜，超过 120 秒隐藏旧剩余并显示“状态待确认”。快速加时和 bedtime 跳过都必须在新鲜状态上继续；刷新失败不得进入写入，旧 bedtime 实例不得自动替换为另一实例。
18. “设置今日总额度”、快速加时自定义值、周计划、节假日、指定日期额度、本机加时码和就寝时刻共用紧凑双栏编辑框。L/R 固定选择小时或分钟；ZL/ZR 对普通时长和就寝时刻前后调整 15 分钟，本机加时码选择上一/下一合法档位。右摇杆首次推动立即调整，300ms 后重复，分钟栏在持续 700ms 与 1.4 秒后依次使用 `±5`、`±15`，重复间隔依次约为 100ms、67ms、33ms；小时栏始终每次 1 小时，只加快频率。普通计划范围 1–1440，快速加时 1–120，就寝时刻在 00:00–23:59 循环；本机加时码只接受协议合法面额和设备上限。取消或非法输入不修改草稿。
