# PCTL1952 标准后台只读取证

标准后台包含默认关闭的生产采集支持。它用于取得冻结标准组件自己的原始读数，不改变 `pctl1952_v1_proxy1440` 策略，也不自动取得真机资格。与 `PLAYWISE_PCTL_CAPTURE` 诊断旁路不同，启用它只准备专用配置，不重编译、不替换 NSP。Device Lab 不启动此记录器；Eden 不能提供真实 wire 证据。

## 配置与生命周期

先完成 clean 三包冻结，再离线准备新目录：

```text
python tools/pctl_standard_evidence.py prepare --packages <冻结packages> --out <全新采集目录> --duration-s 3600
```

工具校验标准/Lab/完整包身份及原字节，生成 `plan.json`（含三包与三个组件哈希）和 `usage-evidence.json`；已有目录不覆盖。准备不部署、不连接设备、不填人工观察。配置具有且仅具有以下五个唯一键：

```json
{"schema_version":1,"run_id":"<32位小写hex>","commit":"<完整40位commit>","release_id":"<冻结release_id>","duration_s":3600}
```

不能立即正常启动时，只暂存候选：

```text
python tools/pctl_standard_evidence.py stage --out <采集目录> --host <FTP地址> --ftp-port 21
```

stage 只写 `sdmc:/switch/playwise-qualification-staging/<run>/`，回读三个冻结组件、manifest和配置，前后核对现用组件/build/公共rules/runtime哈希；不替换live文件、不放boot flag、不激活采集。源包变化、已有本地journal/远端目录、歧义FTP错误、回读失败或现用身份变化均停止；未知结果保留原journal，不重放。恢复与激活是另一个已准备事务，不能把暂存当实际加载。

尤其不能在旧后台继续运行时先覆盖live `build.json`并无限等待重启：标准后台周期检查它与`compatibility.json`接受的release ID，失配会进入`protection`并写`runtime_fingerprint_changed`。本机已实际遇到此门禁并经原像回写、标准`complete_setup`预检恢复。下一次安排立即正常启动时再激活整组文件；新boot可能需要该标准重新检测/接管入口，核对有效raw和环境后执行，不能手改兼容身份或删除保护标记。详见[P1暂存与恢复记录](PCTL1952-P1暂存与恢复记录-20261014.md)。

只有明确准备了现场前像、恢复材料与实际加载身份后，才在授权范围内将配置放到 `sdmc:/switch/playwise/support/usage-evidence.json`，回读原字节，然后正常启动。源码/候选身份必须匹配；默认安装包不提供此配置。标准后台在启动时读取一次，300–7200 秒租期从该次初始化的设备单调时刻起算，每五秒至多一次。启动后改租期不能延长；配置移除或字节变化、单调时间回退、租期到期、连续三次无效读取或保存失败均锁存停止，当前进程不重新激活。正常 handoff 也停采。

输出是 `support/usage-evidence-<run>-<boot>.jsonl`，初始化拒绝已有同名文件，不覆盖旧 raw。开始行绑定完整 commit/release/run/boot、起始 tick、租期和周期；样本只追加；停止行记录原因、尝试样本数和连续失败数。保存失败可能使停止行缺失或最后一行不完整，此时停采证明仍需间隔超过周期的重复只读拉回；不能用文件不变独立证明进程仍存活。

记录器与标准控制同线程、同进程，不增加权限、线程、独立模块、输入、电源、PM/PDM、timer 启动或设置写入。每组通过短时 `pctl:s` 会话读取 1453/1454/1455/1952/145601/1006，每条退出路径释放对象；不修改展示缓存、高水位或上一控制事务 Result。读取导致的资源/时延影响仍须在实际候选上观察，Host 通过不代表长期真机稳定。

## 原始字段与失败语义

| 字段 | 含义 |
| --- | --- |
| `kind` | usage_evidence_start / usage_evidence_sample / usage_evidence_stop |
| `begin_ns/end_ns` | 包含会话初始化、全部命令和设备日期读取的实际组跨度；规范化配对跨度取差，不能填固定容差 |
| `unix_before/unix_after`、`day_before/day_after`、`clock_before_valid/clock_after_valid` | 设备组前后时钟/本地日；跨日或回拨不合格，失败的默认数值不当有效时间 |
| `session_result` | 服务获取、domain、子对象和初始化的 Result |
| `timer_result/timer_enabled` | 1453 Result 与 wire 布尔值 |
| `remaining_result/signed_remaining_ns` | 1454 Result 与未钳制带符号纳秒十进制字符串 |
| `restricted_result/restricted` | 1455 Result 与 wire 布尔值 |
| `spent_result/total_ns` | 1952 Result 与原始带符号纳秒字符串；负值无效但保留 |
| `settings_result/settings_hex` | 145601 Result 与完整 0x44 小写 hex，不把零缓冲当读取成功 |
| `unlocked_result/temporarily_unlocked` | 1006 Result 与官方临时解除状态 |
| `start_timer_calls` | 本进程从初始化起实际派发 1451 的累计次数（十进制字符串），包含失败 IPC，不包括打开会话失败而未派发的路径 |
| `valid` | 时钟有效且同日不回退、跨度 0–2 秒、全部 Result 成功、累计非负；不证明设置语义/业务规则/实际可用性 |

失败字段保留原 Result 和缓冲，不伪造成功或去掉负号。连续失败上限包括任一命令失败、无效时钟/跨度/累计或保存失败；成功采样归零连续失败计数。该计数不能跨 boot 拼接。原始组可用但临时 PIN 为 true 时，正式短链仍不合格；不把 PIN 状态当 IPC 失败。

## 只读拉回和离线核验

```text
python tools/pctl_standard_evidence.py collect --out <采集目录> --host <FTP地址> --ftp-port 21
python tools/pctl_standard_evidence.py audit --raw <保存的jsonl> --plan <plan.json> --output <全新audit.json>
```

collect 每次只做一次 FTP 拉回，不提交 status/控制请求，因此真休眠窗口可使用。外部批次驱动仍需明确截止时间/失败上限；不得无限轮询。文件名只匹配当前 run 和合法 boot；每个原始快照按全部字节 SHA-256 命名，已有相同哈希文件只核对，不覆盖前一次快照。raw 先落盘，再审计；审计失败不会删除原件。保存不完整尾行并单独标记，完整行的畸形/重复键直接拒绝。审计检查实际身份、类型、wire/时钟有效性、1451 单调累计、停止计数和大于 300 秒的采集缺口，输出始终 `qualified:false`。

规范化另存样本文件：monotonic_ns 取该组 begin_ns、captured_at 取 unix_before、day_index 取 day_before；pairing_span_ns 必须取 end_ns−begin_ns；1952/1454/timer/1006/1451 来自同一有效 raw 行。执行模式从该行完整 0x44 按仓库布局解码，失败、无配置或未知布局不强行转换为不限时。业务模式/分钟、限制原因及实际授权另引标准公共规则、阶段操作和同 ID/type 请求回执；原始流没有这些字段，不由 raw BLOCKED 推断业务额度。

四短链保持同 boot/日并满足既有数字门禁；每份规范化样本绑定 raw SHA-256，保留行号、公共规则和回执出处。记录器不生成阶段、不代替操作者签署，不自动修改资格索引。完整 0x44/timer 恢复和实际使用效果仍依赖原始前像、恢复后的有效采样及独立人工观察；停采与规则恢复是不同事务，各危险窗口按原期限恢复。

## 回归与当前范围

`test_pctl_adapter` 执行真实标准 adapter，覆盖全部会话失败、六条读取命令失败、负累计、读中跨日、时钟失败、超跨度、缓存/Result 不受影响、1451 成功与失败派发计数和句柄释放。`test_usage_evidence` 覆盖默认关闭、身份/重复键/尾部拒绝、已有输出不覆盖、五秒限频、读取与保存三次失败、成功复位、租期、配置移除/变更及锁存停采。Python 回归覆盖 clean 三包准备、无效租期、严格 raw、错误值保留、boot 混用/倒退、重复键、不完整尾行和多次只读拉回原件保留。

额外离线故障回归验证服务器可能已保存文件后网络超时：保留唯一write intent和未知结果，同一journal拒绝重放，现用文件不变；plan中的包哈希变化在首次远端写入前拒绝。错误候选、旧诊断流、重复键或完整非法UTF-8行导致审计失败时，先保存的原始字节仍完整保留；随后有效快照使用独立哈希文件，不修复或覆盖旧raw。这些故障只在确定性Host替身中注入，不破坏真实配置或在设备上强造网络故障。

实际验证命令：`python -X utf8 tools/test.py`；`python -X utf8 tools/package_remote.py --port 18881 --docker-container playwise-explain-build`（含默认 Eden）。冻结候选继续运行 `--release`；正式候选稳定性、四短链、画面观察和恢复尚待真机批次，不能由本页回归晋级资格。
