# 构建与测试分层

[开发入口](README.md) · [测试操作手册](测试操作手册.md) · [功能分层测试策略](分层测试策略.md)

## 日常最小门禁

涉及 C、NRO、Overlay、Makefile 或 package 时，直接运行 `python tools/package_remote.py`。入口在一次 SSH 会话中依次完成：

1. Host C/C++、真实 NRO 编排、故障注入、完整 Python 回归，以及 UI 原语、布局与预览存储检查。
2. 采集当前源码和工具链身份，分别生成标准版与 Eden 清单。
3. 增量构建标准后台、NRO、Overlay 和独立 Eden NRO。
4. 重新组织标准 Zip，核验包成员、默认配置、敏感标记、三组件哈希与嵌入身份，并检查 Eden 产物。

测试先通过，才能生成候选身份和构建产物；失败阻止后续依赖步骤。`-j` 只并行同一阶段中可独立执行的任务。默认不启动模拟器，不生成全量文档图片，不构建 Lab 或 Complete。

只改 Python 时用 `python tools/test.py`；只改文档索引时做引用和内容核对。需要完整构建时，无需固定先跑一遍完整 `tools/test.py`：统一入口已经包含同一套 Python 回归。定向测试用于修复过程中的快速反馈，不能取代最终门禁。

## 专项按影响选择

| 目标 | 统一入口参数 | 触发条件及边界 |
| --- | --- | --- |
| 日常完整产物门禁 | 默认，无附加参数 | 保留标准包、全部 Host 回归和默认 Eden NRO 构建／校验 |
| 文档 UI 预览 | `--with-previews` | 默认只生成中文文档引用图（当前 114 张），含所引用的浅暗主题及浮窗；增加渲染、转码和中文文档同步 |
| 扩展视觉检查 | `--with-previews --preview-scope docs`／`all` | `docs` 为中英文文档引用图（当前 228 张）；`all` 为全部页面状态、三语与风格主题矩阵 |
| 只更新文档图片 | `--previews` | 复用预览程序，不构建包；不能作为 C／生产包最终门禁 |
| 离线网页／完整交付 | `--with-complete` | 校验离线 HTML，封装字节不变的标准 Zip |
| Device Lab | `--with-device-lab` | 实验工具或正式资格所需包组；Host Lab 确定性测试仍在日常回归内 |
| 全量发布 | `--release --clean` | 标准、Complete、Lab、Eden、文档预览及全清理；后续模拟器／真机验收另执行 |
| 工具链变化／残留排查 | `--clean` | 清除编译缓存，保留标准清理契约，不作为每次日常构建前置 |
| 独立能力探测 | `--with-usage-probe`／`--with-pctl-capture` | 只用于明确的探测专项，不纳入默认生产包 |

`--only eden`、`--only device-lab` 等只证明所选产物；不能用这些局部门禁替代生产包验证。`--skip-tests` 与关闭 Eden 仍是诊断开关，不能作为日常验证通过或发布依据。Eden 业务场景按发版前最小集合与受影响专项执行；默认构建成功不代表场景通过。

## 重复步骤与复用边界

| 工作 | 处理方式 | 失效／必须重做的条件 |
| --- | --- | --- |
| Host 测试和预览程序编译 | 复用有效二进制；移除无条件强制编译 | 对应源文件、任一受监控头／`.inc`、Makefile、编译器命令／版本或 flags 改变；删除输入也使缓存失效 |
| 文档预览渲染 | 按 NRO／Overlay 分别缓存；默认只选择中文文档图，独立布局检查每次执行 | 预览二进制、字体、包装脚本内容或范围变化，PPM 缺失、为空、大小或纳秒修改时间变化；渲染失败清除该项成功缓存 |
| 预览图 PNG 转码 | 仅转码所选范围，跳过非空且不早于 PPM 的 PNG | PPM 更新、PNG 缺失／为空或显式强制转换；首次完整矩阵仍可能很慢 |
| 多 profile 源码／工具链扫描 | 同一次 Make 只采集一次，输出独立清单 | 每次调用重新采集，绝不跨批缓存 dirty、源码指纹或工具链身份 |
| Switch 目标文件 | 编译器 `.d` 跟踪真实包含关系 | 清单变化只重编译实际引用它的单元；Makefile／项目版本变化仍使相应组件重编译 |
| NACP 元数据 | 仅依赖组件 Makefile 与项目版本 | 不因普通 `.d` 文件更新时间而重复生成 |
| Host 与 Switch、生产与 Eden | 各自保留缓存 | 架构、宏和适配器不同，不能互换目标文件 |
| 测试执行 | 每次完整执行 | 不缓存“上次通过”，不根据源码未变跳过故障与边界检查 |
| Zip 组织及安全／身份核验 | 每次执行 | 校验便宜，复用编译产物不代表当前 Zip 已通过 |

Host 头文件监控采取保守策略，包含 `common/`、`companion/`、`platform/`、`sysmodule/`、`device_lab/`、`tests/`、`third_party/` 的 `.h`、`.hpp` 和 `.inc`。因此无关头文件变动也可能触发 Host 重编译；这是完整依赖保障，不以较窄且可能漏项的手工列表换速度。工具链、平台或挂载路径变化时仍执行 `--clean`。

预览与编译默认采用 8 路预算，统一入口的 `--jobs` 同时传给 Make、渲染器和 PNG 转码，`--jobs 1` 串行。原语、布局、协议、安全与包检查不因预览缓存命中而跳过。单独 `make ui-previews` 使用 `PREVIEW_SCOPE=docs-zh`、`PREVIEW_JOBS=8`；可用 `PREVIEW_FORCE=--force` 强制重绘／转码。已有全量目录不自动删除，普通预览只处理所选文件，不以旧目录总数声称当前矩阵通过。

## 如何测量

保持同一工作区、容器、并行数和目标组合，记录完整命令、退出码与端到端挂钟。首次编译与源码不变的重复构建分别报告；不能将清理构建和增量构建比较成同配置加速，也不能把关闭测试、Eden、Lab 或预览的差异算成编译优化。

统一入口输出 `build/build_timing.json`，原始记录保留每次编译调用；表格按阶段汇总 Host 编译、UI 检查、C 执行、Python、身份生成及产物步骤。耗时自测使用独立的 `PLAYWISE_TIMING_FILE`，不会把 fixture 的 `test-stage` 写进真实构建报告。计时诊断失败不改变门禁结果。

累计阶段计时含并行重叠，除以挂钟不能证明串行基准或“节省了多少秒”。优化收益用前后实际端到端测量计算，并说明样本数、首次成本和磁盘缓存影响。无变化复跑仍应能看到测试执行，Host 编译为零次；有变化、缺失依赖、配置变化和编译失败的拒绝路径由隔离 Make 集成回归验证。
